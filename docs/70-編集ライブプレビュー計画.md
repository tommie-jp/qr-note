# 70. 編集ライブプレビュー計画

編集タブの CodeMirror に Obsidian 風のライブプレビューを足す。カーソルが
乗っていない場所は記法 (`#` や `**`) を隠して装飾済みの見た目にし、カーソル
が入った場所だけ生の markdown に戻る。**本文は 1 バイトも書き換えない** —
装飾は CodeMirror の Decoration (表示層) だけで行う。従来のプレーンな
編集表示はトグルで残す。

## 1. なぜ別の WYSIWYG エディタを載せないか

Milkdown / MDXEditor / Tiptap のような WYSIWYG エディタを編集タブに並べる
案は**却下**した。理由は 3 つ。

- **git 履歴が汚れる**
  ([57-ノートgit履歴計画.md](./57-ノートgit履歴計画.md))。
  この種のエディタは markdown を独自のドキュメントモデルへ読み込み、保存時
  にシリアライズし直す。箇条書き記号・エスケープ・空行が正規化され、
  **触っていない行にも差分が出る**。1 文字直しただけで全文が書き換わった
  履歴が残り、履歴を読む価値そのものが下がる。
- **独自記法の再実装が全部要る**。アラート・タグリンク・```quiz フェンス
  ([58-CBT問題集計画.md](./58-CBT問題集計画.md))・circuitikz / tikz /
  mermaid・KaTeX・脚注。これらをエディタごとのノード + シリアライザとして
  作り直すことになり、閲覧側 (MarkdownView の remark 資産) と二重実装になる。
- **シークレットと相性が悪い**
  ([51-部分暗号化計画.md](./51-部分暗号化計画.md))。
  シークレットは「本文の state を平文が通らない」ことが設計の根幹で、
  本文を意味解釈して抱え込む WYSIWYG のモデルとは根本的に噛み合わない。

加えて、CodeMirror の既存資産 (フェンス補完・linter・文字数 changeFilter・
下書き退避・undo ボタン・添付の挿入経路) を捨てて作り直すことになる。
ライブプレビュー方式ならこれらは**全部そのまま生きる**。

MDXEditor は gzip 851KB という大きさも単独で不採用理由になる
(エディタは初回描画の経路にある。MemoEditor が CodeMirror を遅延読み込み
してまで削っている場所)。

## 2. 方式 — 本文を書き換えない Decoration

CodeMirror 6 の syntaxTree で markdown の構文ノードを列挙し、

- 記法トークン (`**` `#` `-` など) を `Decoration.replace` で隠す、
- 内容側に CSS クラス (`Decoration.mark` / 行クラス) を付けて装飾する、
- selection がノード範囲と重なる間は隠すのをやめて生記法を見せる

だけを行う。`state.doc` は常に生の markdown のままなので、

- undo 履歴に装飾は 1 手も積まれない (「元に戻す」の活殺も従来どおり)、
- 下書き退避 (memoDraft) が見る値も不変、
- アップロード / OCR のプレースホルダ置換 (replaceToken の文字列一致) とも
  干渉しない、
- 保存される本文はトグルの ON/OFF で 1 文字も変わらない。

性能の心配も要らない: 本文上限は 10,000 字 (MAX_TEXT_LENGTH) なので、
全文走査の Decoration 再構築でも十分軽い。

## 3. 部品 — atomic-editor を土台にする

同方式の既存実装 3 つを調査した (2026-08 時点)。

- [atomic-editor](https://github.com/kenforthewin/atomic-editor) (MIT) …
  開発が活発 (最終 push 2026-08-03、npm `@atomic-editor/editor` 0.6.2)。
  見出し・強調・リンク・タスク・スマートリスト・テーブル・画像に対応し、
  3 ブラウザの Playwright E2E と markdown 契約テストを CI で回している。
  React ラッパは薄皮で、**CM6 拡張だけの利用が公式にサポートされた形**
  (`inlinePreview` 等を個別 export)。IME 合成中の commit 抑止・pointerdown
  中の装飾凍結・行高不変 (CLS 対策) など、この方式の落とし穴への防御が
  一番厚い。
- [live-markdown](https://github.com/blueberrycongee/codemirror-live-markdown)
  (MIT) … 全バージョン alpha で 2026-03 から停滞。ただし設計ドキュメント
  (CODEMIRROR_LIVE_PREVIEW_DESIGN.md) が優秀で、KaTeX widget のキャッシュ
  方式など Phase 3 の参考にする。
- [ixora](https://github.com/retronav/ixora) (Apache-2.0) … 2023-05 で
  保守停止。約 1,400 行と小さく設計パターンの読本としては良いが、
  @codemirror/\* を peer でなく通常 dependencies に持ち、
  **state の二重インスタンス事故の火種**になる。

**`@atomic-editor/editor` を採用**する。ただし、

- React ラッパ (`AtomicCodeMirrorEditor`) は使わず、CM6 拡張だけを
  MemoEditorInner の extensions に組む (エディタ本体は今のまま)、
- pre-1.0 で minor に breaking が来る宣言のため **exact pin** (`-E`) し、
  更新は CHANGELOG を読んでから手で上げる、
- 撤退線: MIT + 純 CM6 実装なので、保守が止まる・独自化がぶつかる時点で
  必要ファイルだけ vendoring に切り替えられる。

## 4. 組み込み — Compartment でトグルする

@uiw/react-codemirror は extensions の**参照**が変わると拡張一式を組み直す
(MemoEditorInner の BASIC_SETUP のコメント)。そこでトグルは配列の
差し替えではなく **Compartment.reconfigure** で行う: extensions には
`compartment.of([])` を最初から入れておき、ON で inlinePreview 一式に、
OFF で空に入れ替える。配列の参照は不変のまま保てる。

- トグルボタンは EditToolbar の横スクロール帯に足す (`aria-pressed`)。
  選択は localStorage に記憶する (ノート単位ではなく端末単位。
  記法を隠したい人はどのノートでも隠したいはず)。
- **覚えてある設定は拡張を組むときに読む。** 「常に OFF で組んで、
  マウント時の effect で入れ直す」は効かない — その時点では
  @uiw/react-codemirror がまだ view を作っておらず、dispatch が黙って
  捨てられる。ボタンは ON の見た目なのに装飾が出ない、という形で出た。
- **既定は OFF で出す**。iPhone 実機で日本語 IME の検証 (§8) を経てから
  既定 ON に切り替える (1 行の変更)。
- タブ構成 (markdown / テキスト / 編集) は変えない。あくまで編集タブの
  中の表示切替であり、「従来のテキストエディタを残す」はトグル OFF が
  そのまま満たす。
- スタイルはパッケージの styles.css を編集画面でだけ読み込み、色・余白は
  既存のエディタの見た目 (Tailwind) に合わせて上書きする。

## 5. Phase 1 の範囲 — 入れる装飾と外す装飾

**Phase 1 は実装済み** (トグル・添付チップ・設定の記憶)。既定は OFF のままで、
iPhone 実機の日本語 IME 検証 (§8) を経てから `LIVE_PREVIEW_DEFAULT`
(`src/lib/livePreviewPref.ts`) を true にする。

**入れる** (inlinePreview の範囲): 見出し・太字 / 斜体・打消し線・
箇条書き / 番号付きリスト・チェックボックス・リンク・引用。

**エディタの構文解析は GFM にすること** (`markdown({ base: markdownLanguage })`)。
既定の base は CommonMark だけで、`- [ ]` も `~~消し~~` も表も構文木に
出ない (TaskMarker / Strikethrough / Table のノードが無い) ため、
上のうちチェックボックスと打消し線が**黙って効かない**。本文の描画は
remark-gfm で GFM として解釈しているので、揃えないと食い違う。
これは実機で見るまで判らなかった (装飾が付かない形でしか出ない) ので、
`markdownParser.test.ts` で構文木の中身として固定した。

**外す** (`inlinePreview` と別 export なので単に組まない):

- **画像 widget (imageBlocks)**。本文の画像記法は画像専用ではない —
  音声 / 動画 / PDF / テキスト添付 (`![audio](url)` 等) とシークレット
  (`![ラベル](/api/secrets/名前)`) が同じ記法を使う。素の `<img>` widget
  では音声 URL を画像として描き、シークレットは壊れた画像になる。

  **ただし代わりが要る (実装時に判明。Phase 3 から前倒しした)。**
  `inlinePreview` は非アクティブ行の `![alt](url)` を**丸ごと隠す** —
  画像は imageBlocks が行の下に描く前提だから。imageBlocks を外したまま
  何も足さないと、記法は隠れたのに何も出ず、**添付を消したように見える**。
  そこで URL で描き分ける自前のチップ (`attachmentBlocks`) を対で組む。
  実装は `src/components/editor/attachmentBlocks.ts`、種別 → 見た目の
  対応は `src/lib/attachmentChip.ts`。判定は閲覧側と同じ `classifyImgSrc`
  を使う (そのために `markdownPipeline.tsx` から `src/lib/imgSrcKind.ts`
  へ移設した — 移設前の置き場は Server Component 用で、編集画面から
  import すると react-markdown 一式がクライアントへ降ってくる)。
  alt の幅記法を剥がす `parseAltWidth` も同じ理由で
  `src/lib/altWidth.ts` へ移設した (剥がさないとチップに「図|200」と出る)。
  サムネイルは実物を出すが**箱の大きさは固定**にして、読み込みの前後で
  行の高さを動かさない。出すのは**自前の画像の縮小版 (`?thumb=1`) だけ** —
  原寸は 1 枚数 MB あり、1.75rem の箱のために落とすと写真の多いノートで
  数十 MB を引く。外部画像 (`https://…`) は出さない (編集画面を開くだけで
  第三者へ要求が飛ぶ。一覧プレビューと同じ方針)。
- **テーブル widget (tables)**。contenteditable セルから本文へ**書き戻す**
  機能で、「本文を書き換えない」という Phase 1 の性質から外れる。
  undo との整合を検証してから Phase 3 で判断する。
- **wikiLinks / highlightMarkdown**。`[[ ]]` と `==` の記法はこの
  プロジェクトの本文に無い。有効にすると余計な解釈が増えるだけ。

数式 (`$...$`)・フェンス (quiz / mermaid / circuitikz / tikz)・`#タグ` は
Phase 1 では生のまま表示される。閲覧はこれまでどおり markdown タブがある
ので、段階的で困らない。

チェックボックス widget はクリックで `[ ]` ⇄ `[x]` を dispatch する。
閲覧側の書き換え規則
([55-チェックボックス操作計画.md](./55-チェックボックス操作計画.md) の
taskCheckbox.ts) と同じ本文になることをテストで固定する (§9)。

## 6. Phase 2 — 書式メニュー (実装済み)

「markdown を簡単に編集したい (スマホ)」の実利はライブプレビューより
むしろ書式ボタンが大きい。`#` や `**` はソフトキーボードでは記号面に
切り替えないと打てない。ただし EditToolbar の帯は既に満杯なので、
**「書式」ボタンを 1 つだけ足し、押すとメニューが開く**形にした
(長押しメニューと同じ部品 `SlotMenu`。
[62-下部バー長押し計画.md](./62-下部バー長押し計画.md) §3 の流儀)。

項目は 6 つ: 見出し (段の巡回)・太字・箇条書き・チェックボックス・引用・
コード。**ライブプレビュー OFF でも使える**ので §5 とは独立に効く。

置き場所は「元に戻す / やり直す」の次。打鍵の合間に使うものなので、
たまにしか使わない挿入系 (スキャン・画像・録音…) より手前に出す。

長押しではなくタップで開くのは、このボタン自身には「押したときの既定の
動作」が無いため — 下部バーのスロットは短いタップで値が循環するので、
あちらは長押しに割り当ててある。

決めごと (`src/components/editor/markdownFormat.ts`):

- **行頭の記法は互いに排他**。箇条書きの行でチェックボックスを押したら
  箇条書きの記号を `- [ ]` に**置き換える** (足さない)。番号付き `1.` も
  置き換えの対象にする (でないと `- 1. foo` ができる)。
  `> - item` のような入れ子は手で書けばよく、メニューで作る必要はない。
- **一部だけ付いている選択は「揃える」**。反転させると 2 回押しても
  元に戻らない。全部付いているときだけ外す。
- **見出しは選択の先頭行の段に全行を揃える**。行ごとに独立して回すと、
  段の違う行が混ざったときに何が起きるか読めない。巡回は
  無し → # → ## → ### → 無し (h4 以降は手で書く)。
- **斜体は入れない**。太字 `**` と前後が重なり、「`**太字**` に斜体を
  掛ける」が「星を 1 つずつ剥がして太字を解く」と見分けられなくなる。
- カーソル (選択なし) は記法の**後ろ**へ送り、選択ありは始まりを記法の
  **手前**に残す。前者は続けて打った文字が記法の外に出ないように、
  後者は選んだ 1 行目だけ記法が選択から外れないように。

ここは EditorState を読んで TransactionSpec を返すだけの層にしてある
(view も DOM も触らない) ので、node の vitest でそのまま検証できる。

## 7. Phase 3 — 自前 widget (添付・数式・フェンス)

- ~~**添付チップ**~~ … Phase 1 で実装済み (§5 の経緯)。
- **数式**: KaTeX は既に依存にある。live-markdown の
  「requestIdleCallback で先にレンダリングして HTML をキャッシュ、
  widget の eq() で同一内容の再描画をスキップ」方式を踏襲する。
- **フェンス**: カーソルが外にある間、既存の表示部品 (mermaid・
  CircuitDiagram・QuizMarkdown) を block widget として埋め込む。
  widget の toDOM で createRoot し destroy で unmount する (portal 管理)。
  見た目が本体の mermaid / circuitikz から始める。
- **テーブル**: atomic-editor の tables を評価して採否を決める。

## 8. リスクと検証 — 日本語 IME の実機検証が採用判定

- **日本語 IME (最重要)**。live-markdown には中国語 IME でのフリッカー
  報告がある。atomic-editor は IME 合成中の commit 抑止を実装しているが
  日本語での実績は不明。ここで駄目なら vendoring + 調整に切り替える
  (採用判定をここに置く)。

  **デスクトップ Chromium では問題なし** (CDP の `Input.imeSetComposition`
  で本物の変換操作を再現して確認)。見出し行・太字の中・チェックボックス行の
  いずれで変換しても本文は狙いどおりに入り、装飾は 4 種とも出たまま、
  **変換の直後の undo が 1 手で正しく戻る** (= 装飾が履歴を汚していない)。

  **iOS はまだ**。WebKit の合成は Chromium と別実装で、ここで代替できない。
  既定 ON にするのは iPhone 実機で確かめてから。
- ~~**画像記法の素の表示**~~ … 確認済み。`inlinePreview` は記法を丸ごと
  隠すことが判り、対で `attachmentBlocks` を組む形にした (§5)。
- ~~**state の二重インスタンス**~~ … 確認済み。導入後も
  `npm ls @codemirror/state` は 6.7.1 の 1 本 (他はすべて deduped)。
- ~~**添付チップの見た目**~~ … ブラウザで確認済み。画像は縮小版
  (`?thumb=1`)、音声 🎵 / PDF 📄 / シークレット 🔒 (琥珀色) / 外部画像 🖼 が
  それぞれチップになり、**シークレットと外部画像は取得しに行かない**。
- **行高の変動**。見出しのフォントサイズ差で reveal 時にスクロールが
  跳ねないか実機で見る (atomic-editor は行高不変を設計原則にしている)。
- **干渉なしの確認**。undo 深さ (ボタンの活殺)・下書き退避・
  プレースホルダ置換・文字数上限・フェンス補完 / linter が、トグル ON の
  まま従来どおり動くこと。undo は上の IME 確認で併せて見た。

**この計画で踏んだ穴は 3 つとも「テストは通るのに動かない」形だった** —
帯の overflow によるメニューの切り取り (§6)、構文解析が CommonMark のまま
でチェックボックスが効かない (§5)、マウント時 effect の dispatch が捨てられて
設定が復元されない (§4)。lint・型・vitest・build を全部通しても出ない種類
なので、**画面に出るものはブラウザで見るまで「できた」と言わない**。

## 9. テスト

vitest は node 環境で DOM が無いため、**DOM の要らないところだけ**を
自動で固定し、見た目と操作感は実機に回す。

- `livePreviewPref.test.ts` … 設定の読み書き。壊れた値・読めない環境で
  既定に倒れること (localStorage は外部入力として扱う)。
- `attachmentChip.test.ts` … 種別ごとの出し分け。**シークレットを
  取りに行かない**こと、UUID の形でない `/api/secrets/...` を
  シークレット扱いしないこと。
- `attachmentBlocks.test.ts` … チップの装飾が記法の行末に 1 つずつ出る
  こと、フェンスの中を拾わないこと、壊れた記法を黙って飛ばすこと。
- `livePreview.test.ts` … 拡張一式が組み上がること (@atomic-editor/editor は
  pre-1.0 なので、更新で組めなくなったらここで落ちる)、ON/OFF いずれでも
  **本文が 1 文字も変わらない**こと。
- `markdownParser.test.ts` … エディタの解析が GFM であること
  (チェックボックス・打消し線・表が構文木に出る)。既定に戻したときに
  黙って効かなくなるので、「渡さないと出ない」ことも併せて固定する。
- `markdownFormat.test.ts` … 書式の付け外し (§6)。本文と選択を
  `|` (カーソル) と `«...»` (選択) で書いて 1 行で読めるようにしてある。
  **選択の印に `[...]` は使えない** — チェックボックスの記法と衝突する。
- `EditToolbar.test.tsx` … トグルの文字と `aria-pressed`、書式メニューが
  既定で閉じていること。

**実機に回すもの**: 記法が隠れる/戻る挙動そのもの、日本語 IME (§8)、
行高、チップの見た目、保存して本文が不変であること。

## 10. やらないこと

- 閲覧 (markdown) タブの置き換え。閲覧はサニタイズ済みの完成表示、
  編集は生テキストが真実、という役割分担は変えない。
- 本文の自動整形・正規化。ライブプレビューは見た目だけに徹する。
- Milkdown 等への将来乗り換えの布石づくり。この計画は CodeMirror の
  上で閉じる。
