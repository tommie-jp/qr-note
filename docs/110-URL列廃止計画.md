# URL 列廃止計画

ノートの `url` 列と `mode` 列 (memo / url の種別) を廃止する (2026-10-18)。

## 1. 何が困っていたか

Ver1 には「URL ノート」があった: QR シールの `/item/<番号>` を開くと、
`url` が入っていればサーバがそこへ redirect する
(`ver1/.../Page2Controller.js` の `res.redirect(item.url)`)。名刺の QR を
後から差し替えられるようにする、という使い方を想定していた。

Ver2 ([03](./03-移行計画.md)) はこの redirect を持ち越さず、`/item` は本文の上に
URL の箱を出すだけになっていた。編集も `/edit` の欄だけで、畳んだ編集タブ
([108](./108-ノート全画面表示計画.md)) からは触れない。使っているノートは
ローカルで 14 件 (URL ノート 3 件・メモに URL が付いた物 11 件)。

## 2. 決め

- `url` / `mode` の列と enum `Mode` を落とす。URL は本文の 1 行として持つ。
  全文検索はもともと `(memo, url)` の PGroonga 索引だったので、本文へ移せば
  検索の当たり方は変わらない。索引は `items_memo_pgroonga_idx` (memo だけ) に
  張り直す。
- 既存の行は migration の UPDATE で本文へ折り込む:
  - URL ノート … URL を 1 行目にし、元の本文を空行を挟んで続ける。
    `title` も URL にする (一覧の見出しと並び順が今までと同じになる)。
  - メモのノート … 本文の末尾に空行を挟んで URL の段落を足す。1 行目の
    直後に挟まないのは、1 行目がフェンスの開始や表のヘッダだと構造を割る
    ため (レビューで判明)。
  - UPDATE は冪等 (折り込み済みの行は `position(url IN memo)` で外す)。
    `updated_at` は触らない (内容の意味は変わっていない)。git 履歴
    ([57](./57-ノートgit履歴計画.md)) には乗らない。
- ZIP は読む側だけ残す。旧い ZIP の `url` / `mode` は取り込み時に同じ形で
  本文へ折り込む (`lib/zip/noteFile.ts` の `foldLegacyUrl`)。書き出しは
  `mode` / `url` の行を出さない。
- ENEX の取り込みはもともと memo 固定だったので変わらない。

## 3. 名刺 (redirect) を後で欲しくなったら

列として復活させない。理由:

- 名刺を読む人は未ログインなので、redirect は公開エンドポイントになる。
  ノート (既定は非公開) とは性質が違い、[90](./90-クローラ対策計画.md) の
  門番も別に要る。
- 自分のドメインから任意の URL へ飛ばす口はオープンリダイレクトで、
  フィッシングに使われる典型。飛ばせる先を公開ノートに限るなどの制限が要る。
- 要るのは短縮 URL サービスの機能で、ノートの属性ではない。作るなら
  `/go/<id>` のような専用の口にして、飛び先はノートのプロパティ行
  (`redirect=https://…`、[08](./08-プロパティ計画.md) の抽出で読める) か
  専用の小さな表で持つ。

当面は「QR を公開ノートに向け、本文の 1 行目にリンクを置く」で、1 タップ
増えるだけで同じことができる。

## 4. 触った所

- 消えた: `EditItemFields` (種別と URL の欄)・`ItemUrlBox`・`parseMode`・
  `ADOPT_SERVER_EVENT` (競合バナーから URL / 種別を揃え直す DOM イベント)
- 読み分けが消えて単純になった: `noteName`・`itemRowDecor`・`print` のラベル・
  オフライン検索の連結・オフライン一覧のタイトル順・`sortOrder` の ORDER BY
  (`NULLIF(title, '')` だけ)・編集競合の表示 ([87](./87-編集競合対策計画.md) の
  url / mode の差分)・回路図サムネと数式とプレビューの足切り
- 検索の SQL: `memo &@ 語 OR url &@ 語` → `memo &@ 語`
- `ITEM_COLUMNS` (生 SQL の射影) と offline の同期 API (`/api/sync/items`) から
  `url` / `mode` が消える。古い Service Worker のキャッシュは次の同期で
  入れ替わる (欠けた列を検算で落とす形ではなく、単に読まない)

## 5. 確認

- 単体テスト (where / sortOrder / noteFile の折り込み / offline / zip 往復)
- migration をローカル DB に当て、URL 入りの 14 件が本文に折り込まれていること
- 検索一覧のタイトル順・ゴミ箱・ZIP 書き出し → 取り込みが動くこと
