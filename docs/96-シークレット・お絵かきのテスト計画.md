# シークレット・お絵かきのテスト計画

リファクタリング (docs/93-リファクタリング計画.md §14) で直接テストが付かないまま
残った 3 領域にテストを付ける。挙動は変えない。

- `src/lib/secret/` の `unlock`・`prf`・`store`・`session`・`image`・`route`
- `src/components/secret/` (5 本)
- `src/components/draw/` (13 本)

## 0. なぜ (2026-09-16 時点)

### 何が無いか

| 領域 | 本数 / 行数 | いまの守り |
| --- | --- | --- |
| `lib/secret/` の 6 本 | 6 本 / 657 行 | `route` だけ API のテスト越し |
| `components/secret/` | 5 本 / 1,340 行 | 無し |
| `components/draw/` | 13 本 / 2,354 行 | 純粋部分は `lib/draw/` に 10 本 |

- `lib/secret/` の残り 6 本は **鍵の設定・解錠の手順そのもの** (`unlock`)、
  認証器から鍵の素を取る口 (`prf`)、鍵束と断片の保存 (`store`)、解錠中の鍵の
  置き場 (`session`) で、暗号の要。周辺 (`keyring`・`envelope`・`payload`・
  `secrets`・`api`・`content`) にはテストがある
- `secret/route.ts` は `api/secrets/*` のルートテスト (28 件) が通る経路にあるが、
  本文の読み取りの分岐 (Origin・上限・切れた通信) を直接は押さえていない
- `components/secret/` は解錠 → 復号 → 表示 → Blob URL の解放、ダイアログの
  保存、鍵の設定画面、と操作の塊。SSR の文字列比較では初期状態しか見えない
- `components/draw/` は fabric に縛られた部分 (ブラシ・図形・文字・履歴の
  直列化・レイヤの帯) と、まだ切り出していない純粋な計算 (塗りの範囲・
  ピンチの状態遷移) が混ざっている

### 動くもの・動かないもの (実測)

- vitest は node 環境で `crypto.subtle` が使える (`keyring.test.ts` が既に
  使っている)。`navigator` は Node 22 にもあるが `credentials` は無いので、
  `vi.stubGlobal` で丸ごと差し替える
- fabric 7.4 は DOM 無しで `Rect`・`Line`・`Path`・`PencilBrush` を作れる。
  `StaticCanvas`・`IText` は `document` が無くて作れない。**canvas に触る
  コードは node ではテストできない** (`fabric/node` は native の canvas が要る)
- Playwright 同梱の Chromium 151 の CDP には `WebAuthn.addVirtualAuthenticator`
  の `hasPrf` がある。仮想認証器で PRF が出せる見込み (§4-3 で先に確かめる)
- 手元の DB には鍵束 (`secret_keyring`) が **0 行**、パスキーが 2 本、断片が
  0 行。鍵束は主キー固定で 1 行しか持てない表なので、**テストが本物の鍵束を
  消したり作ったりしてはいけない** (§2-4・§4-3)

## 1. 方針

- **挙動は変えない。** テストのために部品を書き換えるのは、純粋な計算を
  切り出す場合だけ (切り出し前後の結果が同じことをテストで示す)
- **道具は今のまま。** vitest (node)・`renderToStaticMarkup`・Playwright。
  jsdom・testing-library・`fabric/node` は入れない (docs/93 §11)
- **何をどこで見るかを分ける。**
  - 純粋な計算・手順の分岐 → vitest (差し替えは fetch・認証器・DB 層だけ)
  - 描画の初期状態 → SSR 文字列比較
  - 操作 (解錠・描く・保存) → Playwright。**既存の E2E と同じ罠の避け方**
    (`e2e/README.md`) を使う
- **DB を汚さない。** 手元の DB は本物。鍵束のように「1 つしか無い」状態を
  作る E2E は、専用の DB でしか走らせない (§4-3)
- **先に確かめてから書く。** 仮想認証器で PRF が取れるかは、spec を書く前に
  1 本の使い捨てスクリプトで確かめる。取れなければ §4-3 の代替に切り替える

## 2. Phase 1 — `lib/secret/` の単体テスト

### 2-1. `session`・`image`・`route` (小さい 3 本)

    影響しない)

  - `subscribeSecretLock` が解錠でも施錠でも呼ばれ、解除後は呼ばれない
  - `useSecretUnlocked` はサーバ描画で false (`renderToStaticMarkup` で

- `image.test.ts` (`images/imageCanvas` の `redrawImage` を `vi.mock`)
  - 渡す指定 (`image/webp`・quality 0.9・maxEdge 2048) を固定する
  - 返った Blob の型とバイト列がそのまま出る
  - canvas が PNG に落としても通る (`image/png` は許される型)
  - 許されない型 (`image/gif`・空) は「この画像形式はシークレットにできません」
- `route.test.ts` (`readSecretBody` を `Request` で直接叩く。門番

    包み分を引いた値** (足している理由が注に書いてある。そこを固定する)
  - 種別ヘッダ無し・種別ごとの上限超え → `checkSecretPayload` の拒否
  - `arrayBuffer()` が投げる → 400「本文を読み取れませんでした」+ `console.error`
  - 通る → `{ mime, bytes }`

### 2-2. `prf` (認証器を差し替える)

`window.PublicKeyCredential` と `navigator.credentials.get` を `vi.stubGlobal` で
作り、`get` に渡った引数と返した値で分岐を押さえる。

- WebAuthn が無い → `PrfUnsupportedError('この環境ではパスキーを利用できません')`
- 渡す引数: `allowCredentials` が base64url を戻したバイト列 + `public-key`、
  `userVerification: 'required'`、`extensions.prf.eval.first` が `PRF_SALT`、
  challenge が 32 バイト
- 読めない credential ID は **黙って落とさず** `console.error` してから外す
- `NotAllowedError` → `SecretCancelledError`。それ以外の例外 →
  `console.error` + `PrfUnsupportedError` (既定の文言)
- 返りが null、`getClientExtensionResults` が無い、PRF の出力が空 →
  `PrfUnsupportedError`
- 出力が空で `authenticatorAttachment === 'cross-platform'` → QR 委譲の文言
- 通る → `credentialId` は認証器の `id`、`prfOutput` は 32 バイトの写し

### 2-3. `unlock` (手順の分岐。ここが本丸)

差し替えるのは `./api` (`fetchKeyring`・`initKeyring`・`saveKeyWrap`)、
`./prf` (`requestPrf`)、`../offline/keyring` (写しの読み書き) の 3 つ。
`keyring.ts`・`session.ts`・WebCrypto は本物を使い、**包んだ鍵を本物の手順で
開き直して、元のマスターキーに戻ることを確かめる**。

- `setupSecrets`
  - 設定済み → `SecretSetupError('暗号化は既に設定されています')`
  - 通る: `initKeyring` に渡った検証値が `checkVerifier` で通り、包みが
    `unwrapMasterKey` で元の鍵に戻る。セッションは解錠済み。写しが更新される。
    返った復旧キーを `decodeRecoveryKey` に通すと同じ鍵になる
  - PRF で取り消し → `initKeyring` は呼ばれず、セッションは施錠のまま
    (「鍵を作った後で認証器を呼ぶ」順序の裏付け)
- `unlockWithPasskey`
  - 未設定 → 「まだ設定されていません」
  - 包みを持つパスキーが 0 → 「どのパスキーでも…復旧キーで」
  - 候補は包みを持つ ID だけ (`requestPrf` の引数で見る)
  - 包みを持たないパスキーで応えられた → 「このパスキーでは…設定画面から」
  - 通る → 解錠済み。別の PRF 出力 (別の鍵) では開かず、施錠のまま
- `unlockWithRecoveryKey`
  - 形式違い、検証値が null、検証値と合わない → それぞれの文言
  - 通る → 解錠済み (`requestPrf` は呼ばれない)
- `enrollThisDevice`
  - 施錠中 → 「先に解錠してください」
  - 通る → `saveKeyWrap` の包みが元の鍵に戻る。**保存の後に**写しを更新する
- 鍵束の読み方 (`readKeyring`)
  - サーバが答える → 写しを書く。写しの保存が失敗しても `console.warn` だけ
  - サーバが失敗・写しがある → 写しを使う (順番の裏付け: docs/65 §9)
  - サーバが失敗・写しが無い → **サーバの失敗をそのまま**投げる
  - 写しの読み込みも失敗 → `console.warn` してサーバの失敗を投げる
- `refreshKeyringCache` の失敗は `console.warn` だけで手順を止めない

### 2-4. `store` (DB 統合。`RUN_DB_TESTS=1` のときだけ)

`items/items.test.ts` と同じ門 (`DATABASE_URL` + `RUN_DB_TESTS=1`、import は
`beforeAll` で動的に)。加えて **鍵束が既に 1 行でもあれば skip する**。手元の
DB で本物の鍵束を消すことは絶対にしない。CI の `db-tests` は空の DB なので通る。

- 自分の行だけを作って消す: パスキー行 `zzft-secret-cred-*` (`publicKey` は
  ダミー)、断片は固定の UUID 1 つ、鍵束は id=1 (無いことを確かめてから)
- `findSecret` null → `saveSecret` → 読める → 同名で mime を変えて上書き
- `findKeyringVerifier` null → `initKeyring` true → 読める →
  もう一度 `initKeyring` は **false** (主キー衝突だけを捕まえる裏付け) →
  `deleteKeyring` → null
- `hasCredential` true / false、`saveKeyWrap` 知らない ID → false、
  知っている ID → true で `listKeyWraps` に包みが載る (`createdAt` 順、
  包みの無いパスキーは null)
- `.github/workflows/ci.yml` の `db-tests` にこのファイルを足す

### 3-3. E2E `e2e/draw.spec.ts`

Phase 3 の検証で使った使い捨てスクリプト (`~/.cache/qr-refactor/p3-draw-probe/`
の `draw.mjs`。分解前後で結果が一致した 30 段) を spec に写す。

- 開き方: `/edit/zze2e-draw` → ツールバー「お絵かき」→ `dialog` 「お絵かき」
- **アップロードは横取りする** (`/api/images` の POST を `route.fulfill` で
  偽の封筒に)。DB には何も書かない。下敷きの画像も route で配る
- 見るもの (順に): ペン → 色と太さ → マーカー → 消しゴム → 文字 (空なら
  消える) → 四角・矢印・丸 → タップだけでは図形ができない → 塗る → モザイク →
  選択して動かす → 拡大縮小 → 2 本指で打ち切り → レイヤ (切替・非表示・
  レイヤ限定の消しゴム) → 元に戻す / やり直す → 全消しと戻し →
  非表示のまま書き出し → 取り消しの確認 (空なら確認なし) → 下敷きの
  読み込みと失敗 → 離脱
- 判定は **同じ実行の中の前後比較**にする。画素のハッシュは「描いたら
  変わる・戻したら戻る」で見て、黄金ファイルは持たない (Chromium の版で
  描画の画素はずれる)。書き出しは横取りした本文の PNG / WebP ヘッダから
  寸法と形式を読む (1600×900 と 800×600)
- 2 本指は `page.touchscreen` では出せない。`hasTouch` の別コンテキストで
  `TouchEvent` を dispatch する (probe と同じ)

### 4-3. E2E `e2e/secrets.spec.ts` — 専用 DB + 仮想認証器

鍵束は 1 行しか持てず、断片は消す口が無い (docs/51 §11 の GC は未実装)。
**手元の `qr` では走らせず、専用の DB を作って向ける。**

- 専用 DB: `scripts/e2eDb.sh` が compose の db に `qr_e2e` を作り
  (`createdb`)、`prisma migrate deploy` でスキーマを当てる。
  `createdb -T` の複製は使わない (PGroonga の索引が壊れる)。
  作り直しは `dropdb` → もう一度
- 起動: `E2E_DATABASE_URL` があれば `playwright.config.ts` の `webServer` が
  それを dev サーバへ渡す。`QR_GIT_DIR` も一時ディレクトリへ向ける
  (墓石コミットを作業ツリーに残さない)。spec の先頭で DB 名が `qr` なら
  **止める**
- 仮想認証器: 1 つの CDP セッションの中で `WebAuthn.enable` →
  `addVirtualAuthenticator` (`transport: 'usb'`, `hasResidentKey`,
  `hasUserVerification`, `hasPrf: true`, `isUserVerified: true`) →
  `setAutomaticPresenceSimulation` → 操作、までを続けて行う (セッションを
  張り直すと UV が外れて `NotAllowedError` になる。
  `playwright-virtual-authenticator-gotcha` の記憶)
- **先に spike**: `/settings/passkeys` で登録 → `/settings/secrets` の
  「設定する」で `prf.results.first` が返るかを、使い捨てスクリプトで 1 回
  確かめる。返らなければ、鍵束を **seed で入れて復旧キー経路だけを E2E に
  する** (検証値と包みは `keyring.ts` の関数で作れる。`e2e/seedSecrets.ts`)
- **spike の結果 (2026-09-17、Chromium 151 の仮想認証器、アプリ抜きで
  `navigator.credentials` を直に叩いた)**: `hasPrf: true` の認証器は、
  **登録 (`create`) のときに `extensions: { prf: {} }` を要求した credential
  にだけ** PRF を返す (32 バイト、同じ credential なら何度呼んでも同じ)。
  要求しなかった credential では `get` の `prf.results` が空。いまのアプリの
  登録 (`api/auth/passkey/register-options`) は `prf` を要求していない。
  実機の Apple パスキーは要求が無くても PRF を出すので今まで動いていたが、
  hmac-secret 型 (YubiKey・一部の Windows Hello) は登録時の要求が要る
  (docs/51 §6 の注はここに由来する)。**登録時に `prf` を要求する修正**を
  入れれば、仮想認証器でも実機の幅でも解錠経路が揃うので、seed の代替では
  なくそちらを採る。`transport: 'usb'` の仮想認証器は
  `authenticatorAttachment` が `cross-platform` になる (PRF が返るので
  QR 委譲の文言には落ちない)
- 見るもの (順に):
  1. パスキーを登録する (`/settings/passkeys`)
  2. `/settings/secrets` で設定する → 復旧キーが出る (控える) → 状態が
     「解錠中」
  3. 再読込 → 施錠中 → パスキーで解錠 → 解錠中
  4. 再読込 → 復旧キーで解錠 (控えた文字列を貼る) → 解錠中。間違った
     キーは「復旧キーが違います」
  5. `/edit/zze2e-secret` → ツールバー「秘密」→ ダイアログに本文を書いて
     保存 → 本文に `![秘密](/api/secrets/<uuid>)` が入る → 保存
  6. `/item/zze2e-secret` → 🔒 → 復号した本文が出る → コピー → 施錠すると
     引っ込む
  7. ダイアログに画像を入れる (`injectFiles` で小さな PNG) → 入れ子の断片が
     Blob URL の `img` で出る
  8. 後始末: ノートはゴミ箱 → 永久削除。断片と鍵束は専用 DB ごと捨てる
- サーバへ平文が出ないことも見る: `/api/secrets/*` への PUT / POST の本文を
  `page.on('request')` で拾い、書いた文字列が含まれないこと

## 7. 落とし穴 (先に分かっていること)

- `prf.ts` は `client-only` を import する。vitest では空モジュールに
  向いているので読めるが、`window` を stub しないと「利用できません」に落ちる
- `unlock.test.ts` で `keyring.ts` を本物のまま使うと、鍵の生成に
  `crypto.getRandomValues` が要る。node では `globalThis.crypto` にある
- `next/dynamic` を差し替えずに `renderToStaticMarkup` すると読み込み中の
  表示になる。差し替えは `vi.mock('next/dynamic', …)` で loader を同期に
  呼ぶ形にする (loader は `() => import('./X')` なので、テストは実体を
  直接 import して返す)
- fabric の `IText` は `document` が要る。文字道具は node で作れない
- 鍵束の DB テストは **必ず「0 行」を確かめてから** 作る。手元で鍵束を作った
  後に走らせると skip になる (消さない)
- 仮想認証器は CDP セッション単位。`page.reload()` を挟んでも同じセッションを
  持ち続ける。別コンテキストを開くときは `WebAuthn.getCredentials` で鍵を
  写して `addCredential` で入れ直す
- 仮想認証器の PRF 出力は credential ごとに決まる (hmac-secret)。同じ
  credential なら再読込しても同じ鍵が出る。そうでなければ 3. で開かない
- `secrets` の E2E は本文の平文をログに出さない。dev の `/logs` にブラウザ
  ログが転送されるので、平文を `console.log` しない
- 2 本指のジェスチャは `hasTouch` の別コンテキストで `TouchEvent` を
  dispatch する。既定のコンテキストではイベントが出ない
- お絵かきの画素比較は同じ実行の中だけ。黄金ファイルを持つと Chromium の
  更新で落ちる
- `useStageGestures` の切り出しは refs の更新順に依存がある (`zoomRef` と
  `panRef` を `useLatest` で追わせている)。純関数化してもフック側の順序を
  変えない

## 8. やらないこと

- jsdom・testing-library・`fabric/node` の導入
- GC (docs/51 §11)、断片の削除の口。E2E は専用 DB を捨てることで代える
- テストのためだけの `data-testid`。操作子は role と名前で取り、足りなければ
  `aria-label` を足す (それは利用者にも効く変更)
- `message()` の重複の統合 (空文字の扱いが違う。挙動を変えない)
- 実機 (iPhone) の PRF 確認の自動化。QR 委譲で PRF が空になる件は実機の
  事実で、仮想認証器では再現できない

### 計画から変えたこと・分かったこと

- **パスキー登録で PRF を要求するよう直した** (`fix:`)。仮想認証器の実測で、
  hmac-secret 型の認証器は登録時に要求した credential にしか PRF を出さないと
  分かった (§4-3)。Apple のパスキーは要求が無くても出すので実機では動いていた
- **dev サーバのパスキー検証の origin を E2E の口に揃える**必要があった。
  `.env` の `WEBAUTHN_ORIGIN` は手元の dev の口を指すので、Playwright の
  `webServer` が `WEBAUTHN_RP_ID` / `WEBAUTHN_ORIGIN` を上書きする
- `useStageGestures` の切り出しは、DOM 無しでフックを動かせないため、
  テストはフックのコードから期待値を導いて先に書いた (§3-2 の「切り出し前に
  通す」をこの 1 本だけ満たせていない)
- `buildFill` の塗り込みループと、`@erase2d/fabric` の消しゴムの生成は node で
  動かないので単体テストに入れていない。E2E が通している
- お絵かきの履歴は 150ms まとめてから積む。続けて操作すると「元に戻す」が
  2 手ぶん戻る (仕様どおり)。E2E は操作の間で待っている
- 「元に戻す」で JSON から描き直すと、文字や塗りの縁の画素が数階調ずれる。
  E2E はその段だけ、階調差 16 以下を数えない比較にした
- 倍率の E2E が一式の中で 6 回に 1 回落ちた。描き直しが落ち着く前に基準を
  取っていたため。直した後は 6 回続けて緑
