# 検索結果のスライドショー計画

検索結果の画像を、全画面で一定の間隔で次々に見せる。例えば「イラスト」で
検索し、その結果の画像を流し見する。docs/116 の画像ビューアに再生 / 一時停止を
足す形で作り、並び順・次のページの読み込み・原寸の先読みはビューアのものを
そのまま使う。

決めたこと (2026-10-28):

- 新しい画面や API は作らない。ビューアの ▶ と、一覧の見出し行の
  「スライドショー」の 2 つを入口にする
- 再生中は必ず全画面の覆いで出す
- 間隔は原寸を読み終えてから数える
- 手で送ったら (← → 釦・キー) 再生を止める
- 続きのページも尽きた末尾からは一覧の先頭へ戻って流し続ける (2026-10-28 改訂。
  当初は末尾で止めて「最後の画像です」と出していた)。手の ← → は今までどおり
  端で止まる
- 間隔は 3 / 5 / 10 秒。既定 5 秒。端末ごとに localStorage へ覚える
- 動画も流す。画像表示に動画のタイルを並べ、ビューアで自動再生し、
  再生し終えたら次へ送る (2026-10-28 追加。§8)

## 1. 入口

| 入口 | 置き場所 | 始まる画像 |
| --- | --- | --- |
| 「スライドショー」 | 一覧の見出し行 (ResultsToolbar) の左端 | 一覧の先頭の画像 |
| ▶ | ペインの右上・覆いの右下 | いま出ている画像 |
| Space | ビューアが開いているとき | いま出ている画像 |

見出し行の釦は**画像表示のときだけ**、読み込み済みのページに画像を持つ
ノートがあるときだけ出す (HomeResults が `allImageNames` で判定)。行の表示では
1 ノートにサムネが 1 枚しか並ばず、「検索結果の画像を全部見る」にならない。
選択モード中は出さない。provider の外 (オフライン一覧) でも出さない。

押した釦に焦点を残すと、Space が釦を押し直して先頭から始め直してしまうので、
始めるときに焦点を外す。

## 2. 自動送り

送り方は手の → と同じ `advance(1)` (ImageViewerProvider)。並びは送る瞬間に DOM の
`[data-viewer-image]` から拾い直すので、無限スクロールで継ぎ足されたページにも届く。
1 枚送った結果は純粋関数 `planStep` (lib/images/viewerNav.ts) が決める。

| 結果 | 条件 | 自動送りの扱い |
| --- | --- | --- |
| move | 隣の画像がある | 送って、その 1 枚の読み込みから数え直す |
| wait | 末尾で、続きのページがある | 読み込みを頼み、届いた画像へ送る (docs/116 §4 の待ち) |
| end | 末尾で続きも無い | 一覧の先頭の画像へ戻って続ける |

- **間隔は原寸を読み終えてから数える。** ViewerImage の onLoad / onError を
  `onSettled` で親へ上げる。時計だけで進めると、通信が遅いときサムネの
  引き伸ばしのまま次へ行く。読めなかった画像も止めずに進める
- 原寸が 15 秒経っても読み終わらなければ、サムネのまま次へ送る (弱い回線で
  要求が返らないまま、消灯を抑えて止まり続けない)
- 次のページを待っている間は数えない。待ちをあきらめた (続きが尽きた・15 秒)
  ときは、再生中ならそこを末尾として先頭へ戻る
- 再生中は原寸の先読みを 2 枚先から 4 枚先に増やす (3 秒間隔で数 MB の写真が
  続いても追いつくように)
- ▶ はいま出ている 1 枚から始める。末尾の画像で押せば、次は先頭へ戻る
- 一時停止したら次のページの待ちも解く (届いた瞬間に 1 枚進まない)

## 3. 再生中の操作

- 覆いは普段「どこを押しても閉じる」。**再生中だけは押すと一時停止**にする。
  眺めている間にうっかり触って消えるのを防ぐ。止まった後に押せば今までどおり
  閉じる。Esc は再生中でも閉じる
- 触らずに 3 秒経ったら操作の釦 (前後・間隔・再生・コピー・ノートを開く) を
  隠す (`useIdleWhile`)。ポインタかキーで触ればまた出る
- 手で送ったら止める。手で送ったのは「この 1 枚を見たい」意思なので、
  勝手に次へ行かない
- Space は全画面の覆いのときだけ、← → と同じ範囲 (焦点が body・一覧・
  ビューアの中) で受ける。ペインのときは一覧の Space を奪わない。
  釦は Space を離したときに押されるので、keydown と keyup の両方で止める
- 止めても全画面のまま。止めた瞬間にペインへ戻ると絵が跳ねる

## 4. 画面を消さない

再生中だけ Screen Wake Lock (`navigator.wakeLock.request("screen")`) を取る
(`useScreenWakeLock`)。iOS Safari は 16.4 から使える。

- タブが裏に回ると OS がロックを外すので、表に戻ったら取り直す
- 使えない環境・拒否されたときは警告を出すだけで、再生は続ける
- 取りに行っている最中は重ねて頼まない (2 本取ると先の 1 本が離されずに残る)

## 5. 間隔の設定

`lib/prefs/slideshowInterval.ts`。覆いの「5秒」の釦を押すたびに 3 → 5 → 10 秒と
回る。段に無い値 (手で書き換えた localStorage) は既定に倒す。再生中に変えれば
いま出ている 1 枚の時計もその場で掛け直す。

## 7. やらないこと

- シャッフル。欲しくなったら間隔と同じく端末の設定で足す
- 手の ← → の回り込み。端で止まるのが docs/116 の流儀
- 専用ページ (`/slideshow?q=…`) と全画像の名前を返す API。検索条件の受け渡しを
  二重に持つことになり、docs/116 の「URL には載せない」とも逆になる

## 8. 動画 (2026-10-28 追加)

### 8-1. 画像表示に動画のタイルを並べる

画像表示 (ImageMasonry) は画像だけを並べていたので、動画はスライドショーに
入らなかった。本文の画像と動画を出現順に拾う `allViewerMedia`
(lib/images/memoImages.ts) でタイルを組む。

- 動画のタイルは poster (`?thumb=1`) を画像と同じ正方形 + contain で見せ、
  中央に ▶ の印を重ねる (`VideoTilePoster`)。poster が無ければビデオの記号
- 押す口の読み上げ名は「動画を再生」(画像は「画像を大きく表示」のまま)
- タイルの数 (`tileCountOf`) にも動画を数える。ゴミ箱へ入れる確認文と、
  ゴミ箱の「画像表示では見えないノート」の判定がこれを使う
- 見出し行の「スライドショー」も、画像か動画があれば出す
- **画像検索の索引 (`allImageNames`) には混ぜない。** あちらは画像だけを照合する
- 行の表示 (小・中・大) の動画のサムネも、画像と同じくビューアで開く (§8-6)

### 8-2. ビューアで自動再生する

名前が動画ならビューアは `<video>` を出す (`ViewerMedia` → `ViewerVideo`)。
スライドショーでなくても、開いたら自動で再生する。

- `playsInline` 必須 (iOS が全画面のプレーヤーへ飛ばないように)
- **音つきの自動再生は拒まれることがある。** 画像を押して開いた直後は利用者の
  操作の中なので音つきで流せる。スライドショーが時計で送った先では iOS Safari
  などが NotAllowedError で拒むので、消音で流し直す。音はプレーヤーの釦で出せる
- 利用者がプレーヤーで消音を切り替えたら、次の動画もそれに倣う (タブの間だけ)。
  自動の消音は覚えない — 覚えると、次に押して開いた動画まで消音で始まる
- プレーヤーの操作は覆いへ伝えない (覆いは押すと閉じる・一時停止するため)
- 覆いの「コピー」は動画では出さない (クリップボードへ写せるのは画像だけ)
- 前後の先読みで動画の本体は取らない (数十 MB になりうる)。poster だけ温める
- プレーヤーに焦点があるとき (シークバーを押した後など) は、← → (早送り・
  巻き戻し) と Space (再生・停止) をプレーヤーに任せ、前後の送りに使わない

### 8-3. スライドショーでの送り方

| 動画の状態 | 送り方 |
| --- | --- |
| 再生中 | 待つ (長い動画も最後まで見せる) |
| 再生し終えた | 0.8 秒おいて次へ (最後のコマを見る間) |
| 再生できない (エラー・15 秒たっても始まらない) | 画像と同じく間隔ぶん見せて次へ |

読み込み・再生の状態は**表示の番号 (visit) に結びつける**。送る・開く・
ペインから全画面へ移るたびに番号が変わり、1 枚の部品も番号を key に作り直す。
名前で持つと、同じ動画へ戻ったとき前の「再生し終えた」が残って即座に送られ、
動画が 1 本だけの一覧では再生し直さないまま送り続けた (レビューで発覚)。
遅れて流れ始めた動画は「再生できなかった」を取り消し、最後まで待つ。
待ち時間の決め方は純粋関数 `slideDelay` (lib/images/viewerNav.ts) に置いた。

一時停止 (覆いを押す・Space) は自動送りを止めるだけで、動画の再生は止めない。
止めたい動画はプレーヤーの釦で止める。再開したときに動画が終わっていれば次へ送る。

### 8-4. 動画要素を 1 つにして使い回す (2026-10-28 修正)

v0.23.63 では iPhone でスライドショーの動画が再生されずに飛ばされた。
動画ごとに `<video>` を作っていたためで、iOS Safari は「利用者の操作の中で
play() された要素」にだけ以後の再生を許す。時計で送った先の動画は毎回
操作なしの再生になって拒まれ (低電力モードでは消音でも)、「再生できなかった」
として間隔ぶんで次へ送っていた。

- ビューアは動画要素を 1 つだけ持つ (`sharedVideo.ts`)。`ViewerVideo` は
  `<video>` を描かず、この要素を器へ差し込んで使う
- 利用者が押した処理の中 (画像・動画のタイルを押して開く・「スライドショー」・
  ▶・Space) で `unlockSharedVideo` を同期で呼び、play() / load() で許可を取る。
  許可は要素に残るので、以後は時計で送った先でも音つきで流せる
- ▶・Space で始める・再開するときは、出ている動画をその操作の中でその場で
  再生する (`playSharedVideoNow`)。開く・「スライドショー」では `load()` で
  許可だけを取る (`play()` だと止めてあった前の動画が一瞬鳴る)
- それでも消音まで拒まれたら**飛ばさずに待つ**。「タップで再生」と出し、
  利用者がプレーヤー・▶・Space で再生すれば流れ始め、終われば次へ送る。
  15 秒の「始まらない」の見切りもこの間は働かない。**許可の取れない端末では
  無人のスライドショーがその動画で止まる**が、ご依頼の「動画を飛ばさない」を
  優先した。形式・通信のエラーと 15 秒たっても始まらないものは今までどおり
  間隔ぶん見せて送る
- 要素を使い回すので、前の動画で変えた再生速度は動画ごとに 1 倍へ戻す
  (音量はプレーヤーの好みとして残す)。外した後に届いた前の動画の知らせ
  (play() の失敗など) は捨て、次の動画の要素を書き換えない
- E2E は Safari の規則を `HTMLMediaElement.prototype.play` の差し替えで模す
  (クリック・キー入力の処理の最中に play() / load() された要素だけが以後も
  再生できる)。`navigator.userActivation` はテスト用の Chromium では 10 秒
  たっても切れず、模すのに使えなかった。修正前のコードで落ちる (再生位置が
  0 のまま) ことを確かめた

### 8-6. 行の動画のサムネもビューアで開く (2026-10-28 修正)

大 (カード) 表示で動画のサムネを押すとノートが開き、「動画を押してもスライド
ショーにならない」と言われた (Windows の Chrome・3 ペイン)。行の表示の動画の
サムネはノートを開く作りのままだった (docs/116 §1)。

- 行の動画のサムネも `ViewerImageButton` で包み、ビューアで再生する。
  ビューアの ▶ でスライドショーにできる。選択モード中は今までどおり包まない
- **カードでもゴミ箱の釦をサムネの左へ退かせる。** 「96px のサムネの角に
  かかるだけ」として退かせていなかったが、動画の poster と ▶ に重なると
  言われた。退き先は `CARD_PLACEMENT_CLASS` の `right-31` (カードの余白 16px +
  サムネ 96px + gap-3 の 12px)。寸法は `itemRowDecor.test.ts` で固定してある
- 回路図・プレビューの顔のサムネは今までどおりノートを開き、印も付けない
- E2E: 中・大表示でホバーした釦が動画の poster に重ならない / 大表示で動画の
  サムネを押すとノートではなくビューアで再生する。どちらも修正前のコードで
  落ちることを確かめた

### 8-7. 画像表示の動画タイルも動くサムネにする (2026-10-28)

画像表示の動画タイル (`VideoTilePoster`) も、行のサムネ (`RowThumb`) と同じ
`useAnimThumb` で動くサムネ (アニメ WebP。docs/72) にする。PC はホバー中、
スマホは画面に入ったときだけ同じ `<img>` の src を差し替え、動いている間は
▶ を消す。動くサムネが未生成 (404) なら静止の poster に戻す。

▶ の印はタイルでは 32px に固定する (`PlayBadgeIcon` の `sizeClass`)。行と同じ
「サムネの 1/3」では 160px 前後のタイルで約 53px になり、絵を隠しすぎた。

### 8-8. 動画のサムネは常に動かす (2026-10-28)

行のサムネ (`RowThumb`) も画像表示のタイル (`VideoTilePoster`) も、動画は
**常に動くサムネ**にする (ユーザー指示)。docs/72 の「PC はホバー中だけ、
スマホは画面にしっかり入ったものを 1 セッション 30 本まで」は外し、上限の
勘定 (`lib/video/animThumbBudget.ts`) は消した。画面外の `<img>` は
`loading="lazy"` で後回しになるが、スマホでも一覧を開くだけで動くサムネ
(1 本最大 300KB) の転送が増える。

- **サーバ描画は静止サムネ、ブラウザで動き出してから動くサムネに替える**
  (`useAnimThumb` の `useSyncExternalStore`)。サーバが最初から動くサムネの
  URL を描くと、未生成の動画 (既存の動画に多い) は React が動き出す前に
  404 になり、onError を拾えず壊れた画像のまま残る
- 動くサムネが 404 なら静止サムネに戻し、以後は試さない
- ▶ は動いていても出す (タイルは 32px、行はサムネの 1/3)
- E2E: 画像表示の動画タイルは触らなくても動くサムネ / 動くサムネが 404 なら
  静止サムネに戻る (壊れた画像にならない)
