# サーバー情報計画

管理者がログインしているときだけ、ハンバーガーメニューに「サーバー情報」を
出す。開くとホスト・コンテナ・QR-Note 本体・DB の詳細と、要点だけの
ヘルスチェック (OK / 注意 / 異常) が 1 画面に並ぶ。読み取り専用。

## 1. 何が困っていたか

- 本番 (vps2) は 2GB でスワップ中。空きメモリや DB の大きさを見るのに
  毎回 ssh して `free` と `psql` を叩いている。
- PGroonga の索引は `prisma migrate` や `createdb -T` で**静かに消える**。
  消えても seq scan で動くので、遅くなるまで気づけない (memory に 2 度残した)。
- 配布した版・Node・PostgreSQL・PGroonga の版を確かめる場所が無い。
  ヘッダに出るのはアプリの版だけ。

## 2. 決め

- **管理者の判定は env `ADMIN_USER` との完全一致。** 判定は
  `lib/auth/admin.ts` の 1 か所。`"tommie"` をコードに焼かない。
  **未設定なら誰も管理者ではない** — 欠落は安全側へ倒す (isDemoMode と
  同じ向き)。
- **導線はメニューの「ログ」の隣** (診断系の並び)。`isAdminUser(user)` の
  ときだけ出す。押せない物を見せない (ログと同じ)。
- **URL は `/settings/server`。** 設定系なのでデモでは 404
  (requireSettingsPage の流儀)。管理者でないときも 404 — 403 にすると
  存在を教える。既存の設定系と同じ倒し方。
- **env の値は出さない。** あり / なしの真偽だけ。管理者限定の画面でも
  スクショ・共有で漏れる。
- **1 節の失敗で全体を 500 にしない。** その節だけ
  「取得できませんでした」と出し、サーバログに warn を残す。DB が落ちて
  いるときこそ見たい画面。黙って空欄にもしない。
- **節ごとに待ち時間の上限 5 秒。** DB が固まっていると画面が永遠に出ない。
- **操作はコピーだけ。** 読み取り専用。調査で手元へ貼る (ログ画面と同じ)。
- **ホスト OS 名は compose でマウントする。** `/etc/os-release` を
  `/host/os-release` に read-only で当てる。コンテナの中からはコンテナの
  Debian しか見えない。

## 3. 何が見えるか — コンテナの中から

アプリは `node:24-slim` のコンテナに居る。カーネルは共有なので
`os` モジュールと `/proc` はホストの値を返すが、`/etc/os-release` と
ホスト名はコンテナのものになる。ラベルで正直に分ける。

### ホスト

- ホスト名 … `/host/hostname` (`/etc/hostname` のマウント。`os.hostname()` は
  コンテナ ID を返すので使えない)
- OS 名 (PRETTY_NAME) … `/host/os-release` (マウント)
- カーネル・アーキテクチャ・稼働時間・ロードアベレージ・CPU 数 …
  `os.release()` `os.arch()` `os.uptime()` `os.loadavg()` `os.cpus()`
- メモリ合計 / 利用可能・**スワップ合計 / 使用** … `/proc/meminfo`
  (MemTotal・MemAvailable・SwapTotal・SwapFree)

### コンテナ

- OS 名 … `/etc/os-release`
- ホスト名 (= コンテナ ID) … `os.hostname()`
- メモリ上限 (cgroup) … `/sys/fs/cgroup/memory.max`

### QR-Note

- 版・Node・Next・Prisma … `package.json` `process.version`
  `Prisma.prismaVersion`
- `APP_ENV`・`DEMO_MODE`・起動時刻・RSS / ヒープ・タイムゾーン …
  `process.*`
- データ領域 (ノートの git 置き場) の空き … `fs.statfs`
- 外部連携の設定 (Yahoo・楽天・パスキー) … あり / なし のみ

### DB

- PostgreSQL の版 … `version()`
- PGroonga の版 … `pg_extension`
- DB の大きさ・起動時刻・接続数 / 上限 … `pg_database_size`
  `pg_postmaster_start_time` `pg_stat_activity`
- 表の大きさ (上位) … `pg_total_relation_size`
- ノート / 画像の件数 … Prisma の count
- 適用済みの最新マイグレーション … `_prisma_migrations`

git のコミットハッシュとビルド日時は、いまのイメージには入っていない。
入れるなら doDeploy.sh のビルドで `.build-info.json` を書く別件にする。

## 4. ヘルスチェック

「見て判断する」のではなく、判定まで機械にやらせる項目。各行は
OK / 注意 / 異常 のどれかと一言の根拠。全体の判定は最悪の行に揃え、
一番上に出す。

| 項目 | 注意 | 異常 |
| --- | --- | --- |
| DB 応答 (`SELECT 1`) | 200ms 以上 | 失敗・時間切れ |
| PGroonga 拡張 | — | 無い |
| PGroonga 索引 | — | 0 本 (seq scan 落ち) |
| マイグレーション | — | 未完・巻き戻しあり |
| ノートの git 置き場 | `HEAD` が読めない | — |
| ホストのメモリ | 利用可能 15% 未満 | — |
| スワップ | 使用 50% 以上 | — |
| データ領域の空き | 10% 未満 | — |
| 直近のサーバログ | error 1 件以上 | — |
| 楽天の設定 | 3 つのうち一部だけ | — |
| パスキーの設定 | 2 つのうち一部だけ | — |

どの列にも当たらなければ OK。楽天・パスキーは「全部無し」も OK
(使わない選択であって、設定ミスではない)。

## 6. 配るときの手順

compose.yaml は doDeploy.sh が既定では転送しない。vps2 の `.env` に
`ADMIN_USER=tommie` を足し、初回は `./doDeploy.sh patch --send-compose.yml`
で compose.yaml (env の行と `/etc/os-release` のマウント) ごと送る。
.env だけでは届かない (RAKUTEN の事故と同じ)。
