# 動画幅指定計画

本文の動画を、画像と同じ `![録画|300](...)` の記法で幅指定できるようにする。
写真だけが幅を選べて、隣に貼った録画は必ず同じ大きさ、という非対称を消す。

実装済み (この文書は決めたことの記録)。

## §1 なぜ動画だけ落ちていたか

記法のパースは元から 1 か所 (`src/lib/altWidth.ts` の `parseAltWidth`) に
まとまっていて、足りなかったのは**呼ぶ場所**だけだった。

`MarkdownView.tsx` の `imgRenderer` は画像記法を種別ごとに振り分ける。
シークレット → 音声 → 動画 → PDF → テキスト → 画像 の順に `return` し、
`parseAltWidth` を呼ぶのは**最後の画像の枝だけ**。動画はその手前で抜けるので、
`|300` は幅として読まれず、alt にそのまま残っていた。

直したのは動画の 2 つの枝 (通常の `/api/images/*.mp4` と、シークレットを
復号した Blob URL) で `parseAltWidth` を呼ぶこと、それだけ。

一覧プレビュー (`NotePreviewThumb`) と編集チップ (`attachmentChip`) は
**元から全種別で幅を剥がしていた**ので変更なし。「録画|300」というラベルが
一覧に出る事故は最初から起きていない。

## §2 固定幅ではなく上限にする

画像は `<img width={200}>` の固定幅。動画は `style={{ maxWidth }}` の上限に
した。同じ記法・違う効き方なので、判断を残す。

- `<video>` は既定で全幅に伸びる部品で、今も `w-full max-w-md` (上限 448px)
  で描いている。**幅指定はこの上限の数値を差し替えるだけ**、という形が
  既存の見た目と地続きになる。
- 固定幅にすると、`![録画|600]` と書いたノートを iPhone で開いたときに
  プレイヤーが画面からはみ出し、横スクロールが生える。画像より起きやすい
  (動画は「大きめに」書きたくなる) 割に、直す手立てが読み手側に無い。
- 上限にしておけば、狭い画面では縦横比を保ったまま縮む。広い画面では
  指定した幅ちょうどになるので、書いた人の意図は満たされる。

画像を上限側へ揃える案は採らなかった。既存ノートの見た目が変わるうえ、
書影 (`scanRegister.ts` が `![書影|120]` で挿入) のように「必ずこの幅」で
並べたい用途が実際にある。

## §3 効く場所・効かない場所

| 場所 | 幅指定 |
| --- | --- |
| ノート閲覧・公開ビュー・オフライン (MarkdownView) | 画像・動画に効く |
| シークレットの中の動画 (復号後の Blob URL) | 効く |
| 音声・PDF・テキスト・シークレットのラベル | 効かない (alt をそのまま使う) |
| 一覧のノートプレビュー | 剥がすだけ (実寸で描かない) |
| 編集のライブプレビュー (添付チップ) | 剥がすだけ (箱は固定サイズ) |
| quiz フェンスの中 | 効かない (メモ記法.md の表のとおり) |

音声・PDF・テキストへ広げなかったのは、alt が**挿入時のファイル名**だから。
`![仕様書|80.pdf]` のような名前を勝手に削ると、共有・保存のファイル名が
静かに変わる。動画の alt は録画日時か任意ラベルで、この危険がない。

なお剥がしたラベルは共有シート・保存リンクのファイル名の元になる
(`attachmentShareName`)。剥がし忘れると「録画|300.mp4」で保存されるので、
テストで固定してある。
