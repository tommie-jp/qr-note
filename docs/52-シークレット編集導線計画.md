# 52. シークレット編集導線計画

[51-部分暗号化計画.md](./51-部分暗号化計画.md) の続き。断片の編集そのものは
実装済み (51 §9) だが、入口に発見性の問題が 2 つある。

1. エディタの「カーソルを記法に乗せて『秘密』を押すと編集」は、知らないと
   気づけない。ボタンの見た目が新規挿入と同じため。
2. 閲覧画面から直接編集できない。「編集画面を開く → 記法を探す → カーソルを
   置く」の 3 手かかる。

この計画はこの 2 つの導線を足すだけで、**暗号・保存の仕組みには触れない**
(同名上書き・AAD・鍵まわりは 51 のまま)。

## 1. ツールバーのラベル切り替え (エディタ側)

カーソルがシークレット記法の上にあるときだけ、ツールバーの「秘密」を
**「秘密を編集」に変える**。押したときの動作は今と同じ (openSecret が
カーソル位置で新規/編集を分岐済み) なので、変わるのは**見た目だけ**。

### 実装 (エディタ側)

- [MemoEditorInner.tsx](../src/components/MemoEditorInner.tsx) の
  `handleUpdate` に判定を足す。すでに onUpdate はカーソル移動でも呼ばれて
  おり、履歴の深さと同じ流儀で「値が変わったときだけ setState」する
  (boolean 1 個なので再レンダリングは状態が切り替わる瞬間だけ)。
- 判定は既存の `secretAtCursor()` ([secrets.ts](../src/lib/secrets.ts)) を
  `update.state.doc.toString()` + `selection.main.from` で呼ぶだけ。本文は
  最大 10,000 字 (MAX_TEXT_LENGTH) で、正規表現 1 回の走査は打鍵ごとでも
  実測影響なし。重くなったら `update.selectionSet || update.docChanged` の
  ときだけ計算する逃げ道がある。
- [EditToolbar.tsx](../src/components/EditToolbar.tsx) に
  `secretLabel: string` を渡す (「秘密」/「秘密を編集」)。progressLabels の
  uploadLabel などと同じ「呼び出し側が文字列を作る」流儀に合わせる。

### テスト (エディタ側)

- EditToolbar: ラベルがそのまま出ること (既存テストの overrides で足す)。
- ラベルを決める純関数 (`secretToolbarLabel(doc, cursor)` を secrets.ts に
  置く) — 記法上で「秘密を編集」、外で「秘密」。

## 2. 閲覧画面からの編集 (ビュー側)

解錠済みの SecretBlock に「編集」ボタンを足し、その場で SecretDialog を
開く。編集画面へ行かずに中身を直せるようにする。

### 成立する理由と割り切り

- 中身の編集は**同名上書きで本文に触れない** (51 §9)。だから memo を
  持たない閲覧画面からでも保存が成立する。
- **ラベルの変更だけは閲覧画面からはできない**と割り切る。ラベルは本文の
  平文であり、書き換えは memo の保存 = 編集画面の仕事。閲覧から開いた
  ダイアログではラベル欄を出さない。
- 画像の断片には編集ボタンを出さない (文字として開けない。51 §9 の
  ガードと同じ理由)。

### 実装 (ビュー側)

- [SecretDialog.tsx](../src/components/secret/SecretDialog.tsx) に
  `hideLabel?: boolean` を足す。true ならラベル欄を描かず、onSaved には
  既存ラベルをそのまま返す (呼び出し側は本文に触らない)。
- 「編集ボタンを出してよいか」は **MarkdownView の prop で上から流す**。
  `allowRotate` (docs/49 §2) と同じ作法:
  [ItemView.tsx](../src/components/ItemView.tsx) からだけ
  `allowSecretEdit` を true で渡し、公開ビュー・印刷・docs ページには
  出さない (既定 false)。imgRenderer → SecretBlock へ素通しする。
- [SecretBlock.tsx](../src/components/secret/SecretBlock.tsx):
  展開表示のヘッダ (隠す・コピーの並び) に「編集」を足す。押したら
  SecretDialog を `name` 付き + `hideLabel` で開く。保存後は
  `loadSecret()` を呼び直して表示を更新する (サーバの中身が変わったので
  取り直すのが確実。復号済み markdown の組み立て・Blob URL の張り替えも
  既存の reveal の経路をそのまま再実行する)。
- SecretDialog は createPortal の全画面モーダルで、エディタに依存しない
  部品なので閲覧画面からもそのまま使える。動的 import (開くまで読まない)
  も編集側と同じにする。

### テスト (ビュー側)

- SecretDialog: `hideLabel` でラベル欄が出ないこと。
- MarkdownView → SecretBlock へ `allowSecretEdit` が流れること
  (既定 false で「編集」が出ないこと)。
- SecretBlock の表示更新はブラウザで確認 (WebCrypto + fetch が絡むため
  ユニットでは追わない。51 の実機確認と同じ扱い)。

## 3. やらないこと

- 断片の版管理 (上書き前の中身は戻せない。51 §9 の承知事項のまま)。
- 閲覧画面からのラベル変更・断片の削除 (どちらも本文の編集なので
  編集画面の仕事)。
- 記法タップでの編集起動 (閲覧画面はプレースホルダのタップ = 解錠と
  衝突する。ボタンを分けるほうが誤操作がない)。

## 4. 実装の現状

1〜6 は実装済み (2026-08-05)。7 だけが残っている。

| 部品 | 実体 |
| --- | --- |
| ラベルの判定 | `secretToolbarLabel()` ([secrets.ts](../src/lib/secrets.ts)) |
| ラベルの表示 | [EditToolbar.tsx](../src/components/EditToolbar.tsx) の `secretLabel` |
| カーソル追従 | [MemoEditorInner.tsx](../src/components/MemoEditorInner.tsx) の `handleUpdate` |
| ラベル欄を隠す | [SecretDialog.tsx](../src/components/secret/SecretDialog.tsx) の `hideLabel` |
| 権限の受け渡し | MarkdownView の `allowSecretEdit` → SecretBlock の `allowEdit` |
| 閲覧からの編集 | [SecretBlock.tsx](../src/components/secret/SecretBlock.tsx) |

残り: **実機 (iPhone) で閲覧 → 編集 → 表示更新の一連を確認する**。
とくに編集の保存後、`reveal()` の再実行で表示が新しい中身に入れ替わること
(Blob URL の張り替え込み) はブラウザでしか確かめられない。
