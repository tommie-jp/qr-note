# 一覧ノートプレビュー計画

検索結果とゴミ箱の一覧 (小/大) で、画像も回路図も無いノートの顔として
**ノート全体の縮小プレビュー**を出す。文字だけ・数式だけ・コードだけ・
mermaid だけ — どんなノートにも視覚的な顔が付く。

背景: 一覧の顔の優先順位は「画像/動画 → 回路図 → なし」(docs/68 §1) で、
どちらも無いノートはタイトルの文字だけになり見分けにくい。Apple Notes の
ギャラリー表示のように、本文そのものの見た目を縮めて顔にする。

## §1 ラスタ化しない (縮小ライブプレビュー)

ノートを画像 (WebP 等) に焼く案は 3 つとも見送り、**本文の markdown を
そのまま描いて CSS の `transform: scale()` で縮める**。

- headless Chromium でのラスタ化 … 本番 (RAM 2GB・イメージ 631MB の差分
  転送設計。doDeploy.sh) に +数百 MB のブラウザは載せられない。
- satori (next/og) でのサーバ側ラスタ化 … 日本語フォント同梱 (+数 MB) と
  CSS サブセット制限で KaTeX・表の再現度が落ちる。保存経路すべて
  (サーバアクション / ZIP・ENEX インポート / タスクトグル / 画像回転) での
  再生成とバックフィルも要る。
- クライアント側ラスタ化 (html-to-image 等) … iOS Safari の foreignObject
  不具合が既知で、インポート経路では生成されない穴が開く。

縮小ライブプレビューなら生成・保存・無効化・バックフィルの機構が丸ごと
不要で、常に本文どおり。回路図サムネが「ラスタ化せず SVG をインライン」
(docs/68 §3) で成功しているのと同じ系。

## §2 顔の優先順位は第 3 フォールバック

**画像/動画 → 回路図 → ノート全体プレビュー** (分岐の正本は `ItemRow` の
thumb)。画像・回路図があるノートは今までどおりの見た目を保つ。枠は
画像サムネと同じ寸法 (小 40px / 大 96px)。

- キャンバス・縮小率・枠は**必ず 1 つの組で持つ** (`NotePreviewFrame.tsx` の
  `FRAME`)。`canvas × scale = frame` が崩れると中身がはみ出すか余白が空く
  ので、別々の表に散らさない:

  | 表示 | キャンバス | 縮小率 | 枠 | ソース上限 |
  | --- | --- | --- | --- | --- |
  | 小 (compact) | 10rem | 0.25 | 2.5rem (size-10) | 300 字 |
  | 大 (card) | 20rem | 0.3 | 6rem (size-24) | 600 字 |

  比は rem どうしなので、文字サイズ設定 (docs/61) で root が伸縮しても崩れない。
- 40px では文字は読めない (テクスチャとして働く) が、それはラスタ方式でも
  同じ。小のキャンバスを 10rem に落としているのは、同じ 20rem を 0.125 に
  縮めるより「何かが書いてある」感が残るため。カード表示 (96px) では
  見出し・図の形が判る。

## §3 サーバ→クライアント境界は ReactNode のまま越える

`ItemList` は client component なので、react-markdown / KaTeX を
`ItemRow` から import することはできない (client 束に katex ~280KB が
入ってしまう。mathText.ts と同じ事情)。

- サーバページ (`page.tsx`) が `buildNotePreviews` で
  `Record<itemNo, ReactNode>` を作り、props で降ろす
  (`NotePreviewMap`)。RSC の出力を client component の props に通す
  公式の合成パターンで、`ItemRow` の `checkbox` / `footer` と同じ機構。
- HTML 文字列方式 (circuitThumbs / mathTexts の形) は取れない —
  `renderToStaticMarkup` は RSC ランタイムで呼べず、`rehype-stringify` は
  依存に無い。ReactNode ならレンダラ差し替えごと React に任せられる。
- client 側 (`ItemList` / `TrashList`) は `NotePreviewMap` を
  **型だけ** import する (circuitThumbs.ts と同じ線引き)。

## §4 描画規則は本文と共有、押せる物は作らない

本文とプレビューの**解釈は 1 本にする**。`markdownPipeline.tsx` に置いた
共有物 (`sanitizeSchema` / `urlTransform` / `BASE_REMARK_PLUGINS` /
`BASE_REHYPE_PLUGINS` / `REMARK_REHYPE_OPTIONS` / `classifyImgSrc` /
`parseAltWidth` / `readFence` / `blockquoteWithAlert`) を両方が使い、
`NotePreviewThumb.tsx` はレンダラ (種別 → 部品の対応) だけを差し替える。

- **新しい記法のプラグインは `BASE_*` に足す。** 本文だけに足すと、一覧の
  プレビューがその記法を生の文字のまま描くずれ方をする。本文が上乗せする
  のは `remarkTagLinks` と `rehypeTaskLines` の 2 つだけ。
- **添付の判定順は `classifyImgSrc` が正本。** シークレットを最初に見るのは
  安全の要 (下に落ちると暗号文が割れた画像や取得先として露出する)。
  順を 2 か所に書くとここが静かにずれる。
- レンダラの対応:
  - リンク → `<span>` (href なし。stretched link の膜の下にフォーカス可能な
    要素を作らない)。`remarkTagLinks` を足さないので #タグも文字のまま。
  - シークレット断片 → 🔒 伏せ字チップ。復号内容どころか解錠 UI
    (SecretBlock) ごと出さない。
  - 音声 / 動画 / PDF / テキスト / 外部画像 → アイコンチップ。**外部への
    取得はしない** (memoImages.ts が外部画像をサムネにしないのと同じ方針)。
    動画を poster の `<img>` にしないのは、poster の無い動画で 404 の壊れた
    画像になるため — `RowThumb` の `onError` 差し替えはサーバ描画では使えない。
  - 自前の画像 → `?thumb=1` の縮小版 `<img>` (来るのは稀 — 絵のあるノートは
    優先順位 1 が受ける。書式外れとの共存の受け皿)。
  - mermaid / circuitikz / quiz フェンス → 破線のプレースホルダ
    (`fence-placeholder`)。mermaid はブラウザでしか描けない (§6)。
  - タスクリスト → GFM 既定の disabled チェックボックス
    (`rehypeTaskLines` を足さない)。
- 枠 (`NotePreviewFrame`) は `aria-hidden` + `inert` +
  `pointer-events-none` の三重で装飾に閉じ込める (`inert` は古い iOS Safari
  に無いので `pointer-events-none` も残す)。

## §5 重さの抑え方

パースは安くない (remark + KaTeX) ので、3 段構えで抑える
(`src/lib/notePreview.ts`):

- **対象の足切り** … 第 3 フォールバックに届くノートだけ
  (`wantsNotePreview`: memo モード・本文あり・画像なし、かつ
  `buildNotePreviews` が回路図サムネの出るノートを除外)。除外の判定は
  ItemRow の分岐と同じ形 (`circuitThumbs[itemNo]?.[0]`) にする — 片方が
  「図あり」もう片方が「図なし」と読むと、顔が 1 つも出ない行ができる。
  `firstThumbInfo` は `includes('/api/images/')` の足切りを先に通すので、
  添付を持たない大半のノートは正規表現まで進まない。
- **ソースの切り詰め** … 大 600 字 / 小 300 字 / 40 行 / フェンス本体 8 行
  (`notePreviewSource`)。キャンバスに見えるのはその程度が上限で、それ以上は
  パースしても捨てるだけ。行単位で切り、フェンス (```) とブロック数式 ($$)
  の開閉は **memoSummary.ts の `fenceMathTracker` (要約と同じ 1 本)** で追う。
  途中で切れたら閉じ行を補い、区切り行や数式行は半端に切らず丸ごと落とす —
  補いを効かせるため、丸ごと拾えた行までの開閉状態だけを見る。
- **件数の上限** … 60 件/レスポンス (`NOTE_PREVIEW_MAX_ITEMS`)。
  searchItems は「さらに表示」で 1〜N ページの累積を返すため
  (CIRCUIT_THUMB_BUDGET と同じ事情)。ReactNode はバイト数を測れないので、
  バイト予算ではなく件数で抑える — ソースを切ってあるため、件数さえ抑えれば
  合計も抑まる。超えた分は先頭から詰めて黙って落とす。

DB は引かない同期処理 (buildMathTexts と同じ)。表示モードごとの出し分け
(画像モードは作らない・小はさらに足切り) は `buildNotePreviews` の中に置く
— `loadCircuitThumbs(items, mode)` / `buildMathTexts(items, mode)` と同じ
作法で、呼ぶ側 (2 ページ) に同じ三項演算子を複製しない。
**`loadCircuitThumbs` の後に呼ぶこと** (回路図サムネが出るノートに作っても
使われない)。

## §6 mermaid は段階実装 (Phase 2: SVG キャッシュ)

mermaid は DOM の計測が要りサーバで描けない (`MermaidDiagram` は client +
動的 import)。Phase 1 はプレースホルダで、実際の図を出すのは Phase 2:

- `CircuitSvg` と同じ発想の `MermaidSvg` テーブル (hash はソースの sha256、
  **サーバ側で再計算**して client の申告は信じない)。
- `MermaidDiagram` が描画成功時に `/api/mermaid-svgs` へ fire-and-forget で
  POST (認証必須・demo / 公開ビューでは送らない・セッション内 dedupe)。
- 検証: `assertSafeCircuitSvg` は流用不可 — mermaid は既定で
  `<foreignObject>` の HTML ラベルを出す。`htmlLabels: false` で純 SVG に
  してから、許可リスト方式の `assertSafeMermaidSvg` を新設 (64KB 上限・
  疑わしければ拒否)。
- 一覧側は `loadCircuitThumbs` を鏡写しにした `loadMermaidThumbs` を足し、
  優先順位に「画像 → 回路図 → mermaid → プレビュー」と挿す。
- GC: 全 memo に現れない hash の掃除スクリプト (docs/20 の画像 GC と同じ)。

## §7 対象外 (割り切り)

- **画像モード** … タイルは添付単位 (docs/32) で行が無いので作らない。
  画像も回路図も無いノートは今までどおりタイルなし。選択モード中の
  compact フォールバックにもプレビューは出ない。
- **オフライン一覧** (`OfflineList.tsx`) … 行の部品が別実装。出すなら
  同期済み memo からクライアントで描く (react-markdown がオフライン束に
  入る) ことになるため、別の判断として保留。
- **本文プレビューの重複** … カード表示ではタイトル行・本文 3 行と
  プレビュー内の同じ文字が二重に見える。プレビューは「ノート全体の顔」
  (Apple Notes と同じ) なのでそのままにする。
