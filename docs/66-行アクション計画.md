# 66. 検索結果の行アクション計画

検索結果のノートに、PC はホバー・スマホは長押しで「ゴミ箱へ移動」ボタンを
出せるようにする。ボタンは今後増える見込みなので、ゴミ箱を直書きせず
**アクションの一覧を 1 か所で持ち、そこから PC / スマホ両方の見た目を生成する**
形にしておく。

## 1. 今ある導線と足りないもの

ノート 1 件をゴミ箱へ入れる道は今 2 つある。

- **スワイプ削除** ([43-スワイプ削除計画.md](./43-スワイプ削除計画.md)) …
  スマホの最速動線。ただし PC のマウスでは横に払う操作が事実上できない。
- **選択モード** ([12-ゴミ箱計画.md](./12-ゴミ箱計画.md) §5) … 一括用。
  1 件のために「選択 → チェック → ゴミ箱へ」の 3 手は遠い。

つまり **PC に 1 件の近道が無い**。編集画面にも削除ボタンは無い
(あるのは `TrashedBanner` の復元だけ)。ホバーのボタン列はこの穴を埋める。
スマホの長押しは、スワイプと重複するが「今後増えるアクションの置き場」を
先に作る意味を持つ。

## 2. 方式 — PC はホバーでボタン列、スマホは長押しでメニュー

同じ `RowAction` の配列 (§3) から、PC は行の右端のアイコンボタン列、
スマホはその場に開くメニューを生成する。

スマホを「長押しでボタンを行内に出す」方式にしないのは、

- 出したボタンを押す 2 タップ目が誤タップしやすい (指がボタンを隠す)、
- ボタンが増えると行内に収まらない、
- 下部バーで既に「長押し = メニューが出る」を教えてある
  ([62-下部バー長押し計画.md](./62-下部バー長押し計画.md) §2)。同じ合図には
  同じ応え方をする

ため。`useLongPress` + メニューの組は下部バーで実証済みで、そのまま流用できる。

**却下した代替案**: 長押しでスワイプの引き出し (`SwipeToTrashRow` の赤ボタン) を
開く。新しい UI が要らず最小だが、引き出しはボタン 1 個 72px の設計で、
アクションが 3 つ 4 つに増えると行の大半が隠れる。伸びしろが無いので採らない。

スワイプ削除は**そのまま残す**。スワイプは「ゴミ箱専用の最速動線」、
長押しメニューは「汎用アクションの置き場」で役割が違う。ゴミ箱が両方に
居るのは iOS のメール等と同じ共存で、混乱はしない。

## 3. アクションの一覧を 1 か所で持つ

```ts
interface RowAction {
  key: string;
  label: string; // 「ゴミ箱へ移動」
  icon: ReactNode; // TrashIcon (§6)
  danger?: boolean; // 赤系で描く
  onSelect: () => void; // 実行 (server action の呼び出しは呼ぶ側が包む)
}
```

配列は **`SwipeToTrashRow` が組む**。当初は `ItemList` で組むつもりだったが、
実行の状態 (送信中・失敗・削除後の畳み) を持てるのは行の階層だけで、一覧と
実行を離すとその状態だけを親へ持ち上げて配り直すことになる。server action
(`trashItemsAction`) はこれまでどおり page.tsx から prop で降りてくる
(db.ts を巻き込まない。`ItemList.tsx` 冒頭の事情と同じ)。将来ピン留めや複製を
足すときは、この配列に 1 要素足すだけで PC / スマホ両方に現れる。

実行の中身はスワイプ削除の `handleDelete` をそのまま使う
「`FormData` に itemNo → `startTransition` → 失敗したら行内に `role="alert"`」。
確認ダイアログは付けない — スワイプも一括も confirm 無し (復元できるため) なので、
ここだけ聞くと一貫しない。

### 3-1. 成功しても例外は飛んでくる

`trashItemsAction` は最後に `redirect(back)` を呼ぶ。Next.js の `redirect()` は
**内部エラーを投げることで動く**ので、素の `catch` は成功した削除まで「失敗」に
してしまう。実装中に実機で確かめたところ、消えていく行の上に
「削除に失敗しました」が実際に一瞬出ていた (スワイプ削除にも前からあった。
畳んだ直後に画面が遷移するので気づけなかった)。

`catch` の先頭で `unstable_rethrow(error)` を呼び、フレームワークの例外だけ
投げ直す。本物の通信失敗はこれまでどおり行内に出す。

## 4. PC: ホバーで出すアイコンボタン列

行 (`ItemRow` の前面 div) に `group` を付け、右端に
`COMPACT_ICON_BUTTON_CLASS` のボタン列を absolute で重ねる。

- **出し入れは `opacity` + `pointer-events`。**
  `opacity-0 pointer-events-none group-hover:opacity-100
  group-hover:pointer-events-auto group-focus-within:opacity-100
  group-focus-within:pointer-events-auto`。
  - `hidden` にしないのはレイアウトを揺らさないためと、Tab で
    フォーカスが入れるようにするため (`display:none` はフォーカス不能)。
  - `pointer-events-none` は必須。opacity だけだと、ホバーの無い環境で
    **見えないボタンがタップを吸う**。
  - `group-focus-within` はキーボード利用者向け。ホバーでしか出ない
    ボタンは Tab の人には存在しないのと同じになる。
- Tailwind v4 の `hover:` 系は `(hover: hover)` の環境にしか効かないので、
  タッチで hover が貼り付く事故は起きない。
- **stretched link の膜より上に出す** (`relative z-10`)。タグと同じ扱い
  (`ItemRow.tsx` の膜の説明を参照)。膜の下に居るとボタンを押しても
  ノートが開く。
- 置き場所は右端 (compact は行の右、card は右上)。サムネに重なるが、
  出るのはホバー中だけで、そのときユーザが見たいのはボタンのほう。
  下が透けないよう `bg-white/90 rounded` 程度の地を敷く。

## 5. スマホ: 長押しでメニュー

### 5-1. 長押し判定はスワイプと同居させる

`useLongPress` を `SwipeToTrashRow` の前面 div (pointer ハンドラが既に居る所)
に同居させる。判定は元々ほぼ排他になっている —

- スワイプは横 8px (`SWIPE_SLOP`) を超えて初めて dragging、
- 長押しは 10px (`LONG_PRESS_MOVE_TOLERANCE_PX`) 動いたら取り消し、
- 縦スクロールは `touch-pan-y` でブラウザが取り、`pointercancel` が
  長押しも倒す

— が、8〜10px の隙間を塞ぐため、**dragging 成立の瞬間に長押しを明示的に
取り消す** (`moveSwipe` が dragging を返した所で `longPress.cancel()`)。
そのために `useLongPress` の戻り値を `{ handlers, cancel }` に分けた —
`handlers` は要素へそのまま展開される (`CycleSlot` の `{...press.handlers}`)
ので、ハンドラでない物を同じ袋に混ぜると React が未知の属性として警告する。

**マウスでは長押しを仕掛けない** (`pointerType === "mouse"` を弾く)。PC の
近道はホバーのボタン列で、こちらは指のための入口。仕掛けると、ゆっくり
クリックした人 (0.5 秒は意外と短い) の click が握り潰され、押しても
ノートが開かない行になる。ペンは指と同じ扱い — ホバーを持たない入力なので
長押しが要る。

### 5-2. iOS のリンクプレビューと PC の右クリック

- 行の当たり判定は `<a>` (stretched link) なので、iOS は長押しで
  リンクプレビューを出してしまう。長押し対象の行に
  `[-webkit-touch-callout:none]` を敷く (`BOTTOM_BAR_CLASS` と同じ手。
  あちらは `<button>` だったので顕在化しなかった罠)。
  **文字選択の禁止はタッチだけに絞る** — `select-none` を PC まで効かせると
  一覧のタイトルや本文をマウスで選んでコピーできなくなる。`globals.css` に
  `@custom-variant touch (@media (hover: none))` を足し、`touch:select-none`
  で書く。
- **PC の右クリックは素通しにする。** `useLongPress` は `contextmenu` を
  常に止めて「右クリック = 長押し」に読み替えるが、行では
  「右クリックで URL コピー」を守ると `ItemRow` が明言している。
  幸い既存実装に「まだ押している最中か (`start !== null`)」で
  タッチ長押しと PC 右クリックを見分ける仕組みが既にあるので
  (`useLongPress.ts` の onContextMenu)、**押している最中だけ止めて開き、
  そうでなければ既定に任せる**オプションを `useLongPress` に足す。
  Android の長押し contextmenu は「押している最中」側なので今までどおり
  こちらが取る。

### 5-3. メニューの出し方

`SlotMenu` は下部バーのスロット専用 (`absolute bottom-full` + 中央寄せ) で、
そのままは使えない。**`SwipeToTrashRow` の li は `overflow-hidden`**
(はみ出した削除ボタンを切るため) なので、行の中に absolute で出すと
メニューごと切られる。

- 新しく `RowActionMenu` を作り、**`position: fixed` で押した位置の近くに
  出す**。ただし**行の前面 div は `translateX` を持っており、transform のある
  要素は `position: fixed` の包含ブロックになる** — 中に置くと、画面座標の
  つもりの位置が行の中を指す ([62 §3](./62-下部バー長押し計画.md) の
  `backdrop-filter` と同じ罠)。**`createPortal` で body へ出す**ことで、
  この罠と li の `overflow-hidden` の両方を同時に外す。
- 画面端で切れないよう位置をクランプする。**クランプ計算は
  `src/lib/rowActionMenu.ts` の純関数に置く** — この土台は jsdom を持たず
  (`vitest.config.ts` の `environment: 'node'`)、lib に置いた分だけが
  検査できる (`swipeRow.ts` / `longPress.ts` と同じ分担)。
- 外側タップで閉じる・Escape で閉じるは `SlotMenu` の
  「document の `pointerdown` を capture で拾う」方式をそのまま使う
  (click では iOS Safari が取りこぼす)。
- **開くメニューは常に 1 つ。**ただしスワイプの `openItemNo` のように
  `ItemList` へ持ち上げる必要はなかった — 上の document 押下で閉じる仕組みが
  あるので、別の行を押した時点で先に閉じる。state は行に置いたままでよい
  (スワイプの開閉を親に置いてあるのは、あちらが「押されていない間も開いた
  まま」だから)。メニューを開くときはスワイプの引き出しだけ畳む。
- 画面がスクロール・回転したら閉じる。fixed で画面座標に置いてあるので、
  行だけが動くとメニューが無関係な場所を指したまま残る。
- 項目は `SLOT_MENU_ITEM_CLASS`、danger は赤字。長押し成立後の click は
  `useLongPress` が握り潰すので、離した指がノートを開く事故は起きない。
- **色は土台のクラスから抜いて使う側で与える** (`ui.ts` の
  `SLOT_MENU_ITEM_SKIN`)。土台に `text-gray-700` を残したまま `text-red-700`
  を足すと、どちらが勝つかは class 属性の並び順ではなく生成 CSS の並び順で
  決まる (同じ詳細度の同族ユーティリティ) — 効いたり効かなかったりする指定に
  なる。ホバーのアイコンボタンは色だけ内側の `span` に持たせて同じ衝突を避ける。

## 6. ゴミ箱アイコン

アイコンは全て `MenuIcons.tsx` の手書き SVG (`viewBox="0 0 24 24"` 統一) だが、
ゴミ箱だけ絵文字 `🗑` が使われている (`BulkTagToolbar.tsx`、`ItemList.tsx` の
0 件案内)。`TrashIcon` を SVG で足し、絵文字 2 か所も置き換えて統一する。
絵文字はプラットフォームごとに字形も色も違い、単色アイコンの列に混ざると
そこだけ浮く。

## 7. 対象範囲

- **小 (compact) と大 (card) の、非選択モードのみ。** スワイプ削除と同じ枠
  ([43 §9-4](./43-スワイプ削除計画.md))。選択モード中は一括ツールバーが
  あるので要らない。
- **画像モードは対象外。** タイルは画像単位でノート単位ではなく
  ([32-画像表示モード計画.md](./32-画像表示モード計画.md))、どの画像を
  長押ししてもノートごと消える、は直感に合わない。必要になったら別途。
- **ゴミ箱一覧 (`TrashList`) は対象外。** あちらは復元 / 完全削除のボタンが
  常時見えており、隠す理由が無い。

## 8. 試験

**node で回る単体試験** (vitest。判断を lib の純関数と手へ寄せるのはこのため):

- `rowActionMenu.test.ts` … メニュー位置のクランプ (指の上 / 入らなければ下 /
  画面端 / メニューが画面より大きいとき)。
- `useLongPress.test.tsx` … 押し始めの座標を渡すこと、外からの `cancel`、
  `rightClick: "native"` の 2 経路 (PC の右クリックは素通し / 押している最中の
  contextmenu は長押し扱い)。

**ブラウザで確かめたこと** (dev サーバ + Playwright、生成 CSS も確認):

- 生成 CSS で `group-hover:*` が `@media (hover: hover)` に、`touch:select-none`
  が `@media (hover: none)` に包まれていること (スマホでボタンが貼り付かない /
  PC で文字が選べる、をクラス名ではなく出力で確かめる)。
- ホバー時にボタンの中心の当たり判定がボタン自身になる (stretched link の膜に
  負けていない)。ホバーしていない行では当たらない (`pointer-events-none`)。
- 長押しでメニューが body 直下に開き、押した指の上・画面内に収まる。
- マウスの長押しでは開かない / タッチとペンでは開く。
- 横 9px 払うとメニューは出ない (§5-1 の 2px の隙間)。
- 外側の押下でメニューが閉じる。
- ホバーのボタンからも長押しメニューからもノートがゴミ箱へ入り、指を離した
  click でノートが開かない。

## 9. 進め方

1. **TrashIcon + PC ホバー列** — 新規部品が少なくリスクが小さい。
   ここまでで PC の穴 (§1) は塞がる。
2. **長押し + RowActionMenu** — スワイプとの調停 (§5-1)、
   iOS プレビュー抑止 (§5-2)、fixed 配置 (§5-3) を含む本体。
3. 以降のアクション追加は §3 の配列に足すだけ。

各段階とも、実装後に /code-review を通してからコミットする。
