# 行メニュー計画

検索結果の行に、操作の入口として ⋮ ボタンを常に出す。押すと文字付きの
メニューが開く。PC のホバーの近道とスマホの長押しは残す。操作はこれから
増える見込みで、[66-行アクション計画.md](./66-行アクション計画.md) の
「一覧を 1 か所で持つ」形はそのまま使う。

## 1. 何が足りなかったか

66 の形は「PC はホバーでアイコン列、スマホは長押しでアイコンだけのメニュー」
だった。操作がゴミ箱 1 つのうちは困らないが、増やすと 3 つの穴が出る。

- **スマホに見える入口が無い。** 長押しもスワイプも、知っている人しか使えない。
  行に操作があると気づく手掛かりが画面のどこにも無い。
- **絵だけでは意味が読めない。** ゴミ箱は絵で通じるが、ピン留め・複製・
  移動などは 20px の線画では見分けにくい。❌ は「閉じる」と読まれやすい。
- **ホバーの列が伸びる。** 全部をホバーで並べると、サムネとタイトルを覆う
  帯が操作の数だけ長くなる。

## 2. 方式 — ⋮ を常設し、近道は quick の付いた物だけ

| 入口 | PC | スマホ |
| --- | --- | --- |
| ⋮ ボタン | 常に見える (薄い灰。ホバー中の行で濃く) | 常に見える |
| ホバーの近道 | `quick` の付いた操作だけ、⋮ の左に | 出ない (hover が無い) |
| 長押し | 仕掛けない (66 §5-1) | ⋮ と同じメニューを指の近くに |
| スワイプ | 無し | ゴミ箱専用の最速動線 (43) |

- ⋮ は Gmail・Google Drive と同じ「行の右端」。縦の三点にするのは、行末の
  省略記号 (…) と見分けるため。
- `RowAction` に `quick?: boolean` を足した。ホバーの列 (`RowActionButtons`)
  は quick の付いた物だけを描き、メニューは全部を描く。付けるのはよく使う
  1〜2 個まで。今はゴミ箱だけが quick。
- **置き場所。**
  - 小・中表示 … 行の右端で行の全高を当たり判定にする (幅 40px)。行は
    32px ほどで、36px 角を中央に置くと li の `overflow-hidden` に上下を
    切られる。中身は `pr-10` で ⋮ の幅だけ左へ寄せる。
  - カード … 右上の 36px 角に、白い半透明の丸い地を敷く。サムネの角に
    重なってよい。サムネが無いカードだけ、文字の列を `pr-8` で空ける
    (⋮ はタグの行まで届くので、題の行だけでは足りない)。
- ホバーの近道は、キーボードのフォーカスが行に入ったときにも出す。
  ただし **`focus-within` ではなく「行の中に `:focus-visible` があるか」**
  (`group-has-[:focus-visible]`) で見る。Android の Chrome はタップした
  ボタンにフォーカスを置くので、`focus-within` だと ⋮ をタップしただけで
  スマホにも近道が出る。
- `data-row-action` を付けて、押下をスワイプ・長押し・stretched link に
  渡さない (`useRowGestureArbiter` の既存の仕組み)。`z-10` でタイトルの
  当たり判定の膜より前に出す。
- 選択モードとゴミ箱の一覧では出さない。スワイプと同じ枠 (66 §7) で、
  `RowSwipe` の袋が来た行だけに出る。画像モードは §8 で別に扱う。

## 3. メニューの中身 — アイコン + 文字

- 項目は **アイコン + 文字** にした (`ROW_MENU_ITEM_CLASS`)。66 §5-3 は
  「指のすぐ上に出る的に文字を載せると行を覆う」としてアイコンだけに
  していたが、項目が増えると絵だけでは読めない (§1)。高さ 44px は
  下部バーのメニューと揃える。
- **危険な操作は末尾に寄せ、境に区切り線を 1 本引く** (`orderMenuActions`)。
  ⋮ の真下に開くので先頭が一番押されやすく、そこから遠ざける。危険な物
  しか無い・普通の物しか無いときは線を引かない。
- 確認ダイアログは今までどおり付けない。ゴミ箱は復元できる (66 §3)。

## 4. 出す位置

- ⋮ から開いたら **ボタンの真下に右端を揃えて** 出す。下に入らなければ上へ
  回し、どちらにも入らなければ画面の中へ収める
  (`placeRowActionMenuAtAnchor`)。指の点と違って起点が見えたまま残るので、
  上へ逃がす理由が無い。
- 長押しから開いたら今までどおり指の上 (`placeRowActionMenu`)。
- どちらから開いたかは `MenuOrigin` (`point` / `anchor`) で持ち、
  `placeRowActionMenuFrom` が振り分ける。body へ portal して fixed で
  置く仕組み (66 §5-3) はそのまま。
- **スワイプの引き出しが開いた行で ⋮ を押したとき**は、測った矩形から
  ずらし量を差し引く。⋮ は前面 div ごと左へずれていて、開くと同時に
  引き出しを畳むので、測ったままの位置ではメニューがボタンから離れて残る。

## 5. キーボードと読み上げ

WAI-ARIA のメニューボタンの作法に合わせた。

- ⋮ は `aria-haspopup="menu"` と `aria-expanded` を持ち、名前は
  「#12 の操作」。メニューも同じ名前を名乗る。
- ⋮ から開くと先頭の項目へフォーカスを移す。長押しから開いたときは
  移さない (指の操作で、閉じたときの返し先も無い)。**置き終わってから移す** — 測る間の
  メニューは `visibility:hidden` で、隠れた要素はフォーカスを受けない。
  `preventScroll` を付ける (動くとスクロール監視が閉じてしまう)。
- ↑↓ で項目を渡り、端では反対側へ回る。Home / End で両端
  (`nextMenuIndex`)。↑↓ の既定のスクロールは止める。
- Esc で閉じ、⋮ へフォーカスを返す。項目を選んだときも返す。Esc は
  document で拾う (メニューの余白を押してフォーカスが外れた後も効くように)。
- Tab はメニューを閉じて次の部品へ進める。先に ⋮ へフォーカスを返し、
  既定の Tab は止めない — ブラウザが ⋮ の次 (Shift なら前) へ進める。
- 外側を押して閉じたときはフォーカスを返さない (押した先が次の
  フォーカスを持つ)。
- ⋮ をもう一度押すと閉じる。メニューの「外側の押下で閉じる」は ⋮ への
  押下を数えない — 数えると押下で閉じた直後の click がまた開く。

## 6. 試験

- `src/lib/gesture/rowActionMenu.test.ts` … ⋮ 起点の位置 (真下・右揃え・
  上へ回す・左端・上下とも入らない)。
- `src/components/item/row-actions/rowMenuOrder.test.ts` … 危険な操作の
  並びと区切り線、↑↓ Home End の行き先。
- `e2e/row-menu.spec.ts` … PC で ⋮ が文字付きのメニューを開き先頭に
  フォーカスが移る、Esc で閉じて ⋮ へ戻る、Tab で閉じて次へ進む、もう一度押すと閉じる、押しても
  ノートは開かない、スマホ (タッチ) でホバー無しに ⋮ が見えてメニューから
  ゴミ箱へ入れられる。
- 既存の `trashFromSearch` (ホバーのゴミ箱) と `touch-callout.spec.ts` も
  通ることを確かめた。

## 7. 画像モードのタイル

当初は 66 §7 に揃えて画像モードを外していたが、ユーザーの指定で付けた
(2026-10-17)。タイルは画像 1 枚ごとで、1 ノートに画像が 3 枚あれば 3 タイル
並ぶ。そこで行とは次の点を変えた。

- **⋮ は画像の上ではなく、キャプション行 (#番号 タイトル) の右端に置く。**
  画像への操作ではなくノートへの操作だと読ませるため。タイル (li) を
  `@container` にし、⋮ の top を `100cqw` (= タイルの幅 = 正方形の画像の
  高さ) にして画像のすぐ下へ揃える。⋮ は 24px × 36px。
- **キャプション行は ⋮ より高く取る** (`min-h-7`)。タグの無いタイルで ⋮ が
  li の下端からはみ出すと、押した瞬間にブラウザが li (overflow-hidden) の
  中をスクロールして ⋮ を見せようとし、そのスクロールでメニューが閉じる。
  E2E で実際に踏んだ。
- **長押し・スワイプ・ホバーの近道は付けない。** 画像を長押ししたら
  ノートが消えた、を起こさない。入口は ⋮ だけ。
- **ゴミ箱へ入れる前に確認する** (`window.confirm`、ユーザーの指定)。
  行では確認しない (66 §3) が、タイルは「この画像だけ消す」と読まれやすく、
  同じノートの他のタイルもまとめて消える。確認文は
  `tileTrashConfirmMessage` が組み、ノートごと入ること・戻せることを言い、
  同じノートのタイルが複数あればその枚数も言う。
- **送信の状態はノート単位で一覧に 1 つ持つ** (`SearchTileMenuProvider`)。行の
  ように部品ごとに持つと、同じノートの他のタイルの ⋮ が押せるままで二重に
  送れ、送信中の覆いも失敗の文も押した 1 枚にしか出ない。送信中は同じ
  ノートのタイル全部に白い覆いを掛け、失敗したら全部に文を出す。
- タイルの li は `ImageMasonry` (ゴミ箱の一覧と共有する、サーバでも描ける
  部品) が持つ。⋮ とメニューはクライアント部品 `TileActions` に閉じ、
  `tileActions` を立てて `SearchTileMenuProvider` で包むのは検索一覧
  (`ItemList`) だけ。
- メニューは**先に閉じてから操作を実行する**。確認ダイアログの後ろに
  メニューが残らないように。⋮ は送信中に `disabled` ではなく
  `aria-disabled` で止める — 閉じたときにフォーカスが ⋮ へ返るので、
  直後に `disabled` にするとフォーカスが body へ落ちる。

試験は `tileTrash.test.ts` (確認文)、`ImageMasonry.test.tsx` (袋があれば
タイルごとに ⋮、無ければ出さない)、`e2e/row-menu.spec.ts` (取り消せば残る・
OK で同じノートの 2 枚がまとめて消える)。

## 8. 残っている確認

- iPhone 実機。⋮ を押したときに iOS のリンクプレビューやタップの
  ハイライトが出ないか、40px 幅の当たり判定が指で狙えるか。
- カードのサムネの角に ⋮ の丸い地が重なる見た目。
- 引き出しを開いた行で ⋮ を押したときの位置。Playwright で横に払う操作を
  組んでいないので、ブラウザでは確かめていない。
- 画像モードの ⋮ (§7) を iPhone 実機で。キャプション行の ⋮ が狙えるか、
  確認ダイアログの文面。
- ゴミ箱の画像表示の ⋮ (§9) を iPhone 実機で。

## 9. ゴミ箱の画像表示

**不具合 (2026-10-17、ユーザー報告):** 画像モードでノートを消すとゴミ箱も
画像表示になり、復元できなかった。表示形式の cookie (`view`) は検索一覧と
ゴミ箱で共有で、ゴミ箱の画像表示 (67) は「永久削除をタイルの数だけ並べない」
ためにタイルの操作を出していなかった。案内の文 (「ノートを開くか、小・大表示に
切り替えて」) はあったが、その場で戻す手が無かった。

ゴミ箱のタイルにも §7 と同じ ⋮ を付け、メニューに「復元」と「永久削除」を出す。

- メニューに畳めば、永久削除がボタンとしてタイルの数だけ並ぶことはない。
  67 が操作を外した理由はこれで解ける。
- 復元は確認しない (行の「復元」ボタンと同じ)。永久削除は行と同じ文で確認し
  (`purgeConfirmMessage`)、同じノートのタイルが複数あれば枚数を添える。
- メニューの中身と送信の状態は包みが持つ。検索一覧は `SearchTileMenuProvider`、
  ゴミ箱は `TrashTileMenuProvider`。状態の持ち方 (ノート単位) は共通
  (`useNoteSubmissions`)。復元・永久削除はリダイレクトせず revalidate で
  一覧が描き直され、タイルが消える。
- 試験は `TrashList.test.tsx` (タイルごとに ⋮、永久削除をボタンで並べない)、
  `purgeConfirm.test.ts`、`e2e/row-menu.spec.ts` (画像モードで消したノートを
  ゴミ箱の ⋮ から復元すると検索一覧に戻る・永久削除は確認し取り消せば残る)。
