# スキャン音量計画 (メニュー｜スキャン音)

QR・バーコードを読めたときのピッの大きさを、ハンバーガーメニューの
「スキャン音」で **消音 / 小 / 中 / 大** の 4 段から選べるようにする。
形はメニューの「テキストサイズ」(docs/61) と同じ「− / 今の段 / ＋」。

決めたこと (2026-10-18):

- 音はライブラリ内蔵のビープをやめ、**振幅を焼き込んだ自前の WAV** を
  **自前の要素で**鳴らす (`<Scanner sound={false}>`。§2-4)
- 段は離散 4 段。スライダーにはしない
- 既定は「大」。設定を足す前の音量を黙って下げない
- 保存は localStorage (端末ごと)
- ＋ / − を押すたびに新しい音量で 1 回鳴らす

## 1. 現状 (2026-10-18)

ピッを鳴らしているのはアプリではなく、読み取りライブラリ
`@yudiel/react-qr-scanner` (2.6.0) の `useScanner` である。`sound` の既定が
`true` で、base64 の mp3 を `new Audio()` で鳴らす。アプリ側のコードは
`navigator.vibrate(50)` だけで、これは iOS Safari では効かない。

`sound` は `boolean | string` を受け、文字列なら URL / data URI として
鳴らす。文字列が変わると Audio を作り直す。

## 2. 方式

### 2-1. 音量は波形に焼き込む

**iOS は `HTMLMediaElement.volume` を JS から変えられない** (代入しても常に 1)。
ライブラリの Audio に音量を掛ける手は、参照を取れたとしても iPhone で効かない。

そこで段ごとに振幅の違う WAV を実行時に組み立て、data URI にする
(`src/lib/audio/scanBeepWav.ts`)。鳴らすのは `<audio>` と同じ
HTMLMediaElement なので、iPhone での鳴り方 (メディア音量に乗る) は
内蔵のビープと同じで、大きさだけが変わる。

当初 (v0.23.45) はこの data URI をライブラリの `sound` に渡していたが、
スキャンではほぼ鳴らなかった。§2-4 で自前の要素に替えた。

| 項目 | 値 |
| --- | --- |
| 波形 | 正弦波 2093 Hz (C7) |
| 長さ | 80 ms。頭 5 ms・尻 30 ms の直線の傾斜 |
| 形式 | 16 bit / モノラル / 22.05 kHz の PCM WAV (約 3.5 KB) |

スマホのスピーカーは 1 kHz 以下が弱いので高めの音にした。傾斜を付けないと
頭と尻でプチ音が乗る。音色はライブラリの mp3 から変わる。「大」だけ
ライブラリの音を残すと段で音色が変わるので、全段を自前にした。

### 2-2. 段

| 表示 | 振幅 |
| --- | --- |
| 消音 | 0 |
| 小 | 0.06 (−24 dB) |
| 中 | 0.25 (−12 dB) |
| 大 | 1.0 (0 dB) |

振幅は等比 (12 dB 刻み) にして、1 段ごとの聞こえ方の差を揃える。
線形のスライダーだと、聞こえ方の変化が左端に偏る。

**刻みは広めに取る。** v0.23.45 では 0.2 / 0.5 / 1 (約 −14 / −6 / 0 dB) に
していたが、iPhone 実機で「小中大で差がない」と言われた。スマホのスピーカーは
音量を上げると強く頭打ちになり、6 dB 程度の差は潰れる。

**消音を入れる。** ピッは手応えであって本筋ではなく、図書館や職場で
黙らせたい場面がある。消音でも読めればモーダルが閉じて遷移するので、
「押しても何も起きない」にはならない。

### 2-3. 捨てた案

- **Web Audio (`GainNode`)**: 音量は確実に効くが、消音スイッチで黙るように
  変わる。さらに AudioContext をスキャナを開く 3 か所のクリックで解錠し、
  バックグラウンドからの復帰も面倒を見る必要がある。data URI で足りるので
  採らない
- **スライダー**: テキストサイズと同じ理由 (片手で狙いにくい・戻し方が曖昧)。
  同じメニューに段送りとスライダーが並ぶと流儀も割れる

### 2-4. ライブラリに鳴らさせない (v0.23.46)

v0.23.45 の iPhone 実機で「メニューの試し鳴りは鳴るが、スキャンでは
鳴ったり鳴らなかったり、殆ど鳴らない」と出た。

ライブラリの `useScanner` は、読めた瞬間に `audio.play()` してすぐ `onScan` を
呼ぶ。こちらは `onScan` でモーダルを閉じるので、ライブラリの `useEffect` の
後始末が直後に `audio.pause()` する。iPhone は `play()` から音が出るまでに
間があり、その間に止められる。間に合ったときだけ鳴る。メニューの試し鳴りは
画面が閉じないので毎回鳴る。

直し方:

- `<Scanner sound={false}>` にして、ライブラリには鳴らさせない
- 鳴らすのは**モジュールに 1 つだけ持つ要素** (`src/lib/audio/scanBeepPlayer.ts`)。
  モーダルを開いたときに段の音源で用意し、読めたら鳴らす。モーダルより
  長生きするので、閉じても誰も止めない
- 鳴り始める (`play()` が解決する) のを最大 150 ms 待ってから閉じる。
  鳴らせなくても待つのはそこまでで、遷移は止めない。失敗は診断ログに残す

読み取りの瞬間はユーザー操作の外だが、iOS Safari はカメラで撮っている
間のページに再生を許す (ライブラリの `play()` がたまに鳴っていたのも
このため)。

内蔵の mp3 (約 34 KB) が以前は鳴っていた理由は確かめていない。同じ経路で
止められていたはずで、長い音の残りが聞こえていた可能性がある。

## 3. UI

メニューのテキストサイズの直下に「スキャン音」の行を置く。

```text
🔊 スキャン音            −   大   ＋
```

- 段の名前を押すと既定の「大」に戻る (テキストサイズの「100%」と同じ)
- ＋ / − は端で disabled
- クリックは行で止める。素通しするとシートが閉じ、続けて押せない
- 押すたびに新しい音量で試し鳴りする。音量は目に見えないので、閉じて
  スキャンするまで判らないのでは選べない。押した操作の中で鳴らすので
  iOS でも鳴る。消音では鳴らさない
- 試し鳴りの失敗は診断ログ (`[スキャン音]`) に残す
- ログイン状態・デモに依らず出す。保存先が端末なので、選択色のように
  保存する相手を要らない

## 4. 実装

| ファイル | 役目 |
| --- | --- |
| `src/lib/prefs/scanBeepVolume.ts` | 段の表・保存・step・名前 |
| `src/lib/audio/scanBeepWav.ts` | WAV の組み立てと data URI (段ごとにメモ化) |
| `src/lib/audio/scanBeepPlayer.ts` | モーダルより長生きする要素で鳴らす |
| `src/components/camera/ScannerModal.tsx` | 開いた時点の段で用意し、読めたら鳴らしてから閉じる |
| `src/components/bottombar/ScanBeepMenuItem.tsx` | メニューの行 |
| `src/components/icons/menu.tsx` | `ScanBeepIcon` (スピーカー) |

スキャナを開いている間はメニューに触れないので、段はマウント時に 1 度読む
(購読しない)。

## 5. 確認

自動テストで確かめるのは WAV のヘッダ・振幅・傾斜、段の保存と寄せ方、
メニューの初期描画まで。次は iPhone 実機で確かめる。

- [ ] スキャンで毎回鳴る (v0.23.45 ではほぼ鳴らなかった)
- [ ] Safari とホーム画面の PWA の両方で、段ごとに音量が変わる
- [ ] 「消音」で鳴らない
- [ ] メニューの ＋ / − で試し鳴りする
- [ ] 消音スイッチ ON でも鳴り方が今と同じ
- [ ] スキャン直後に録音を始められる (iOS の AudioSession の罠を踏まない)
