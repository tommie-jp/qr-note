# 一覧回路図サムネ計画

検索結果とゴミ箱の一覧 (小/大/画像) で、ノート内の回路図 (```` ```circuitikz ````
フェンス) を画像として見せる。

背景: 一覧は markdown を描画せずプレーンテキスト + 添付サムネだけを出すため
(docs/23 §4)、回路図しか持たないノートは文字だけになり見分けにくい。回路図は
すでにサーバ側で SVG 化され `circuit_svgs` にキャッシュ済み (docs/07) なので、
これを流用する。

## §1 小/大表示: 画像の無いノートの顔にする

- 顔の優先順位は **画像/動画 → 回路図 → なし**。画像があるノートは今までどおり
  (`firstThumbInfo` の絵) で、文字だけだったノートにだけ回路図が加わる。
- 本文の出現順で画像と回路図を混ぜる案は見送り。`extractCircuitSources`
  (remark) が位置情報を持たず、`memoImages` (正規表現) との突き合わせが増える
  割に益が薄い。画像優先なら、図が未描画かどうかで画像持ちノートの見た目が
  揺れない利点もある。
- 枠は画像サムネ (RowThumb) と同じ寸法 (小 40px / 大 96px)。分岐は
  `ItemRow` の thumb が持つ (優先順位の正本)。

## §2 引くだけ、描かない

一覧の表示で `renderCircuit` (1 図あたり最大 10 秒) を呼ぶことはしない。
`src/lib/circuitThumbs.ts` の `loadCircuitThumbs` が `circuit_svgs` を
**引くだけ**で、未描画の図は黙って飛ばす — オフライン同期の口が描かないのと
同じ理由 (docs/65 §8-2、`loadOfflineCircuits`)。

- 足切り: URL モード / フェンスの気配 (`includes('circuitikz')`) が無い /
  first で画像サムネを持つノートは、パースもクエリもしない。
- ページぶんの hash を重複なしの 1 クエリ (`findMany ... in`) で引く。
- キャッシュ済みでも毎回 `assertSafeCircuitSvg` を通してから埋め込む
  (`getOrRenderCircuit` と同じ作法)。検査 NG・DB エラーは「サムネなし」へ
  静かに畳む — 回路図はおまけで、一覧本体を道連れにしない。

## §3 配信はインライン SVG

`<img src>` や PNG 化ではなく、`CircuitDiagram` と同じ `dangerouslySetInnerHTML`
のインライン埋め込み (`src/components/CircuitThumb.tsx`)。

- SVG のフォントは `/tikzjax/fonts.css` への外部参照で、`<img>` の
  secure static mode では読めず文字が崩れる。sharp (librsvg) の PNG 化も同じ
  問題 + Docker への fontconfig 整備が要る。インラインなら document の
  コンテキストでフォントが効く (本文表示と同じ)。
- 大きさ合わせは CSS (`globals.css` の `.circuit-thumb > svg`)。サーバ生成
  SVG は固定 px の width/height 属性を持つが、枠いっぱいに上書きすれば
  viewBox + preserveAspectRatio 既定が object-contain 相当に働く。
  本文用 `.circuit-diagram` と分けるのは、あちらの zoom (文字サイズ追随) を
  サムネに効かせないため。
- `aria-hidden` の装飾扱い (RowThumb の `alt=""` と同じ理屈)。SVG 内の
  `<text>` (素子名など) を読み上げに混ぜない。

## §4 画像表示: タイルとして並べる

ノートごとに **画像タイル → 回路図タイル** の順で追加 (種類内は出現順)。
完全な文書内順は §1 と同じ理由で見送り。タイルのリンク先はノートで、
キャプション (compact 準拠の 2 行) も stretched link も画像タイルと同じ。
空メッセージは「このページには画像・回路図がありません」。

## §5 データの配線

props はサーバ→クライアント境界を越えるので `Record` (CircuitThumbMap =
itemNo → SVG の配列、出現順)。

```text
(search)/page.tsx ─ loadCircuitThumbs(items, view==='image' ? 'all' : 'first')
        └ ItemList ─ ItemRow (先頭 1 枚) / ImageMasonry (全部)
trash/page.tsx ──── 同上 ─ TrashList ─ ItemRow / ImageMasonry
```

- mode='first' は小/大用 (画像の無いノートに、最初に描画済みの 1 枚)。
  'all' は画像モード用。表示モードはサーバで既知なので引く量を絞れる。
- 部品は共有だがデータはページごとに配線が要る (ゴミ箱は自動では効かない)。
- `circuitThumbs.ts` は prisma を引き込むサーバ専用 module。client component
  からは型だけ import する (offline/circuits.ts と同じ線引き。値を混ぜると
  編集画面ごと 500 になる)。

## §6 予算と初回の埋め方

- SVG 1 枚 32KB (`MAX_CIRCUIT_THUMB_BYTES`。実測平均 2.9KB の余裕枠)、
  1 レスポンス合計 256KB (`CIRCUIT_THUMB_BUDGET`)。`searchItems` は
  「さらに表示」で 1〜N ページの累積を返すため、件数はページを送るほど
  増える。一覧の先頭から詰めて、超過分は黙って落とす (前例:
  `OFFLINE_CIRCUIT_BUDGET`)。ItemList は client component なので SVG は
  SSR の HTML と Flight payload の両方に載り、線上は約 2 倍になる — 予算は
  それを織り込んだ値。
- 一度も開かれていないノートの図はキャッシュに無くサムネも出ない。導入時に
  `scripts/backfillCircuits.ts` を 1 回流して全図を描いておく (本番へは
  `doBackfillCircuits.sh`、SSH トンネル越し。doBackfillThumbs.sh と同じ仕掛け)。
  以後はノートの表示時に描かれて自然に揃うので、定期実行は要らない。
