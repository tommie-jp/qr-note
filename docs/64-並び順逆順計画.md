# 64. 並び順の逆順

一覧の並び順 ([37-アクセス順計画.md](./37-アクセス順計画.md)、
[63-タイトル順計画.md](./63-タイトル順計画.md)) の 4 種別すべてに、
逆向きに辿る並びを足す。

## 1. 行を増やさずに足す

種別は 4 つあり、方向を素直にメニューへ並べると 8 行になる。

```text
更新順 (新しい順)      アクセス順 (新しい順)      番号順 (小さい順) …
更新順 (古い順)        アクセス順 (古い順)        番号順 (大きい順) …
```

8 行のメニューは、選ぶ前に読む量が倍になる。**片手の親指で押す帯から出す
一覧なので、行数がそのまま「選びにくさ」になる** ([31-下部操作バー計画.md](./31-下部操作バー計画.md) §3)。
下部バーのスロットも短いタップで循環する形 ([62-下部バー長押し計画.md](./62-下部バー長押し計画.md) §3)
なので、8 値にすると一周も遠くなる。

そこで**メニューは 4 行のまま**にして、方向は「選んである行をもう一度押す」に
載せる。選び直す意味の無いタップ (今と同じ種別を選ぶ) が空いているので、
そこへ入れる。ファイラーの列見出しと同じ操作で、覚え直す物は無い。

## 2. 種別と方向を 1 本の文字列に畳む

`Sort` に逆順の 4 値を足す (`src/lib/validation.ts`)。

```ts
export type SortBase = 'itemNo' | 'updated' | 'accessed' | 'title'
export type ReversedSort = 'itemNoDesc' | 'updatedAsc' | 'accessedAsc' | 'titleDesc'
export type Sort = SortBase | ReversedSort
```

**方向を別のパラメータにしない**のが要点。並び順は cookie ([sortMode.ts](../src/lib/sortMode.ts))、
URL の `?sort=`、一覧のクエリ、ノートの前後ナビ ([60-学習進捗計画.md](./60-学習進捗計画.md) §4)
を 1 値で通っていて、方向を足すと全部の経路が二本立てになる。

基底の 4 値は**その種別の既定の方向**を指す、という取り決めも要る。おかげで
前に選んだ cookie (寿命 1 年) も、共有された `?sort=title` のリンクも、
意味が変わらないまま開ける。移行処理は要らない。

既定の方向は種別で違う:

| 種別 | 既定 | 逆順 |
| ------ | ------ | ------ |
| 更新順 | 新しい順 (降順) | 古い順 |
| アクセス順 | 新しい順 (降順) | 長く見ていない順 |
| 番号順 | 小さい順 (昇順) | 大きい順 |
| タイトル順 | 昇順 | 降順 |

種別と方向の出し入れは [sortDirection.ts](../src/lib/sortDirection.ts) に集める
(`baseOf` / `reverseOf` / `isDescending`)。

## 3. 押したときに何が起きるか

- 短いタップ … 今までどおり**種別だけ**を回し、方向はその種別の既定に戻す。
  方向を引き継ぐと、同じ「番号順」を押しても前回どちらを見ていたかで結果が
  変わり、押す前に何が起きるか読めない
- 長押しのメニューで**別の**行 … その種別の既定の方向で並ぶ
- 長押しのメニューで**選んである**行 … 種別はそのままで方向が裏返る。
  2 回押せば元に戻るので迷子にならない

送る値はメニューを描くときに決まるので、cookie を書くフォーム送信のまま
実現できる (クライアント JS は増えない = JS 無効でも切り替わる)。

## 4. 方向をどこに出すか

**下部バーはアイコン、メニューは行の右端の矢印**に出す。

バーのラベルに「↓」を足す案は採らない。5 スロットの帯で 1 枠は 320px 端末で
56px しかなく、いちばん長い「アクセス順」に 1 文字足すとあふれる。
アイコンなら幅は変わらないので、上下両向きの `SortIcon` を方向付きの
`SortDescIcon` / `SortAscIcon` に描き分ける。

メニュー側は行の右端に `↓` / `↑` を離して置く。ラベルの隣に付けると種別の
名前の一部に見えるが、離すと「この行にもう 1 つ的がある」と読める。

矢印の向きは**並びそのもの** (降順なら ↓) で、「押すと下がる」ではない。
画面の矢印と実際の並びが食い違わないよう、`isDescending` と `orderByClause`
を突き合わせるテストを置いてある (`src/lib/sortDirection.test.ts`)。

読み上げには言葉で出す。矢印だけでは方向が判らないし、現在行が押せることも
伝わらない。

```text
バー      並び順: 更新順・新しい順 (押すとアクセス順に切替、長押しで一覧)
現在行    更新順・新しい順 (押すと古い順に切替)
```

## 5. 裏返さないもの

`ORDER BY` ([sortOrder.ts](../src/lib/sortOrder.ts)) で向きを変えるのは
**並べる鍵だけ**にする。

- **末尾のタイブレーク (`item_no ASC`)** … 同着をいつも同じ順で解くための鍵で、
  見せたい並びの一部ではない。ここが揺れるとページ送りと前後ナビが読み込みの
  たびにずれる ([15-単語帳向け改善計画.md](./15-単語帳向け改善計画.md) §2-2)
- **`NULLS LAST`** … 番号として読めない `item_no` と見出しの無いノートは、
  どちらの向きでも末尾に置く。方向を変えたとたんに読めない行が先頭を埋めるのでは、
  逆順にした意味 (端から辿る) が消える

```sql
-- 番号順の逆順。item_no_num だけを裏返す
item_no_num DESC NULLS LAST, item_no ASC
```
