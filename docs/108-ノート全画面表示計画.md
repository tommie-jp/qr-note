# ノート全画面表示計画

ノートを開いたとき、既定では本文だけを見せる。見出し行 (`item #…`・公開と
オフラインのトグル・編集 / 履歴 / QR / ページ / 画像 / 記法)・タグ・タブ・
作成と更新の時刻は畳み、呼んだときだけ本文の上に重ねて出す。ペイン構成
(3 / 2 / 1) とヘッダーの帯には手を付けない。

## 1. 何が困っていたか

本文の前に操作が 3〜4 行積まれている。下部ペイン (高さ 45dvh) のスマホでは
画面の 1/3 近くが操作で埋まり、本文は 2〜3 行しか見えない。
[75-ノート上部圧縮計画.md](./75-ノート上部圧縮計画.md) で隙間を詰め、
[82-ノート操作アイコン計画.md](./82-ノート操作アイコン計画.md) で文字を
アイコンへ縮めたが、行そのものは残っていた。

## 2. 決め

| 要素 | 扱い |
| --- | --- |
| 見出し行 (番号・トグル・操作リンク) | 畳む |
| タグ | 畳む |
| タブ (markdown / テキスト / 編集) | 畳む |
| 作成・更新の時刻 | 畳む (重ねた面の末尾) |
| 未登録・ゴミ箱のバナー | 畳まない (警告) |
| URL の箱 | 畳まない (QR の飛び先そのもの) |
| 閉じる・全画面で開く | 畳まない ([86](./86-検索3ペイン計画.md) §4-17 で ◀ だけでは戻れないと判った) |
| 前 / 次 | 畳まない (本文の末尾に居て場所を取らない) |
| 公開中であること | 畳んでいる間も小さな印を出す |

- **呼び方は 3 つ。** PC はマウスを上端の行 (閉じる・全画面で開くの行) に
  載せる。指の端末はその行の右の ⋯ を押す。キーボードはその行へ Tab で
  入る。ホバーだけにすると iPhone から操作が消える
  ([82](./82-ノート操作アイコン計画.md) §5 の PressTip と同じ反省)。
- **編集タブの間は畳まない。** 編集中に戻り口が消えると迷う。編集タブに
  居る間は、これまでどおり本文の上に積む。
- **畳まない好みも持つ。** 重ねた面の 📌 で「常に出す」に切り替えられる。
  端末ごとの好みで、正本は localStorage (`qr-search:note-chrome-pinned`)。
  常に出すにした端末では、これまでと同じ積み方になる。
- **公開ビュー (未ログイン) は畳まない。** 読者に ⋯ の意味を教える手段が
  無く、操作も少ない。

## 3. 作り

### 3-1. 重ねる面は上端の行の中に置く

上端の行は器の上端に貼り付いている (ペインは `sticky top-0`、全画面の
`/item` は `sticky top-[var(--header-h)]`)。重ねる面をその行の直下に
`absolute top-full` で描けば、本文を押し下げずに被さり、どこまで
スクロールしていても上端から出る。

行 (`NoteChromeBar`) はペイン (`PreviewPane`) と全画面 (`ItemDetail`) の
両方が使う。中に 2 つの差し込み口を持つ。

- 呼び口 … ⋯ と公開中の印。閉じる・全画面で開くの間。
- 重ねる面 … 行の直下。

### 3-2. 中身はタブの持ち主が portal で差し込む

タブの選択は `MemoPanel` (client) が持つ。見出し行・タグ・時刻は
`ItemView` (server) が作り、`MemoPanel` に `chrome` として渡す。
`MemoPanel` は畳むかどうかを決め、畳むときは差し込み口へ `createPortal`
で描く。portal は React の木の上では `MemoPanel` の子のままなので、
タブの状態はそのまま使える。

差し込み口と開閉の状態は `NoteChromeProvider` (context) が持つ。
`ItemDetail` のログイン中の枝だけがこれで包む。包まれていない
`MemoPanel` (公開ビュー) は従来どおり積む。

### 3-3. ホバーと外側の押下は DOM で見る

React の `onPointerLeave` は React の木で判定するので、portal で差し込んだ
重ねる面へマウスを動かしただけで「行を離れた」と判定される。行の要素に
素の `pointerenter` / `pointerleave` / `focusin` / `focusout` を付ける。
重ねる面は DOM の上では行の子なので、行の外へ出るまで閉じない。

- ホバーは `pointerType === "mouse"` だけ。指のタップでも `pointerenter` は
  飛んでくる。
- 開くのは 150ms、閉じるのは 250ms 待つ。上端をかすめただけで面がちらつく
  のを防ぎ、行から面へ移る隙間で閉じないようにする。
- 面は、行の外を押す・⋯ をもう一度押す・Esc・タブを選ぶ、のどれかで閉じる。
  どれも開いている理由 (ホバー・⋯・フォーカス) を全部捨てる。PC で面から
  タブを選んだときも、マウスが面の上に残ったまま閉じる。
- **閉じるときはホバーの予約も取り消す。** ⋯ を押す瞬間にマウスが行へ入って
  開く予約が入る。すぐ面のタブを選んで閉じると、予約が後から発火して面を
  開き直し、マウスはもう行の外なので離れる合図も来ない (E2E で判明)。
  予約は `NoteChromeProvider` が持つ。
- Esc は面が開いている間だけ document で拾う。面の中のトグルは押すと釦ごと
  差し替わり、フォーカスが body へ落ちるため、行の keydown では届かない。
- キーボードは行の中に `:focus-visible` が入ったら開く。タップのフォーカスは
  `focus-visible` にならないので、指の端末で勝手に開くことはない
  ([107](./107-行メニュー計画.md) §2 と同じ判断)。

### 3-4. 積む形と畳む形で木の形を変えない

編集タブに入ると積む形、出ると畳む形へ切り替わる。`MemoPanel` がタブの
パネルを形ごとに別の親へ置くと、React は切り替えのたびにパネルを作り直す。
開いたエディタが捨てられ、打ちかけの文字・undo の履歴・離脱の確認が消える
(レビューで判明)。出さない物は `null` の穴にして、パネルの器はどちらの形でも
同じ位置の同じ `div` に置く。E2E はエディタの DOM に印を付け、行き来の後も
同じ要素であることを確かめている。

### 3-5. 割り切り

- **「常に出す」の端末では、読み込み直後に一瞬だけ畳んだ形が出る。**
  好みは localStorage にしか無く、サーバは既定 (畳む) で描く。既定の端末
  では跳ねない。
- 画像の表示モード「全体」の高さは重ねる面のぶんを引かない。面を開いて
  いる間だけ画像の上端が隠れる。

### 3-6. 下部ペインでは行を本文の上に浮かせる (2026-10-18)

下部ペイン (3 / 2 ペイン) の上端の行は、左端の「閉じる」が無い
([86](./86-検索3ペイン計画.md) §4-4) ので、⋯ と「全画面で開く」だけで
45dvh のうち 48px を占めていた。畳む形のときはこの行を本文の上に浮かせ、
行の高さを本文に貸す。

- **行は sticky のまま、負の margin (`-mb-12`) で本文を引き上げる。** 行の
  高さは残るので、重ねる面の `top-full` はそのまま札の下から出る。地色は
  外し、根を `pointer-events-none` にして空いた左側で本文のリンクや画像を
  塞がない。押せる物 (札・重ねる面) だけ `pointer-events-auto` に戻す。
  根の `pointerenter` は子に入っても飛んでくるので、ホバーで開く仕掛けは
  そのまま効く (入口が行全体から札に縮むだけ)。
- **⋯ と「全画面で開く」は半透明の丸い札 (`bg-white/85 backdrop-blur`) に
  まとめる。** 本文の上に乗っても読めるように。「全画面で開く」は ⋯ と同じ
  44px の輪に入れた絵 (`OpenFullIcon`) にして、名前は aria-label と長押しの
  吹き出し (PressTip) が言う。全画面 (1 ペイン) は場所があるので文字のまま。
- **本文の先頭に札と同じ大きさの `float-right` の詰め物を置く**
  (`NoteChromeFloatSpacer`)。見出しや段落の最初の数行が札を避けて折り返す
  ので、iPhone の幅でも 1 行目が札の下に潜らない。画像 (block) は避けずに
  札の下へ潜るが、角が少し隠れるだけ。
- **浮かせるのは畳む形のときだけ。** 「常に出す」の端末と編集タブでは
  見出し行 (編集 / 履歴 / QR / 記法) が本文の上に積まれ、右端に札が
  重なる。持ち主 (MemoPanel) が「いま積む形か」を器 (`NoteChromeProvider` の
  `inline`) に知らせ、帯はそれを見て行に戻る。
- **全画面 (1 ペイン) も浮かせる (2026-10-18 追記)。** 「閉じる」は右の札に
  合流させる (⋯ 全画面で開く 閉じる の順。左は空ける)。本文の先頭の
  詰め物は右だけで、文字の釦が並ぶので広め (`w-72`)。畳まない (常に出す・
  編集タブ) ときは行に戻る。
- 本文の器の頭に 1/4em (`pt-[0.25em]`) の余白を置く。浮かせた行を引き上げた
  結果、見出しがペインの上端に張り付いて見えたため。
- 行自身に `min-h-12` の下限を持たせる。釦が 1 つも無い間 (loading は
  「全画面で開く」が無く、⋯ はマウント後に portal で来る) も行が 48px で
  ないと、引き上げた本文の頭がスクロールで届かない負の領域に入る。
- 開いている間は行全体の pointer-events を戻す。札から重ねる面へ、行の
  空いた所を横切ってマウスを運ぶと、根を離れた扱いになって面が閉じるため。
- 割り切り: サーバ描画は常に浮いた形。積む形で始まるノート (空のメモは
  編集タブ・「常に出す」の端末) は useLayoutEffect で描いた直後に行へ戻す
  ので、ハイドレーション前の静的な HTML だけ札が見出し行に重なる。

## 4. 確認

- 単体: 畳むかどうかの判定・好みの読み書き・`MemoPanel` の積み方・
  `ItemDetail` の器。
- E2E (`e2e/note-chrome.spec.ts`): PC のホバーで出て離れると消える、
  指の端末で ⋯ を押すと出て外を押すと消える、編集タブでは積む、
  📌 で常に出す。
- iPhone 実機: ⋯ が押しやすいか、外を押して閉じるか、standalone で行が
  帯の下に潜らないか。
