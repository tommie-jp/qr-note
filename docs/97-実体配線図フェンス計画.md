# 実体配線図フェンス計画 (breadboard・perfboard)

実装日: 2026-09-21 / 状態: **実装済み**

上流 ([tommie-fence](https://github.com/tommie-jp/tommie-fence)) が
circuit / breadboard / perfboard の 3 つのフェンスを 1 つのモノレポに統一し、
ライブラリとして配れる形になった。ブレッドボードとユニバーサル基板の
実体配線図を QR ノートでも描けるようにする。

前例は [91-回路YAMLフェンス計画.md](91-回路YAMLフェンス計画.md) (回路図の
YAML フェンス) と [83-健康管理フェンス計画.md](83-健康管理フェンス計画.md)。
**この 2 つよりずっと小さい** — 理由は §2。

## 1. 取り込み方 — tarball を vendor/ に置く

回路図と同じ。npm レジストリには無い。

- `vendor/breadboard-fence-0.9.0.tgz` と `vendor/perfboard-fence-0.6.0.tgz`。
  `package.json` は `file:vendor/…` で指す
- **上流の GitHub Release から落とす。** 版ごとに tgz と `SHA256SUMS` が
  添えてあるので、どの版かがタグで一意に決まる (照合して置いた)
- `Dockerfile` の `COPY vendor ./vendor` はそのまま効く (ディレクトリごと写す)
- 実行時の依存は `yaml` だけで、これは circuit-fence が既に連れてきている

同じ日に circuit-fence も 0.3.0 → 0.8.0 に上げた (別のコミット)。

## 2. 決め — サーバで描かない

**回路図の作りをなぞらない。** 91 が必要とした仕掛けは、この 2 つには要らない。

| もの | 回路図 (circuit) | 実体配線図 (breadboard / perfboard) |
| --- | --- | --- |
| 描くところ | サーバ (node-tikzjax が子プロセスで TeX) | **ブラウザ** (同期の純関数) |
| 1 枚の時間 | 秒 | **1〜11 ミリ秒** (実測) |
| DB の控え (`circuit_svgs`) | 要る | **要らない** |
| `/api/circuits` に当たる口 | 要る | **要らない** |
| 閲覧で渡す Map | `PendingCircuitMap` | **無し** (本文だけで図が決まる) |
| オフライン | SVG を持ち出す | **本文だけ** (端末で描ける) |
| 一覧のサムネ | 控えから読む | **出さない** |

| # | 決め | なぜ |
| --- | --- | --- |
| 1 | **ブラウザで描く** (mermaid と同じ扱い)。処理系は使うときに動的 import | 処理系は DOM も Node も使わない同期の純関数で、1 枚 10 ミリ秒ほど。サーバで描いて渡す仕掛け (`planCircuits`・Map・DB) を建てる理由が無い。閲覧・編集・オフラインが**同じ関数**を通るので、図が食い違わない |
| 2 | **回路図とは別の一族にする** (`BOARD_LANGS` / `isBoardLang`)。`CIRCUIT_LANGS` には入れない | 入れると `circuitKey`・DB の控え・サムネ・オフライン・backfill に自動で乗ってしまう。どれも要らないどころか、TeX 前提の道に板を流し込むことになる |
| 3 | **一覧のサムネには出さない** | 板の図は 1 枚 12〜72 KB で、回路図の平均 2.9 KB の 10〜25 倍。`CIRCUIT_THUMB_BUDGET` (256 KB) は回路図の大きさを前提にしていて、同じ予算に相乗りさせると回路図のサムネが押し出される。**別の予算を作るより、出さないほうが正直** — サムネは「何のノートか」を示すもので、板の図は縮めると読めない。一覧では `RENDERED_LANGS` に入れたぶん、今までどおり畳まれた印が出る |
| 4 | **DB の控えを持たない** | 毎回描いても 10 ミリ秒。控えると鍵・版・掃除・backfill が付いてきて、得るものより高い |
| 5 | **SVG の検査は回路図と同じ関数を通す。写しを作らない** | `assertSafeCircuitSvg` は `server-only` の `circuit/hash.ts` にあり、ブラウザから呼べない。検査だけを `markdown/safeSvg.ts` へ出し、`hash.ts` は**綴りを変えずに再輸出**した。呼び手も試験もそのままで、実体は 1 つ。写しを 2 つ持つと片方だけ直したときに穴が開く |
| 6 | **処理系の `errorHtml` は使わない** | 独自の class が付いた生の HTML で、SVG の許可リストも掛からない。`errors` / `notices` / `erc` の配列から画面側で組む (React が字を逃がす) |
| 7 | **読めない行があっても図を出す** | 上流がそう作ってある (52 の docs/54)。板は既定を持つので必ず描ける。図が消えると直す手がかりも消える |
| 8 | ERC (つながっていない足) はお知らせとして図の下に出す | 上流が `erc` として別に返す。書いた人が直すものなので、読めなかった行より弱い見た目にする |

## 5. やらないこと

- **マウスで部品を動かすエディタ。** 上流の処理系は持っているが、殻 (マウスと
  タッチ、掴む層、属性パネル) は playground 1 つぶんの仕事で、フェンスを
  読めるようにする話とは規模が違う (上流 41 の docs/26 §7)
- **配色の差し替え。** 処理系にホストから色を渡す口が無い。板の図は実物の写しな
  ので明るいままでよい。QR ノートにダークモードが入るときに改めて決める
- **一覧のサムネ** (決め 3)
