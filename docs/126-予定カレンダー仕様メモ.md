## 1. 最小仕様

### 1-1. 記法 (プロパティ行、docs/08 のまま)

```text
# 歯医者

#予定 #通院
date=2026-11-05 start=10:00 end=11:00
```

| キー | 値 | 省略時 | Phase |
| --- | --- | --- | --- |
| `date` | `YYYY-MM-DD`。この行を持つノートが「予定」 | 予定ではない | 1 |
| `start` | `HH:MM` (JST) | 終日 | 1 |
| `end` | `HH:MM` (JST) | `start` + 1 時間。`start` 無しなら終日 | 1 |
| `until` | `YYYY-MM-DD`。複数日の最終日 | `date` と同じ日 | 1 |
| `repeat` | 下の語。`date` が初回 | 1 回きり | 3 |
| `skip` | `YYYY-MM-DD` をコンマ区切り (`skip=2026-12-03,2027-01-07`) | 無し | 3 |

`repeat=` の語 (Phase 3。`=` と空白を含まない。内部で RRULE に変換して `rrule` で展開):

| 書き方 | 意味 | RRULE |
| --- | --- | --- |
| `daily` | 毎日 | `FREQ=DAILY` |
| `weekly` / `weekly:mo,th` | 毎週 (date の曜日) / 毎週月・木 | `FREQ=WEEKLY[;BYDAY=MO,TH]` |
| `2weeks` | 隔週 (date から) | `FREQ=WEEKLY;INTERVAL=2` |
| `monthly` / `monthly:1we` / `monthly:last` | 毎月同じ日 / 第 1 水曜 / 月末 | `FREQ=MONTHLY[;BYDAY=1WE]` / `BYMONTHDAY=-1` |
| `yearly` | 毎年 | `FREQ=YEARLY` |
| `…;until:2027-03-31` / `…;count:10` | 終わり | `UNTIL` / `COUNT` |

cron 記法は採らない。値に空白が要る、隔週・第 N 曜日・月末・開始日が標準では書けない、
瞬間しか表せず長さが無い、間違えても気づけない、の 4 点 (2026-11-03 の検討)。

**キーの衝突は無い (2026-11-03 確認)。** 本番の写し (2026-10-25 時点、1,514 件) で
`props @> '[{"key":"date"}]'`、本文の `position('date=' in memo)`、`start` `end` `until`
`repeat` `skip` の各キーを数えて、すべて 0 件。アプリの検索窓で「date=」が 0 件なのも
同じ事実を指している (`memo &@ 'date='` は語句の一致なので、`date=…` を含む本文があれば当たる)。

### 1-2. 派生列 (正本は memo。`derivedFromMemo` が保存のたびに作り直す)

| 列 | 型 | 中身 |
| --- | --- | --- |
| `event_start` | `timestamp(3) NULL` (UTC。他の日時の列と同じ) | `date` + `start` (無ければ 00:00 JST) |
| `event_end` | `timestamp(3) NULL` | `until` or `date` + `end`。終日は翌日 00:00 JST (半開区間)。繰り返しは「繰り返しの終わり」、無期限なら `infinity` (Phase 3) |
| `event_repeat` | `text NULL` | `repeat=` の値そのまま。Phase 3 まで常に NULL |

- 月の条件は 1 本: `event_start < 翌月 1 日 00:00 JST AND event_end > 当月 1 日 00:00 JST`
  に `buildWhere(検索式)` を AND する。
- 索引は `@@index([eventStart])` を **schema.prisma に書く** (部分索引にしない)。
  移行 SQL に手で書いた索引は次の `migrate` が落とす (PGroonga の索引が消えたのと同じ罠)。
- `date=` が読めない (`date=来週`、`start=25:00`) ときは 3 列とも NULL。予定として出さない。
- 時刻は JST 固定。`new Date(\`${date}T${time}:00+09:00\`)` で組む (サーバの TZ に依らない)。

### 1-3. カレンダーは検索結果のビュー

- URL: `/?q=%23予定&cal=2026-11`。`cal=` があればペイン 2 の一覧の中身 (`data-results-scroll`)
  がカレンダーになる。無ければ今までの一覧。月は「何を見ているか」なので URL (docs/11 §3)。
  表示モード (小/中/大/画像) の cookie とは別の軸。
- 切替は結果ツールバー (docs/86 §4-11) の「一覧 / カレンダー」。カレンダーへ切り替えるとき
  `q` が空なら `#予定` を補う。
- 上: 月送り (◀ ▶)・今日。中: 7 列 × 最大 6 週のマス目。各日に題名のチップ (終日を先に、
  時刻順)。題名が空なら「(無題)」。
- データは専用の口 `GET /api/calendar?q=…&month=YYYY-MM`。一覧の `/api/items` は使わない
  (20 件ずつのページ・本文を丸ごと運ぶ・並び順、のどれもカレンダーに合わない)。
  返すのは軽い DTO: `{ itemId, title, start, end, allDay }` の配列。上限 `CALENDAR_ROW_LIMIT = 200`。
- 予定のチップをタップ → `/item/<id>?tab=event` (3/2 ペインは右ペイン、1 ペインは全画面)。

### 1-4. 「予定」タブ (ノートの 4 つ目のタブ)

- キーは `event`、ラベルは「予定」(キーは英語・ラベルは日本語、既存タブと同じ分け方)。
- 出す条件: ノートの props に `date=` がある、または URL が `?tab=event` を求めている。
- 中身 `EventForm`: 題名・日付・終日の切替・開始・終了・「保存」・「削除」(ゴミ箱へ)・
  「ノートで開く」は不要 (すでにノートの中)。
- 保存は純関数 `applyEvent(memo, fields) → memo` で本文を組み、既存の `PUT /api/items/<id>`
  に `base: { kind: 'at', at: updatedAt }` で送る (docs/87 の競合検知がそのまま効く)。
  - 題名は先頭の `# …` 行だけ差し替える。無ければ先頭に挿す。
  - 日時は `date=` を含むプロパティ行の `date` `start` `end` `until` の**トークンだけ**差し替え、
    無ければその行に足し、終日にしたら `start` `end` を抜く。他のキー・タグ・本文は触らない
    (docs/83 §7 の `recordMeasurement` と同じ作法)。
- `defaultMode` は URL の `tab` で上書きできる (無ければ今までどおり本文の有無で決める)。
- 「編集」タブと同じく `editing` 扱い (docs/108: 書く間は見出し行を畳まない)。
- 保存後は `refreshRouter` を通し (直に呼ぶと全画面 /item に化ける)、カレンダーの控えも捨てる。
- 衝突したら「別の端末で変わっています」と出して読み直させる。入力した値は消さない。

### 1-5. 追加 = 未登録のノートを「予定」タブで開く

- 日の帯 (§1-6) の「+」→ 端末で `newItemId()` → `/item/<id>?tab=event&date=2026-11-05`。
- 未登録の id でもノートの画面は開く (QR シールの前貼りと同じ道)。日付は URL から埋まる。
- 「保存」で `PUT` (`base: { kind: 'new' }`)。本文は `# <題名>\n\n#予定\ndate=…[ start=… end=…]\n`。
  タグはいま見ているカレンダーの検索式のタグ (`#予定 #仕事`) を全部付ける
  (足した予定が、見ているカレンダーに必ず出る)。
- 1 ペイン (全画面) で**新規**を保存したときだけ、保存後に閉じて月表示へ戻る。
  既存の修正は留まる。
- 「未登録」の知らせは出たままにする (core に予定の事情を持ち込まない)。
- `/new?draft=`・追加ダイアログは作らない。

### 1-6. 日の予定を浮かせて出す (2026-11-04 改め)

日をタップすると、**そのマスの右に**その日の全予定と「＋」(予定の追加) を浮かせて出す。
右が画面からはみ出すなら左、左右どちらにも入らない狭い画面では画面の中へ寄せる
(マスに重なってよい)。縦はマスの上端に揃え、下がはみ出すなら上へずらして全部見せる。
画面より背が高ければ画面の高さに縮めて中を送る (`event/placePopover.ts`)。

予定をタップすると閉じて予定のペイン (ノートの「予定」タブ) を開く。外を押す・Esc・
マス目のスクロール・月送りでも閉じる。body へ portal する (検索結果の器の transform と
overflow に縛られないため)。月の予定が届く前は「予定はありません」ではなく「読み込み中…」。

以下は最初の版 (マス目の下の帯) の記述。

#### 日の帯 (v0.23.101、置き換え済み)

日をタップするとマス目の下に、その日の予定 (題名・時刻。タップで開く) と「+」を出す。
足す前に重複が見える。使ってみて不要なら帯を飛ばして即「+」の動きにできる。

### 1-7. モジュール化

```text
src/modules/
  registry.ts                 ← core が読む唯一の入口 (結果ビューの一覧・ノートのタブの一覧)
  calendar/
    index.ts                  ← 登録情報 (id・ラベル・アイコン・next/dynamic の部品)
    event/parseEvent.ts       ← props → EventFields | null (純関数)
    event/eventColumns.ts     ← memo → { eventStart, eventEnd, eventRepeat } (純関数)
    event/applyEvent.ts       ← (memo, fields) → memo (純関数)
    event/newEventMemo.ts     ← (fields, tags) → memo (純関数)
    api/calendarQuery.ts      ← server-only。searchItemRows + buildWhere + 月の窓
    api/calendarDto.ts        ← EventDto と isEventDto (両側)
    client/calendarStore.ts   ← createResourceCache({ query, month })
    client/CalendarView.tsx   ← ペイン 2 の中身 (月送り・MonthGrid・DayStrip)
    client/MonthGrid.tsx / DayStrip.tsx / monthLayout.ts (純関数)
    client/EventForm.tsx      ← 「予定」タブの中身
```

core 側の継ぎ目は 4 つだけ:

1. `src/lib/items/write.ts` の `derivedFromMemo` が `...eventColumnsOf(memo)` を 1 行呼ぶ
2. `src/modules/registry.ts` — 結果ツールバーの切替と `SearchResultsClient` の差し替え、
   `MemoPanel` の `extraTabs` の供給元
3. `MemoPanel` に `extraTabs?: { key, label, content }[]` を足す
4. `NoteView` の `defaultMode` を URL の `tab` で上書きできるようにする

境界は eslint で守る: `src/lib/**`・`src/components/**`・`src/app/**` から `@/modules/*` を
import できるのは `@/modules/registry` だけ (`no-restricted-imports` の patterns に足す)。
モジュールは core の公開部品 (`searchItemRows`・`buildWhere`・`createResourceCache`・
`ModalOverlay` 等) を import してよい (依存は module → core の一方向)。
`rrule`・マス目の部品は `next/dynamic` で遅延読み込みし、本体のバンドルに乗せない。
別パッケージ化 (tommie-fence の core と同じ型) は、純関数を使う 2 つ目の利用者
(オフライン・単体アプリ) が現れてから。

### 1-8. やらないこと (Phase 1〜2)

繰り返し・祝日・オフライン・ドラッグ移動・一覧からの隠し (docs/125 §7)・週/日の時間軸・
`#予定` ノートのサムネ付きチップ。

## 2.5 実装の記録 (2026-11-03、Phase 1・2)

Phase 1・2 を実装した。§1-7 の木と違う所と、決めたこと:

- 列は `timestamp(3)` (Prisma の既定、UTC)。他の日時の列と揃えた。比べる値は
  タイムゾーン無しの文字列にして `::timestamp` で渡す (`calendarQuery.ts`。
  セッションの TZ に依らない)
- 純関数は `event/` にまとめた: `parseEvent.ts`・`eventTime.ts` (JST の組み立て)・
  `eventColumns.ts`・`eventMemo.ts` (applyEvent・newEventMemo・requiredTags を
  1 ファイルに)・`monthLayout.ts` (サーバの取る範囲と端末の並びが共有するので
  client/ ではなく event/ に置いた)
- 取る範囲は月ではなく**マス目 (日曜始まり、4〜6 週)**。前後の月のはみ出しのマスにも予定が出る
- core の継ぎ目は 3 つの入口: `@/modules/registry` (画面。`.tsx`)・
  `@/modules/derivedColumns` (派生列)・`@/modules/<名前>/api/route`
  (`src/app/api/calendar/route.ts` は 1 行の再輸出)。eslint は正規表現の pattern で
  それ以外を止める (gitignore 形式の `!` は親が除外済みだと効かなかった)
- ItemDto に 3 列を足した (省略可。知らない版の応答も受ける)。テストの固定データ
  18 ファイルに `eventStart: null` などを補った
- ノートを開く URL にも `q` と `cal` を載せる (`/item/<id>?q=…&cal=…&tab=event`)。
  端末で開いたノート (pushState) を出している間も検索画面は URL を読むので、
  `cal` が落ちると後ろが一覧に戻る。月送りは今のパスのまま `cal` だけ替える
- `?tab=` と `?date=` は NoteView が開いたときの値を控える (3 ペインでは URL が
  /item を離れてもノートが残るため)
- 足したタブが消えたら (本文から `date=` を消した) MemoPanel は markdown へ戻す
- マスの中の予定は押せる物にしない (iPhone で日を選ぶ指が予定を開いてしまう)。
  開くのは日の帯から
- 削除はフォームの「ゴミ箱へ」(既存の trashItemsAction)
- 本番に `date=` を持つノートは無いので、導入時のバックフィルは不要
  (`doBackfill.sh events` は用意した)

確かめたこと: 単体 (純関数・API の口・登録口・MemoPanel のタブ)、手元の DB での
月の取得 (月をまたぐ複数日・翌月の予定が外れる)、E2E `e2e/calendar.spec.ts`
(日を選ぶ → 「+」→ 予定タブ → 追加 → 月に出る / 時刻を直す → 本文の行だけ変わる /
一覧 ⇄ カレンダー)、iPhone 幅 (390px) と PC 3 ペインの画面。
