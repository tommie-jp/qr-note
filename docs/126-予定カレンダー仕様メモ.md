## 1. 最小仕様

### 1-1. 記法 (プロパティ行、docs/08 のまま)

```text
# 歯医者

#予定 #通院
date=2026-11-05 start=10:00 end=11:00
```

| キー | 値 | 省略時 | Phase |
| --- | --- | --- | --- |
| `date` | `YYYY-MM-DD`。この行を持つノートが「予定」 | 予定ではない | 1 |
| `start` | `HH:MM` (JST) | 終日 | 1 |
| `end` | `HH:MM` (JST) | `start` + 1 時間。`start` 無しなら終日 | 1 |
| `until` | `YYYY-MM-DD`。複数日の最終日 | `date` と同じ日 | 1 |
| `repeat` | 下の語。`date` が初回 | 1 回きり | 3 |
| `skip` | `YYYY-MM-DD` をコンマ区切り (`skip=2026-12-03,2027-01-07`) | 無し | 3 |

`repeat=` の語 (Phase 3。`=` と空白を含まない。内部で RRULE に変換して `rrule` で展開):

| 書き方 | 意味 | RRULE |
| --- | --- | --- |
| `daily` | 毎日 | `FREQ=DAILY` |
| `weekly` / `weekly:mo,th` | 毎週 (date の曜日) / 毎週月・木 | `FREQ=WEEKLY[;BYDAY=MO,TH]` |
| `2weeks` | 隔週 (date から) | `FREQ=WEEKLY;INTERVAL=2` |
| `monthly` / `monthly:1we` / `monthly:last` | 毎月同じ日 / 第 1 水曜 / 月末 | `FREQ=MONTHLY[;BYDAY=1WE]` / `BYMONTHDAY=-1` |
| `yearly` | 毎年 | `FREQ=YEARLY` |
| `…;until:2027-03-31` / `…;count:10` | 終わり | `UNTIL` / `COUNT` |

cron 記法は採らない。値に空白が要る、隔週・第 N 曜日・月末・開始日が標準では書けない、
瞬間しか表せず長さが無い、間違えても気づけない、の 4 点 (2026-11-03 の検討)。

**キーの衝突は無い (2026-11-03 確認)。** 本番の写し (2026-10-25 時点、1,514 件) で
`props @> '[{"key":"date"}]'`、本文の `position('date=' in memo)`、`start` `end` `until`
`repeat` `skip` の各キーを数えて、すべて 0 件。アプリの検索窓で「date=」が 0 件なのも
同じ事実を指している (`memo &@ 'date='` は語句の一致なので、`date=…` を含む本文があれば当たる)。

### 1-2. 派生列 (正本は memo。`derivedFromMemo` が保存のたびに作り直す)

| 列 | 型 | 中身 |
| --- | --- | --- |
| `event_start` | `timestamp(3) NULL` (UTC。他の日時の列と同じ) | `date` + `start` (無ければ 00:00 JST) |
| `event_end` | `timestamp(3) NULL` | `until` or `date` + `end`。終日は翌日 00:00 JST (半開区間)。繰り返しは「繰り返しの終わり」、無期限なら `infinity` (Phase 3) |
| `event_repeat` | `text NULL` | `repeat=` の値そのまま。Phase 3 まで常に NULL |

- 月の条件は 1 本: `event_start < 翌月 1 日 00:00 JST AND event_end > 当月 1 日 00:00 JST`
  に `buildWhere(検索式)` を AND する。
- 索引は `@@index([eventStart])` を **schema.prisma に書く** (部分索引にしない)。
  移行 SQL に手で書いた索引は次の `migrate` が落とす (PGroonga の索引が消えたのと同じ罠)。
- `date=` が読めない (`date=来週`、`start=25:00`) ときは 3 列とも NULL。予定として出さない。
- 時刻は JST 固定。`new Date(\`${date}T${time}:00+09:00\`)` で組む (サーバの TZ に依らない)。

### 1-3. カレンダーは検索結果のビュー

- URL: `/?q=%23予定&cal=2026-11`。`cal=` があればペイン 2 の一覧の中身 (`data-results-scroll`)
  がカレンダーになる。無ければ今までの一覧。月は「何を見ているか」なので URL (docs/11 §3)。
  表示モード (小/中/大/画像) の cookie とは別の軸。
- 切替は結果ツールバー (docs/86 §4-11) の「一覧 / カレンダー」。カレンダーへ切り替えるとき
  `q` が空なら `#予定` を補う。
- 上: 月送り (◀ ▶)・今日。中: 7 列 × 最大 6 週のマス目。各日に題名のチップ (終日を先に、
  時刻順)。題名が空なら「(無題)」。
- データは専用の口 `GET /api/calendar?q=…&month=YYYY-MM`。一覧の `/api/items` は使わない
  (20 件ずつのページ・本文を丸ごと運ぶ・並び順、のどれもカレンダーに合わない)。
  返すのは軽い DTO: `{ itemId, title, start, end, allDay }` の配列。上限 `CALENDAR_ROW_LIMIT = 200`。
- 予定のチップをタップ → `/item/<id>?tab=event` (3/2 ペインは右ペイン、1 ペインは全画面)。

### 1-4. 「予定」タブ (ノートの 4 つ目のタブ)

- キーは `event`、ラベルは「予定」(キーは英語・ラベルは日本語、既存タブと同じ分け方)。
- 出す条件: ノートの props に `date=` がある、または URL が `?tab=event` を求めている。
- 中身 `EventForm`: 題名・日付・終日の切替・開始・終了・「保存」・「削除」(ゴミ箱へ)・
  「ノートで開く」は不要 (すでにノートの中)。
- 保存は純関数 `applyEvent(memo, fields) → memo` で本文を組み、既存の `PUT /api/items/<id>`
  に `base: { kind: 'at', at: updatedAt }` で送る (docs/87 の競合検知がそのまま効く)。
  - 題名は先頭の `# …` 行だけ差し替える。無ければ先頭に挿す。
  - 日時は `date=` を含むプロパティ行の `date` `start` `end` `until` の**トークンだけ**差し替え、
    無ければその行に足し、終日にしたら `start` `end` を抜く。他のキー・タグ・本文は触らない
    (docs/83 §7 の `recordMeasurement` と同じ作法)。
- `defaultMode` は URL の `tab` で上書きできる (無ければ今までどおり本文の有無で決める)。
- 「編集」タブと同じく `editing` 扱い (docs/108: 書く間は見出し行を畳まない)。
- 保存後は `refreshRouter` を通し (直に呼ぶと全画面 /item に化ける)、カレンダーの控えも捨てる。
- 衝突したら「別の端末で変わっています」と出して読み直させる。入力した値は消さない。

### 1-5. 追加 = 未登録のノートを「予定」タブで開く

- 日の帯 (§1-6) の「+」→ 端末で `newItemId()` → `/item/<id>?tab=event&date=2026-11-05`。
- 未登録の id でもノートの画面は開く (QR シールの前貼りと同じ道)。日付は URL から埋まる。
- 「保存」で `PUT` (`base: { kind: 'new' }`)。本文は `# <題名>\n\n#予定\ndate=…[ start=… end=…]\n`。
  タグはいま見ているカレンダーの検索式のタグ (`#予定 #仕事`) を全部付ける
  (足した予定が、見ているカレンダーに必ず出る)。
- 1 ペイン (全画面) で**新規**を保存したときだけ、保存後に閉じて月表示へ戻る。
  既存の修正は留まる。
- 「未登録」の知らせは出たままにする (core に予定の事情を持ち込まない)。
- `/new?draft=`・追加ダイアログは作らない。

### 1-6. 日の予定は下のペイン、予定のフォームは行のそば (2026-11-04 再改め)

**2・3 ペイン:** 日をタップすると、**ノートのペインの場所に**その日の全予定と「＋」を出す
(`client/DayPane.tsx`)。器は画像ビューアのペイン (docs/116 §3) と同じ作りで、
`PANE_BOX_CLASS.pane` を body へ portal し、下に隠れたノートのペインは inert にする。
「×」・Esc・月送り・別のノートが開いたとき (戻る・一覧から開く) に閉じる。
上端の境界 (`PaneResizer`) も日のペインが自分で描く。ノートを開いていない
カレンダーでは、ノートのペインの境界が無く高さを変えられなかった (v0.23.104 の不具合)。

予定 (または「＋」) をタップすると、**その行のすぐ上か下に**予定のフォームを浮かせる
(`client/EventPopover.tsx`、置き方は `event/placePopover.ts` の `placeAround`)。
中身はノートの「予定」タブと同じ `EventForm` で、保存・ゴミ箱へ移したら閉じる。
外を押す・「×」・Esc でも閉じる。送り (scroll) では閉じずに置き直す
(iPhone はキーボードが出ると画面を送るため)。「＋」はノートを作らずにフォームを出し、
「追加」で初めて作る。

**1 ペイン:** 下のペインが無いので、下の「浮かせる一覧」のままにする
(予定をタップすると全画面のノートの「予定」タブ)。

#### マスの横に浮かせる一覧 (v0.23.102、2・3 ペインでは置き換え済み)

日をタップすると、**そのマスの右に**その日の全予定と「＋」(予定の追加) を浮かせて出す。
右が画面からはみ出すなら左、左右どちらにも入らない狭い画面では画面の中へ寄せる
(マスに重なってよい)。縦はマスの上端に揃え、下がはみ出すなら上へずらして全部見せる。
画面より背が高ければ画面の高さに縮めて中を送る (`event/placePopover.ts`)。

予定をタップすると閉じて予定のペイン (ノートの「予定」タブ) を開く。外を押す・Esc・
マス目のスクロール・月送りでも閉じる。body へ portal する (検索結果の器の transform と
overflow に縛られないため)。月の予定が届く前は「予定はありません」ではなく「読み込み中…」。

以下は最初の版 (マス目の下の帯) の記述。

#### 日の帯 (v0.23.101、置き換え済み)

日をタップするとマス目の下に、その日の予定 (題名・時刻。タップで開く) と「+」を出す。
足す前に重複が見える。使ってみて不要なら帯を飛ばして即「+」の動きにできる。

### 1-8. 済み (2026-11-08)

日の予定の一覧 (下のペイン・浮かせた一覧) の行の左端に「済み」の丸を置く。押すと
予定の行に `done=<今日>` を足し、もう一度押すと `done=` を抜く (`setEventDone`。
他のトークン・行は触らない。`applyEvent` も `done=` を残す)。値の形は問わず、
`done=` に値があれば済みと見る (`isEventDone`)。

- 押した値はすぐ見せ、保存は裏で行う。控えの本文が古くて 409 なら 1 度だけ取り直して
  やり直す。失敗したら一覧の下に知らせて元に戻す。
- 済みの予定はマス目でも一覧でも題名に取り消し線を引いて薄くし、日の中では最後に並べる
  (`compareDayEvents`)。
- 新しい列は足さない。カレンダーの API は props から `done` を読んで運ぶ
  (古い応答には無いので省略可)。
- 繰り返し (Phase 3) では回ごとの済みが要る。そのときに考え直す。

### 1-9. 祝日 (2026-11-08)

祝日・休日のマスは背景を薄いピンク (`bg-pink-50`) にし、日付を日曜と同じ赤にする。
PC 幅は日付の横に祝日名を出す (スマホ幅のマスには入らない)。日の予定の一覧の見出しにも
祝日名を添える。祝日はノートにしない (docs/125 §5 の方針どおり)。

docs/125 §5 の `@holiday-jp/holiday_jp` は入れず、祝日法の規則から端末で計算する
(`event/holidays.ts`。依存を増やさない)。固定日・ハッピーマンデー・春分/秋分の近似式
(1980〜2099 年)・振替休日・国民の休日と、2019〜2021 年の特例 (即位・東京五輪の移動)。
範囲は 2007〜2099 年で、外は祝日なしと見る。

- 正しさは内閣府の CSV (`syukujitsu.csv`、2026-11-08 取得) の 2016〜2027 年 219 件と
  突き合わせるテストで見る (日付は全件、名前は内閣府が「休日」と書く行を除いて一致)。
- 春分・秋分は前年 2 月の官報で決まる。毎年 2 月に翌年分を CSV と見比べ、近似式が外れたら
  `SPECIAL` に足す。法改正 (祝日の新設・移動) も `SPECIAL` か規則に足す。

### 1-10. 見た目を SaiSuke2 に寄せる (2026-11-08)

iPhone の SaiSuke2 の月表示に見た目と文字の大きさを寄せる (スクリーンショットの
3 倍画像を CSS px に直して合わせた)。

- 週は**月曜始まり** (`monthGridRange` の `mondayIndex`)。2026-11 は 10/26〜12/6 の 6 週。
- 曜日 16px。日付 20px (今日は日付の帯が緑、選んだ日は黄)。前後の月の日付は灰。
- 土日・祝日のマスは薄いピンク。祝日名はスマホ幅でもマスの 1 行目に出す。
- マスの予定は時刻を出さず、14px の色の帯 (未済は赤、済みは灰に取り消し線)。
  祝日名と予定で 3 行、溢れた分は右下の角に「+N」。マスの高さは 88px で固定。
- 日の一覧は緑の見出しの帯 (「11/5 木曜日」) と、56px の色の帯の行
  (左に開始・終了の 2 段の時刻か「終日」、右に題名)。左端に「済み」の丸。
- 予定の色は優先度で決める (§1-11)。SaiSuke2 の分類ごとの色は持たない。

### 1-11. 優先度 (2026-11-08)

予定の行に `priority=high` (高い) / `priority=low` (低い) を書く。書かない・読めない値は
標準 (`eventPriority`)。フォームの「優先度」(高い / 標準 / 低い) で選び、標準を選ぶと
`priority=` を抜く (`applyEvent` は入力が優先度を持つときだけ触る)。

色はマス目の帯・日の一覧の行とも `client/priorityColor.ts` の 1 か所で決める。
既定の色は次のとおりで、カレンダーの設定 (§1-12) で変えられる。

| 優先度 | 既定の色 |
| --- | --- |
| 高い | 薄い赤 (`bg-red-200`) |
| 標準 | 薄いオレンジ (`bg-orange-200`) |
| 低い | 薄い緑 (`bg-green-200`) |
| 済み (優先度を問わず) | 灰 + 取り消し線 |

カレンダーの API は props から `priority` を読んで運ぶ (古い応答には無いので省略可)。
日の中の並び (`compareDayEvents`) は優先度で変えない。

### 1-12. カレンダーの設定 (2026-11-08)

月の見出し行の左端 (「◀」の左) に設定のアイコンを置き、押すとパネルを開く
(`client/CalendarMenu.tsx`)。

- 日の予定の行は題名の文字 1.5 行 (36px。2026-11-11 に 28px へ詰めた、§1-26)。時刻は 12px の 2 段。未済の「済み」の丸は灰の縁に白の中身
  (地を白にしても溶けない)。
- 日付の文字の大きさ: 小 16px / 中 20px (既定) / 大 24px。行の高さは変えないので
  マスの高さ (88px) は変わらない。
- 優先度ごとの色: テンプレート色 15 色 (白 + 薄い 9 色 + 濃い 5 色) か、カラーピッカー
  (`<input type="color">`)。文字の色は地の明るさ (WCAG の相対輝度) で白か濃い灰を選ぶ。
- 優先度ごとの文字の色 (2026-11-08 追加): 「自動」(既定。地の明るさから白か濃い灰)・
  文字向けの濃い 7 色・カラーピッカー。見本の帯に「予定」と出して組み合わせを見せる。
  保存値は `textColors` (`#rrggbb` か `auto`)。前の版の保存値・PUT (`textColors` 無し) は
  自動と見る。
- 予定の文字の大きさ (2026-11-11 追加、§1-18): 小 12px / 中 14px (既定) / 大 16px。
- 月の左右の余白・1 日に出す予定の数 (2026-11-11 追加、§1-19)。
- 「既定に戻す」で §1-11 の色・文字は自動・日付と予定の大きさは中に戻す。

保存は `user_settings` の 1 行 (key = `calendar-prefs`、値は JSON)。
**2026-11-11 から大きさ・余白・予定数は端末ごと (§1-20)。** サーバに置くのは色だけ。口は
`GET / PUT /api/calendar/settings` (`api/settings/route.ts`)。PUT は知らない値を
畳まず 400 で断り、デモでは断る (選択行の色と同じ)。端末は `localStorage` に写しを
持って開いた直後から自分の色で描き、変えたらすぐ当てて 600ms 待ってから保存する
(カラーピッカーは引きずる間ずっと値を送るため)。保存に失敗したらパネルに知らせる。

### 1-13. 題名のインライン編集 (2026-11-08)

下のペインの日の一覧 (2・3 ペイン) で、題名の**文字**を押すとその場で入力欄になる
(行で F2 でも)。Enter・外を押すで保存、Esc で取り消し。空にしたら元のまま。
行の残り (時刻・余白) を押したときは今までどおりフォームを開く。

- 本文は先頭の `# 題名` だけを差し替える (`setEventTitle`。見出しが無ければ先頭に挿す)。
  保存は「済み」と同じ道 (`client/eventDone.ts` の `saveEventEdit`。409 は 1 度取り直す)。
- 保存の前から新しい題名を一覧に見せ、月の予定の取り直しが追いついたら上書きを外す。
- 直しても行の位置は変えない。日の中の並び (`compareDayEvents`) は同じ時刻なら番号順
  (UUID v7 = 作った順) で、題名では並べない (以前は題名順で、直すと行が動いた)。
- 1 ペインの浮かせる一覧には付けない。行がノートを開くリンクで、押した瞬間に
  `clientNoteNav` (document の capture) が先に受けて移ってしまうため。

### 1-14. 時刻の 1 行表示と 15 分刻みの時刻のパネル (2026-11-08)

日の一覧の時刻は 1 行で出す (「10:00 ~ 11:00」、終日は「終日」)。下のペイン (2・3 ペイン) では
時刻を押すと、そのそばに時刻のパネル (`client/TimePopover.tsx`) が出る。

- 「終日」のチェックと、開始・終了の選択欄 (00:00〜23:45 の 15 分刻み、`quarterHours`)。
  iPhone の `<input type="time">` は `step` を守らないので選択欄にした。刻みに乗らない
  いまの値 (手で書いた 10:10) も欄に入れる。終了は「1 時間後」(end= を書かない) も選べる。
- 選んだらすぐ保存する (`setEventTime` で予定の行の start= end= だけを差し替え、
  足すときは date= の直後)。開始を動かすと長さを保って終了も動かす (`moveStart`。
  日をまたぐなら終了を外す)。保存の前から一覧とマス目に新しい時刻を見せる。
- 予定のフォームの時刻欄にも `step={900}` を付けた (PC の欄は 15 分刻みになる)。
- 題名・時刻以外 (行の右の余白) を押すと今までどおりフォームを開く。

### 1-15. 日の中の並べ替え (2026-11-08)

日の一覧の行の左端に並べ替えのつまみ (︙) を置き、上下にドラッグすると日の中の順を
変えられる (焦点があれば ↑ ↓ でも)。離したとき、順の変わった予定の行にだけ
`order=1, 2, …` を書く (`setEventOrder`。既にあれば位置ごと差し替え、無ければ末尾)。

- 日の中の並び (`compareDayEvents`): 済みは最後 → `order=` を持つ予定を番号順に先へ →
  持たない予定は今までどおり (終日 → 開始時刻 → 作った順)。新しく足した予定は
  並べ替えた予定の後ろに入る。マス目も同じ並び。
- ドラッグはパッケージを使わずポインタで組む (`DayEventList.tsx`)。掴んだときの各行の
  中心と指の位置を比べて落とし先を決め、行を入れ替えて見せる。つまみは `touch-none`
  (指でなぞっても一覧ごとスクロールしない)。
- 1 ペインの浮かせる一覧でも使える (つまみはリンクの外にある)。
- 予定ごとの番号なので、複数日の予定はどの日でも同じ番号で並ぶ。

### 1-16. ︙ のドラッグで別の日へ移す (2026-11-08)

日の一覧の ︙ を掴んだまま月のマス目の別の日のマスまで持っていって離すと、その日へ移す。
ドラッグ中は指の下 (`elementFromPoint`) が別の日のマスならそのマスに青い枠
(`data-drop-target`) を出し、並べ替えはしない。一覧の中で離したときは今までどおり並べ替え。

- 本文は `date=` だけを差し替え、`until=` (複数日の最終日) があれば同じ日数だけずらす
  (`moveEventDate`)。時刻・優先度・`order=` などは残す。
- 移した予定はすぐこの日の一覧から隠し、月の予定の取り直しで移した日のマスに出る。
  保存に失敗したら一覧に戻して知らせる。
- 1 ペインの浮かせる一覧からも移せる (浮かせた一覧に隠れていないマスへ)。

### 1-17. 検索窓の＋で選んだ日に予定を足す (2026-11-11)

カレンダーを出している間、検索窓の右端の＋は「新規ノート」(`/new`) ではなく
「カレンダーに追加」になり、選んでいる日 (黄色のマス) の新しい予定を「予定」タブで開く
(日の一覧の「＋」の 1 ペインの動きと同じ `eventNoteHref(…, date)`)。2・3 ペインでは
ノートのペインに開き、日のペインは退く。

- 日を選んでいなければ、見ている月が今月なら今日、別の月ならその月の 1 日 (`event/addDay.ts`)。
- core (SearchForm) はカレンダーの名前を知らない。registry の `ResultView.newItemHref` を
  いまの表示 (`activeResultView`) から引き、あれば＋をそれに向ける。
- 選んだ日は CalendarView の state なので、木の外の検索窓のために `client/selectedDay.ts` に
  写す (押した瞬間に 1 度読むだけなので購読はしない)。カレンダーを離れたら消す。
- 番号は押したときに振る (リンクにすると描くたびに振られる)。

### 1-18. 予定の文字の大きさ (2026-11-11)

カレンダーの設定 (§1-12) に「予定の文字の大きさ」(小・中・大) を足した。マス目の予定の帯の
文字だけが変わる (12 / 14 / 16px)。行の高さ (20px) は変えないので、1 マス 3 行と
マスの高さ (88px) はそのまま。大は 1 行に入る文字が減る。日の一覧の行は変えない。

- 保存値は `eventSize` (`sm` / `md` / `lg`)。前の版の保存値・PUT (`eventSize` 無し) は中と見る。

### 1-19. 月の左右の余白・1 日の予定数・見出し行の横送り (2026-11-11)

カレンダーの設定 (§1-12) に 2 つ足し、月の見出し行を横に送れるようにした。

- **月の左右の余白:** 0 / 小 8px / 中 16px (既定。画面の余白と同じ)。マス目だけが広がり、
  見出し行は動かない。結果の器 (`SearchResultsClient` の `ModuleResults`) を
  `-mx-safe px-safe` で画面の余白まで広げ、マス目が負の margin でそこへはみ出す。
  2・3 ペインではこの器が縦に送る (`overflow-y:auto`) ので、横のはみ出しは器の中で
  しか見えないため。safe-area (iPhone の切り欠き) より内へは出さない。
- 余白はフォルダーペインの左右の余白にも効く (2026-11-11、docs/86 §4-20)。
- **1 日に出す予定の数:** 3〜20 (既定 5。以前は 3 で固定)。マスの高さはこの行数で
  固定し (25 + 21 × 行数 px、5 行で 130px)、月は画面より縦に長くなって送って見る前提。
  祝日名もこの行数に含む。超えた分は今までどおり右下の「+N」。
- **見出し行:** 設定のアイコンは左端に固定し、右の ◀ 年月 ▶ 今日 一覧 を 1 行の帯に入れて
  横に送る (折り返さない。スクロールバーは出さない)。
- 保存値は `sidePadding` (`none` / `sm` / `md`) と `eventsPerDay` (3〜20 の整数)。
  省略は既定、範囲外・小数は PUT で断る。

### 1-20. 表示の設定は端末ごと (2026-11-11)

カレンダーの設定のうち、表示の形に関わる 4 項目 (日付の文字の大きさ・予定の文字の大きさ・
月の左右の余白・1 日に出す予定の数) を**端末ごと**にした。iPhone と PC で別々に選べる。
優先度の色と文字の色は今までどおり**利用者ごと** (サーバ) — どの優先度を何色で見るかは
意味づけで、端末で変わると読み違えるため。

- 表示は端末の `localStorage` の `qr-calendar-layout` が正本で、サーバへは送らない
  (`client/prefsStore.ts`)。色の写し `qr-calendar-prefs` は今までどおりサーバの写し。
- PUT は色 (`colors`・`textColors`) だけを送る。API は前の版の画面が送る全体も受けて検査する
  (保存はするが、読む側は表示の値を使わない)。
- 前の版から: 端末の表示がまだ無ければ、その端末の色の写し (前の版は表示も含む全体) から
  引き継ぐ。写しの無い端末は既定 (日付・予定とも中、余白 中、予定 5)。
- 「既定に戻す」は、この端末の表示と、利用者の色を戻す。

### 1-21. 日付の右の ✓ と「残n」 (2026-11-11)

月のマスの日付の帯の右端に、その日の予定の進み具合を出す (`event/dayProgress.ts`)。

- すべて済みなら緑の ✓、済みでない予定があればその数を「残2」のように出す。
  予定の無い日は何も出さない。複数日の予定は掛かっている日のどれでも 1 件と数える。
- 「+N」で隠れている予定も数に入る (マスに見えている行だけではない)。
- 印は日付の大きさの設定に関わらず 12px。マスの読み上げ名にも「すべて済み」「残り n 件」を足した。

### 1-22. マスの題名に「…」を付けない (2026-11-11)

月のマスの予定の帯は、はみ出した題名を「…」なしで切る (`truncate` をやめて
`overflow-hidden whitespace-nowrap`)。iPhone のマスは 55px ほどで、… が 1 文字ぶんを食い、
読める字が減るため。日の一覧の題名は今までどおり。

### 1-23. 見出しまわりを詰める (2026-11-11)

カレンダーの見出し行と曜日の行の縦を詰めた。年月は 20px → 16px、見出し行の釦 (設定・◀ ▶・今日・一覧) は
36px → 32px 角、曜日の行は 16px → 14px の文字で上下の余白 4px → 2px、見出し行と
マス目の間は 8px → 4px。検索窓の行は一覧と共有する部品なので変えていない。

### 1-24. ヘッダーのロゴでカレンダーを出し直す (2026-11-11)

カレンダーを出しているとき、ヘッダーのロゴ (QR Note) を押すとホーム (検索語なしの一覧) へは
行かず、同じ検索語・同じ月のカレンダーを出し直す。ノートを開いていれば閉じ、月の予定を取り直す。

- ロゴは端末の部品 `components/chrome/HomeLink.tsx`。いまの表示 (`activeResultView`) があれば
  リンクの移動を止め、`searchHrefKeepingView` の URL へ移って registry の `refresh` を呼ぶ
  (カレンダーは `invalidateCalendar`。控えは 'client-only' なので押したときに読み込む)。
- 一覧の画面・修飾キー付き・中クリックは今までどおりのリンク。

### 1-25. 日の一覧のペインの左右の余白も月と同じ (2026-11-11)

2・3 ペインで下に出す日の一覧 (DayPane) の左右の余白を、月の左右の余白の設定と同じにした
(`--pane-side-pad`。以前は画面の余白 16px 固定)。フォルダーペイン (docs/86 §4-20) と同じ変数。

### 1-26. 日の一覧の行を詰める (2026-11-11)

日の一覧の行を詰めた。行の高さ 36px → 28px、済みの丸 20px → 16px (釦の幅 36px → 24px)、
時刻の列は文字 14px → 12px・幅 104px → 80px、列の間 12px → 8px。題名をその場で直すときの行も同じ寸法。

### 1-27. 日の一覧は表の罫線で区切る (2026-11-11)

日の一覧 (下のペイン・1 ペインの浮かせる一覧とも) を表の形にした。行のすきまと角丸の枠をやめ、
一覧の外枠・行の下・列 (︙・済み・時刻) の右に灰の罫線 (`border-gray-300`) を引く。
行の高さは 28px + 罫線 1px。ドラッグ中の行は今までどおり青い枠。
「時間軸のマス目」(0〜23 時を縦に並べる形) も候補に挙げたが、ユーザーは罫線の形を選んだ。

### 1-28. 見出し行と曜日の行を上端に貼り付ける (2026-11-12)

月を縦に送っても、カレンダーの見出し行 (設定・◀ 年月 ▶・今日・一覧) と曜日の行は上端に残す。
ヘッダーと検索窓も動かない。

- 検索結果の表示 (カレンダーなど) を出している間は、**1 ペインでも 2・3 ペインと同じく結果の器
  (`[data-results-scroll]`) の中だけを送る**。器に `data-results-view` を付け、globals.css の
  2・3 ペインの積み方の決まりにこの印を足した。引っ張って更新はこの器の先頭を見る (元から対応済み)。
- 見出し行と曜日の行 (`WeekdayHeader`、マス目から切り出した) を `sticky top-0` の帯にまとめ、
  器の左右の余白ごと白で覆う (マス目が両脇から透けないように)。

### 1-29. 日の一覧の縦の罫線を消す (2026-11-12)

日の一覧の罫線を横だけにした (一覧の上・行の下)。列 (︙・済み・時刻) の右と、外枠の左右の線は引かない。

### 1-30. 指で ︙ を動かせなかった (2026-11-12 修正)

日の一覧の ︙ を指でなぞっても並べ替え・別の日への移動ができなかった (マウスでは動く)。
globals.css の `button { touch-action: manipulation }` がレイヤーの外にあり、Tailwind の
ユーティリティ (`@layer utilities`) より常に強いため、釦に付けた `touch-none` が効かず、
ブラウザがなぞりをスクロールとして横取りして `pointercancel` で止まっていた。
隠したペインの端のタブ (docs/86 §4-21) も同じ。

- その指定を `@layer base` に入れ、ユーティリティで上書きできるようにした (全画面に効く)。
- E2E は `e2e/touch-drag.spec.ts` (CDP のタッチでなぞる。マウスの E2E では出ない)。

### 1-7. モジュール化

```text
src/modules/
  registry.ts                 ← core が読む唯一の入口 (結果ビューの一覧・ノートのタブの一覧)
  calendar/
    index.ts                  ← 登録情報 (id・ラベル・アイコン・next/dynamic の部品)
    event/parseEvent.ts       ← props → EventFields | null (純関数)
    event/eventColumns.ts     ← memo → { eventStart, eventEnd, eventRepeat } (純関数)
    event/applyEvent.ts       ← (memo, fields) → memo (純関数)
    event/newEventMemo.ts     ← (fields, tags) → memo (純関数)
    api/calendarQuery.ts      ← server-only。searchItemRows + buildWhere + 月の窓
    api/calendarDto.ts        ← EventDto と isEventDto (両側)
    client/calendarStore.ts   ← createResourceCache({ query, month })
    client/CalendarView.tsx   ← ペイン 2 の中身 (月送り・MonthGrid・DayStrip)
    client/MonthGrid.tsx / DayStrip.tsx / monthLayout.ts (純関数)
    client/EventForm.tsx      ← 「予定」タブの中身
```

core 側の継ぎ目は 4 つだけ:

1. `src/lib/items/write.ts` の `derivedFromMemo` が `...eventColumnsOf(memo)` を 1 行呼ぶ
2. `src/modules/registry.ts` — 結果ツールバーの切替と `SearchResultsClient` の差し替え、
   `MemoPanel` の `extraTabs` の供給元
3. `MemoPanel` に `extraTabs?: { key, label, content }[]` を足す
4. `NoteView` の `defaultMode` を URL の `tab` で上書きできるようにする

境界は eslint で守る: `src/lib/**`・`src/components/**`・`src/app/**` から `@/modules/*` を
import できるのは `@/modules/registry` だけ (`no-restricted-imports` の patterns に足す)。
モジュールは core の公開部品 (`searchItemRows`・`buildWhere`・`createResourceCache`・
`ModalOverlay` 等) を import してよい (依存は module → core の一方向)。
`rrule`・マス目の部品は `next/dynamic` で遅延読み込みし、本体のバンドルに乗せない。
別パッケージ化 (tommie-fence の core と同じ型) は、純関数を使う 2 つ目の利用者
(オフライン・単体アプリ) が現れてから。

### 1-8. やらないこと (Phase 1〜2)

繰り返し・オフライン・ドラッグ移動・一覧からの隠し (docs/125 §7)・週/日の時間軸・
`#予定` ノートのサムネ付きチップ。

## 2.5 実装の記録 (2026-11-03、Phase 1・2)

Phase 1・2 を実装した。§1-7 の木と違う所と、決めたこと:

- 列は `timestamp(3)` (Prisma の既定、UTC)。他の日時の列と揃えた。比べる値は
  タイムゾーン無しの文字列にして `::timestamp` で渡す (`calendarQuery.ts`。
  セッションの TZ に依らない)
- 純関数は `event/` にまとめた: `parseEvent.ts`・`eventTime.ts` (JST の組み立て)・
  `eventColumns.ts`・`eventMemo.ts` (applyEvent・newEventMemo・requiredTags を
  1 ファイルに)・`monthLayout.ts` (サーバの取る範囲と端末の並びが共有するので
  client/ ではなく event/ に置いた)
- 取る範囲は月ではなく**マス目 (日曜始まり、4〜6 週)**。前後の月のはみ出しのマスにも予定が出る
- core の継ぎ目は 3 つの入口: `@/modules/registry` (画面。`.tsx`)・
  `@/modules/derivedColumns` (派生列)・`@/modules/<名前>/api/route`・`@/modules/<名前>/api/<口>/route`
  (2026-11-08 に設定の口のため足した)
  (`src/app/api/calendar/route.ts` は 1 行の再輸出)。eslint は正規表現の pattern で
  それ以外を止める (gitignore 形式の `!` は親が除外済みだと効かなかった)
- ItemDto に 3 列を足した (省略可。知らない版の応答も受ける)。テストの固定データ
  18 ファイルに `eventStart: null` などを補った
- ノートを開く URL にも `q` と `cal` を載せる (`/item/<id>?q=…&cal=…&tab=event`)。
  端末で開いたノート (pushState) を出している間も検索画面は URL を読むので、
  `cal` が落ちると後ろが一覧に戻る。月送りは今のパスのまま `cal` だけ替える
- `?tab=` と `?date=` は NoteView が開いたときの値を控える (3 ペインでは URL が
  /item を離れてもノートが残るため)
- 足したタブが消えたら (本文から `date=` を消した) MemoPanel は markdown へ戻す
- マスの中の予定は押せる物にしない (iPhone で日を選ぶ指が予定を開いてしまう)。
  開くのは日の帯から
- 削除はフォームの「ゴミ箱へ」(既存の trashItemsAction)
- 本番に `date=` を持つノートは無いので、導入時のバックフィルは不要
  (`doBackfill.sh events` は用意した)

確かめたこと: 単体 (純関数・API の口・登録口・MemoPanel のタブ)、手元の DB での
月の取得 (月をまたぐ複数日・翌月の予定が外れる)、E2E `e2e/calendar.spec.ts`
(日を選ぶ → 「+」→ 予定タブ → 追加 → 月に出る / 時刻を直す → 本文の行だけ変わる /
一覧 ⇄ カレンダー)、iPhone 幅 (390px) と PC 3 ペインの画面。
