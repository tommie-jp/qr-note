# 動画アニメサムネ計画

一覧に並ぶ動画のサムネを、ホバー中 (PC) / 画面に入った時 (スマホ) だけ
**アニメーション WebP へ差し替える**。静止画 1 枚では中身が動画だと伝わり
にくく、▶ バッジが付いていても「何が写っているか」は開くまで判らない。

先行事例は 13-kick-work の切り抜きランキング (`405604b`)。あちらで
確かめた判断はそのまま持ち込み、生成のしかただけを QR-Note の事情に
合わせて作り直す。

## §1 13-kick-work から持ち込んだ判断

- **GIF ではなく WebP**。同条件 (3秒 / 8fps / 320px) の実測で GIF 約 1.1MB に
  対し WebP 約 100KB。30 行並ぶ一覧では桁違いの転送量になる。`<img>` に
  そのまま入る点は GIF と同じ。
- **一覧に `<video>` を並べない**。行数ぶんの動画を同時に読みに行くと
  モバイル回線で破綻する (あちらのショートで実測済み)。
- **出来上がりが本当にアニメか自分で検算する**。あちらでは ffmpeg が rc=0 の
  まま 1 コマだけの静止画を吐くことが約 300 件に 1 件あった。素通しすると
  「動かない動くサムネ」が残り続けるので、RIFF の `ANIM` チャンクを見て弾く
  (`isAnimatedWebp`)。
- **差し替え条件を端末で変え、スマホには本数の上限を置く**。一覧は延々と
  スクロールできるので、素直に「見えたら差し替える」だけだと最後まで見た人が
  全件を引く。
- **静止サムネは残し、動くサムネは上乗せ**。404・生成失敗は静かに静止画へ
  戻し、同じ行では二度と試さない。

持ち込まないのは ffmpeg・HLS 取得・cron・prune・失敗回数の記憶。あちらは
「外部の動画 URL を後から巡回する」構造だったが、QR-Note は**アップロードの
瞬間にブラウザが動画の実体を持っている**ので、作る契機も寿命 (行が消えれば
列も消える) も既に解決している。

## §2 コマはクライアント、束ねるのはサーバ

サーバに ffmpeg を入れる案は採らない。`videoPoster.ts` が「サーバに ffmpeg を
持ち込まずに poster を出す」ために置かれている経路をそのまま伸ばす。

| | クライアント (`videoPoster.ts`) | サーバ (`video/videoAnim.ts`) |
| --- | --- | --- |
| 仕事 | `<video>` をシークして N コマを canvas へ描く | コマを検算して 1 本のアニメ WebP に束ねる |
| 出力 | JPEG 320px x 最大 8 コマ | アニメ WebP (`images.thumb_anim`) |

ffmpeg をイメージに足すと +80〜130MB になり、ユーザーが投げたバイト列を
ffmpeg に食わせる攻撃面も増える。得られるのは「既存動画のバックフィル」
だけで、それは §7 のとおり静止のままで実害がない。

束ねるのに sharp を使えるのは `join: { animated: true }` があるため。
実装で踏んだ罠が 3 つある (いずれも実測):

- **join の後ろに resize を置くとアニメが静止画に潰れる。** ページの扱いが
  失われ `pages` が消える。コマごとに縮めてから join すること。
- **`delay` は配列で渡す。** 数値 1 つだと 1 コマ目にしか効かず、残りは
  既定の 100ms になる。
- **寸法違いのコマでも例外は出ない。** 1 コマ目に合わせて余白が入るだけなので、
  揃えずに渡すと動かした瞬間に絵が飛び跳ねる。サーバ側で全コマを同じ寸法へ写す。

## §3 生成パラメータ

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| コマ数 | 8 (`MAX_VIDEO_ANIM_FRAMES`) | シークの回数がそのままコストになる |
| サンプル位置 | 動画**全体**を等間隔 (`frameTimes`) | 手元の記録は冒頭が支度の時間であることが多い |
| 表示間隔 | 400ms (一巡 3.2 秒) | 速すぎると何も読み取れない |
| 一辺 | 320px (`VIDEO_ANIM_MAX_PX`) | 静止サムネ (384px) より一段小さく。コマ数ぶん積み上がるので効きが大きい |
| 品質 | webp q50 | 13-kick-work の実測で静止画サムネ相当の見え方 |
| 抽出の時間上限 | 6 秒 (`ANIM_BUDGET_MS`) | 間に合ったぶんだけで作る |
| コマ数の下限 | 3 (`MIN_VIDEO_ANIM_FRAMES`) | 2 コマ以下は点滅にしかならない |
| 尺の下限 | 1.0 秒 (`MIN_ANIM_DURATION_SEC`) | それ未満はどこから抜いても同じ絵 |
| 出力の上限 | 300KB (`MAX_VIDEO_ANIM_BYTES`) | 超えたら捨てる (静止のまま) |

**冒頭 3 秒の連写にしないのが 13-kick-work との違い。** あちらは ffmpeg で
連続デコードできたが、こちらはブラウザのシークでコマを取るので枚数が
そのままコストになる。同じ枚数を使うなら全体に散らしたほうが中身が伝わる。

送信量の上限は multipart の枠と連動している。動画本体の上限 +
`MULTIPART_OVERHEAD_BYTES` (1MB) が `checkUploadRequest` の門なので、
poster 200KB + コマ 8 x 80KB = 840KB がその内側に収まるよう決めてある
(`uploads.test.ts` に式で残した)。ここを緩めるなら門も一緒に見直すこと。

## §4 列を分ける (`thumb` と `thumb_anim`)

`images` に `thumb_anim BYTEA` を足す。1 列にまとめてアニメで上書きしない:

- 一覧の既定は静止のままにしたい。全行が一斉に動くと転送量も見た目も破綻する。
- `<video poster>` は静止であるべき (再生ボタンの隣で poster が動くのは紛らわしい)。
- アニメだけ作れないことが普通に起こる (§5)。同じ列に置くと巻き添えになる。

配信は `?thumb=1&anim=1` で、**無ければ必ず 404**。静止で代替しないのは、
表示側が 404 を「静止のままでよい」の合図に使うから — ここで静止を返すと
差し替えが効いたのか判らず、未生成の動画に要求を出し続けることになる。

キャッシュバスターの版 (`THUMB_ANIM_VERSION`) は静止の `THUMB_VERSION` と
分ける。コマ数や間隔を触るたびに全画像のキャッシュを割る理由はない。

## §5 静止とアニメの成否は独立

コマの抽出は端末とコーデック次第で途中で打ち切られるので、**「静止は作れたが
アニメは作れない」は正常な結果**として起こる。13-kick-work が
`make_anim` を `make_assets` に作り直して出力別に成否を返すようにしたのと
同じ判断で、`storeAttachment` は poster と `thumbAnim` を別々に組み立てる。

`makeVideoAnim` は**例外を投げない** (`makeThumbnail` / `makeVideoPoster` と
同じ流儀)。動くサムネは「あれば嬉しい派生物」で、これのために動画の
アップロードを失敗させる価値はない。

解凍爆弾よけ (`MAX_INPUT_PIXELS`) は**コマごとに**効かせる。束ねてから
判定すると合計で落ち、どのコマが悪いかに関係なく丸ごと失われる。

## §6 表示の差し替え

`useAnimThumb.ts` (13-kick-work の `html/src/clip-anim.js` の移植)。

- ポインタがある端末 (`(hover: hover) and (pointer: fine)`) … ホバー中だけ。
  一覧を眺めるだけの人に全行ぶんの転送をさせない。
- それ以外 … `IntersectionObserver` (可視率 0.6、先読みしない) で画面に
  しっかり入ったものだけ。画面から出たら静止画へ戻し、1 セッションの本数を
  `MAX_AUTO_ANIM` (30 本) で頭打ちにする。
  **`threshold` を渡すだけでは足切りにならない** — 交差の報告は
  `isIntersecting` (少しでも重なれば true) でも飛んでくるので、判定は
  交差率そのもので行う (`isVisibleEnough`)。素通しすると、下端に少し覗いた
  行が次々と枠を取り、目当ての動画に着く前に上限を使い切る。
- 未生成 (404) は静止へ戻し、**上限の勘定からも枠を返す**。返さないと、
  生成されていない動画が並ぶ一覧で 404 だけで枠を使い切る。
- 動いている間は ▶ バッジを消す (動いていれば動画だと判る)。

ホバーは `<img>` ではなく**容器で受ける**。▶ バッジが上に重なっているため、
`<img>` に付けると中央にポインタを置いたときだけ差し替わらない
(13-kick-work が `animThumbFrom` で兄弟を探して回避していた問題。こちらは
バッジ側の `pointer-events: none` と併せて元から起こらないようにする)。

上限の勘定を持つ `Set` は**モジュールスコープ**に置く。一覧の行は再描画で
作り直されるので、コンポーネントの中に持つとリセットされて上限が効かない。

## §7 対象外 (割り切り)

- **既存の動画は静止のまま。** サーバに動画デコーダが無く、コマを抜けるのは
  アップロード時のブラウザだけなのでバックフィルできない。`?anim=1` が
  404 を返し、表示は今までどおりになる。遡って作りたくなったら、編集画面に
  「動くサムネを作り直す」導線を足せばクライアント側だけで解決できる。
- **端末がデコードできない動画** (iOS の HEVC など) は静止サムネも付かない
  (従来どおりビデオアイコン)。
- **本文の `<video poster>` は静止のまま** (§4)。
- **オフラインには持ち出さない** (`pinCache` / `sync` は静止サムネだけ)。
  圏外では 404 になって静止のままになるだけで、実害はない。
- **画像モードのタイル** (`ImageMasonry`) は `allImageNames` を使うため
  そもそも動画を含まない。対象は一覧の `ItemRow` / `RowThumb` だけ。
