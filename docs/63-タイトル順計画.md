# 63. タイトル順

一覧の並び順 ([37-アクセス順計画.md](./37-アクセス順計画.md)) に「タイトル順」を足す。
下部バーの並び順スロット ([31-下部操作バー計画.md](./31-下部操作バー計画.md)) で選ぶ。

## 1. なぜ足すか

今ある 3 つはどれも「いつ」か「番号」で引く並びで、**名前で引く道が無い**。

- 更新順 … 最近書いたものを上から辿る
- アクセス順 … 最近見たものを上から辿る
- 番号順 … シールに印刷した番号を辿る

部品のノートは `0.96 OLED 128x64 I2C WHITE #1` のように名前が付いていて、
「あの部品どこだったか」を思い出すとき、日時も番号も手掛かりにならない。
頭文字が判れば辿り着ける並びが要る。

検索で引けばよいのでは、とはならない。**綴りをうろ覚えのときこそ一覧で探す**ので、
そこは並びの仕事になる。

## 2. 何を「タイトル」と呼ぶか

一覧に出ている見出しをそのまま使う。画面と並びが食い違うのがいちばん困る。

見出しの決め方は `src/components/ItemRow.tsx` が既に持っている:

- URL モードのノート … `url` (本文が無い)
- それ以外 … `memoSummary(memo)` = 本文の先頭行から Markdown 記法を剥がしたもの
  (`src/lib/memoSummary.ts`)

見出しの無いノート (空メモ・画像だけ) は末尾へ回す。空文字は照合順序では先頭に
来てしまい、名前で引きたいときに邪魔になる。番号順が非数字の `item_no` を
`NULLS LAST` で末尾へ回すのと同じ考え方。

## 3. 並べる鍵をどこに置くか

**`items.title` を派生キャッシュ列として足す** (`tags` / `props` /
`task_todo` と同じ形。正本は `memo`、保存のたびに作り直す)。

SQL で本文から見出しを切り出すことはできない。`memoSummary` はコードフェンス
(` ``` `) と折りたたみ (`:::details`) を飛ばし、行頭記法とインライン記法を
剥がす小さなパーサで、これを SQL で書き直せば二重実装になり、必ずずれる。

書き込み経路は `src/lib/items.ts` の `derivedFromMemo()` 1 箇所に集約済みなので、
そこに 1 行足すだけで全経路 (編集・スキャン登録・ENEX / ZIP 取り込み・画像回転に
伴う本文書き換え) が追随する。

URL モードの `url` は **列に入れない**。正本が二重になるので、並べるときに
`ORDER BY` 側で切り分ける:

```sql
NULLIF(CASE WHEN mode = 'url' THEN url ELSE title END, '') ASC NULLS LAST,
item_no ASC
```

`item_no ASC` のタイブレークは全ての並びと揃える。同着で並びが揺れると、
ページ送りと前後ナビが読み込みのたびにずれる
([15-単語帳向け改善計画.md](./15-単語帳向け改善計画.md) §2-2)。

索引は張らない。数百件では seq scan + sort で足り、書き込みのたびに索引を
更新する方が高くつく ([56-チェック検索計画.md](./56-チェック検索計画.md) と同じ判断)。

表示側は変えない。`ItemRow` は今までどおり `memoSummary()` をその場で通す —
この列は並べ替え専用で、読むのは `ORDER BY` だけ。

### 照合順序

DB の既定 (`en_US.utf8`) をそのまま使う。英数字は大文字小文字を混ぜて自然に並び、
かな・漢字はコードポイント順になる。読み仮名を持っていない以上、五十音順には
できないので、ここは望みうる最善。不満が出たら `COLLATE` を後から検討する。

## 4. 導入の段取り

1. マイグレーション `20260808120000_add_item_title` で列を足す。既存行は `''`。
2. `./doBackfillTitles.sh` で全ノートの見出しを切り出して埋める
   (`scripts/backfillTitles.ts`)。**流し忘れると全件同着 = 番号順にしか見えない。**
3. デモも同じ (`DEPLOY_REMOTE_DIR=qr-demo DEPLOY_DB_PORT=5433`、種の `qr_seed` にも)。

派生キャッシュなので、ずれたと思ったらいつでも流し直してよい (冪等)。

## 5. UI

下部バーの並び順スロットを 4 値の循環にする
(更新順 → アクセス順 → 番号順 → タイトル順)。

タイトル順は**末尾に足す**。よく使う 2 つ (更新順・アクセス順) を隣どうしに
置いた並びを崩さない。4 値になると短いタップで一周するのが遠くなるが、
長押しで直接選べる ([62 §3](./62-下部バー長押し計画.md)) ので、循環の順を
組み替えてまで近づけない。

`?sort=title` と cookie の扱いは他の 3 つと同じ
([sortMode.ts](../src/lib/sortMode.ts): URL → cookie → 既定)。既定は更新順のまま。
