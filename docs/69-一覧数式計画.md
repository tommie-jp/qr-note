# 一覧数式計画

検索結果とゴミ箱の一覧 (タイトル・カードの本文プレビュー・画像モードの
キャプション) と特性表の要約列で、インライン数式 `$...$` を KaTeX で描画する。
`$E=100\,\mathrm{V}$` のような生 TeX が一覧に並ぶのは読みにくい。

## §1 どこで描くか

回路図サムネ (docs/68) と同じ型:
**サーバで HTML 化 → Record を prop で降ろす → 共有部品が埋め込むだけ**。

- 生成: `src/lib/mathText.ts` (サーバ専用)。`memoSummary` / `memoPreview` が
  返したプレーンテキストの `$...$` を `katex.renderToString` で HTML にし、
  地の文は自前でエスケープして繋ぐ。`maxSize` はノート表示と同じ
  `KATEX_OPTIONS` (markdownPipeline.tsx) を使い、`throwOnError: false` で
  構文エラーは赤字ソース表示 (rehype-katex の既定と同じ)。
- 表示: `src/components/MathText.tsx` が `dangerouslySetInnerHTML` で埋める。
  ここで `katex/dist/katex.min.css` を import する (MarkdownView に次ぐ
  2 か所目) — これで一覧ルートにも KaTeX の CSS とフォントが届く。
  SW のフォントキャッシュは CSS スキャン方式 (public/sw.js) なので追従する。
- katex (~280KB) はクライアント束に入れない。client 部品からは型
  (`MathTextMap`) だけ import する (circuitThumbs.ts と同じ線引き)。

## §2 前提修正: 一覧テキスト側の数式の扱い

`stripLineMarkdown` の強調・リンク剥がしが数式の中身を壊していた
(`$x^*$ と $y^*$` → `$x^$ と $y^$`、`$[a](b)$` → `$a$`)。

- インライン数式は剥がしの前に番号つき目印 (`￼n￼`) へ退避して最後に戻す。
  番号で戻すのは、リンク剥がしが URL 内の数式を目印ごと消しても残りの復元が
  ずれないため。本文に元から居る U+FFFC は捨てる (復元の取り違え防止)。
  `\$` エスケープ (通貨) は開き・閉じどちらの区切りにもしない。数式の
  見つけ方は `memoSummary.ts` の `INLINE_MATH` / `inlineMathRanges` に一本化
  (マスク・打ち切り・KaTeX 描画・props.ts の stripNonProse が共有)。
- ブロック数式 `$$...$$` は行ごと落とす (描画フェンスと同じ「図扱い」。
  ユーザー決定)。実装はフェンスと同じ行単位の状態機械 (`hiddenLineSkipper`)
  で、開きは行頭の `$$` だけ・フェンス内の `$$` (`echo $$` 等) は無視・
  閉じない `$$` は残り全部を隠す (remark-math も末尾まで数式として描くので
  ノート表示と揃う)。行内で閉じる `$$x$$` はその場で落とし、行の残りは保つ。
- プレビューの行の区切りは空白ではなく改行 (表示では同じに見える)。空白で
  繋ぐと別々の行の `$` 同士が数式の対に見えてしまう。
- プレビューの 200 字打ち切りが `$...$` の内側に落ちるときは、その数式の
  開始 `$` の手前で切る (生 TeX の切れ端を出さない)。切り戻しで空になる
  ときだけは従来位置で切る (空の 3 行よりまし)。
- 既知の近似 (許容): インラインコード由来の `$` が同じ行に 2 つあると
  (`` `$PATH` と `$HOME` `` 等)、一覧では数式に見えることがある。ノート
  表示は正しくコードとして描く。

## §3 適用範囲

- 検索一覧: タイトル (小/大)・カードの本文プレビュー・画像モードの
  キャプション。ゴミ箱も同じ (trash/page.tsx が同じ配線を持つ)。
- 特性表 (PropsTable): 要約列のみ。`mathSummaries` (itemNo → HTML) を
  ページ側で作って降ろす (`lib/items.ts` に katex を持ち込まない)。
  ツールチップ (title 属性) は HTML を入れられないのでプレーンのまま。
- **オフライン一覧 (OfflineList) は対象外**: 一覧テキストはクライアントで
  memoSummary を通すだけで、サーバの KaTeX 描画が使えない。生 TeX のまま
  (現状維持)。ノートを開けば同期済みの描画で数式は出る。

## §4 予算

KaTeX の HTML はソースの数倍〜十数倍で、SSR の HTML と hydration 用の
Flight payload に二重に載る (docs/68 §6 と同じ事情)。3 段構え:

- プレビューの HTML はカード表示のときだけ作る (`buildMathTexts` の mode。
  小/画像モードではどの行にも描かれない)。
- 1 フィールド 16KB を超えたらプレーンテキストへ静かに劣化
  (`MAX_MATH_HTML_CHARS`。超過確定の時点で描画も打ち切る)。
- 1 レスポンス合計 256KB (`MATH_TEXT_BUDGET`)。「さらに表示」の累積で件数に
  上限が無いため。先頭から詰めて、超えた分はプレーンテキストのまま。

特性表の要約列はタイトルと同一文字列なので描画を使い回す
(`buildMathSummaries`)。

## §5 導入時の運用

`memoSummary` の出力が変わる (ブロック数式まわり) ため、並べ替え用の派生列
`items.title` が既存ノートで古くなる。表示は常にその場で計算するので正しく
出るが、タイトル順の並びだけ食い違う。気になる場合は `doBackfillTitles.sh`
を 1 回流す (対象は `$$` を含む十数ノートのみ)。
