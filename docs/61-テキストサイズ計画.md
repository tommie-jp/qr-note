# テキストサイズ計画 (画面の文字を大きくする)

画面の文字を、ハンバーガーメニューの ＋ / − で大きくできるようにする。

```text
[Aa] テキストサイズ        −  115%  ＋
```

## 1. root ごと動かす (本文だけの倍率はやめた)

`html` へ CSS 変数 `--note-font-scale` を 1 つ立て、**`html` の `font-size`
そのもの**を `calc(100% * var(--note-font-scale, 1))` で動かす。アプリの寸法は
Tailwind でほぼ `rem` なので、文字・余白・タップ目標・アイコンが比率を保った
まま一斉に伸縮する (ブラウザのズームと同じ挙動)。

当初はこの案を採らず、本文の器にだけ倍率クラス (`.note-text-scale`) を
掛けていた。**「一覧やタグの文字も大きくしたい」となった時点でその形は
破綻する** — 画面ごとにクラスを貼って回れば、貼り忘れた場所だけ小さいままの
「まだら」が必ず残り、画面を足すたびに貼る義務が増えるため。個別の倍率クラス
(`.note-text-scale` / `--note-text-base` / `.note-input-scale`) は全部これに
置き換えて消した。

`%` で書くこと。`rem` / `em` にすると自分自身を参照して倍率が累乗になる。

巻き込まない例外は 3 つだけ:

| 例外 | 理由 |
| --- | --- |
| 入力欄 (§2) | 16px 未満で iOS が自動ズームする |
| 図 (§4) | SVG の固定 px 属性は rem に追随しない |
| 印刷 | 紙の大きさは画面の設定と無関係。`@media print` で 100% に戻す |

PDF のテキストレイヤ (`.textLayer`) は canvas の絵と px で位置を合わせており、
式もすべて px なので root が動いても絵と文字はずれない (200% で実測確認済み)。

### 横に並んだ物は折り返させる

大きくすると、横並びの行が画面幅に入らなくなる。**横スクロールにするのではなく
折り返す** — 縦に伸びるのは目に見えるが、横スクロールは「なぜか右にずれる」形で
気づきにくいため。実測して足りなかったのは次の 4 か所 (390px 幅, 200%):

| 場所 | 直し方 |
| --- | --- |
| ヘッダーの帯 (サイト名・版・目印・ユーザー名) | `flex-wrap` |
| ノートの見出し行 (`item #123` + 編集 / 履歴 / QR / 記法) | `flex-wrap` |
| メモのタブ (markdown / テキスト / 編集) | `flex-wrap` |
| メニューの「テキストサイズ」行 | `flex-wrap` |

検索窓は折り返しではなく **`min-w-40` (10rem) を `min-w-[160px]` に**変えた。
rem のままだと下限が倍率ぶん広がり、200% では窓だけで 320px を要求する。
窓の中の文字は倍率どおり大きくなるので、器の下限まで広げる必要はない。

折り返す項目を入れたら **入れ物の側で `shrink-0`** も要る。ボトムシートのように
`flex-col` で積んだ入れ物は既定で子を縮めるため、2 行になった項目の高さが
1 行ぶんに詰められ、あふれた行が次の項目に重なって描かれる。

### 下部バーだけは上限を設ける

下部バーは 5 スロットを**必ず横に並べる**帯なので、折り返しでは解けない
(折り返した時点でバーではなくなる)。バーの中だけ `zoom: min(1, 1.3 / 倍率)` で
130% 頭打ちにする。余白 (spacer) にも同じ上限を掛けること — 掛け忘れると、
バーの高さが止まった後も一覧の下の空きだけが伸び続ける。

**式はカスタムプロパティに逃がすこと。** `zoom` へ直接書くと、ビルド時の CSS
最適化が `var()` 込みの除算を畳めずに宣言ごと落とし、ブラウザには何も届かない
(実際それで無反応だった)。

## 2. 段は 8 つ (75%〜200%)、入力欄は 16px を割らせない

`75% / 85% / 100% / 115% / 130% / 150% / 175% / 200%` の離散。連続の
スライダーは片手で狙いにくく、「元に戻す」も曖昧になる。

縮小方向 (75% / 85%) が効くのは**読む文字だけ**。入力欄は globals.css の
`max(16px, 1em)` が下限を留める — 16px 未満の入力欄は iOS Safari がフォーカス
時に自動ズームして戻らなくなるため。つまり縮小時は「読む文字は小さく、書く
文字は等倍のまま」。当初は防御として縮小段そのものを作らなかったが、防波堤を
入力欄側の clamp に移して範囲を広げた。

**下限は `px` で書くこと。** `1rem` は root の倍率で一緒に縮むので、rem で
書くと 75% では下限ごと 12px まで落ちて防御にならない。対象は入力欄すべて
(検索窓を含む) にまとめる — チェックボックスとラジオだけ外す。字を持たない
ので `font-size` は的の大きさに効かず、一覧のタスクチェックが膨らむだけ。

75% ではタップ目標が 44px → 33px まで縮む。原則を割るが、意図して選ぶ段なので
許容する (「もっと詰めて見たい」がその選択の中身そのもの)。

保存値は誰でも書き換えられるので、読むときは**いちばん近い段へ寄せる**。
段を後から増減しても、古い端末に残った値が捨てられない。

## 3. 置き場所はメニューの 1 行

ログイン状態やデモに依らず出す。読みやすさの設定であって、ノートを持って
いるかとは関係がない (公開ノートにも効く)。

**＋ / − はクリックを行で止める** ([TextSizeMenuItem.tsx](../src/components/TextSizeMenuItem.tsx))。
メニューのシートは「項目を押したら閉じる」を親のバブリング 1 か所で受けて
いるので (docs/11 §6)、素通しすると 1 回押しただけで閉じて続けて押せない。
`HeaderQrButton` と同じ「自前の状態を持つ項目」の扱い。開いたままなら、
暗くした覆いの向こうに本文の変化も見える。

真ん中の倍率表示は押すと等倍に戻る。何段上げたか数えなくても戻れるように。

## 4. 図 (circuitikz / mermaid) も連動する

root の `font-size` に追随しないのはこの 2 つだけ。KaTeX 数式は em 組みなので
自動で追随する。画像は対象外 — `|幅` の指定とピンチズームが既にあり、倍率まで
掛けると「指定した幅」の意味が壊れる。

circuitikz の SVG はサーバ生成で `width="222.046"` のような固定 px 属性を
持つため、font-size では動かない。`transform: scale()` はレイアウト箱が
変わらず余白だけ崩れるので、レイアウトごと拡縮する **CSS `zoom`** を使う
(Safari / Chrome は昔から、Firefox は 126+ で対応。非対応では等倍のまま =
安全な劣化)。あわせて `.circuit-diagram` / `.mermaid-diagram` に
`overflow-x: auto` を敷き、拡大して本文カードの幅を超えた分は図の中だけ
横スクロールさせる (コードブロックと同じ作法。等倍でも幅広の回路図に効く)。

## 5. 反映は初回描画の前に

`useEffect` で当てると、サーバが描いた等倍の本文が一度見えてから大きくなる。
文字サイズを上げた人は毎回その跳ねを見ることになるので、`<head>` の
インラインスクリプトで HTML の解析中に当てる (Next の
`docs/01-app/02-guides/preventing-flash-before-hydration.md` の theme と同じ手)。
`<html>` には `suppressHydrationWarning` が要る — 付けないと React が
書き足された style を不整合と見なし、境界ごと描き直して倍率が失われる。

スクリプトは import できない (バンドル前に走る) ため、**寄せ方の実装が
`normalizeNoteFontScale` と二重になる**。ずれると読み込み直後だけ別の大きさで
描かれるので、`noteFontScale.test.ts` が同じ表で両方を確かめている
(スクリプト文字列を `new Function` で実際に走らせる)。

## 6. 確かめ方

このリポジトリは jsdom を持たないため、自動で確かめられるのは倍率のロジックと
「開いた直後の描画」まで。次はブラウザで実物を通して見る。

- ＋ / − を連打してもシートが閉じない
- 覆いの向こうで本文の大きさが変わる
- 再読み込みしても大きさが残り、**初回描画から跳ねない**
- 検索結果の一覧・タグ・ヘッダー・下部バーも一緒に伸縮する
- **どの倍率でも画面が横スクロールしない** (390px 幅で 75%〜200% を実測)
- 75% でも入力欄 (検索窓・編集画面) は 16px のまま
- PDF のテキストレイヤが絵とずれない
- 印刷プレビューは等倍
- 200% で circuitikz / mermaid の図が拡大し、はみ出す分は図の中で横スクロール
- 編集タブにフォーカスしても iOS が自動ズームしない
