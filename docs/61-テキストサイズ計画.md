# テキストサイズ計画 (本文の文字を大きくする)

ノート本文の文字を、ハンバーガーメニューの ＋ / − で大きくできるようにする。

```text
[Aa] テキストサイズ        −  115%  ＋
```

## 1. 大きくするのは本文だけ

`html` の `font-size` を動かせば画面全体が一度に大きくなるが、この案は採らない。
アプリの寸法は rem で組んであり、**44px のタップ目標・ヘッダーの `1cap` の
ベースライン揃え・ボトムシートの `max-h` の式**がまとめて動く。どれも狙って
詰めてある値なので、文字を読みやすくするためだけに巻き込むのは割に合わない。

代わりに `html` へ CSS 変数 `--note-font-scale` を 1 つ立て、本文側だけが読む。

| 対象 | 基準サイズ | 置き場所 |
| --- | --- | --- |
| markdown 表示 | 0.875rem (`prose-sm` と同じ) | [MarkdownView.tsx](../src/components/MarkdownView.tsx) |
| テキスト表示 | 1rem (従来の `text-base`) | [ItemView.tsx](../src/components/ItemView.tsx) |
| 編集 (CodeMirror) | 1rem | `.cm-editor` (globals.css) |

`prose-sm` は外さない。上書きするのは器の `font-size` だけで、見出しや余白は
`em` で書かれているため丸ごと追随する。

`.note-text-scale` は **cascade layer の外の素の CSS** で書く。`@utility` に
すると Tailwind と同じ layer の中で並び順の勝負になり、`prose-sm` の
`font-size` に負けて効かないことがある。`.cm-editor` / `.textLayer` が素の CSS
なのと同じ理由。

## 2. 段は 8 つ (75%〜200%)、入力欄は 16px を割らせない

`75% / 85% / 100% / 115% / 130% / 150% / 175% / 200%` の離散。連続の
スライダーは片手で狙いにくく、「元に戻す」も曖昧になる。

縮小方向 (75% / 85%) が効くのは**本文の表示だけ**。入力欄 (`.cm-editor` と
読み込み中の textarea) は globals.css の `max(1rem, calc(…))` が 16px を
下限に留める — 16px 未満の入力欄は iOS Safari がフォーカス時に自動ズームして
戻らなくなるため。つまり縮小時は「読む文字は小さく、書く文字は等倍のまま」。
当初は防御として縮小段そのものを作らなかったが、防波堤を入力欄側の clamp に
移して範囲を広げた。

保存値は誰でも書き換えられるので、読むときは**いちばん近い段へ寄せる**。
段を後から増減しても、古い端末に残った値が捨てられない。

## 3. 置き場所はメニューの 1 行

ログイン状態やデモに依らず出す。読みやすさの設定であって、ノートを持って
いるかとは関係がない (公開ノートにも効く)。

**＋ / − はクリックを行で止める** ([TextSizeMenuItem.tsx](../src/components/TextSizeMenuItem.tsx))。
メニューのシートは「項目を押したら閉じる」を親のバブリング 1 か所で受けて
いるので (docs/11 §6)、素通しすると 1 回押しただけで閉じて続けて押せない。
`HeaderQrButton` と同じ「自前の状態を持つ項目」の扱い。開いたままなら、
暗くした覆いの向こうに本文の変化も見える。

真ん中の倍率表示は押すと等倍に戻る。何段上げたか数えなくても戻れるように。

## 4. 図 (circuitikz / mermaid) も連動する

対象はこの 2 つ。KaTeX 数式は em 組みなので本文の font-size に既に追随する。
画像は対象外 — `|幅` の指定とピンチズームが既にあり、倍率まで掛けると
「指定した幅」の意味が壊れる。

circuitikz の SVG はサーバ生成で `width="222.046"` のような固定 px 属性を
持つため、font-size では動かない。`transform: scale()` はレイアウト箱が
変わらず余白だけ崩れるので、レイアウトごと拡縮する **CSS `zoom`** を使う
(Safari / Chrome は昔から、Firefox は 126+ で対応。非対応では等倍のまま =
安全な劣化)。あわせて `.circuit-diagram` / `.mermaid-diagram` に
`overflow-x: auto` を敷き、拡大して本文カードの幅を超えた分は図の中だけ
横スクロールさせる (コードブロックと同じ作法。等倍でも幅広の回路図に効く)。

## 5. 反映は初回描画の前に

`useEffect` で当てると、サーバが描いた等倍の本文が一度見えてから大きくなる。
文字サイズを上げた人は毎回その跳ねを見ることになるので、`<head>` の
インラインスクリプトで HTML の解析中に当てる (Next の
`docs/01-app/02-guides/preventing-flash-before-hydration.md` の theme と同じ手)。
`<html>` には `suppressHydrationWarning` が要る — 付けないと React が
書き足された style を不整合と見なし、境界ごと描き直して倍率が失われる。

スクリプトは import できない (バンドル前に走る) ため、**寄せ方の実装が
`normalizeNoteFontScale` と二重になる**。ずれると読み込み直後だけ別の大きさで
描かれるので、`noteFontScale.test.ts` が同じ表で両方を確かめている
(スクリプト文字列を `new Function` で実際に走らせる)。

## 6. 確かめ方

このリポジトリは jsdom を持たないため、自動で確かめられるのは倍率のロジックと
「開いた直後の描画」まで。次はブラウザで実物を通して見る。

- ＋ / − を連打してもシートが閉じない
- 覆いの向こうで本文の大きさが変わる
- 再読み込みしても大きさが残り、**初回描画から跳ねない**
- 75% で本文は縮み、編集画面 (と読み込み中の textarea) は 16px のまま
- 200% で circuitikz / mermaid の図が拡大し、はみ出す分は図の中で横スクロール
- 編集タブにフォーカスしても iOS が自動ズームしない
