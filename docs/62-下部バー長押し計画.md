# 62. 下部バー長押しと検索行のアイコン化

下部操作バー ([31-下部操作バー計画.md](./31-下部操作バー計画.md)) と検索窓の行を、
スマホで使っていて引っかかった点だけ直す。新しい機能は足さない。

## 1. 帯の文字を選択させない

バーは押す物だけが並ぶ帯で、文字を読んで持ち出す場所ではない。既定のままだと
指を置いた瞬間にラベルが青く反転し、iOS では「コピー / 調べる」の吹き出しが出る。
§2 の長押しをメニューに使うなら、これが毎回かぶる。

`BOTTOM_BAR_CLASS` に `select-none` と `-webkit-touch-callout: none` を持たせる
(`src/components/ui.ts`)。

## 2. 長押しでスロットの値を直接選ぶ

表示モードは 小 → 大 → 画像、並び順は 更新順 → アクセス順 → 番号順 の 3 値循環で、
どちらも 1 スロットのトグルになっている ([31 §3-4](./31-下部操作バー計画.md)、
[37-アクセス順計画.md](./37-アクセス順計画.md))。狙った値まで 2 回押すことがあり、
そのたびにサーバへ行って一覧が組み直される。

長押し (PC は右クリック) で選択肢を出し、**循環を飛ばして直接選べる**ようにする。
短いタップの循環は今までどおり残す — 長押しは近道であって、置き換えではない。

判定は `src/lib/longPress.ts` と `src/components/useLongPress.ts` に分ける。
閾値だけを lib に置くのは、jsdom を持たないこの土台 (`vitest.config.ts` の
`environment: 'node'`) でも検査できるようにするため。

- 待ち時間 0.5 秒。iOS の触覚メニューに合わせる。
- 指が 10px を超えて動いたら取り消す。バーの上をかすめるスクロールで
  メニューが出ては使い物にならない。
- 長押しが成立したら、放したときの `click` を握り潰す。スロットは submit
  ボタンなので、握り潰さないと「メニューを出したのにモードも変わっていた」になる。
- `contextmenu` は常に止める。Android の長押しと PC の右クリックで出る
  ブラウザ既定のメニューがこちらに重なるため。止めたうえで、右クリックは
  メニューを開く合図として使う。
- **`contextmenu` はタイマーより先に来ることがある** (Android Chrome)。
  こちらは `contextmenu` でタイマーを畳むので、先を越されるとタイマーは
  もう「長押しが成立した」印を立てられない。放した指の `click` がただの
  タップと見なされ、開いたばかりのメニューをその場で閉じていた
  (長押しが効かないように見える)。**印を立てるかは「まだ押している最中か」**
  で決める — 押している最中なら指を離した `click` が続くので握り潰し、
  押していない (PC の右クリック) なら続く `click` は無いので握り潰さない。
  右クリックで印を立てたままにすると、次の Enter / Space や読み上げソフト
  からの実行を食べてしまい、押しても何も起きないボタンになる。
- **`pointerleave` は「押している最中」だけ取り消しに使う**。タッチの
  ポインタは `pointerdown` で押した要素に暗黙に捕まるので、指が枠の外へ
  出ても leave は来ず、代わりに **`pointerup` の直後・互換 `click` の前**に
  後始末として飛んでくる。素通しで印を倒すと、続く `click` が握り潰されずに
  スロット本来の送信として通り、開いたばかりのメニューがその場で閉じる —
  スマホで長押しメニューが一瞬光って消える形で出た。押している最中かは
  押した点 (`start`) の有無で判る (`pointerup` が畳むので、後始末として来た
  leave では既に空)。検索結果の行 (docs/66) が `onPointerLeave` を繋がないのと
  同じ事情で、あちらは繋がない・こちらは条件を付ける、と対処だけが違っていた。

## 3. メニューの出し方

`src/components/SlotMenu.tsx`。押したスロットの真上に、選択肢だけを縦に並べる。

- **`absolute` で出す。`fixed` は使えない。** バーは `backdrop-blur` を持ち、
  `backdrop-filter` のある要素は `position: fixed` の包含ブロックになるので、
  `fixed` の `inset` がバーの矩形を指す ([11 §8-4](./11-アプリ的UIUX計画.md) と
  同じ罠)。
- **位置決めと動きは別の要素に分ける。** 中央寄せの `-translate-x-1/2` は
  Tailwind v4 では `translate` プロパティで出る。せり上がりの `sheet-up` も
  `translate` を `animation-fill-mode: both` で動かすため、同じ要素に置くと
  終了後もアニメーション側の `translate: 0 0` が残り、中央寄せが消える。
  実際それで、右寄りの並び順メニューが画面外へはみ出して文字が切れていた。
- 外側タップ用の覆いは置かない。覆いは全画面を覆う `fixed` が要るが上の理由で
  中に置けず、portal で body へ出すと今度は覆いがメニューより上に来る。
  3 行のメニューに背面の暗転は要らないので、`document` の `pointerdown` を
  capture で拾うだけにする (`click` では iOS Safari で取りこぼす)。
- **行を選んだとき、その場でメニューを閉じてはいけない。** 行はフォームの
  submit ボタンで、送信はクリックの既定動作として後から走る。`onClick` で
  閉じるとボタンが DOM から外れ、form owner を失った submit ボタンは何もしない
  — メニューで選んでも表示モードが変わらない、という形で出る。
  `setTimeout(…, 0)` で送信が起動した後に閉じる。microtask では早すぎる。

現在値には ✓ を付けるだけで、行の背景は塗らない。3 行のうち 1 行が塗られていると
「選ばれている」ではなく「押せる主ボタン」に見える。

## 3-1. 選んだ結果は送信の完了を待たずに見せる

「長押しで選ぶとタップの循環より遅い」という声から調べたところ、**往復そのものは
同じだった** — どちらも同じフォームの `POST` 1 回で、実測でも 68〜210ms の範囲に
収まる。違うのは待っている間に画面が何を返すかで、

- タップは指の下でスロットが押下反転するので、往復のあいだも手応えがある。
- 長押しの経路は**選んだ瞬間にメニューが消えるだけ**。スロットは古い値のまま
  動かず、一覧が組み直されるまで何も起きない時間がむき出しになる。

さらに長押しには判定の 0.5 秒 (§2) とメニューがせり上がる 0.2 秒 (§3) が
先に乗るので、合計の体感は 1.5 秒ほどになる。ここを縮める余地は待ち時間ではなく
**「選んだ後の無反応」**のほうにあった。

そこで `CycleSlot` (`src/components/CycleSlot.tsx`) を切り出し、送信中は
**送った先の値を先に見せる**。ラベル・アイコン・`aria-label`・次に押したときの
送信値まで、すべて「表示している値」から引く。

- **`useFormStatus` で送信中の `FormData` を覗く。`useOptimistic` は使わない。**
  `useOptimistic` は `action` をクライアント関数で包む必要があり、包んだ時点で
  フォームはネイティブ送信できなくなる — §2 から通してきた「JS 無効でも
  切り替わる」(`action` は素のサーバアクションのまま) が崩れる。`useFormStatus`
  なら form の中から状態を読むだけで、`action` に触らない。
- この手はフォームの**中**の部品でしか使えないので、ボタンごと切り出してある。
- 循環の次は現在値ではなく**表示している値**から引く。現在値から引くと、往復の
  あいだに続けて押したとき同じ値をもう一度送ることになる。
- 送信中はアイコンだけ薄くする (`SlotIcon` の `busy`)。ラベルが先に切り替わる
  以上、「まだ一覧は組み直されていない」と伝えるものが他に無くなるため。
  薄めるのをアイコンに限るのは、ラベルは読む情報だから。`transition-opacity` を
  掛けてあるので、往復が 50ms で終わる場面では薄まりきる前に戻る (点滅しない)。

メニューのせり上がり (`sheet-up`) は 0.2 秒のままにする。ハンバーガーメニューの
ボトムシートと同じユーティリティで、あちらは大きく動くぶん 0.2 秒が要る。

## 4. 新規ノートの ＋

文字の `+` はフォントごとに字面の中の上下位置が違い、中央寄せしても中央に
見えなかった (行ボックスの中でベースラインに載るため)。`PlusIcon` (svg) に
置き換えると viewBox の中心がそのまま図形の中心になる。

色は緑 (`text-emerald-600`)。「足す」の合図であり、隣の検索ボタン (青い主ボタン) と
役割が違うことを色で分ける — 同じ青で並べると 2 つの正方形が同じ物に見える。

## 5. 「検索」を虫眼鏡にする

打つそばから検索するので普段は押さないボタンだが、JS 無効時の唯一の検索手段
として残してある。窓の中身が何か、隣に何があるかから用途は明らかなので、
文字 2 文字ぶんは入力欄の幅に回す。意味は `aria-label` / `title` で補う。

## 6. 検索語を消す ✕ をスマホでも出す

`type="search"` の標準の消去ボタンは Windows の Chrome/Edge にはあるが、
iOS Safari と Android Chrome には無い。スマホだけ長い検索語を 1 文字ずつ
消す羽目になっていた。

自前の ✕ を入力欄の右端に重ね、標準側は
`[&::-webkit-search-cancel-button]:hidden` で常に隠す (隠さないと Windows で
✕ が 2 つ並ぶ)。窓が空のときは出さない。押した瞬間に `blur` して候補が
閉じないよう、`mousedown` で `preventDefault` する (★/☆ と同じ手)。

## 7. ノートのタグは 1 行

タグを 10 個も付けたノートでは、折り返した帯が 3 行 4 行と縦に伸びて本文を
画面の下へ押し出していた。タグは本文を読みに来た人にとって脇の情報なので、
縦は 1 行に固定して横スクロールにする (`ItemTags`)。

スクロールバーは隠さない。隠すと PC で「まだ右にある」合図が一切なくなる
(スマホは指で弾けば判るが、マウスでは判らない)。

## 8. 「非公開」に説明を添えない

非公開はこのアプリの既定の状態で、ノートを開くたびに
「ログインした人だけが見られます。」を読まされる値打ちはない。

公開中の側の文は残す。あちらは事故ると取り返しがつかない (見た人の手元からは
消せない) ので、そこだけは毎回言う ([22-ノート公開計画.md](./22-ノート公開計画.md) §7)。
