# OCR 切替と全画像 OCR 計画

計画日: 2026-10-17 / 状態: **v0.23.27 で本番配布済み・iPhone 実機確認済み (2026-10-17)**

画像を入れるたびに OCR が走るのを止められるようにし、止めて入れた画像や
昔の画像を後からまとめて OCR できるようにする。OCR そのものの仕組みは
docs/24-画像OCR計画.md。

想定する使い方は 2 つ。

- イラスト: 新規ノート → 「OCR しない」 → 画像をドロップ → 更新
- 後から読む: 画像のあるノートを開く → OCR → 「ノートの全画像」 → 更新

## 1. 切替 (OCR する / しない)

- 下部バーの帯の末尾、「装飾表示」の隣にトグル釦を置く。文字は**いまの状態**を
  言う (「OCR する」「OCR しない」)。装飾表示は「押すと何が起きるか」を言うが、
  こちらは入れる前に「読まれるか」が判ることのほうが大事で、aria-pressed とも
  向きが揃う
- **端末単位で覚える** (`lib/prefs/ocrOnInsert.ts`、localStorage の
  `qr-search:ocr-on-insert`)。イラストは Windows、部品の写真は iPhone と
  端末で使い分けることが多い。既定は ON で、触らなければ今までと同じ
- 効き先は `insertFiles` の既定値 1 か所。ドロップ・貼り付け・ファイル選択・
  クリップボード・スキャンのすべてに効く。お絵かきは明示で `ocr: false` のまま
- ペースト・ドロップの拡張は一度しか組まないので、設定は useLatest の ref で渡す
- 切り替えても、いま走っている OCR は止めない。次に入れる画像から効く

## 2. ノートの全画像を OCR

- 下部バーの OCR 釦を 2 項目のメニューにした (`OcrMenuButton`)。
  「この画像 (カーソルの近く)」は従来の後から OCR。「ノートの全画像 (n 枚)」が新設
- **釦は帯の外 (書式の隣) に移した。** 帯は overflow-x-auto で、中に置いた
  メニューは切り取られる (書式で一度踏んだ罠)
- 対象は `imagesWithoutOcr` (`lib/ocr/ocrQuote.ts`)。自前画像のうち、記法の
  直後 (空行 0〜1 つの後) の行が `>` で始まらないもの。処理中のプレースホルダも
  `>` 始まりなので飛ぶ。外部画像・音声・PDF・テキストの添付は対象外
- 手で書いた普通の引用が画像の直後にあると「済み」に見える。その画像は
  「この画像」で読ませる
- **コードフェンスの中と、引用の中の画像は外す。** フェンスの中は記法の例で、
  引用を差すとコードが変わる。引用の中は直後に `>` の行が続くので済みと区別できず、
  差すと元の引用に混ざる。どちらも要るなら「この画像」で読ませる
- 1 枚ずつ直列に読む。**1 枚ごとに今の本文から次の対象を選び直す。**
  読んでいる間に本文が編集されると、最初に控えた位置はずれる。画像の取得も
  待たずに `ocrIntoDoc` へ Promise で渡す (待つ間の打鍵で位置がずれないように)
- 引用が付かなかった画像 (文字なし・取得失敗) は本文に残るので、選び直すと
  また対象に見える。**URL ごとに付かなかった回数を数え、その URL の先頭から
  その数だけ飛ばす。** URL の集合で飛ばすと、同じ画像を 2 か所に貼ったノートで
  2 か所目を読まない
- 進み具合の全体数は「読み終えた数 + 今の本文に残る対象」で毎回数え直す。
  走っている間に画像を足すと増える
- **OCR そのもの (モデルの読み込みなど) が失敗したら残りを読まない。** 次の画像でも
  同じ所で落ちる。画像の取得の失敗は 1 枚だけのことなので、知らせて次へ進む
- 編集画面を離れたら残りを捨てる。続けると、離脱で落とした Worker を次の 1 枚が
  また立ち上げる
- 二重起動の門番は ref で持つ。state だと続けて 2 回押したとき両方が通る
- 走っている間は OCR 釦が「中止 済/全」になる。押すと、読んでいる 1 枚は最後まで
  読み、残りを捨てる。止める手段がメニューの奥にあると、数十枚のノートで待たされる。
  押した後は読み終えるまで「中止中…」で押せなくする (変わらないと壊れて見える)
- 走っている間は「更新」を止める。1 枚の合間 (次の画像の取得中) は OCR の本数が
  0 に戻るので、本数だけを見ていると隙間で保存が通る

## 3. 見送り

- 読み直し (済みの引用を消して読み直す)。引用を手で消してから全画像を押せば済む
- ノート単位の設定。端末単位で足りる
- 一覧からの一括 OCR (docs/24 §8 の「Node 側の一括 OCR」も見送りのまま)
- メニューの「(n 枚)」は開いた時点の数で、開いたまま画像を足しても変わらない。
  開き直せば数え直す (レビューの指摘。見送りで了承済み)

## 4. テスト

- 単体: `lib/prefs/ocrOnInsert.test.ts`、`lib/ocr/ocrQuote.test.ts`
  (`imagesWithoutOcr` の境界 9 件)、`components/editor/EditToolbar.test.tsx`
  (OCR 釦が帯の外・中止と中止中の表示・切替の文字と押下状態)
- E2E: `e2e/ocr-toggle.spec.ts`。既定で落とすとプレースホルダが入る、
  「OCR しない」は開き直しても残り落としても読まない、全画像のメニューが
  未読の画像だけを数える、の 3 本。OCR は走らせない (モデルが重い)
- 全画像 OCR の実行は、文字入りの PNG を route で配る一時的な E2E で実モデルを
  走らせて確かめた (2026-10-17)。済みを飛ばす・同じ画像の 2 か所目も読む・
  フェンスの中は読まない・中止で読んでいる 1 枚の後が止まる。モデルの読み込みが
  重いので常設の E2E にはしていない
- iPhone 実機で、画像の多いノートの全画像 OCR を途中で離れても落ちないことを
  確かめた (2026-10-17)
