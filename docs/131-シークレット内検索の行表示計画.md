# 131. シークレット内検索の行表示計画

<!-- markdownlint-disable MD013 -->

シークレット内検索 (docs/130) で一致したノートを、黄色い枠の中の文字の行ではなく、
**通常の検索一覧と同じ行**として出す。シークレット内の一致は一覧の先頭に置く。
行の材料は検索語に関係なく先に取り、行にはサムネを出さない。一致したノートがサーバに見えない線
(docs/130 §1) を保つ。

## 0. 現状 (2026-11-20)

実装済み (§9 の 1〜8)。計画から変わった点は下の 4 つ。

| 項目 | 今 |
| --- | --- |
| 状態 | 実装済み。単体・口・E2E (専用 DB + 仮想認証器) で確認。本番ビルドでも E2E を通した |
| 残り | iPhone 実機の確認・§8 の残り |

計画から変わった点:

- **一致の行にはサムネを出さない** (§2)。当初は「ON のときにサムネを全部先に取る」計画で
  実装まで進めたが、レビューで先取りでは塞ぎ切れないと分かり、やめた。理由は §2 の表
- それに伴い、口の応答に回路図サムネは足さない (§4-1)。先取りの部品も無い
- **画像表示では行にしない** (§8)。タイルは画像そのものなので、画像を抜くと何も残らない。
  画像表示では今までどおり黄色い枠に文字の行で出す
- **ノートの控え (`noteStore`) には入れない** (§4-2)。行を押したときに取り直すが、
  それは利用者が押した結果で、今までと同じ
- **書き込みの後は取り直す** (§6)。書き込みの後始末 (`client/invalidate.ts`) と
  断片の保存 (`secret/content.ts`) が合図を出し、入っている間だけ材料を取り直す。
  docs/130 §11 の「編集したら入れ直し」もこれで要らなくなった

主なコード:

- `src/lib/secret/search.ts` — `secretRowLabels`・`mergeSecretRows` (純関数)
- `src/lib/secret/textIndex.ts`・`src/app/api/secret-texts/route.ts` — 応答にノート
- `src/lib/secret/searchSession.ts` — ノートの写しの保持と、書き込みの後の取り直し
- `src/components/search/useSecretRows.ts` — 描く直前に混ぜる (`useShownRows`)
- `src/components/item/itemListParts.tsx` — 行の印 (`SecretRowBadge`) と、顔を出さない指定 (`hideFace`)

実装前の状態 (経緯):

- 一致は検索欄の下の黄色い枠 (`SecretSearchHits.tsx`) に、題名とラベルだけの行で出ていた。
  サムネ・プレビュー・タグ・表示モード (小・中・大・画像)・行の操作 (⋮) は無かった
- 黄色い枠が持つ材料は、断片の一覧の `itemId`・`title`・`label` だけだった (docs/130 §5-1)
- 通常の一覧は `ResultsItemList` → `ItemList` が描く。`ItemList` は受け取った `items` を
  並べるだけで、件数・続き・空の枠は外 (`ResultsSummaryRow`・`Continuation`) が
  サーバの値 (`ListValue`) から決める
- 選択モードの「選んだノート」は `ItemList` の中に持つ (`useItemListSelection`)。
  `ItemList` を 2 つ置くと、選択と一括操作の帯が 2 組になる

## 1. やりたいこと

| 項目 | 決めたこと |
| --- | --- |
| 出す場所 | 通常の一覧の**先頭**。シークレット内の一致 → 通常の一致、の順 |
| 行の見た目 | 通常の行と同じ (題名・タグ・本文の抜粋・⋮)。表示モード (小・中・大) にも従う。**サムネだけは出さない** (§2) |
| 見分け | 行に「🔒 ラベル」の印を付ける。一覧の上に「🔒 シークレット内 n 件」と件数を出す |
| 重複 | 同じノートが通常の一致にもあれば、先頭に 1 回だけ出す (下からは外す) |
| 並び順の設定 | 足さない。ON の間は常にシークレット内が先 |
| 中身の抜粋 | 今までどおり出さない (docs/130 §3-2) |

## 2. 守る線

docs/130 §1 の線をそのまま守る。行として出すことで増える漏れ口は 2 つある。

| 漏れ口 | 何が見えるか | 手当て |
| --- | --- | --- |
| 行の材料の取得 | 一致したノートだけを取ると、「この検索語の直後にこのノートを取った」がログに並ぶ | ON にしたとき、シークレットを含むノートを**全部**取る (§4)。照合の後は通信しない |
| 行のサムネ | 行が出た瞬間に、そのノートの画像 (`/api/images/…`・回路図の SVG) を取りに行く。一致したノートの画像だけが、検索語の直後に要求される | **一致の行にはサムネを出さない** (`ItemRow` の `hideFace`) |

サムネは「ON のときに全部先に取って端末に置く」手を先に試した。次の抜け道があり、塞ぎ切れない。

| 抜け道 | 中身 |
| --- | --- |
| 404 は端末に残らない | 動くサムネが未生成の動画は 404 で返る。Service Worker の棚に入るのは 200 だけなので、行が出るたびに取りに行く |
| 棚から押し出される | 添付の棚は 600 件で古い順に捨てる。通常の閲覧が多いと、先に取った分が消える |
| 棚を通らない物がある | 回路図の SVG は Service Worker を通らず、ブラウザの HTTP キャッシュだけが頼り |
| 画像ビューアの先読み | 行のサムネは画像ビューアの入口になる。近くの画像を開くと、前後の画像として一致の行の**原寸**まで先読みされる |
| プレビューの中の画像 | 行の顔が本文の縮小プレビューのとき、その中の画像は行のサムネと別の経路で取られる |

行から顔を外せば、行が出ても画像の通信は起きない。画像ビューアの入口も無くなる。
見た目は「サムネの無い通常の行」になる。

一致の行を押してノートを開けば、どのノートを開いたかはサーバに見える (アクセス日時の記録)。
これは今までと同じで、押すという利用者の操作の結果なので受け入れる。

## 3. 方式 — 描く直前に混ぜる

**`ItemList` は 1 つのまま、渡す `items` を描く直前に組む。** 一覧の控え (`listStore`) には
入れない。

```text
描く items = [シークレット内の一致のノート…, 通常の一致 (重複を除く)…]
```

| 案 | 中身 | 判断 |
| --- | --- | --- |
| A. 描く直前に混ぜる | `ResultsItemList` で 2 つの配列をつなぎ、1 つの `ItemList` に渡す | **採る** |
| B. `ItemList` を 2 つ置く | シークレットの束と通常の束を別の `ItemList` で描く | 採らない。選択と一括操作の帯が 2 組になる (§0) |
| C. `listStore` に入れる | 控えの配列そのものに足す | 採らない。件数・続き・空の枠がずれる。控えは端末に 30 日残り、一致したノートが書かれる (docs/129) |

A なら、件数・続きの読み込み・空の枠・端末の控えはサーバの値のまま動き、触らずに済む。
選択・スワイプ・画像モード・画像ビューアは `ItemList` の中の話なので、混ぜた配列でそのまま効く。

## 4. データの流れ

```text
トグル ON
  → GET /api/secret-texts      断片の一覧 + シークレットを含むノート (全件)
  → 暗号文を取って復号 (docs/130 §5)
検索語を打つたび
  → 端末で照合 → 一致した断片 → 参照元ノートの id
  → 先に取ってあるノートから行を組み、通常の一致の前に置く (通信なし)
```

### 4-1. 口の応答に足すもの

`GET /api/secret-texts` の応答に 1 つ足す。口はいまもこのノートの本文を読んで参照元を
引いている (`textIndex.ts`) ので、読む行は増えない。

| 足すもの | 中身 |
| --- | --- |
| `items` | シークレットを含む、ゴミ箱でないノート。通常の一覧と同じ形 (`ItemDto`) |

- **テキスト断片を持たないノートも含める** (画像だけの断片のノート)。含めても害は無く、
  「テキスト断片を持つノートはどれか」を応答の形から読み取らせない
- 検索語は今までどおり受け取らない
- 応答が太る分は小さい。シークレットを含むノートは少なく、本文は 1 件 32,000 字が上限

### 4-2. 端末で持つもの

| 置き場 | 中身 |
| --- | --- |
| `searchSession.ts` の state | 断片の一覧・平文に加えて、ノート (`Item`)。トグル OFF・施錠で捨てる |
| ノートの控え (`noteStore`) | **入れない**。行を押したときは今までどおり取りに行く (押した結果なので、サーバに見えてよい) |
| IndexedDB | **足さない**。ノートは ON のたびに取り直す (暗号文と違い、差分を見る手がかりが無い) |

## 5. 画面

```text
[🔒 シークレット内 2 件]                      ← 黄色い枠は見出しだけに縮める
「口座」の検索結果: 5 件   [表示] [並び順] [選択]
┌──────────────────────────────┐
│ 銀行まとめ            🔒 口座      │ ← シークレット内の一致 (通常と同じ行 + 印)
│ 水道申請              🔒 シークレット │
├──────────────────────────────┤
│ (通常の一致の行…)                  │
└──────────────────────────────┘
```

| 項目 | 決めたこと |
| --- | --- |
| 黄色い枠 | 見出し (件数・対象外の断り・施錠で切れた断り) だけを残す。行は一覧へ移す |
| 行の印 | 行の下の補助行に「🔒 ラベル」(`ItemRow` の `footer`)。同じノートの断片が複数当たったら、ラベルを「・」で並べる |
| 件数の行 | 「n 件」はサーバの値のまま (通常の一致の件数)。シークレットの件数は黄色い枠が言う |
| 0 件の案内 | 通常が 0 件でもシークレットの一致があれば、「該当する部品がありません」を出さない |
| 一覧がまだ無いとき | 通常の検索が読み込み中・失敗でも、シークレットの一致の行は出す (docs/130 §3-2 と同じ) |
| モジュールの表示 | カレンダーなどでは行にできない。今までどおり黄色い枠に文字の行で出す |

行の印は `RowContext` (`itemListParts.tsx`) に「itemId → ラベルの配列」を足して渡す。
`ItemList` は印の有無で並べ方を変えない (並びは渡された `items` の順)。

## 6. 効かないもの・変わるもの

| 項目 | どうなるか |
| --- | --- |
| 開いた先の「前へ・次へ」 | サーバの検索結果の順をたどる。通常の一致に無いノートは前後が出ない (今と同じ) |
| スライドショー | 通常の一致の中だけを送る。シークレットの一致の行は含めない |
| 続きの読み込み・空の枠 | サーバの件数で動く。先頭に足した行の分はずれない (`ItemList` の外で決まる) |
| 一括操作 | 混ぜた行も選べる。タグ・ゴミ箱・オフラインの印はノートの id で動くので効く |
| 書き込みの後 | シークレット側のノートは ON のときの写しなので、書き込みの合図で取り直す (`requestSecretSearchReload`)。取り直しに失敗しても切らず、前の写しのまま探せる |
| リンクの検索語 | 通常の行と同じく、検索語を載せた URL で開く。当初は外していたが (v0.23.158)、行を押した瞬間に検索窓が空になり一覧が全件へ戻る不具合になったので戻した。語は通常の検索で既にサーバへ届いており、押すのは利用者の操作なので、増える漏れは無い |

## 7. テスト

| 種類 | 見ること |
| --- | --- |
| 単体 | 混ぜる純関数 (先頭に置く・重複を除く・順を保つ)。ラベルの集約。口の応答の検算 |
| API | 応答にノートと回路図サムネが載る。ゴミ箱のノートは載らない。検索語を受け取らない |
| 部品 | 行に印が出る。一致の行は画像も回路図も出さない (`<img>` が無い)。印の無い行は今までと同じ HTML |
| E2E | 専用 DB と仮想認証器 (`e2e/secrets.spec.ts`)。ON → 一致が一覧の先頭に行で出る → OFF で消える |
| 漏れの確認 | ON にした後の検索で `/api/secret`・`/api/images/`・`/api/circuits/`・`/item/` への要求が出ないことを E2E が見る (`e2e/secrets.spec.ts`)。**本番ビルドでも流す** — 先読みは `next dev` では起きない (docs/130 のレビューで見つかった穴と同じ種類) |

## 8. 決めたこと・残り

| 項目 | 結論 |
| --- | --- |
| 行のサムネ | 出さない (§2) |
| 画像モードの扱い | 行にしない。黄色い枠に文字の行で出す (§0) |
| 書き込みの後の取り直し | 書き込みの後始末と断片の保存が合図を出す (§6) |
| 印の置き場所 | 行の下の補助行 (§5) |

残り:

- 一致の行にサムネを出す。端末に確かに残っている画像だけを、通信なしで出す仕組み
  (専用の棚に置き、棚に無ければ出さない) が要る
- 画像表示でもタイルとして出す (上と同じ仕組みが前提)

## 9. 作業の順

1. 混ぜる純関数とテスト (`secret/search.ts` に足す)
2. `GET /api/secret-texts` にノートを足す。端末側の検算と state
3. `ResultsItemList` で混ぜる。0 件の案内・一覧がまだ無いときの出し方
4. 行の印 (`RowContext`) と、その行だけ検索語を付けない URL
5. ~~サムネの先取り~~ → 一致の行にはサムネを出さない (§2)
6. 黄色い枠を見出しだけに縮める (モジュールの表示では今の行を残す)
7. E2E と、本番ビルドでの漏れの確認
8. docs/130 §3-2・§10 を直す

口とシークレットの state に触れるので、コミット前に security-reviewer を通す。
