# CBT 風問題集をノートで解けるようにする計画

電験三種 理論「過渡現象」の問題集 (9 問: 易 3・普通 3・難 3) を、ノートの markdown
タブ上で実際の試験 (CBT) と同じ**五肢択一・押して採点・解説表示**で解けるように
する。普通 3 問が本試験の標準レベルになるように較正する。

機能 (§1〜§4) とコンテンツ (§5) の二部構成。機能は問題集に依存しない汎用の
記法として作る (単語帳と同じで、他の科目・資格にもそのまま使える)。

## 1. 方針 — 図と同じ「特別なフェンス」を増やす

`mermaid` / `circuitikz` と同じ作法で ```` ```quiz ```` フェンスを足す。
描画の差し替え点は [MarkdownView.tsx](../src/components/MarkdownView.tsx) の
`preOrDiagram` の分岐 1 つ。

- **正本はメモ本文。** 問題・正解・解説はすべてフェンス内のテキストで、専用の
  DB テーブルや API は作らない (タグ・チェックボックスと同じ考え方)。
- **回路図は既存の ```` ```circuitikz ```` を quiz フェンスの直前に置く。**
  quiz フェンスの中に回路図を埋め込む案は採らない —
  [circuitFences](../src/lib/circuitFences.ts) の走査はフェンス言語を見ており、
  入れ子にすると走査とキャッシュの両方に手が入る。並べるだけで見た目は足りる。

## 2. 記法

行頭キーワードで区切る行指向の形式にする。YAML/JSON にしないのは iPhone で
手打ちするから ([メモ記法.md](メモ記法.md) の他の記法と同じ温度感)。

````text
```quiz
問: 図の回路でスイッチ S を閉じた直後に流れる電流 $i_0$ [A] は。
1. $0$
2. $\dfrac{E}{R_1}$
3. $\dfrac{E}{R_2}$
4. $\dfrac{E}{R_1+R_2}$
5. $\dfrac{E R_2}{R_1 R_2}$
正解: 2
解説: 投入直後のコンデンサは短絡とみなせるので、回路は $E$ と $R_1$ だけの
直列になり…
```
````

- 問・選択肢・解説の中身は本文と同じ markdown + 数式 (`$...$`, KaTeX) で書ける。
  描くのは [QuizMarkdown.tsx](../src/components/quiz/QuizMarkdown.tsx) —
  MarkdownView をそのまま入れ子にすると循環参照になり、枠も二重に見えるため、
  **サニタイズ規則と URL の通し方だけを共有する**
  ([markdownPipeline.ts](../src/components/markdownPipeline.ts) に切り出し)。
  ここだけ緩い規則を持つと本文では通らない書き方がフェンス内で通る穴になる。
- **選択肢は 2〜9 個**。計画当初は五肢択一に固定するつもりだったが、§1 の
  「汎用の記法」に反する (4 択の試験もある) ので幅を持たせた。番号は 1 からの
  連番で、飛んでいる番号は選択肢の始まりと見ない — 問題文中の番号付きリストを
  選択肢と読み違えないための歯止めでもある。
- **`解説:` は省略できる。** 単語帳のような軽い出題では要らない
  (`問:` `選択肢` `正解:` は必須)。
- 形式エラー (選択肢が足りない・正解番号が範囲外・欠落・重複) は
  [CircuitDiagram.tsx](../src/components/CircuitDiagram.tsx) と同じ作法で
  「何が悪いか + 元ソース」を表示する。黙ってコードブロックに落とさない。
  `正解:` の後ろに宙に浮いた行があるとき (「解説」の打ち間違い) も知らせる。
- [fenceLanguages.ts](../src/lib/fenceLanguages.ts) の `RENDERED_LANGS` にも
  足し、打ち間違い (`quis` 等) を linter が警告するようにする。補完
  (`FENCE_LANGUAGES`) にも足す。

## 3. 動作 (CBT の再現)

- 選択肢 (1)〜(5) をボタンにする。押すと正誤 (○/×)・正解番号・解説が開く。
  **解答前は正解と解説を隠す** (ここが CBT らしさの本体)。
- 正誤は色だけで伝えない。○ / × の記号も添える (色覚・白黒印刷で消えるため)。
- 「やり直す」ボタンで未解答に戻す。
- 解答状態は React state だけで持ち、**保存しない**。単語帳のチェックボックス
  (docs/55) と違い、演習は毎回まっさらから解き直すものだから。
- 保存が無いので `allowRotate` のような許可 prop は要らず、公開ビュー・印刷でも
  同じ描画でよい。印刷では押せないだけ (問題文と選択肢は紙でも成立する)。
- **問題文と選択肢はサーバでも描く。** カード (client 部品) には描画済みの
  ReactNode を渡す — シークレット断片のような動的 import + `ssr: false` に
  すると、JS を待つ間と印刷で問題そのものが消えてしまう。

## 4. 実装ステップ (TDD)

1. `src/lib/quizParse.ts` — フェンス本文 → 問・選択肢・正解・解説 (または
   エラー)。テスト先行: 正常系 / 選択肢数の過不足 / 正解番号の範囲 /
   フィールド欠落 / 複数行の問題文・解説。
2. `src/components/quiz/` — `QuizFence` (解いて描く) + `QuizCard` (押したときの
   出し分け) + `QuizMarkdown` (中身の markdown)。
3. `fenceLanguages.ts` に `QUIZ_LANG` を追加し、`MarkdownView` に分岐を足す。
   [メモ記法.md](メモ記法.md) に記法を追記。
4. /code-review → デモではなく本番ノートに貼って iPhone 実機で確認。

### レビューで直した「黙って壊れる」もの

- **番号を振り間違えた選択肢を吸い込まない。** `1. / 2. / 4.` と書くと、
  以前は `4.` が選択肢 2 の続きとして黙って吸い込まれ、3 択のはずが 2 択の
  「解ける問題」として成立してしまった (正解番号が生き残った範囲内なら
  誰も気付けない)。選択肢を並べている**途中**の番号付きらしい行は、番号が
  合わなければエラーにする。問題文の中の番号付きリストは今までどおり通す。
- **`正解:` は番号 1 つだけ。** 先頭の数字だけ拾う実装だと `正解: 1と3` が
  黙って `1` になる。余分な文字が残るならエラー。
- **選択肢の中のブロック要素を落とす。** `<button>` に入れられるのは
  phrasing content だけで、とくに GFM のタスクリストは `<input>` を生んで
  「押せるものの入れ子」になる。`disallowedElements` + `unwrapDisallowed` で
  中身の文字だけ残す。
- **カード内のリンクも本文と同じ `rel="noreferrer"` + 別タブ。**
  入れ子だけ素の `<a>` だと、参照元 (ノートの URL) が外部サイトへ漏れる。
  サニタイズ規則と一緒にリンクの描き方も markdownPipeline へ寄せた。

### テストの届く範囲

このリポジトリのコンポーネントテストは `renderToStaticMarkup` した HTML を
見る作法 (jsdom も testing-library も入れていない) なので、**押した後の
出し分けは自動テストでは踏めない**。そこは純関数 (`choiceClassOf` / `markOf`)
と parser 側に寄せ、カードのテストは未解答の初期表示 —
「問題文と選択肢が出る」「正解と解説が出ていない」— に絞っている。
押した後の見た目は実機確認で担保する。

## 5. 問題集の中身 (電験三種 理論・過渡現象)

### 出題マトリクス

| 難易度 | 問 | テーマ |
| --- | --- | --- |
| 易 | 1 | RC 回路: 投入直後と定常状態の電流 (C = 短絡→開放の基本性質) |
| 易 | 2 | RL 回路: 時定数 $\tau = L/R$ の計算と物理的意味 |
| 易 | 3 | 定常状態の各部電圧 (コイル短絡・コンデンサ開放) |
| 普 | 4 | 抵抗 2 個 + C: 投入直後と十分時間後の電流の組合せ (定番形式) |
| 普 | 5 | RL 回路の電流波形グラフ選択 (63.2% 到達・初期傾き・漸近値) |
| 普 | 6 | スイッチ切替による充電→放電 (切替前後で時定数が変わる) |
| 難 | 7 | 2 段階スイッチ切替の再過渡 (B 問題 (a)(b) 形式) |
| 難 | 8 | RL と RC の混在回路: 直後・定常・エネルギー (B 問題形式) |
| 難 | 9 | 充電済みコンデンサの並列接続: 電荷保存とエネルギー収支 |

### 作り方

- 1 ノートに 9 問。各問は「`circuitikz` の回路図 + `quiz`」のフェンスの組で書く。
  B 問題形式は共通の回路図 1 つの後に quiz フェンスを (a)(b) の 2 個並べる。
- 難易度較正: 直近数年分の過去問 (令和期) と突き合わせ、普通 3 問を本試験の
  標準 A 問題 (正答率 50〜70% 帯) に合わせる。
- 誤答肢は当てずっぽうで絞れないよう、典型ミスから逆算して作る:
  τ の取り違え (RC ↔ L/R)・直後と定常の逆転・係数落ち・分母分子の入れ替え。
- 全問の数値解は使い捨ての検算スクリプト (scratchpad、コミットしない) で
  解析解 $e^{-t/\tau}$ を計算して照合する。偶然正答と同値になる誤答肢が
  無いこともここで確かめる。
- **問題集の原稿はこのリポジトリに入れない** (公開リポジトリのため)。
  ワークスペース側の `docs-ignore/` に原稿を置き、ノートへ貼って使う。

## 6. 今回やらないこと (後段候補)

- **成績集計 (9 問中 N 問正解)** — ノート内の quiz を横断する context が要る。
  まず 1 問ずつの採点で使ってみてから。
- **制限時間タイマー** — CBT の再現度は上がるが、ノートは中断・再開が前提。
- **解答履歴の保存** — 保存するなら正本 (本文) に刻む方式 (docs/55 の作法) に
  なるが、演習は解き直すものなので当面不要。
- **選択肢のシャッフル** — 解説が「(2) が正解」と番号で書けなくなる。
