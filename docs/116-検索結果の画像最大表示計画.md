# 検索結果の画像最大表示計画 (画像ビューア)

検索結果の画像を押したら、その画像を大きく見せる。3 / 2 ペインでは
ノートのペインの場所に画像だけを出し、**縦が全部ペインに収まる**ように縮める。
1 ペインでは画面全体の覆いに出す。どちらも ← → で一覧の前後の画像へ送れる。

決めたこと (2026-10-26):

- 画像を押したら画像、題とタグの行を押したらノート。当たり判定を分ける
- 2 / 3 ペインでは**ノートではなく画像だけ**をペインに出す (写真を探しながら
  見比べるのに、本文が挟まらないほうが速い)
- 画像表示のタイルだけでなく、**小・中・大表示の行のサムネ**も対象にする
- ← → (釦とキー) で前後へ送る。ノートをまたいで、一覧に並んでいる順に送る
- URL には載せない。再読み込みすればノートの表示に戻る

## 1. 当たり判定を分ける

タイル (ImageMasonry) も行 (ItemRow) も、題のリンクの `::after` を枠いっぱいに
広げた stretched link で、画像はその膜の下に居た。画像を
`ViewerImageButton` (relative z-10 の `<button>`) で包んで膜の上に出す。

- タイルの画像は**リンクの外**へ出した (`<a>` の中に `<button>` は置けない)。
  リンクに残るのは 1 行目 (#番号 タイトル) だけで、膜はそのまま枠いっぱい
- 行のサムネは画像の顔のときだけ包む。動画はノートを開いて再生するので
  今までどおり。選択モード中は行のどこを押しても選択にしたいので包まない
- provider の外 (オフライン一覧など) では素の画像のままで、押せばノートが開く
- 回路図のタイル・ノートのプレビューの顔は今までどおりノートを開く

### PC のホバーで出る近道の釦を退かせる

小・中表示では、ホバーで出るゴミ箱の釦 (RowActionButtons、⋮ の左) が
サムネの真上に重なっていた。小表示のサムネ (24px) は釦 (36px) にまるごと
隠れ、押そうとするとゴミ箱を押すことになる。押せるサムネ (ViewerImageButton)
に `data-row-thumb` の印を付け、印のある行では釦をサムネの左へ退かせる
(`group-has-[[data-row-thumb=…]]`)。押せないサムネ (動画・回路図・
プレビュー) には付けない — 退くと題の末尾に釦がかぶるだけになる。
カードはサムネが 96px あり角にかかるだけなので退かせない。
退き先の数値はサムネの寸法と組なので、寸法をテストで固定してある。

## 2. 出し方はペイン構成で決める

| 構成 | 出し方 |
| --- | --- |
| 1 ペイン・ゴミ箱 | 画面全体の覆い (`ModalOverlay variant="zoom"`) |
| 2 / 3 ペイン | ノートのペインの場所に `ImageViewerPane` |

覆いはどこを押しても閉じ、Esc でも閉じる。釦はコピーと「ノートを開く」。
ゴミ箱はノートのペインが無いので `ImageViewerProvider overlayOnly`。

## 3. ペインの中で縦を全部見せる

- 器はノートのペイン (PreviewPane) と**同じ `PANE_BOX_CLASS.pane`**。高さ
  (`--preview-pane-h`) も下端 (`--bottom-bar-h`) も同じ式なので、境界の
  ドラッグにもそのまま追随する。境界の帯はノートのペインの PaneResizer
  (z-20) がこの上に出ている
- body へ portal するので、同じ z-0 でも DOM 順でノートのペインの上に来る
- `data-preview-pane` (一覧の底上げ・フォルダーぶんの左寄せ) と
  `data-note-pane` (引っ張って更新を始めない) を付ける
- 中は縦の flex。操作行の下を `flex-1 min-h-0` の器にし、画像は
  `h-full w-full object-contain`。縦長でも横長でも絵の全体が器に収まり、
  小さい画像は器まで拡大する
- 原寸が届くまでは、一覧が読み込み済みのサムネを同じ位置に敷く (ViewerImage)。
  原寸を読めなければサムネのまま「原寸の画像を読み込めませんでした」と出す
- 下に隠れたノートのペインは `inert` にする (Tab で焦点が潜らない・読み上げに
  2 つの面が並ばない)
- 操作は右上に「ノートを開く」「全画面」「閉じる」、前後は画像の左右の中ほど。
  3 ペインの狭い画面ではペインが 170px ほどしか無いので、右上は折り返す
- Esc は持たない (docs/86 §2 の流儀)。覆いのときだけ Esc で閉じる

## 4. 前後へ送る

無限スクロールは読み込んだページごとに別の一覧を描くので、どれか 1 つの
一覧の props からは「次の 1 枚」が決まらない。押せる画像の釦に
`data-viewer-image` / `data-viewer-item` / `data-viewer-href` を付け、送る
瞬間に DOM の順で拾い直す (`neighborTarget`)。送った先は一覧の見える所まで
寄せ (`scrollIntoView({ block: "nearest" })`)、釦に outline の印を付ける。

- **次のページはビューアから直接頼む** (`requestLoadMore`。AutoLoadMore が
  window のイベントで受ける)。2 / 3 ペインの一覧は内側でスクロールする器の
  中にあり、IntersectionObserver の `rootMargin` は画面の縁にしか付かず器の
  切り取りには効かない。→ で末尾の画像まで寄せても「さらに表示」の目印が
  器の外に隠れたままで、**最後の画像で止まっていた** (v0.23.57 で報告)。
  残り 3 枚になったら先読みし、末尾で押されたら読み込みを待って
  (MutationObserver) 増えた画像へそのまま送る。読み込んだページに画像が
  無ければ、続きがある限りもう 1 ページ頼む
- 続きも尽きた端では止まる (回り込まない)
- 出している画像が一覧から消えた (3 ペインで検索語を打ち替えた) ときは、
  送る向きの端 (次なら先頭・前なら末尾) から出直す
- ← → キーを受けるのは、焦点が body か一覧 (`[data-search-results]`)・
  ビューア (`[data-image-viewer]`) の中にあるときだけ。メニューや検索パネル
  など矢印を自分で使う部品からは奪わない。入力欄と修飾キー付きも除く

## 5. 閉じる条件

- 「閉じる」・覆いを押す・Esc (覆いのみ)
- **利用者が選んだノートが変わったら捨てる** — 開いたときのノート
  (`openedFor`) と今のノートが違えば、描画中に state を null に戻す。
  見るのは横取りスロットのノート (`detailItemId`) だけで、3 ペインの
  自動の先頭ノートは数えない。自動のノートは一覧より遅れて届くことがあり、
  数えると届いた瞬間に開いたばかりの画像が閉じた (E2E で発覚)。
  隠すだけにすると、前のノートへ戻った瞬間に閉じたはずの画像が蘇る
  (レビューで発覚)。一覧の題を押した・「ノートを開く」で別のノートを開いた、が該当
- 「ノートを開く」で開くのが今のペインのノートと同じ場合は出ているノートが
  変わらないので、押した時点で自分から閉じる
