# 計測テスト自動化計画

速度計測ログ (docs/119) で前後を比べるには、PC と iPhone で同じ操作をして、
/logs?perf=1 の行をコピーして渡す必要があった。手で打つと速さが毎回違い、
iPhone からのコピーも手間がかかる。メニューから**決まった手順を自動で
流し**、行は**手元のスクリプトから取得鍵で読める**ようにする。

決めたこと (2026-10-28):

- 利用者の操作はメニューの「計測開始」を押すことだけにする。計測を立てて
  読み込み直し、ブラウザが検索 3 語 → ノートを開く → 同期を自分で流し、
  終わったら計測を止める (§1・§2)
- 計測中も「開始」を出す。PC で始めた後の 2 台目 (iPhone) が流せるように
- 行の取得は**読み取り専用の取得鍵**で行う。鍵は手元で作り、配布のたびに
  hash だけを本番へ揃える (§3-2)。利用者が鍵を受け渡す手間は無い。
  Claude は `scripts/fetchPerfLog.sh` で読む。ログインも ssh も使わない

初版は「開始 / 終了」の 2 つを押し、鍵は画面で発行して手元のファイルへ
貼る形だった。鍵の貼り付けで 2 度つまずいた (見本の文字列のまま保存・
隠し入力が空のまま進む) ので、同じ日に今の形へ改めた。

## 1. メニュー

`components/diag/PerfTestMenuItem.tsx`。ログインしていてデモでないときに、
ヘッダーメニューの「ログ」の下に出す。

- **計測開始**: 計測が止まっていれば `POST /api/logs/perf` で立て、流す印を
  sessionStorage に付けて `/` を読み込み直す。読み込み直すのは、ブラウザ側の
  観測が root layout の描画で決まるため (docs/119 §1-4)
- **計測停止**: 途中でやめるとき用。計測を止めて読み込み直す (計測中だけ出る)
- 印 (`lib/logging/perfTestFlag.ts`) はこのタブだけ。読んだら消すので、
  読み込み直しのたびに流れ直すことはない

## 2. 手順

`lib/logging/perfTest.ts` の `runPerfTest` が並びを持ち、DOM の手足は
`components/diag/PerfTestRunner.tsx` が組む (root layout が計測中だけ置く)。
12 段階で、PC は約 40 秒かかる。

1. 読み込み直した後 3 秒待つ (ページの残りと起動時の同期)
2. `[計測] テスト 結果=開始 panes=… 幅=…` を送る
3. 検索窓に `抵抗`・`コンデンサ`・`オペアンプ` を 1 文字 120ms で打つ。
   打ち終えて 0.7 秒後から、進行中の計測が閉じるまで待つ (上限 20 秒)
4. 検索語を空にして**全件** (1 ページ目) を表示する
5. **表示モードを切り替える** (§2-1)
6. 一覧を一番下まで送って**続きを読み込む**。続きが無ければ `結果=続きなし`
7. 一覧の 2 件目・3 件目の題名リンク (`a[data-note-title]`) を順に押し、
   計測が閉じるまで待つ。`a[href^="/item/"]` で拾うと、3 ペインでは一覧の
   領域に入っているノート側の釦 (アイコン・「次 →」) を押してしまう。
   本番の初回はこれで全体の読み込み直しになり、手順が途切れた
8. `syncOfflineItems()` で同期を 1 回流す (5 分の間隔を待たない)
9. `[計測] テスト 結果=完了 全体=…` を送り、待ち行列を flush する
10. 2 秒置いてから計測を止める (`POST /api/logs/perf` に `enabled: false`)。
    ブラウザの計測行の受け口は切替を見ないので、止めた後に届いた行も落ちない

### 2-1. 表示モードの切替

利用者の「小・中・大・画像の切り替えが遅い」を測る (2026-10-28 の指摘)。
表示モードの釦 (`aria-label` が「表示: …」) を**実際に押す**。押すと次の
モードへ循環し、cookie を書いて一覧を描き直す Server Action になる。

- 計測の種別は `表示`。押した瞬間に `ResultsToolbar` が `perfStart` を打ち、
  行の先頭に `切替=compact→medium` を載せる。閉じる印は検索と同じ
  (一覧が描き直されるので `PerfMarks` の検索が閉じる)
- 切替は Server Action の POST で、URL に `_rsc=` を持たないため、
  `pickRsc` では本体を拾えない。`pickActionResponse` が、窓の中で行き先の
  パスに向かう `_rsc` なしの要求のうち最大を本体にする
- **測るのは小→中→大→画像→小の 1 周**。開始時の表示が小以外なら、先に
  小へ揃え (`区分=揃え`)、最後に元の表示へ戻す (`区分=戻し`)。比べるのは
  `区分=測定` の 4 行だけ。開始時の表示でこの 4 行は変わらない
- 切替は利用者の cookie (`view`) を書き換えるので、**途中で例外が出ても
  元の表示へ戻す**。切替で例外が出ても残りの手順 (続き・ノート・同期) は流し、
  `結果=表示切替失敗` を残す
- 現在の表示は釦の `aria-label` から読む (cookie は httpOnly で JS から読めない)

進み具合は画面の下に「計測 2/12: 「コンデンサ」を検索…」と出し、終わると
「計測完了。Claude に「終わった」と伝えてください」に変わる。完了の知らせは
8 秒で消える。打つ語は docs/118 §0-2 と同じで、前後の数字をそのまま比べられる。

流している間は sessionStorage に「流している最中」の印を置き、終わったら
消す。途中で全体の読み込み直しが起きると印が残るので、次の読み込みで
`[計測] テスト 結果=中断` を送って計測を止める。手順が例外で止まったときも
計測を止める。どちらも、計測が立ったまま残って普段の操作の行が控えを
押し流すのを防ぐため。

## 3. 取得鍵と取得口

| 口 | 門番 | 役目 |
| --- | --- | --- |
| `POST /api/logs/perf/token` | ログイン・同じサイト・デモは断る | 鍵を発行して 1 度だけ返す |
| `GET /api/logs/perf/export` | 取得鍵 (`Authorization: Bearer`) | 計測行を素のテキストで返す |

- 鍵は 32 バイトの乱数 (base64url 43 文字)。`user_settings` には sha256
  だけを保存する (key `perf_export_token`)。発行し直すと前の鍵は使えない
- 取得口は proxy の `isSelfGuardedPath` に完全一致で載せ、GET/HEAD だけ
  素通しする。照合は route が行い、理由を分けずに 401 を返す
- 読めるのは計測行だけ。警告・エラーのログやノートには届かない。計測行に
  載るのは検索語の先頭 20 文字とノート id の頭まで (docs/119 §1-5)
- 返す形は /logs?perf=1 の「コピー」と同じ (`formatPerfLinesForCopy`)
- 取得口は誰でも叩けるので、nginx でログインと同じ枠 (`qr_login`) の
  回数制限をかける。鍵は 256 ビットで当てずっぽうは成り立たないが、1 回ごとに
  DB を引くので、乱打で VPS を削られないようにする (セキュリティレビューの指摘)
- デモの判定は鍵の照合の後。鍵を持たない人に「デモかどうか」を返さない

### 3-2. 鍵を配布で揃える

`doDeploy.sh` の 6 段目 (SSH トンネル越しにマイグレーションと派生列を流す所)
で `scripts/syncPerfToken.ts` を流す。

- 手元の `~/.config/qr-note/perf-token` が無いか形が違えば、新しい鍵を作って
  chmod 600 で書く
- その sha256 を本番の `user_settings` に書く。持ち主は `__deploy__` で、
  画面から発行した鍵 (持ち主は利用者名) とは行を分ける。どちらかを発行し
  直しても、もう片方は使えるまま
- 鍵そのものは本番へ送らない。冪等で、毎配布流す
- 落ちても配布は止めない (WARN を出して続ける)。デモの配布では流さない

画面の「取得鍵を発行」(§3) は残す。手元以外の場所から読みたいとき用。

手元では `scripts/fetchPerfLog.sh` で読む。鍵はヘッダとして標準入力から
curl へ渡し、コマンドラインには載せない。

```bash
scripts/fetchPerfLog.sh > perf.txt
QR_PERF_URL=http://localhost:3301 scripts/fetchPerfLog.sh   # 手元の計測用
```

## 4. 使い方

1. PC のメニューで「計測開始」。「計測完了」が出るまで触らない
2. iPhone のメニューでも「計測開始」
3. Claude に「終わった」と伝える。Claude が `scripts/fetchPerfLog.sh` で
   行を取って読む

計測行はサーバのメモリに最新 200 行だけ残る。再起動・配布で消えるので、
取得が済むまで配布しない。

## 5. やらないこと

- 手順の中でペイン構成を切り替える。利用者の cookie を書き換えることになる。
  構成ごとに測りたいときは、構成を変えてから開始を押し直す
- 取得口から計測の切替や消去をする。読み取りだけに留める
