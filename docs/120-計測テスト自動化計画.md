# 計測テスト自動化計画

速度計測ログ (docs/119) で前後を比べるには、PC と iPhone で同じ操作をして、
/logs?perf=1 の行をコピーして渡す必要があった。手で打つと速さが毎回違い、
iPhone からのコピーも手間がかかる。メニューから**決まった手順を自動で
流し**、行は**手元のスクリプトから取得鍵で読める**ようにする。

決めたこと (2026-10-28):

- メニューに「計測テスト開始 / 終了」を置く。開始で計測を立てて読み込み
  直し、ブラウザが検索 3 語 → ノートを開く → 同期を自分で流す (§1・§2)
- 計測中も「開始」を出す。PC で始めた後の 2 台目 (iPhone) が流せるように
- 行の取得は、/logs?perf=1 で発行する**読み取り専用の取得鍵**で行う。
  Claude からの取得はこれで済む。ログインも ssh も使わない (§3)

## 1. メニュー

`components/diag/PerfTestMenuItem.tsx`。ログインしていてデモでないときに、
ヘッダーメニューの「ログ」の下に出す。

- **開始**: 計測が止まっていれば `POST /api/logs/perf` で立て、流す印を
  sessionStorage に付けて `/` を読み込み直す。読み込み直すのは、ブラウザ側の
  観測が root layout の描画で決まるため (docs/119 §1-4)
- **終了**: 計測を止めて読み込み直す (計測中だけ出る)
- 印 (`lib/logging/perfTestFlag.ts`) はこのタブだけ。読んだら消すので、
  読み込み直しのたびに流れ直すことはない

## 2. 手順

`lib/logging/perfTest.ts` の `runPerfTest` が並びを持ち、DOM の手足は
`components/diag/PerfTestRunner.tsx` が組む (root layout が計測中だけ置く)。

1. 読み込み直した後 3 秒待つ (ページの残りと起動時の同期)
2. `[計測] テスト 結果=開始 panes=… 幅=…` を送る
3. 検索窓に `抵抗`・`コンデンサ`・`オペアンプ` を 1 文字 120ms で打つ。
   打ち終えて 0.7 秒後から、進行中の計測が閉じるまで待つ (上限 20 秒)
4. 一覧の 2 件目 (無ければ先頭) を押し、計測が閉じるまで待つ
5. `syncOfflineItems()` で同期を 1 回流す (5 分の間隔を待たない)
6. `[計測] テスト 結果=完了 全体=…` を送り、待ち行列を flush する

進み具合は画面の下に「計測テスト 2/5: 「コンデンサ」を検索…」と出す。
完了の知らせは 8 秒で消える。打つ語は docs/118 §0-2 と同じで、前後の
数字をそのまま比べられる。

## 3. 取得鍵と取得口

| 口 | 門番 | 役目 |
| --- | --- | --- |
| `POST /api/logs/perf/token` | ログイン・同じサイト・デモは断る | 鍵を発行して 1 度だけ返す |
| `GET /api/logs/perf/export` | 取得鍵 (`Authorization: Bearer`) | 計測行を素のテキストで返す |

- 鍵は 32 バイトの乱数 (base64url 43 文字)。`user_settings` には sha256
  だけを保存する (key `perf_export_token`)。発行し直すと前の鍵は使えない
- 取得口は proxy の `isSelfGuardedPath` に完全一致で載せ、GET/HEAD だけ
  素通しする。照合は route が行い、理由を分けずに 401 を返す
- 読めるのは計測行だけ。警告・エラーのログやノートには届かない。計測行に
  載るのは検索語の先頭 20 文字とノート id の頭まで (docs/119 §1-5)
- 返す形は /logs?perf=1 の「コピー」と同じ (`formatPerfLinesForCopy`)
- 取得口は誰でも叩けるので、nginx でログインと同じ枠 (`qr_login`) の
  回数制限をかける。鍵は 256 ビットで当てずっぽうは成り立たないが、1 回ごとに
  DB を引くので、乱打で VPS を削られないようにする (セキュリティレビューの指摘)
- デモの判定は鍵の照合の後。鍵を持たない人に「デモかどうか」を返さない

手元では `scripts/fetchPerfLog.sh` で読む。鍵は
`~/.config/qr-note/perf-token` (chmod 600) に置く。鍵はヘッダとして標準入力
から curl へ渡し、コマンドラインには載せない。

```bash
scripts/fetchPerfLog.sh > perf.txt
QR_PERF_URL=http://localhost:3301 scripts/fetchPerfLog.sh   # 手元の計測用
```

## 4. 使い方

1. PC で /logs?perf=1 を開き「取得鍵を発行」を押す。出た鍵を
   `~/.config/qr-note/perf-token` に保存する (初回だけ)
2. PC のメニューで「計測テスト開始」。完了の知らせが出るまで触らない
3. iPhone のメニューでも「計測テスト開始」
4. `scripts/fetchPerfLog.sh` で行を取る (Claude に頼めば取って読む)
5. どちらかのメニューで「計測テスト終了」

## 5. やらないこと

- 手順の中でペイン構成を切り替える。利用者の cookie を書き換えることになる。
  構成ごとに測りたいときは、構成を変えてから開始を押し直す
- 取得口から計測の切替や消去をする。読み取りだけに留める
