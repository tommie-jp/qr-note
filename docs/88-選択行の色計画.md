# 選択行の色計画

3 ペイン (docs/86) で「いま開いているノートの行」を示す地色を、利用者が
選べるようにする。あわせてハンバーガーメニューの行の高さを詰める。

## 1. 何が問題か

### 1-1. 選択の目印が環境に合わない

3 ペインでは一覧とノートが同時に見えるので、どの行を開いているかの目印が
常時出ている (docs/86 §4)。色は `bg-blue-50` の決め打ちだった。

決め打ちで困るのは、見やすさが人と環境で変わるからである。

- 明るい所や輝度を上げた画面では、blue-50 は白い一覧の中でほぼ消える
- 逆に「もっと控えめでいい」場合もある (灰色で十分)
- 好みの問題でもある。1 日に何百回も見る面なので、慣れない色は疲れる

### 1-2. メニューが縦に長い

ハンバーガーメニューの行は 44px (`min-h-11`) だった。項目が 11 個まで
増えた今は、iPhone の縦画面でシートが画面の半分以上を占める。

44px は「指で狙える最小」の目安だが、この行は幅いっぱい (`w-full`) が
当たり判定なので、高さを 36px に詰めても指を外しにくい。詰めれば
1 画面に全項目が収まり、スクロールして探す手間がなくなる。

## 2. 決めたこと

### 2-1. 色は CSS 変数 3 つで配る

`--row-tint-bg` / `--row-tint-active` / `--row-tint-border` を `html` に立て、
使う側 (`ItemRow` / `ImageMasonry`) は `bg-[var(--row-tint-bg)]` の 1 通りだけを
書く。

色ごとに Tailwind のクラスを用意しない。Tailwind はソース中の**完全な
クラス名**しか拾うので、`bg-${color}-50` のような組み立ては CSS が生成
されない。6 色 × 3 用途を全部書き並べる形になり、色を足すたびに増える。

既定値は `globals.css` の `:root` が持つ。layout を通さない場面 (単体テスト、
色を選ぶ前の利用者) でも変数が空にならないようにするため。

### 2-2. 保存はサーバ (user_settings)

これまでの「どう見たいか」は端末に置いてきた。

| 設定 | 置き場 |
| ------ | -------- |
| 表示モード (小/大/カード/画像) | cookie |
| ペイン構成 (3/2/1) | cookie |
| ペインの寸法 | localStorage |
| テキストサイズ | localStorage |
| **選択行の色** | **DB (user_settings)** |

色だけサーバに置くのは、**見やすい色は端末ではなく人に付く**からである。
同じ人が iPhone と PC を行き来するので、片方で選んだ色がもう片方に無いと
毎回選び直すことになる。同じ判断で localStorage から DB へ移したのが
検索履歴 (docs/59 §7) で、置き方もそちらに倣う。

`user_settings` は `(user_name, key)` を主キーにした素の key-value 表。
**1 設定 = 1 行**にするのは、JSON を 1 列に持つと 2 台から別々の設定を
変えたときに後勝ちで消し合うため (SearchQuery と同じ理由)。

意味づけは表に持たせない。値の妥当性と既定値は読む側 (`rowTint.ts`) が畳む。
手で書き換えた値や、選択肢を減らした後に残る古い値が必ずあるためである。

### 2-3. サーバが読んでサーバが当てる

文字サイズは初回描画前に走るインラインスクリプトが localStorage から読んで
当てているが (docs/61)、DB の値はスクリプトからは読めない。代わりに
`layout.tsx` が読んで `html` の `style` に直接書ける — こちらのほうが確実で、
ちらつきも起きない。

読むのは layout。ヘッダーはどのページにも出るうえ、メニューの初期値としても
要る。未ログインなら DB を引かずに既定を返す。

## 3. 画面

ハンバーガーメニューの「テキストサイズ」の下に「選択色」の行を足す。
どちらも「どう見えるか」の設定で、探す場所は同じであってほしい。

色は 6 つ。青 (既定) / 緑 / 黄 / 桃 / 紫 / 灰。値は Tailwind の 50 / 100 / 400 で、
灰だけ 100 / 200 / 400 を使う — 50 は選択していない行の hover (`bg-gray-50`) と
同じ色で、「触れているだけの行」と見分けが付かなくなるため。

- 押した瞬間に当てる。保存の返事を待つと、色を押し比べる操作 (この機能の
  主な使い方) が毎回もたつく
- 保存に失敗しても色は戻さない。見えている色と押した色が食い違うほうが
  混乱する。失敗は行の下に文言で出し、次の読み込みで戻ることを含みにする
- 保存中はボタンを止める。連打すると、遅れて届いた古い色が最後に書かれて
  「押した色と違う色で保存される」ことがある
- クリックはこの行で止める。シートは「項目を押したら閉じる」を親 1 か所で
  受けているので (`HeaderMenu.tsx`)、素通しすると 1 色押しただけで閉じる

### 3-1. 出す相手

ログイン中の非デモだけ。

- 未ログイン … 保存する相手がいない
- デモ … 共有アカウントなので、1 人が変えると同時に見ている全員の色が変わる

導線を隠すだけでなく、口 (`PUT /api/settings/row-tint`) の側でも断る。
旗の欠落や導線の隠蔽に頼らない (docs/38 §2)。

## 4. メニューの行の高さ

`HEADER_MENU_ROW_CLASS` の `min-h-11` を `min-h-9` にする (44px → 36px)。
検索画面の詰めた操作 (`COMPACT_SIZE`) と同じ寸法。

文字は `text-base` のまま下げない。`COMPACT_SIZE` が `text-sm` を伴うのは
一覧の密度が目的だからで、こちらの目的は「1 画面に収める」ことなので、
読みにくくしてまで縮める必要がない。

**行の中に自前のボタンを持つ項目も同じ 36px に揃える。** 揃えないとその行
だけ背が高く残り、行の間隔がガタつく。対象は 2 つ:

- テキストサイズ … ＋ / − (`size-11` → `size-9`)、倍率 (`min-h-11` → `min-h-9`)
- 選択色 … 色見本 6 つ (`size-9`)

## 5. 触るもの

| ファイル | 役割 |
| ---------- | ------ |
| `src/lib/rowTint.ts` | 色の表・変数名・畳み方 (クライアントからも import) |
| `src/lib/rowTintStore.ts` | DB の読み書き (サーバ専用) |
| `src/lib/userSettingStore.ts` | `user_settings` の素の key-value |
| `src/app/api/settings/row-tint/route.ts` | 保存の口 (PUT のみ) |
| `src/components/RowTintMenuItem.tsx` | メニューの「選択色」の行 |
| `src/app/layout.tsx` | DB から読んで `html` に変数を立てる / 行を並べる |
| `src/app/globals.css` | 既定の色 (`:root`) |
| `src/components/ItemRow.tsx` | 一覧の行の地色 |
| `src/components/ImageMasonry.tsx` | 画像タイルの枠と地色 |
| `src/components/ui.ts` | メニューの行の高さ |

`rowTint.ts` と `rowTintStore.ts` を分けているのが要点。メニューの部品が
色の一覧を import しただけで prisma がクライアント側へ混ざるのを防ぐ
(`thumbnail.ts` が sharp を漏らしたのと同じ罠)。

## 6. やらないこと

- **自由な色 (カラーピッカー)** … 淡すぎて見えない色や、文字が読めない濃さを
  選べてしまう。6 色に絞れば、どれを選んでも成立することを確かめられる
- **フォルダーペインの選択色** … 左ペインで選んでいる仮想フォルダーは
  `bg-blue-100` のまま。あちらは「検索結果の行」ではなく、同じ色にすると
  一覧の目印と紛れる
- **端末ごとの上書き** … 「PC だけ別の色」は要望が出てから考える。
  先に作ると、サーバと端末のどちらが勝つかという話が増える
