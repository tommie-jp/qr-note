# 全文検索の使い方

このアプリ (`qr.tommie.jp`) の検索窓で使える検索方法をまとめる。
実装は PGroonga による全文検索 (`src/lib/items/where.ts` / `src/lib/search/`)。
実装の背景・設計判断は [04-全文検索計画.md](./04-全文検索計画.md)、
論理演算 (AND / OR / NOT / 括弧) の細かい規則は
[16-検索の論理演算.md](./16-検索の論理演算.md) を参照。

## 1. 何が検索対象か

トップ画面の検索窓に入力した語は、メモ本文を探す。

| 対象 | 一致方式 | 補足 |
| --- | --- | --- |
| メモ本文 (`memo`) | 全文検索 (`&@`) | 日本語バイグラム。文中のどこにあっても一致 |

(かつては URL 欄 (`url`) も対象だったが、[110](./110-URL列廃止計画.md) で
列を廃止し、URL は本文の 1 行として検索に掛かる)

`#タグ` (§3.5) と `is:` で始まる語 (§3.6・§3.6.5) は全文検索ではなく、
ノートに付いたタグやチェックの状態で絞り込む。

**ノートの番号 (旧番号) で探すとき**は、その番号をそのまま打つ。番号は本文の
タグ (`#1003` など) になっているので、`1003` なら全文検索で、`#1003` なら
タグ検索で当たる。番号の前方一致 (`10` で 1000 番台) は無くなった。
`#10` まで打つとタグの候補に出るので、そこから選ぶ (§3.5「タグ名の補完」)。

### 表記ゆれの吸収 (正規化)

PGroonga の `NormalizerAuto` により、次は同一視される。

- 全角/半角: `２ＳＣ１８１５` ↔ `2SC1815`
- 大文字/小文字: `NPN` ↔ `npn`

そのため `2sc1815` と打っても `２ＳＣ１８１５` を含むメモがヒットする。

## 2. AND 検索 (すべての語を含む)

**語をスペースで区切る**と AND 検索になる。半角スペースでも全角スペースでもよい。

```text
抵抗 1608
```

→「抵抗」**かつ**「1608」の両方を含むものだけがヒットする。

- 区切りは半角スペース・全角スペース・タブ・改行のいずれでも可
- 連続スペースや前後の余分なスペースは無視される
- 同じ語を重複して入れても 1 回として扱う
- 1 回の検索で使える語は最大 10 個 (`MAX_SEARCH_TERMS`)。`#タグ` や `is:todo`
  も 1 個に数える。11 個目からは捨てる

各語ごとに「メモ or URL」を評価し、**語と語の間が AND** になる。
たとえば `抵抗 1608` は次の意味になる。

```text
(memo に「抵抗」 or url に「抵抗」)
  AND
(memo に「1608」 or url に「1608」)
```

## 3. OR 検索 (どれかを含む)

### 3-1. 暗黙の OR — 1 語は 2 フィールドを OR で探す

前述のとおり、1 語は「メモ or URL」を横断する。
つまり `1815` と 1 語だけ打てば、**メモに 1815 を含むもの / URL に 1815 を含むもの**が
OR でまとめてヒットする。
フィールドを跨いだ OR は意識しなくても効いている。

### 3-2. 語と語の OR — `OR` または `|` で区切る

「抵抗 OR コンデンサ」のように**別々のキーワードを OR したい**場合、
`OR` (大文字小文字は区別しない) か `|` (パイプ) で区切る。

```text
抵抗 OR コンデンサ
抵抗|コンデンサ
```

→「抵抗」**または**「コンデンサ」のどちらかを含むものがヒットする。

- `OR` は前後を空白で区切った**単独の語**のときだけ演算子になる
  (`or` / `Or` でも同じ。`DOOR` などの中の文字列は演算子にならない)
- `|` は前後の空白の有無を問わず区切る (`A|B` でも `A | B` でもよい)
- 3 語以上も可: `A OR B OR C` / `A|B|C`
- **全角のまま打ってもよい** (`ＯＲ` / `｜`)。日本語入力を切り替える必要はない

#### 演算子の優先順位

強く結合する順に **`!` (NOT) > 空白 (AND) > `OR`**。SQL や Google 検索と同じ
感覚でよい。そのため次は同じ意味になる。

```text
抵抗 1608 OR コンデンサ
```

→ `(「抵抗」かつ「1608」) または 「コンデンサ」` と解釈される。
この順番を変えたいときは括弧で囲む (§3.8)。

内部では式を組み立て直してから SQL の `AND` / `OR` / `NOT` に写し、各語は
これまでどおり素のキーワードとして `&@` に渡す。演算子構文を PGroonga に
直接渡さないため、構文エラーやエスケープ漏れは起きない
([04-全文検索計画.md](./04-全文検索計画.md) §3-3)。

#### `or` / `|` を語として検索したいとき

`OR` や `|` は演算子として予約されている。これらを**文字どおり検索したい**
ときはダブルクォートで囲む。

```text
"or"       ← 語「or」を検索 (OR 演算子にならない)
"A|B"      ← 語「A|B」を検索 (パイプで区切られない)
A "or" B   ← 「A」かつ「or」かつ「B」の AND
```

## 3.5. タグ検索 (#tag)

メモ本文に書いた**タグ** (`#トランジスタ` など) で絞り込める。タグ記法は
[メモ記法](/docs/memo) を参照。検索窓では、引用されていない `#○○` が
タグ検索になる。

```text
#トランジスタ
```

→ タグ `トランジスタ` の付いたノートだけがヒットする (本文に文字列として
「トランジスタ」を含むだけのノートは**ヒットしない**。タグとして付けたものだけ)。

- 大小文字・全半角は同一視される (`#NPN` = `#npn`)
- タグも論理演算できる (空白 = AND、`OR` / `|` = OR、`!` = NOT、`()` でグループ化)

```text
#tag1 #tag2      ← tag1 かつ tag2
#tag1 | #tag2    ← tag1 または tag2
#tag1 !#tag2     ← tag1 かつ tag2 でない
#トランジスタ 2SC1815   ← タグと全文検索の混在も可
```

### タグ名の補完

検索窓で `#` を打つと、既存タグの候補が出る。`#t` のように途中まで打つと
前方一致で絞り込まれる。

- タグ名は**前方一致**で絞る (`#tr` で `#transistor` は出るが、`#sistor` では出ない)
- `↓` / `↑` で候補を選び `Enter` で確定 (候補を選んでいないときの `Enter` は
  通常の検索送信)
- `Tab` は bash 風の補完 (候補が 1 つなら確定、複数なら共通部分まで補完)
- `Esc` で候補を閉じる。日本語入力の変換中はキー操作を邪魔しない

### `#` を文字として検索したいとき

`#` はタグの記号として予約されている。`#` やタグ名を**文字どおり検索**
したいときはダブルクォートで囲む。

```text
"#"        ← 記号「#」を全文検索
"#tag1"    ← 文字列「#tag1」を全文検索 (タグ検索にならない)
```

引用しない `#` 単独 (タグ名なし) は無視される。

## 3.6. チェック状態で絞る (is:todo / is:done)

メモ本文のチェックボックス (`- [ ]` / `- [x]`。[メモ記法](/docs/memo) 参照) の
状態で絞り込める。

```text
is:todo    ← 未チェックの項目が 1 つでも残っているノート
is:done    ← チェック済みの項目が 1 つでもあるノート
```

単語帳として使うときの定番の組み合わせ。

```text
#英単語 is:todo        ← 英単語ノートのうち、まだ覚えていないものだけ
!is:todo is:done       ← 全部チェックし終えたノート
is:todo OR is:done     ← チェックボックスを含むノート全部
```

- 1 つのノートに複数のチェックがある場合、**1 つでも未チェックが残っていれば**
  `is:todo` に出る (全部チェックすると消える)。途中のノートは `is:todo` と
  `is:done` の両方に出る。
- コードブロックの中に書いた `- [ ]` は数えない (表示上もチェックボックスに
  ならないものは数えない、で一貫させている)。
- 大小文字・全半角は同一視される (`IS:TODO` / `ｉｓ：ｔｏｄｏ` も同じ)。
- `is:todo` / `is:done` 以外の値 (`is:foo`) はただの検索語として扱う。
- 文字どおり検索したいときはダブルクォートで囲む (`"is:todo"`)。

### 進み具合が出る

`is:todo` / `is:done` で絞ると、件数の下に**学習の進み具合**が出る。

```text
チェック完了 3 / 9 (33%)
```

- 分母は「同じ検索でチェックを持つノート」— チェックの無いノートは数えない。
- 分子は「**全部**チェックし終えたノート」。途中のノートは分子に入らない。

### チェックを 2 つ置いて 3 段階にする

「覚えた/覚えていない」の 2 択で足りないときは、チェックを 2 つ並べる。

```text
- [ ] 学習済み
- [ ] 自信あり
```

| 状態 | 検索 |
| --- | --- |
| まだ手を付けていない | `#英単語 !is:done` |
| やったが自信がない | `#英単語 is:todo is:done` |
| 仕上がった | `#英単語 !is:todo` |

**どちらも「できたら付ける」向きに書く**のが要点。「要復習」のように
まずいときに付ける向きにすると、仕上がった物も未チェックのまま残り、
`is:todo` から消えなくなる。

### 一覧の中を「前 / 次」で回る

検索結果からノートを開くと、本文の下に **「← 前 / 一覧へ / 次 →」** が出る。
ブラウザの戻る/進むとは別物で、辿るのは**その検索結果の並び**。
`is:todo` で絞っていれば、仕上げた分は自動で飛ばされる。

順番に回すときは**並び順を「登録順」にしておく**。既定の更新順だと、
チェックを押したノートが一覧の先頭へ移ってしまい、前後がずれる。

## 3.6.5. タグの無いノートを探す (is:untagged)

タグを 1 つも付けていないノートだけに絞れる。整理し忘れたノートを
洗い出すための語で、検索フォルダーの「未分類」もこれを使っている。

```text
is:untagged        ← タグの無いノート全部
抵抗 is:untagged   ← 「抵抗」を含み、タグが無いもの
!is:untagged       ← タグのあるノート全部
```

- 大小文字・全半角は同一視される (`is:todo` と同じ)。
- 文字どおり検索したいときはダブルクォートで囲む (`"is:untagged"`)。

## 3.7. NOT 検索 (`!` で除外)

**語の前に `!` を付けると、その語を含むものを除外**する。全角の `！` も同じ。

```text
#bjt !#npn
```

→ タグ `bjt` が付いていて、**かつ** タグ `npn` が付いて**いない**ものだけ。

- `!` と語の間はスペースがあってもなくてもよい (`!#npn` も `! #npn` も同じ)
- `!` は**直後の 1 つ**だけに掛かる。`!#npn #bjt` は
  「npn でない **かつ** bjt」であって、bjt までは否定されない
- テキスト語の否定は「メモにも URL にも含まない」の意味になる
- 否定だけのクエリも書ける。`!#覚えた` → タグ `覚えた` が付いていない全ノート
- `!` を文字として検索したいときはダブルクォートで囲む (`"!"` / `"!foo"`)

## 3.8. 括弧でグループ化

`()` で囲むと、その中身がひとかたまりの条件になる。全角の `（）` も同じ。

```text
#bjt !(#npn OR #pnp)
(抵抗 OR コンデンサ) 1608
```

→ 上は「bjt で、npn でも pnp でもないもの」、
下は「(抵抗 または コンデンサ) かつ 1608」。

括弧がないと「空白 (AND) は OR より強い」ため、`抵抗 OR コンデンサ 1608` は
`抵抗 または (コンデンサ かつ 1608)` になってしまう。**OR を先に評価させたい
ときに括弧を使う。**

- 括弧の前後にスペースは要らない (`#bjt(!#npn)` でもよい)
- 何重にでも入れ子にできる
- 括弧を文字として検索したいときはダブルクォートで囲む (`"(株)"`)

### 打ち間違えても止まらない

エラーにはせず、それらしく解釈する。

| 打ち間違い | 扱い |
| --- | --- |
| `(抵抗 OR コンデンサ` (閉じ忘れ) | 末尾で閉じたものとみなす |
| `抵抗) 1608` (余分な `)`) | その `)` を無視 |
| `抵抗 !` (相手のいない `!`) | その `!` を無視 |
| `()` (空の括弧) | 無視 |

## 3.9. URL でクエリを直接組み立てる

検索窓は使わず URL パラメータ `q` に語を渡してもよい (検索窓と同じ文法。
スペースは AND、`OR` / `|` は OR、`!` は NOT)。

```text
https://qr.tommie.jp/?q=抵抗%201608
https://qr.tommie.jp/?q=抵抗%201608&sort=registered&page=2
https://qr.tommie.jp/?q=抵抗%20OR%20コンデンサ
https://qr.tommie.jp/?q=%23bjt%20!%23npn
```

- `q` — 検索語 (スペース AND・`OR`/`|` で OR・`!` で NOT・`#○○` でタグ)
- `sort` — 並び順。値は §4 の表のとおり (省略すると `updated`)
- `page` — ページ番号 (1 ページ 20 件)

ブックマークしておけば、よく使う検索をワンクリックで再実行できる。

## 4. 並び順とページング

既定は **更新順** (`sort=updated`, 新しい順)。画面下のバーで次の 4 種類に
切り替えられ、それぞれ逆向きにもできる。

| 並び | `sort` の値 (既定の向き / 逆向き) | 並べる鍵 |
| --- | --- | --- |
| 更新順 | `updated` (新しい順) / `updatedAsc` (古い順) | 最後に書き換えた日時 |
| アクセス順 | `accessed` (新しい順) / `accessedAsc` (古い順) | 最後に開いた日時 |
| 登録順 | `registered` (古い順) / `registeredDesc` (新しい順) | 作った順。番号のあった古いノートは番号順 |
| タイトル順 | `title` (昇順) / `titleDesc` (降順) | 一覧に出る見出し。見出しの無いノートは末尾 |

- 以前の `sort=itemNo` (番号順) / `itemNoDesc` は、登録順 (`registered` /
  `registeredDesc`) として受け付ける。古いブックマークもそのまま開ける
- 選んだ並び順は覚えておき、次に開いたときも同じ並びで出る
- 関連度 (スコア) 順は**採用していない**。小規模データでは PGroonga の
  インデックスが使われず score が 0 になるため
  ([04-全文検索計画.md](./04-全文検索計画.md) §3-4)
- 1 ページ 20 件 (`PAGE_SIZE`)
- 検索窓を空のまま検索すると、全件を並び順どおりにブラウズできる

## 6. 検索窓の候補と自動検索

- **打つと自動で検索する。** 打ち終わって 0.3 秒たつと結果が入れ替わる。
  `Enter` を押すとすぐ検索する。日本語入力の変換中は検索しない
- **窓が空のときは候補が出る。** ★ が登録パターン、🕐 が最近の検索
  (それぞれ 5 件ずつ出し、「もっと表示」で 10 件まで)。最近の検索の ☆ を
  押すと登録パターンになる。
  候補は同じアカウントならどの端末でも共通
- **`i` まで打つとキーワードの候補が出る** (`is:todo` / `is:done` / `is:untagged`)。
  `#` で始めるとタグの候補になる (§3.5)
