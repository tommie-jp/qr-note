# 表タイトル短縮計画

` ```matrix ` の表 ([docs/77](./77-進捗マトリックス計画.md)) で、**行に並ぶ
ノート名の共通する先頭を自動で省く**。フェンスの記法は増やさない。

## 0. 何が困っているか

問題集のノート名は、探すために長い。

```text
01電験三種 01理論 01直流回路 問01 (直列と並列の合成抵抗)
01電験三種 01理論 01直流回路 問02 (分圧則・直列抵抗の電圧配分)
```

ところが表の側は既に `#電験三種 #理論 #直流回路` で絞り込んでおり、置いて
あるノートにも「電験三種 理論 進捗」という見出しが付いている。**表の中では
`01電験三種 01理論 01直流回路` は全行に等しく付いた飾り**で、1 行の情報量に
寄与しない。スマホでは名前の列が先に潰れるので、いちばん見たい `問01` 以降が
その飾りに押し出されて読めなくなる。

ノート名そのものを短くする案は採らない。一覧・検索・前後ナビでは、その飾りが
まさに「どの科目のどの単元か」を名乗る仕事をしている。**長いのは表の中だけの
問題**なので、表の中だけで直す。

## 1. 削る量は書かせない — 共通の先頭から求める

フェンスに `skip=01電験三種 01理論 01直流回路` と書かせる案 (§5) ではなく、
**表に並んだ行から共通する先頭を計算する**。

- 検索式 (`#電験三種 #理論 #直流回路`) とほぼ同じ内容を、別の綴りで
  もう一度書かせずに済む。章ごとに表を作れば理論だけで十数枚になる。
- ノート名を直しても腐らない。明示指定は一致しなくなった瞬間に黙って
  効かなくなり、**エラーにもできない** (一部の行だけ一致しないのは正常)。
- 章をまたぐ表 (`#電験三種 #理論` だけで絞る) では共通部分が自動的に
  `01電験三種 01理論` まで縮む。書き分けなくてよい。

## 2. 削り方の規則

`commonTitlePrefix(summaries)` … 削るべき接頭辞を返す純関数。空文字なら
何も削らない。

1. **行が 2 つ未満なら削らない。** 1 行しかない表は共通接頭辞 = その名前
   そのものになり、全部消える。
2. 全行の**文字単位**の共通接頭辞を求める。
3. その中の**最後の空白の直後まで後退**する。空白が無ければ空文字 (削らない)。
4. どれか 1 行でも残りが空になるなら空文字 (最後の語は必ず残す)。

**語の途中で切らない (規則 3) のが要点。** 文字単位のまま使うと、問 01〜問 09
だけの表で共通接頭辞が `…問0` まで伸び、行が `1 (直列と並列の合成抵抗)` に
なる。規則 3 があれば `問0` は空白を含まないので後退先が `問` の手前に戻り、
`問01` が残る。

空白は JS の `\s` で見る (全角空白 `　` を含む)。区切りだけを見て**名前は
打ったまま持つ**のは `col=` の区切り判定と同じ作法
([matrixFence.ts](../src/lib/matrixFence.ts) の `isComma`)。

## 3. 削ったものは捨てない

省いた語は、表の上の件数行の下に 1 度だけ出す。

```text
全 24 件  学習済み 0.0% (0)  自信あり 0.0% (0)
01電験三種 01理論 01直流回路
#7000  問01 (直列と並列の合成抵抗)
#7001  問02 (分圧則・直列抵抗の電圧配分)
```

- 灰色・小さめの 1 行。溢れたら省略記号で切り、`title` に全文を持たせる
  (表の**外**なので横スクロールの帯には入らない)。
- 行のリンクの `title={row.summary}` は**全文のまま**触らない。マウスなら
  行の上で全体が読める。
- 読み上げは短いほうを読む。共通部分は表の上で 1 度読まれるので、24 行ぶん
  同じ飾りを読み上げさせるより短い。

列見出しの `ノート` を接頭辞に差し替える案は採らない。あの `th` は横スクロール
する帯の中にあり、`max-w-0 truncate` で名前の列と幅を取り合っている。長い
接頭辞を置くと、いちばん幅を空けたい列の見出しが自分で幅を要求し始める。

## 4. 実装は表示側 1 箇所

**データの形 (`MatrixTableData`) もフェンスの記法も変えない。**

| 触るもの | 内容 |
| ---------- | ------ |
| [matrixTable.ts](../src/lib/matrixTable.ts) | `commonTitlePrefix()` を足す (DB 非依存の純関数) |
| [MatrixTable.tsx](../src/components/matrix/MatrixTable.tsx) | 描くときに呼び、`summary.slice(prefix.length)` を出す |

サーバ側 (`buildMatrixTable`) で `summary` を短く畳んで返す案は採らない。
全文が消えて `title` の hover が死ぬうえ、`MatrixTableData` に接頭辞の
フィールドが増え、`MatrixResult` → props → 表示と 4 段に値を通すことになる。
**表示だけの都合は表示側で閉じる。**

計算量は 200 行 × 名前の長さで、1 回の描画で 1 度。オフラインの写し
([docs/65](./65-オフライン対応計画.md)) も同じ `MatrixTable` を描くので、
サーバとクライアントで同じ表になる。

## 5. 採らない案

| 案 | 採らない理由 |
| ---- | -------------- |
| ノート名から `01電験三種 01理論` を消す | 一覧・検索・前後ナビでの識別が落ちる。困っているのは表の中だけ |
| `skip=…` で削る文字を明示 | 検索式との二重管理。章ごとに書き足す必要があり、ノート名を直すと黙って腐る |
| 末尾優先の省略 (`…問01 (直列と…)`) | `direction: rtl` は日本語の括弧の向きを崩す。常に切れて共通部分も読めない |
| 正規表現で削る部分を指定 | 今ある困りごと 1 つに対して自由度が過剰 (YAGNI) |

`skip=` は**後から足せる**。自動が効きすぎる表が出てきたら、そのとき
`skip=none` / `skip=<文字列>` を 1 キーで足せばよい (綴りは既存の
`sort` / `col` / `mark` に揃えて短い英語 1 語にする)。先に入れない。

## 6. テスト

- 行が 1 つなら空文字

## 7. 承知しておくこと

- **200 件で打ち切られた表**では、載っている行だけの共通接頭辞になる。
  絞り込むと削れる量が変わる。省いた語は表の上に出ているので、
  食い違って見えることはない。
- 全行が**まったく同じ名前**なら最後の語だけが残る。区別は `#番号` しか
  付かない状態なので実害は無い。
- 状態 1 列 (`col=` を省いてチェックに名前が無いとき) でも同じに効く。
- 公開ビューでは表そのものが出ない ([docs/77](./77-進捗マトリックス計画.md) §6)
  ので、この変更は公開の境界に触れない。
