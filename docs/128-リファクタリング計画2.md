# リファクタリング計画 2 (長い関数・よく変わる部品)

<!-- markdownlint-disable MD013 -->

[docs/93](93-リファクタリング計画.md) の整理 (2026-09) から 2 か月で、ファイルの大きさは保たれているが**関数が長くなった**。
この計画は、長い関数と複雑な分岐を、変更と不具合が集中している場所から減らす。
挙動は変えない。速度とメモリは [docs/127](127-リファクタリング前プロファイル計画.md) の手順で前後を比べる。

## 2. 方針

- **挙動は変えない** (docs/93 と同じ約束)。途中で不具合を見つけても、その場では直さず §7 に書く
- 対象は「長い関数 × よく変わる場所」に絞る。182 本を全部は直さない
- 部品の分解は、フックと小さな部品へ切り出す形にする。状態の持ち方は変えない
- 段の終わりに lint・型・全テスト・E2E と docs/127 の計測を流し、docs/127 §8 で判定する
- **歯止め** (§3-0) で、直した所が再び長くならないようにする

### 3-0. 歯止めと道具

- `scripts/checkComplexity.mjs`: ESLint の `max-lines-per-function` (50)・`complexity` (15)・
  `max-depth` (4)・`max-params` (5) を流し、**ファイルごとの件数が基準
  (`scripts/complexity-baseline.json`) より増えたら落ちる**。減ったら基準を書き直す
  (`--update`)。新しいファイルは 0 件が基準
- 循環依存は `madge` で見る。生成物 (`src/generated`) を除いて 0 本を保つ
- `knip.json`: スクリプト・E2E・Next の入口を登録し、誤検出を消す
- いずれも `npm run check:quality` から流し、CI の check ジョブに足す

### 3-1. 掃除

- 未使用の export を消す。テストのためだけの公開・ログに出す定数は残す
- 巻き添えで入っている依存を `package.json` に明記する

### 3-2. 純粋なロジック

テストがあり画面に触らない所。写真の撮影情報 (`photoMeta` の `png`・`jpeg`・`webp`)、
`itemDto`・`quizParse`・`calendarPrefs`・`matrixFence`・`markdownFormat`。

### 3-3. よく変わる大きな部品

- カレンダー: `DayEventList`・`CalendarView`・`CalendarMenu`・`EventForm`
- ペイン: `PaneResizer`・`CollapsedPaneTabs`
- 検索と一覧: `SearchResultsClient`・`SearchForm`・`ItemList`
- ノート: `NoteView`
- 画像ビューア: `ImageViewerProvider`

### 3-4. 循環依存

- `PaneModeProvider` ↔ `CollapsedPaneTabs`
- `PaneResizer` → `previewPaneHidden` → `resultViewHref` → `modules/registry` → カレンダー → `PaneResizer`
  (core が registry 経由でカレンダーを読み、カレンダーがペインを読み返している)
- `MarkdownView` ↔ `SecretBlock`

### 3-6. 計測コード

`lib/logging` の計測まわり (`perf`・`perfClient`・`perfNavCheck`・`perfTest`・`perfTestFlag`・
`perfLine`・`perfServer`・`perfExportToken`・`perfSwitch`・`bootTiming`・`netProbe`) を
`lib/perf` へ移す。ログ本体 (`diagLog`・`buffer`・`clientCapture` など) は残す。

## 4. やらないこと

- ほかの機能を `src/modules/` へ移すモジュール化 (継ぎ目の実例がカレンダー 1 つしか無い)
- 速くするための作り直し (挙動を変えない約束の外)
- 182 本すべての解消
