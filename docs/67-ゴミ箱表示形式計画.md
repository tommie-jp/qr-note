# ゴミ箱表示形式計画

ゴミ箱 (`/trash`) の一覧にも、検索一覧と同じ**表示形式 (小・大・画像)** と
**並び順**を用意する。

## 1. なぜ

ゴミ箱は「消してよかったか」を確かめる画面なので、確かめる材料は検索一覧より
**多く**要る。ところが今までのゴミ箱は 1 行 2 段 (番号 + 要約 + 削除日時) の
一形式しかなく、次のことができなかった。

- 写真から思い出す (「あの基板の写真のノート」を画像で探す)
- 本文を読んで確かめる (大表示の 3 行プレビュー)
- 消し忘れを別の軸で探す (更新順・番号順・タイトル順)

「数件しか溜まらない前提」で作った画面 (docs/12-ゴミ箱計画.md §5) だが、
実際には溜まる。溜まるほど、一覧の見え方が効いてくる。

## 2. 並び順 — ゴミ箱だけの「削除順」を足す

種別は 5 つ。**削除順が既定**で、残りは検索一覧と同じ。

| 種別 | 既定の向き | ORDER BY |
| ------ | ------------ | ---------- |
| 削除順 | 新しい順 | `deleted_at DESC` |
| 更新順 | 新しい順 | `updated_at DESC` |
| アクセス順 | 新しい順 | `accessed_at DESC` |
| 番号順 | 小さい順 | `item_no_num ASC NULLS LAST` |
| タイトル順 | 昇順 | 見出し `ASC NULLS LAST` |

逆順の扱いは docs/64-並び順逆順計画.md のまま — メニューの行は種別ぶんだけで、
**選んである行をもう一度押すと方向が裏返る**。

### 型を検索側と分ける

`TrashSort = Sort | 'deleted' | 'deletedAsc'` として、共有の `Sort` には
混ぜない。`deleted_at` は検索一覧では必ず `null` なので、`/?sort=deleted` は
「全件が同着」という意味のない並びになる。型が分かれていれば、検索側の
`parseSort` がゴミ箱の値を既定へ倒してくれる。

逆に `Sort` の 4 種別はゴミ箱でもそのまま使えるので、`TrashSort` は `Sort` を
含む上位集合にする (`orderByClause` も 1 本のまま)。

### cookie も分ける

並び順は検索一覧と同じ二段構え (URL → cookie → 既定。src/lib/sortMode.ts)。
ただし cookie は `trashSort` で別に持つ。

1 つの cookie にすると、ゴミ箱で削除順を選んだ後に検索へ戻ったとき、検索側は
知らない値として既定へ倒す — つまり**検索の並びがゴミ箱を開くたびに巻き戻る**。
逆に検索で選んだ並びがゴミ箱の既定 (削除順) を上書きするのも期待と違う。

URL の `?sort=` はパスで分かれる (`/` と `/trash`) ので分ける必要がない。

### 表示形式の cookie は共有する

こちらは 1 つ (`view`) のまま。「どう見たいか」は端末ごとの好みで、一覧の
種類ごとに分ける物ではない (docs/23-検索結果表示モード計画.md §5)。

## 3. 描画は検索一覧と同じ部品に委ねる

小・大は `ItemRow`、画像は `ImageMasonry`。ゴミ箱用に書き写さない。

行ごとの復元 / 永久削除は `ItemRow` の `footer` に差し込む。footer は
stretched link の膜より前 (`relative z-10`) に出す — 後ろに居ると、ボタンを
押してもノートが開く (タグと同じ罠)。

**画像表示には行ごとの操作を出さない。** タイルは「画像 1 枚 = 1 リンク」で
ノート単位ではなく、1 ノートに複数枚あれば同じ番号の永久削除ボタンがタイルの
数だけ並ぶ。取り返しの付かない操作を重複して置く形になるので、あちらは
ノートを開く導線だけにし、その旨を一覧の上に書いておく (黙って消えていると
「画像表示にしたら復元できなくなった」と読める)。

## 4. 下部バーを 2 スロットで出す

表示・並び順のスロットは検索画面と同じ位置・同じ見た目にする。置き場所が
画面ごとに動くと探す羽目になる。

そのために `BarSlot` (フォーム + 循環ボタン + 長押しメニューの配線) と
`ViewSlot` / `SortSlot` を切り出し、両方のバーが同じ部品を使う。送信を潰さずに
メニューを閉じる順序も、開いているスロットの再タップを循環から外す振り分けも、
一度踏んだ落とし穴の上に建っているので、画面ごとに書き写すと必ずずれる
(docs/62-下部バー長押し計画.md)。

種別が 4 つ (検索) か 5 つ (ゴミ箱) かの違いは `SortSpec` が持つ。

出さないスロットが 3 つある。

- スキャン・画像検索 … ゴミ箱に当たっても開けないノートを指すだけ
- 選択 … 行ごとの復元 / 永久削除で足りている (docs/12 §5 の判断のまま)

器は `max-w-xs` に絞る。スロットは `flex-1` で器を等分するので、`max-w-2xl` の
ままだと 2 つが画面幅の半分ずつを占め、検索画面の同じスロットと別物に見える。

## 5. ページ送りは足さない

ゴミ箱一覧は今までどおり全件を返す。「ゴミ箱を空にする (N)」の N が全件を
指す前提でもあるので、上限を入れるならその表示と一緒に考える。
