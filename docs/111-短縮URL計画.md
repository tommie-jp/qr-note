# 短縮 URL 計画 (番号タグで `/s/1234`)

UUID v7 を主キーにした (docs/107) ことで QR の URL が 62 文字になり、
「4 桁の番号をポストイットに手書きし、手で打って探す」運用ができなくなった。
**番号タグ `#1234` を持つノートだけ**を短縮 URL `https://qr.tommie.jp/s/1234` で
受け、印刷 QR にもその URL を載せる。番号は「番号を振る」ボタンで任意に付ける。

決めたこと (2026-10-18):

- 短縮 URL の正本は**本文のタグ**。列・フラグ・対応表は作らない (docs/107 §2-2 の
  「2 つ目の識別子を持たない」を守る)
- 対応するのは番号タグを持つノートだけ。番号は「番号を振る」ボタンで付ける
  (`/new` では自動で振らない)
- 番号は **4 桁 (1000〜9999) の裸のタグ**。接頭辞は付けない (印刷済みシール 1470 枚と
  形を揃える)
- `/s/<番号>` は `/item/<番号>` の別名で、同じ規則 (タグで引いて 308) で受ける
- 印刷 QR は番号タグがちょうど 1 つなら `/s/<番号>`、それ以外は今の `/item/<id>`

## 1. 問題

| 運用 | 旧 (itemNo) | 今 (UUID) |
| --- | --- | --- |
| ポストイットに手書き | `1234` | 36 文字。書けない |
| 手打ちで開く | `qr.tommie.jp/item/1234` | 旧ノートは開ける。**新しいノートには番号が無い** |
| QR の大きさ (M) | 29x29 | 33x33 |

欠けているのは「新しいノートに番号を振る手段」と「印刷 QR に番号の URL を載せること」の
2 つ。短縮 URL の仕組み自体は docs/107 のタグ解決がそのまま使える。

QR の版 (`qrcode` で確認、訂正レベル M):

| URL | 文字数 | 版 |
| --- | --- | --- |
| `https://qr.tommie.jp/item/<uuid>` | 62 | 4 (33x33) |
| `https://qr.tommie.jp/item/1234` | 30 | 3 (29x29) |
| `https://qr.tommie.jp/s/1234` | 27 | **2 (25x25)** |

`https://` は落とさない (URL と認識しないカメラアプリがある。13-kick-work docs/33)。

## 2. 方針

### 2-1. 「番号タグがある = 短縮 URL に対応している」

ノートごとの対応/非対応を**番号タグの有無で表す**。列を足すと docs/107 で消した
「2 つ目の識別子」が戻る。タグなら

- 旧ノート 1470 件は自動的に対応済み
- 教科書 (`#wb01-03-08`)・JAN のノートは対応外のまま (望ましい)
- タグ検索・チップ・GIN 索引・ZIP・git 履歴がそのまま効く

### 2-2. 番号の形

`^[1-9][0-9]{3}$` (1000〜9999)。旧採番 (docs/10 §4) と同じ範囲。
JAN / ISBN (13 桁) とは桁で区別できる。

- 受け入れる副作用: 年号 (`#2026`) のような 4 桁タグも番号と見なされる。
  `/s/2026` はそのノートに着く。接頭辞 (`#n1234`) で避けられるが、手書き・手打ちが
  伸び、印刷済みシールと形が揃わないので採らない
- 9000 番で尽きる。今 1470 件なので当面は足りる。尽きたら `null` を返し、ボタンは
  「空き番号がありません」を出す (桁を増やすのはそのとき)

### 2-3. 空き番号

1000 以上の最小の空き。**ゴミ箱の行も数える** (タグは残っているので、旧採番の
「ゴミ箱が番号を予約する」が自然に再現される)。永久削除でタグごと消えれば再利用される
(旧仕様と同じ)。

同時に 2 人が押すと同じ番号が付きうる。防がない — `/s/1234` が 2 件なら検索一覧に
落ちる (docs/107 §2-2 が受け入れ済み)。片方の番号を振り直せば直る。

### 2-4. 短縮 URL は `/s/<番号>`

`/item/<番号>` でも開けるが、`/s/` を足すのは QR が 1 版小さくなる (25x25) のと、
手打ちが短いため。別名なので解決規則は増やさない — `legacyPath` の prefix に `/s/` を
足し、着地は `/item/<id>` にする。

## 3. 番号タグの関数 — `src/lib/items/noteNumber.ts` (新規)

DB に触らない純関数と、空き番号を引く関数を分ける。

```ts
// 番号タグの形 (docs/111 §2-2)
export const NOTE_NUMBER_PATTERN = /^[1-9][0-9]{3}$/
export const NOTE_NUMBER_MIN = 1000
export const NOTE_NUMBER_MAX = 9999

export function isNoteNumber(tag: string): boolean

// ノートの番号タグ。ちょうど 1 つのときだけ返す (0 個・複数は null)。
// 複数あると「どれを QR に載せるか」が決まらない。印刷は id の URL に倒す
export function noteNumberOf(tags: string[]): string | null

// 短縮 URL。buildItemUrl (validation.ts) と同じく qrBaseUrl() を起点にする
export function buildShortItemUrl(baseUrl: string, number: string): string
  // → `${base}/s/${number}`
```

`src/lib/items/noteNumber.server.ts` (新規、`server-only`):

```ts
// 1000 以上の最小の空き番号。ゴミ箱を含む全行の 4 桁タグを集めて TS で探す
// (1500 行の unnest は seq scan で足りる。read.ts の allTags と同じ判断)。
// 尽きたら null
export async function nextFreeNoteNumber(): Promise<string | null>
```

SQL は 1 本:

```sql
SELECT DISTINCT tag FROM (SELECT unnest(tags) AS tag FROM items) AS t
WHERE tag ~ '^[1-9][0-9]{3}$'
```

テスト (`noteNumber.test.ts`): 形 (999・10000・`01234`・13 桁・`wb01` は偽)、
`noteNumberOf` の 0/1/2 個、URL の組み立て (末尾 `/` の除去は buildItemUrl と同じ)。
`nextFreeNoteNumber` は DB 統合テスト (`src/test/db` の流儀) で、欠番・ゴミ箱の予約・
9999 まで埋まった場合の null を見る。

## 4. `/s/<番号>` の受け

### 4-1. `src/lib/items/legacyPath.ts`

`LEGACY_PATH` に `/s/` を足す。`/s/` は履歴の続き (`/history`) を取らない。
着地の prefix は `/item/` に写す。

```ts
export interface LegacyItemPath {
  key: string
  prefix: '/item/' | '/edit/' | '/print/'   // /s/ は '/item/' に写して返す
  suffix: string
}
```

`/s/<uuid>` は旧番号の形でない (`isLegacyItemNo` が偽) ので null → 404。
短縮 URL に UUID を載せる意味は無いので通さない。

テスト追加: `/s/1234` → `{ prefix: '/item/', key: '1234', suffix: '' }`、
`/s/1234/history` は null、`/s/<uuid>` は null、`/s/` は null。

### 4-2. `src/proxy.ts`

変更なし (`parseLegacyItemPath` の結果で 308 を組むので、prefix が `/item/` に
写っていれば `/s/1234` → `/item/<id>` になる)。`proxy.test.ts` に 1 件足す。

### 4-3. `src/lib/auth/publicPaths.ts`

`ITEM_ID_PREFIXES` に `/s/` を足す。未ログインで公開ノートのシールを読んだとき、
`/item/` と同じ扱い (pass-noindex) で proxy の判定を通し、`redirectLegacyItemPath` の
publicOnly の規則に乗せる。テストは `/item/1003` の既存ケースを `/s/1234` でも通す。

### 4-4. スキャナ `src/lib/external/scanResult.ts`

`itemIdFromUrl` の正規表現を `^\/(?:item|s)\/([^/]+)\/?$` にする。`/s/` の
ときは `isLegacyItemNo` だけ認め、返す path は今までどおり `/item/<番号>`
(ペインが `resolveItemKey` で解く。docs/107 §12)。
テスト: `https://qr.tommie.jp/s/1234` → `/item/1234`、`/s/<uuid>` → 検索に落ちる。

nginx (`deploy/nginx/qr.tommie.jp.conf`) は `location /` が丸ごと app に渡すので変更なし。

## 5. 印刷 QR — `src/app/print/[itemId]/page.tsx`

```ts
const number = item === null ? null : noteNumberOf(item.tags)
const itemUrl = number === null
  ? buildItemUrl(qrBaseUrl(), itemId)
  : buildShortItemUrl(qrBaseUrl(), number)
```

QR の下のラベル:

- 番号あり: **`#1234` を大きく**、その下に見出しを小さく (truncate)。
  ポストイットに写すのは番号なので、番号を主にする
- 番号なし: 今のまま見出しだけ

URL の表示行 (`print:hidden`) はそのまま。番号が無いノートには
「番号を振ると短い QR になります」の 1 行と `/item/<id>` へ戻るリンクを添える
(ボタンは置かない。振る場所はノート表示の 1 か所にする)。

テスト: ページの単体テストは無いので E2E (§9) で QR の中身を読む。

## 6. 「番号を振る」ボタン

### 6-1. サーバーアクション `src/app/actions/number.ts` (新規)

```ts
'use server'
export async function assignNoteNumberAction(itemId: string): Promise<AssignOutcome>
//   'assigned' | 'already' | 'exhausted' | 'missing' | 'rejected'
```

1. `requireUser()`
2. `getItem(itemId)` のタグに番号があれば `'already'` (何も書かない)
3. `nextFreeNoteNumber()` が null なら `'exhausted'`
4. `modifyMemo(itemId, (memo) => addTagToMemo(memo, number))`。
   `addTagToMemo` は 2 行目のタグ行に足す (無ければ 2 行目に挿入)。
   移行で足した旧番号は末尾の行にあるが、置き場所は揃えなくてよい
   (タグの抽出は場所を問わない)
5. `revalidatePath('/item/' + itemId)` と `'/'`

bulkTagAction と同じく本文を書き換えて保存するので、派生列 `tags` も揃う。
git 履歴には、ほかの保存と同じくユーザーが履歴を残したときに載る
(`modifyMemo` 自体はコミットしない)。
デモモードでは出さない (PublicToggle と同じ判断。アクション側でも `isDemoMode()` で断る)。

テスト (`actions.test.ts` の流儀): 番号なし → 本文に `#<空き>` が入る、
番号あり → `'already'` で本文不変、行なし → `'missing'`、尽きた → `'exhausted'`。

### 6-2. 置き場所 — `src/components/item/ItemView.tsx`

操作行 (編集・履歴・QR …) の **QR の左**に「番号」を出す。番号タグが無いノートだけ。
色は docs/82 の規則 (行の中で重ならない色) に従って 1 色決める。
押すと `assignNoteNumberAction` を呼び、結果で `router.refresh()`。
`'exhausted'` は「空き番号がありません (1000〜9999)」を出す。

部品は `NumberAssignButton.tsx` (新規、client)。PendingLink と同じく押してから
戻るまでスピナー。PressTip のラベルは「4 桁の番号を振り、短い QR と手打ちで開けるようにする」。

行の ⋮ メニューには足さない (§10)。

## 7. 手打ちで開く

導線は 2 つ:

- 検索窓に `#1234` (タグ検索で 1 件)。`1234` だけだと全文検索で抵抗値や年にも当たる
- アドレスバーに `qr.tommie.jp/s/1234`

記法ヘルプ (`docs/メモ記法.md` か利用者向けの文書) に「番号タグと短縮 URL」の
節を 1 つ足す。

### 7-1. 決まらないときの倒し先 (2026-10-18 の iPhone 確認で変更)

当初は docs/107 §3-2 のまま「0 件・複数なら全文検索 `/?q=1250`」だったが、
iPhone で確かめると 2 つ困った。

- **未ログインの Safari で `/s/1250` を打つと、検索へ送られてからログインを求められ、
  ログイン後の再読み込みが検索結果に着く**。開こうとしたノートに辿り着けない
  (PWA と Safari は cookie が別なので、Safari の手打ちは未ログインになりがち)
- ログイン済みでも、全文検索 `1250` は型番や年に同じ数字を含むノートまで混ざる
  (実データで `1250` は 3 件、`#1250` は 1 件)

直した形:

| 状態 | 1 件 | 0 件・複数 |
| --- | --- | --- |
| ログイン済み | 308 でノートへ | 307 で**タグ検索** `/?q=%231250` へ |
| 未ログイン | 公開ノートなら 308 | **同じ URL のままログイン画面** (rewrite)。ログイン後の再読み込みで全ノートから引き直す |

- 未ログインでノートの有無や id は出ない (どの場合もログイン画面)。
  以前の「検索へ送る」も結局ログイン画面になっていたので、漏れる情報は変わらない
- タグ検索で 0 件のときの「新規登録」は、検索語が `#1250` の形でも出す
  (`registerCodeOf` が `#` を 1 つ剥がす。`lib/external/scanRegister.ts`)。
  docs/107 §3-2 の「0 件なら新規登録が出る」はこれで保たれる
- `/item/1003` (印刷済みシール) も同じ規則になる。未ログインでシールを読んだときに
  ログイン → ノート、と着くようになった

## 8. 段階と配布

1 回の配布。migration は無い (列を足さない)。

配る前に手元で: 単体 + DB 統合 + E2E (§9) を通す。配布後に iPhone で:

- 旧シール (`/item/1003`) が今までどおり開く (回帰)
- 番号の無いノートを開き「番号」→ チップに `#<番号>` が出る → QR を開くと
  `/s/<番号>` の小さい QR (25x25) とラベル `#<番号>`
- その QR を iPhone のカメラアプリで読む → ノートが開く (ログイン済み)
- 公開ノートの QR を未ログインの Safari で読む → 開く。非公開なら検索 → ログイン
- アプリ内スキャナで同じ QR → ペインで開く (全画面遷移しない)
- Safari のアドレスバーに `qr.tommie.jp/s/<番号>` を手打ち → 開く

## 10. 見送り

- **`/new` で自動採番**。docs/107 §5 で「＋」に番号を付けないと決めた。全行に
  チップが戻る。欲しくなったら設定 (user_settings) で選べる形で足す
- **行の ⋮ メニューに「番号を振る」**。一覧から番号を振る場面は想像しにくい。
  ノート表示の 1 か所で足りなければ actions 配列に足すだけ
- **単一トークンの 4 桁でタグ 1 件ならそのまま開く** (検索の近道)。`/s/` の手打ちで足りる
- **同時押しの重複防止** (保存後に再検査して振り直す)。起きても検索一覧で見える
- **番号の付け替え・外す操作**。タグなので編集画面で消せば済む
- **接頭辞付きの番号** (§2-2)
- **`/s/` の訂正レベルを L に下げる** (13-kick-work docs/33 と同じ理由で M のまま)

## 14. 実装で計画から変えたこと (2026-10-18)

- **「番号」を出す条件は番号タグが 1 つも無いこと** (`hasNoteNumber`)。
  `noteNumberOf` (ちょうど 1 つ) で見ると、番号が 2 つあるノートに 3 つ目を足してしまう
- **アクションはフォーム送信** (`assignNoteNumberAction(formData)`、PublicToggle と同じ形)。
  空き番号が尽きたときとノートが無いときは投げる (エラー画面)。結果の種類は返さない
- **E2E は Location を相対で読む**。proxy の 308 は相対の Location を返すことがある
- **QR の版は単体テストで見る** (`noteNumber.test.ts`。`qrcode` で版 2)。E2E は
  img の alt (`QR: <URL>`) で中身を確かめ、画像の読み取りはしない
- **DB 統合テストは書かなかった**。空き番号の探索は純関数 `firstFreeNoteNumber` に出して
  単体テストで見る。SQL は正規表現 1 つで、TS と同じ集合であることを単体テストで照合する
- **決まらないときの倒し先を変えた** (§7-1)。未ログインは同じ URL でログイン画面、
  ログイン済みはタグ検索
- **「番号」が iPhone で非常に遅かった件は原因を特定できていない**。本番の DB の
  書き込み時刻と nginx の応答完了が同じ秒で、空き番号の問い合わせは 70 ms、
  ローカルの計測は全画面 0.12 秒・ペイン 0.83 秒。サーバの処理は速い。
  当時 vps2 はスワップ 807 MB・kcompactd が CPU 83% のメモリ逼迫で、
  nginx の access log に処理時間が無いため開始時刻が分からない。
  再発時に切り分けるには nginx の log_format に `$request_time` と
  `$upstream_response_time` を足す (ホスト側の設定なので手で入れる)
