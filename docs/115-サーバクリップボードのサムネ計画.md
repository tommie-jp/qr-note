# サーバクリップボードのサムネ計画

docs/114 のサーバクリップボードで、「サーバへコピー」した後に、メニューの
「サーバからペースト / 保存 / 共有」の行の下へ、**枠に入っているものの中身が分かる
見本 (サムネ)** を出す。画像は縮小した絵、画像以外もなるべく中身が分かる形にする。

## 0. なぜ

- いまの予告は「画像 1.2MB・3 分前」「議事録.docx 2.5MB」の文字だけ。何を送ったか
  (どの写真か、どの動画か) は受け取ってみないと分からない
- 枠は 1 つで上書きなので、「いま入っているのは、さっき送ったあれか」を押す前に
  確かめたい。別の端末で上書きされていれば、絵が変わって気づける
- 一覧のサムネ (docs/23) と同じく、**見本は派生物**で、無くても機能は成立する。
  作れなければ出さないだけで、送受信を止めない

## 1. 決めたこと

### 1-1. 見本はサーバの枠に 1 つだけ持つ (置くときに作る)

- 表 `clipboard_slots` に `thumb` (bytea、WebP) と `preview` (text、抜粋) を足す。
  メニューを開くたびに本体 (最大 30MB) を取って端末で作り直すのは重く、受け取る
  端末では読めない形式 (HEIC) もある。**置くときに 1 回だけ作り**、後は小さな
  WebP (数十 KB) を配る
- 文字 (kind `text`) は本文がメタに同梱されているので、列も API も要らない。
  先頭数行をそのまま見本にする
- 置き直せば見本も置き直す。文字で上書きしたら `thumb` と `preview` は null
  (「どちらか 1 つ」の約束を列ごと守る。docs/114 §1-1)

### 1-2. 種類ごとに「どこで」「何を」作るか

| 種類 | 見本 | 作る場所 | 材料 |
| --- | --- | --- | --- |
| 文字 | 先頭 4 行の抜粋 | 不要 | メタの `text` |
| 画像 | 縮小した絵 (長辺 384) | サーバ | `makeThumbnail` (sharp) |
| 動画 | 先頭コマの絵 + ▶ 印 | クライアント | `makeVideoThumbs(file).poster` |
| PDF | 1 ページ目の絵 + PDF 印 | クライアント | pdf.js (`loadPdfDocument`) |
| テキストファイル | 先頭 300 字の抜粋 (等幅) | サーバ | 正規化済み UTF-8 の先頭 |
| 音声 | 波形の絵 (Phase 4、任意) | クライアント | `decodeAudioData` → canvas |
| Office | 本文の抜粋 (Phase 3) | サーバ | fflate で中の XML を読む |
| それ以外 | 拡張子の札 + 名前 + 大きさ | 不要 | メタの `name` と `bytes` |

**作る場所の決め方は添付と同じ。** サーバに ffmpeg も pdf.js も持ち込まない
(docs/14・docs/72 の判断)。画像は sharp が居るのでサーバで、動画と PDF は
ブラウザでしか描けないのでクライアントで作って、**別の口で後から貼る**。

### 1-3. クライアントが作った見本の受け口

- `PUT /api/clipboard/thumb` に、画像の生バイト (PNG/WebP/JPEG、**200KB 以下**) を送る。
  本体の `PUT /api/clipboard/data` が返したメタの `updatedAt` を `X-Slot-Version`
  ヘッダに添える
- サーバは `isValidVideoThumb` (大きさと画像の署名) で受け、**必ず `makeThumbnail` で
  WebP に作り直して**置く。クライアントのバイト列をそのまま配らない
  (storeVideo.ts の poster と同じ扱い)
- **版が合うときだけ貼る。** `updateMany({ where: { userName, updatedAt: version } })`
  で、別の端末が先に上書きしていれば 0 件 → 409 で返し、クライアントは黙って諦める
  (古い動画の絵が新しい枠に付くのを防ぐ)
- **`@updatedAt` を進めない。** Prisma は update のたびに `updatedAt` を今に書き換える。
  見本を貼ったときに進むと期限 (10 分) が延び、版も変わって次の attach が外れる。
  `data` に `updatedAt: version` を**明示して**同じ値を書き戻す (明示すれば Prisma は
  その値を使う)

### 1-4. 配り方

- `GET /api/clipboard/thumb` … WebP の生バイト。`Cache-Control: no-store`、
  `X-Content-Type-Options: nosniff`、`Content-Security-Policy: sandbox`。無い・期限切れ・
  見本の無い枠は 404
- メタ (`GET /api/clipboard`) に `hasThumb: boolean` と `preview?: string` を足す。
  画面は `hasThumb` のときだけ `<img src="/api/clipboard/thumb?v=<updatedAt>">` を出す
  (`?v=` は置き直しで絵が変わっても古い絵を掴まないため。no-store と二重の守り)
- デモは他の口と同じく 403。門は `guardRequest(request, { demo: 'deny' })`

### 1-5. 見本の見た目

```text
┌─────────────────────────────────┐
│ ⇧ サーバへコピー                   │
│ ⇧ ファイルを選んで送る              │
│ ⇩ サーバからペースト   画像 1.2MB・いま │
│ ┌───────────────────────┐          │
│ │                       │          │  ← 画像: 高さ最大 160px、
│ │     (縮小した絵)        │          │     object-contain、角丸
│ │                       │          │
│ └───────────────────────┘          │
│   どれも 10 分で消えます…    保存 消す │
└─────────────────────────────────┘
```

- 置き場は「ペースト / 保存 / 共有」の行の**直下**、説明文の上
- 高さの上限は 160px (`max-h-40`)。メニューはせり上がるシートで、縦に伸びると
  上の項目が画面外へ出る。横は行の幅いっぱい (`max-w-2xl` の中)
- 動画は絵の中央に既存の `PlayBadgeIcon`、PDF は左上に「PDF」の札
- 文字・テキストファイルの抜粋は 4 行で切る (`line-clamp-4`)。テキストファイルは等幅
- Office・その他は「札」: 拡張子を大きく (DOCX / XLSX / ZIP)、横に名前と大きさ。
  色は系統で分ける (Word 系は青、Excel 系は緑、PowerPoint 系は橙、他は灰)。
  Phase 3 で抜粋が取れた Office は、札の下に抜粋を足す
- 見本を押しても何も起きない (押せる物に見せない)。受け取る操作は上の行

### 1-6. 送った直後の見え方

- 画像とテキストファイルは、本体の PUT が返った時点で見本も出来ている
  (サーバが置くときに作る) → 「送りました」と同時に絵が出る
- 動画と PDF は、本体の PUT → クライアントで絵を作る → thumb の PUT、の順。
  その間は札だけが出て、貼れたら絵に置き換わる。絵が作れなければ札のまま
- 送っている間にメニューを閉じられても、thumb の PUT は進む。次に開いたときの
  GET で `hasThumb` が立っていれば出る
- 見本の生成・貼り付けの失敗は**知らせない** (console には残す)。本体は届いている

## 2. API

| メソッド | パス | 本文 | 応答 |
| --- | --- | --- | --- |
| GET | `/api/clipboard` | なし | メタに `hasThumb`・`preview?` が増える |
| GET | `/api/clipboard/thumb` | なし | WebP の生バイト。無ければ 404 |
| PUT | `/api/clipboard/thumb` | 画像の生バイト (200KB 以下) | `{ slot }` |

- thumb の PUT は `X-Slot-Version` ヘッダ (本体のメタの `updatedAt`) を要る。版が
  違えば 409、枠が無ければ 404
- thumb の PUT は `readBodyBounded(request, MAX_VIDEO_THUMB_BYTES)` で読む
  (超えたら 413)。chunked でも上限を守る (docs/114 §9-1)
- `X-Slot-Version` は ISO 8601 の文字列。読めない日時は 400

## 4. 進め方

### Phase 1. 表・口・画像とテキストの見本・表示部 (TDD)

1. `slot.ts`: `parseSlotMeta` が `hasThumb`・`preview` を読む、`previewLines` が
   4 行で切る (空行は詰めない)。テストから
2. 移行とモデル。ローカルは `prisma migrate deploy` で当て、前後で `\di`
3. `slotStore.ts`: 書くときに `thumb`・`preview` も書く、文字で上書きすると null、
   `attachSlotThumb` は版が合うときだけ 1 件・`updatedAt` を進めない、`readSlotThumb`
4. `slotPreview.ts`: PNG/JPEG → WebP の見本ができる、壊れた画像は null、
   テキストは 300 字で切る (code point)、動画・Office は両方 null
5. `api/clipboard/thumb/route.ts`: 門の 3 検査、GET の 404 とヘッダ、PUT の 200KB 超 413・
   画像でない 400・版違い 409・枠なし 404・正常は WebP に作り直して置く
6. `api/clipboard/data/route.ts`: 画像を置くと `hasThumb: true`、テキストを置くと `preview`
7. `SlotPreview.tsx`: 種類ごとの描き分けを `renderToStaticMarkup` で固定
   (画像は `<img>`、文字は抜粋、動画は札 + ▶、Office は拡張子の札)
8. ここで**画像を送って絵が出る**ところまで実機に出せる

### Phase 2. 動画と PDF (クライアントで作る)

1. `slotThumbClient.ts`: 動画は `makeVideoThumbs` の poster、PDF は pdf.js。
   テストは依存を差し替えて「どちらを呼ぶか」「失敗で null」を見る
2. `serverClipboard.ts` の `attachThumbIfPossible`: 本体の PUT の後に呼ぶ、
   `X-Slot-Version` にメタの `updatedAt`、409 と失敗は握る。テストは fetch を差し替え
3. hook: 貼れたらメタを置き換える
4. E2E: 小さな PDF (手書きの最小 PDF) を送ると `hasThumb` が立ち、`<img>` が出る。
   動画は chromium が合成の mp4 を描けないので札で止まることだけ見る
   (絵は iPhone と Windows の実機で)

### Phase 3. Office の抜粋 (fflate)

- docx は `word/document.xml`、xlsx は `xl/sharedStrings.xml`、pptx は
  `ppt/slides/slide1.xml` を読み、タグを落として先頭 300 字。fflate は ZIP 取り込みで
  既に居る
- **解凍爆弾よけ**: 読むのは上の 1 エントリだけ、展開は 2MB (`OFFICE_XML_MAX_BYTES`)
  で打ち切る (`unzipSync` の filter、または `Unzip` のストリームで数える)。
  中身の XML は文字として扱い、解釈しない (タグを正規表現で落とすだけ)
- 旧 Office (doc/xls/ppt、OLE) と ODF は対象外。札のまま

### Phase 4 (任意). 音声の波形

- `AudioContext.decodeAudioData` で復号し、384×96 の canvas に波形を描いて thumb に。
  10MB の mp3 を iPhone で復号するのに数秒かかる。復号できない形式は札のまま
- 欲しくなってから。音声は「名前と長さ」で足りることが多い

### Phase 5. 確認と配布

- 実機 (iPhone・Windows): 写真・スクショ・HEIC (JPEG になった絵)・動画の先頭コマ・
  PDF の 1 ページ目・csv の抜粋・docx の札 (Phase 3 なら抜粋)
- 配布後に `\d clipboard_slots` と PGroonga 索引を確認 (移行が入る)

## 5. 落とし穴 (先に分かっていること)

- **`@updatedAt` は update のたびに進む。** 見本を貼る update で `updatedAt` を明示して
  書き戻さないと、期限が延びて版もずれる (§1-3)
- **クライアントの絵はそのまま配らない。** 必ず `makeThumbnail` で作り直す
  (SVG やスクリプト混入の余地を残さない。`isValidVideoThumb` が署名で弾くのと二重)
- **メニューは閉じると部品ごと捨てられる。** thumb の PUT の結果を受ける部品が無くても
  サーバには貼られている。次の GET で見える (docs/114 §7 と同じ)
- **pdf.js は数 MB。** PDF を送るときだけ `import()` する (pdfService.ts と同じ)。
  メニューを開いただけで読まない
- **iOS の canvas は WebP を書けない** (PNG が返る)。200KB を超えるなら JPEG で書き直す
  (`redrawImage` で `image/jpeg` 0.8)。サーバが WebP に作り直すので形式は問わない
- **HEIC の見本は変換後の JPEG から作る。** `prepareSlotFile` の後に `makeSlotPreview`
  を呼ぶ順にする (変換前の HEIC は sharp が読めない)
- **アニメ GIF の見本は動く** (makeThumbnail がアニメ WebP にする)。一覧と同じ
- **`<img>` の URL に `?v=` を付ける。** no-store でも、同じ URL を同じ文書内で
  2 回出すとブラウザが描画キャッシュを使い回すことがある
- **見本は秘密を漏らしうる。** 枠と同じ 10 分で消え、同じ門で守られる。
  期限切れの削除は行ごとなので見本も一緒に消える
- **vps のメモリ。** sharp の見本生成は添付の保存と同じ負荷。Office の XML 展開は
  2MB で打ち切る。pdf.js はクライアントなのでサーバの負荷ではない

## 6. やらないこと

- 見本を押して拡大・再生する。受け取りは上の行で、見本は確認のため
- 見本の履歴。枠が 1 つなので見本も 1 つ
- サーバでの動画・PDF の描画 (ffmpeg・pdf.js を持ち込まない)
- Office の見た目の再現 (1 ページ目の絵)。本文の抜粋まで
- 旧 Office (doc/xls/ppt) と ODF の抜粋。札のまま

## 7. 実装の記録 (2026-10-26)

Phase 1〜3 を実装した。Phase 4 (音声の波形) は見送り (札で足りる)。

### 7-1. 計画から変えたこと

- **行の右の概要から名前を外した。** 名前は下の見本 (札) に出るので、行には
  「種類 大きさ・時刻」だけを出す。長い名前で「サーバから保存」の行が 2 行に折れた
  (撮影して判明)
- **1KB 未満はバイトで出す** (「0KB」だと空のファイルに見える)
- 動画の絵は `makeVideoThumbs(file, { withFrames: false })` で静止の 1 枚だけを取る
  (動くサムネのコマ集めの時間を使わない)。videoPoster.ts に引数を足した
- PDF の絵は pdf.js で 1 ページ目を描き、`redrawImage` で長辺 384 の JPEG にしてから送る
  (200KB の上限に確実に収める)

### 7-2. 確かめたこと

- **`@updatedAt` を明示すれば進まない**ことを、ローカルの実 DB で確かめた
  (`attachSlotThumb` の前後で `updatedAt` が同じ。古い版は `stale`)
- fflate の `unzipSync` は宣言サイズの出力枠で展開を打ち切る。宣言を 10 バイトに偽った
  1MB の XML は 10 バイトしか出ない
- vitest: 抜粋の切り方・Office の本文の取り出し (docx・xlsx・pptx・文字参照・2MB 超)・
  置くときの見本・見本の口 (門・作り直し・版・200KB・SVG)・後貼りの握りつぶし・表示の描き分け
- Playwright (chromium): 画像の絵が読み込める・文字の抜粋・**PDF の 1 ページ目が後から
  貼られる** (最小の PDF をテスト内で組み立てて pdf.js で描く)・docx の札と抜粋・描けない
  動画は札のまま
- 390px 幅で撮影し、画像の絵 (高さ 160px 以内) と docx の札・抜粋の見た目を確かめた

### 7-3. セキュリティレビューで直したこと

- **ReDoS (HIGH)**: Office の XML からタグを落とす `/<[^>]*>/g` は、`>` の来ない `<` の
  連なりで二乗時間になる (2MB の `<` だけの docx で数分イベントループが止まる)。
  `/<[^<>]*>/g` にして線形にした (2MB で 4ms)。あわせて、タグを落とす XML を先頭 256KB、
  テキストファイルの抜粋の材料を先頭 64KB に絞った
- **同名エントリ (MEDIUM)**: 同名の `word/document.xml` を大量に並べた zip で展開が件数ぶん
  走らないよう、最初の 1 件だけを読む (fflate の filter で 2 件目以降を断る)。重複エントリの
  zip を手元で組めないので、テストは書いていない
- **見送り (MEDIUM)**: メタの取得 (`hasThumb` を決めるため) で見本の絵 (数十 KB) を毎回
  読む。メタはメニューを開いたときにしか読まないので実害は小さい。気になるなら
  `has_thumb` の列を持つ

### 7-4. 残り

- iPhone・Windows 実機: 動画の先頭コマ (chromium は合成の mp4 を描けない)、HEIC の写真の絵、
  iPhone の PDF
