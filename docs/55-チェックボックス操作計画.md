# 閲覧画面でチェックボックスを押せるようにする計画

markdown タブに出ている GFM のタスクリスト (`- [ ]` / `- [x]`) を、**編集タブへ
切り替えずにその場で押せる**ようにする。単語帳として使うときに、覚えた語へ
チェックを付けて管理できるようにするのが目的。

押すと本文そのもの (`- [ ]` → `- [x]`) が書き換わって保存される。表示だけの
状態をどこかに別に持つ作りにはしない — 正本は常にメモ本文だから
(タグ・プロパティと同じ考え方。[tags.ts](../src/lib/tags.ts))。

## 1. いまの状態

`remark-gfm` は既に入っているので `- [ ]` はチェックボックスとして描画されて
いる。ただし押せない。押せない理由は二重で、

- `mdast-util-to-hast` が `<input type="checkbox" disabled>` を出す。
- `rehype-sanitize` の既定スキーマが `input` に `disabled` を**必ず付け直す**
  (`required.input = {disabled: true, type: 'checkbox'}`)。

つまりスキーマを緩めるだけでは押せるようにならない。react-markdown の
`components` で `input` を差し替え、**サニタイズ後に React が自前で組み立てる**
入力欄にするのが正攻法 (`img` / `a` / `pre` で既にやっている手)。

## 2. どの行を書き換えるかの決め方

押されたチェックボックスが本文の何行目かが判らないと書き換えられない。

`<input>` の hast ノードは合成物で `position` を持たないが、**親の `<li>` は
持っている** (サニタイズを通しても残ることを確認済み)。そこで
[rehypeTaskLines.ts](../src/components/rehypeTaskLines.ts) が
`li.task-list-item` の行番号を、その中の最初のチェックボックスへ
`data-line` として写す。`input` の差し替え側はこれを読む。

注意点:

- **サニタイズの後に走らせる。** 前に置くと `data-line` が落ちる。値は
  パーサ由来 (利用者の入力ではない) なのでスキーマを緩める必要はない。
- **押せない画面でもプラグインは外さない。** 出し分けを 2 か所 (プラグインと
  差し替え) に持つと、片方だけ直したときに「静かに押せないだけ」に戻る。
  刻むのは行番号だけなので、公開ビューに出ても実害はない。
- **ゆるいリスト** (項目の間に空行があるもの) では `<input>` は `<li>` の直下では
  なく `<p>` の中に入る。直下の子だけ見る実装では取りこぼすので、子孫から探す。
- 入れ子のタスクリストは、外側の `<li>` の「最初の」チェックボックスが必ず
  自分のものになる (文書順) ので、内外が混ざることはない。

「DOM 上の N 番目のチェックボックス」で数える方式は採らない。コードフェンスの
中の `- [ ]` やシークレット断片でソース上の順番とずれる。

## 3. 書き換えは「パーサに聞いてから正規表現で置換」

[taskCheckbox.ts](../src/lib/taskCheckbox.ts) の `toggleTaskLine(memo, line, checked)`。

1. その行が正規表現で見てタスク項目の形をしているかを見る (違えば解析もしない)。
2. `remark-parse` + `remark-gfm` で本文を解析し、**その行が本当にタスク項目か**を
   確かめる (`listItem.checked` が非 null で `position.start.line` が一致)。
3. 確かめてからその 1 行だけを正規表現で `[ ]` ↔ `[x]` に置換する。

正規表現だけで判定しないのは、コードフェンスの中の `- [ ]` を本物と読んで
しまうから。逆にパーサだけでは `[ ]` の桁位置が判らないので、両方を使う。
行番号が古い (別タブで本文が変わった) 場合はここで弾き、null を返す。

- 番号付き (`1. [ ]` / `1) [ ]`)、引用の中 (`> - [ ]`)、入れ子のインデントも
  タスク項目になるので、いずれも受ける。
- `[X]` (大文字) もチェック済みとして読む。書き込みは小文字 `x` に統一する。
- 改行コードは保つ ([tagEdit.ts](../src/lib/tagEdit.ts) と同じ作法。Ver1 由来の
  CRLF メモを壊さない)。

## 4. 保存は Server Action で「望む状態」を送る

`toggleMemoTaskAction(itemNo, line, checked)`。裏返せではなく**望む状態**を
送るのは公開トグルと同じ約束で、二重送信や連打で意図と逆に倒れないため。

- `requireUser()` は必須。Server Action は画面を通さず叩ける POST の口。
- `upsertMemo` で保存する (派生列 tags/props も再計算される)。
- `revalidatePath` を呼ぶと、Next.js は**同じ応答の中で**現在のルートを
  描き直して返す (`server-actions.md`)。したがって `router.refresh()` は要らない
  (画像回転はルートハンドラ経由なので必要だった)。
- 押した瞬間はクライアント側の state で即座に反転させ (楽観更新)、失敗したら
  戻して文言を出す。握り潰さない。

## 5. どこで有効にするか

`MarkdownView` に `onToggleTask?: (line, checked) => Promise<void>` を足し、
**渡されたときだけ**押せるようにする。`allowRotate` / `allowSecretEdit` のような
真偽値ではなく処理そのものを受けるのは、この描画部品に「どのノートか」を
持ち込まないため — ノート番号は [ItemView.tsx](../src/components/ItemView.tsx) が
`toggleMemoTaskAction.bind(null, itemNo)` で束ねて渡す。

- [ItemView.tsx](../src/components/ItemView.tsx) (持ち主の閲覧画面) からのみ渡す。
- 公開ビュー・`/docs/*`・印刷では渡さない (保存を伴うため)。
- **シークレット断片の中でも渡さない** ([SecretBlock.tsx](../src/components/secret/SecretBlock.tsx))。
  断片は独立した MarkdownView で描かれるので、行番号が断片の中の番号になり、
  メモ本文の行番号と一致しない。押せるようにするなら断片側の書き換え
  (暗号文の作り直し) が要るので、初版では対象外にする。

## 6. 実装フェーズ (TDD)

1. `src/lib/taskCheckbox.ts` — 行の切り替え (純関数)。フェンス内の擬似タスク・
   番号付き・引用・CRLF・範囲外の行をテスト。
2. `src/components/rehypeTaskLines.ts` — `data-line` の刻印。ゆるいリスト・
   入れ子・非タスクの `li` をテスト。
3. `toggleMemoTaskAction` — 認証・不正な itemNo・本文が変わっている場合。
4. UI — `TaskCheckbox` (クライアント) と `MarkdownView` の差し替え。

## 7. 承知しておく制約

- **編集タブに未保存の変更があるとき**にチェックを付けると、その後の保存で
  チェックが巻き戻る。画像回転と同じ既存の性質 (docs/49 §5)。
- 別タブで本文を書き換えてから古い画面のチェックを押すと、行がずれていれば
  §3 の検算で弾かれる。ただし**同じ行が別のタスク項目になっている**場合までは
  見分けられない (行番号しか手掛かりがないため)。単一利用者の道具として許容する。
- 1 回押すごとにサーバ往復と `ItemView` 全体の再描画 (`renderCircuits` 込み) が
  入る。まとめ送りはしない — 押した分だけ即保存されるほうが、途中で閉じても
  失われないので単語帳向き。再描画を省けないのは、テキストタブとまだ開いて
  いない編集タブが本文をサーバ描画から受け取るため。
- 行の判定はパーサと正規表現の二段構えなので、remark が認めるのに正規表現が
  取りこぼす書き方があると「本文が変わっています」と誤って出る。番号付き・
  引用・タブ・入れ子は試験済み。
