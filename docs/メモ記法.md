# メモ記法

memo 欄で使える Markdown 記法のメモ(2026-08-05 時点)。
実装は `src/components/MarkdownView.tsx` と
`MermaidDiagram.tsx`。

## 基本(Markdown)

- GFM 対応: 表・タスクリスト・打消し線・裸 URL の自動リンク
  (remark-gfm)
- 単一改行はそのまま改行として表示される(remark-breaks)
- 生 HTML は無効(react-markdown のデフォルト + rehype-sanitize)。
  `<img width="...">` のような HTML タグは書けない
- 本文は最大 32,000 文字

## ページ

水平線(`---`)がページの区切りになる。ページが集まったものが 1 つのノート。

```text
1 ページ目の中身

---

2 ページ目の中身
```

- **区切りを書かなければ 1 ページのノート**。今までのノートは何も変わらない
- 閲覧では「前のページ / 次のページ」で送る。URL の `#p3` で 3 ページ目を
  直接開ける(共有したリンクもそのページで開く)
- 編集では下部バーの **＋ページ** で、いま書いているページの**直後**に
  新しいページを足す
- ページ名は**そのページの先頭行**から作る(ノートのタイトルと同じ規則)。
  見出し(`# 出汁`)を先頭に置くとページ送りの帯に出る
- 印刷すると全ページが続けて出る(ページごとに改ページ)。一覧のサムネと
  タグ・検索はノート全体が対象のまま — 2 ページ目のタグでも見つかる

### 罫線とページ区切りの違い

**文字の直後**に引いた線は、その文字の**見出し(下線)**か表の罫線であって
ページの区切りではない。区切りになるのは**前に空行がある**線だけ。

```text
赤LED          ← 見出しになる(ページは割れない)
------
点灯    充電中
----    ----   ← 列を空白で揃えた罫線(ページは割れない)
消灯    完了

前のページの終わり

---            ← 前が空行なので区切りになる
```

- コードブロック・折りたたみ・引用・リストの中の `---` も区切りにならない
- `***` と `___` も Markdown の水平線なので、書けば区切りになる
- 文字の直後に引いた線は**表示では線として出る**ことがある(`----    ----` の
  形)。線は出てもページは割れない — 区切りにしたいときは前に空行を置く

## タスクリスト(チェックボックス)

```text
- [ ] 覚えていない単語
- [x] 覚えた単語
```

- markdown タブの表示のまま**チェックボックスを押せる**。押すと本文が
  `- [ ]` ↔ `- [x]` に書き換わって保存される(編集タブに切り替えなくてよい)
- 番号付き(`1. [ ]`)・引用の中(`> - [ ]`)・入れ子でも使える
- 押せるのは自分のノートを開いているときだけ。公開ページや記法ヘルプでは
  表示のみ
- **チェック状態で検索できる**。`is:todo` で未チェックが残っているノート、
  `is:done` でチェック済みがあるノート([検索の使い方](/docs/search))。
  単語帳なら `#英単語 is:todo` で「まだ覚えていない単語」だけを並べられる
- チェックで絞ると、検索結果に**進み具合**(`チェック完了 3 / 9 (33%)`)が出る。
  「学習済み」「自信あり」のように**できたら付けるチェックを 2 つ**並べると、
  未着手 / 自信なし / 仕上がり の 3 段階を検索で切り分けられる

## 注意書き(アラート)

引用の 1 行目に目印を書くと、色付きの枠になる(GitHub と同じ記法)。

```text
> [!WARNING]
> 通電したまま触らない
```

- 使えるのは `[!NOTE]` `[!TIP]` `[!IMPORTANT]` `[!WARNING]` `[!CAUTION]` の 5 種
- 知らない目印(`[!FOO]`)はただの引用として、文字のまま表示される
- 記法としてはただの引用なので、GitHub や Obsidian に貼っても壊れない

## 折りたたみ

長いログや調査メモを畳んでおける。押すと開く。

```text
:::details[長いログ]
畳んでおきたい中身。画像・表・コードも入れられる
:::
```

- ラベル(`[...]`)を省くと「詳細」と表示される
- 中身はふつうの Markdown として描かれる
- 入れ子にするときは外側のコロンを増やす(`::::details[外]` … `::::`)
- **印刷では閉じたままの中身は出ない**
- この記法は GitHub では効かない(`:::` の行がそのまま文字として見える)

## 脚注

```text
本文のここに注釈を付ける[^1]

[^1]: 注釈の中身。ページの一番下にまとまる
```

- 番号を押すと脚注へ飛び、`↩` で元の位置に戻る
- 脚注はノートの末尾に、区切り線を挟んでまとめて表示される
- 複数ページのノートでは**そのページで使った脚注だけ**がそのページの末尾に出る。
  注釈の中身を別のページ(例えば最後のページ)にまとめて書いても繋がる。
  ただし番号はページごとに 1 から振り直される
- 参照リンク(`[サイト][x]` と `[x]: https://…`)も同じで、定義を別のページに
  書いてよい

## コードブロック

````text
```bash
ls -la
```
````

- 右上の「コピー」を押すと中身をクリップボードに写す(iPhone で範囲選択が
  難しいため)。言語指定のないフェンス・字下げのコードブロックでも出る
- `mermaid` / `circuitikz` は図になるのでコピーボタンは出ない
- 印刷にはボタンを出さない

## 画像

- エディタの添付ボタン・貼り付け・ドロップでアップロードすると
  `![](/api/images/<uuid>.png)` が本文に挿入される
- 対応形式: png / jpeg / gif / webp、1 ファイル 10MB まで
- 保存先: DB の `images` テーブル(bytea)。ファイルシステムには置かないため、
  `pg_dump` だけでメモと画像が一緒にバックアップできる
- 画像はクリックで拡大表示される(もう一度クリックか Esc で閉じる)

## 動画

- 録画・添付でアップロードすると、画像と同じ記法で
  `![録画 2026-08-11 09:12](/api/images/<uuid>.mp4)` が本文に挿入される
- 対応形式: mp4 / mkv(ブラウザ録画の webm) / mov、1 ファイル 30MB まで
- 表示はプレイヤー(再生・共有/保存ボタン)になる。サムネが作れていれば
  再生前の 1 枚として出る
- 音声・PDF・テキストも同じ記法で、URL の拡張子で描き分けている

## 幅指定(独自記法)

alt の末尾に `|数字` を付けると表示幅(px)を指定できる(Obsidian 風)。
**画像と動画で使える。**

```text
![|200](/api/images/xxxx.png)          ← 幅 200px、alt なし
![スクショ|200](/api/images/xxxx.png)  ← 幅 200px、alt「スクショ」
![録画|300](/api/images/xxxx.mp4)      ← 幅 300px までのプレイヤー
```

- 高さは縦横比を保って自動で決まる
- 画像は指定した幅ちょうど、**動画は指定した幅を上限**にして、画面が狭ければ
  そのぶん縮む(指定しない動画の上限は 448px)
- 末尾が数字でない `|` は通常の alt として扱う(例: `![a|b](...)`)
- 音声・PDF・テキスト・シークレットには効かない(`|数字` もラベルの一部として
  そのまま出る)

## シークレット(暗号化した断片)

住所やパスワードなど、**サーバ管理者にも読まれたくない部分だけ**を暗号化して
保存できる(docs/51-部分暗号化計画.md)。

- エディタのツールバー「秘密」でダイアログを開き、中身を書いて保存すると
  `![ラベル](/api/secrets/<uuid>)` が本文に挿入される
- 文字を選んでから押すと、その選択範囲を引き継いで暗号化できる
  (既存メモの一部を後から隠すときの手順)
- 記法の上にカーソルを置いて押すと、その断片を開いて編集できる
- 表示は「🔒 ラベル」のプレースホルダで、押すと Face ID で解錠して中身を出す
- 中身は markdown として描かれる。ダイアログのツール行から、画像・録音・
  録画・お絵かき・OCR・スキャンも使える。どれも暗号化されて保存され、
  復号したものだけが表示される
- スキャンは**読み取った文字を入れるだけ**で、書誌・商品情報は取得しない
  (コードを外部へ送ると「何をスキャンしたか」が漏れるため)
- 音声・動画は復号してから再生するため、シーク (早送り) はできない

覚えておくこと:

- **ラベルは平文のまま本文に残る**(検索にも掛かる)。隠せるのは中身だけ
- **中身は全文検索の対象にならない**。探すための手掛かりはラベルに書く
- 鍵の設定と復旧キーはメニューの「シークレット」から。復旧キーを失い、かつ
  パスキーも全部失うと中身は永久に読めない
- 通常の画像 `![](/api/images/…)` は暗号化されない。隠したい画像は
  シークレットのダイアログから貼ること

## タグ(#tag)

本文に `#` から始まる語を書くと**タグ**になる。タグは検索で使え
(`#タグ名` でそのタグの付いたノートだけを絞り込める)、アイテム画面には
タグの一覧が表示される。実装は `src/lib/tags.ts`。

```text
#トランジスタ #2sc1815 #part-a
```

- `#`(半角)または `＃`(全角)の直後に 1 文字以上続けるとタグになる
- タグに使える文字: 文字・数字・`_`・`-`(日本語も可)。数字だけのタグ
  (`#1608` など)も付けられる
- 大小文字・全半角は同一視される(`#NPN` と `#npn` は同じタグ)
- `# 見出し` のように `#` の直後に空白があるものは Markdown 見出しで、
  タグにならない。URL 中の `#fragment` やコード内の `#` も対象外
- タグは本文から自動抽出される(保存時に再計算)。専用の入力欄はない
- 本文中のタグはクリックするとそのタグ検索になる

## プロパティ(hFE=208)

**行全体が `キー=値` だけでできている行**を書くと、その行は部品の**プロパティ**に
なる。タグで検索すると、ヒットしたノートのプロパティが検索結果の上に
**特性表**として並ぶ(同じ種類の部品を並べて比べられる)。
実装は `src/lib/props.ts` と `src/components/PropsTable.tsx`。

```text
#BJT #2sc2712-y
hFE=208 Vf=700mV
```

上のノートは `#BJT` で検索すると、他の `#BJT` のノートと一緒にこう並ぶ。

```text
部品                    device    hFE   Vf
#4951 2SC2712-Y        —         208   700mV
#4908 2SC2166 NPN-BJT  2SC2166   170   625mV
#4339 BJT NPN SS8050   SS8050    300   630mV
```

- **書く位置は自由**。行全体が `キー=値` なら何行目でもよく、複数行に分けても
  まとめて 1 つの部品のプロパティになる(同じキーを 2 回書いたら先に書いたほうが勝ち)
- **散文に混ざった `キー=値` は拾わない**。`実測では hFE=195 だった` のような行は
  行全体が `キー=値` ではないので、ただの本文として扱われる。
  だから本文中で気軽に `=` を使ってよい
- `=` の前後に空白を入れない(`hFE = 208` はプロパティにならない)
- キーは英字で始める(`hFE` `Vf` `Vceo` `device`)。大小・全半角は同一視される
  (`hFE` と `HFE` は同じ列)。表のヘッダには最初に書いた綴りが出る
- 値は空白を含まなければ何でもよい(`208` `700mV` `0.7V` `-40` `120～200`
  `TO-92` `2SC1815`)。表には書いたまま出る
- 箇条書き(`- hFE=208`)や表の中はプロパティにならない。行頭から `キー=値` だけを書く
- コード・数式の中も対象外

### 部品名を列に出す

`Item` に部品名の欄は無いため、表の「部品」列には番号とメモの要約が出る。
部品名を確実に列として出したいときは `device=` に書く。

```text
device=2SC2712-Y hFE=208 Vf=700mV
```

### 単位は値に付ける

`Vf=700mV` のように単位は値へ付ける。半年後の自分が「Vf はミリボルトで書く」規約を
覚えている保証はないので、値に単位があるほうがノート単体で読める。

ヘッダをクリックするとその列で並べ替わる。**単位の換算はしない**ので、
`Vf=700mV` と `Vf=0.7V` が混ざると数値の大小(700 > 0.7)で並ぶ。
同じ列は単位を揃えて書くと期待どおりに並ぶ。

## 数式(KaTeX)

`$...$` で囲むとインライン数式、`$$` だけの行で囲むとブロック数式として
KaTeX で描画される(remark-math + rehype-katex、サーバー側で HTML に変換)。

```text
インライン: 質量エネルギーは $E = mc^2$ で表せる

ブロック:
$$
\int_0^1 x^2 \, dx = \frac{1}{3}
$$
```

- 使える記法は KaTeX がサポートする LaTeX コマンドの範囲
  ([https://katex.org/docs/supported](https://katex.org/docs/supported))
- 通貨表記など数式にしたくない `$` は `\$` とエスケープする。
  同じ段落に `$` が 2 つあると、挟まれた文字列が数式として
  解釈されることがある
- 構文エラーの数式は、書いた内容がそのまま赤字で表示される

## 回路図(CircuiTikZ)

` ```circuitikz ` フェンスを書くと電子回路図として描画される
(TeX を WebAssembly に移植した node-tikzjax をサーバー側で実行)。

````markdown
```circuitikz
\begin{circuitikz}
\draw (0,0) to[R=$R_1$] (2,0) to[C=$C_1$] (2,-2) node[ground]{};
\end{circuitikz}
```
````

- `\begin{circuitikz}` 〜 `\end{circuitikz}` まで自分で書く。
  `\usepackage{circuitikz}` と `\begin{document}` は自動で付く
  (web で見つけた CircuiTikZ の例をほぼそのまま貼れる)
- 部品やオプションは
  [CircuiTikZ のマニュアル](https://ctan.org/pkg/circuitikz)を参照
- ラベルの `$R_1$` は TeX の数式記法がそのまま使える
- 描画は初回だけ 1 秒ほどかかり、以降はキャッシュから即座に表示される
  (本文を書き換えると描き直す)
- 描画が 10 秒を超えると中断される。TeX は無限ループを書けてしまうため
- 1 つのメモに描ける回路図は 8 個まで
- 構文エラーのときは TeX のエラーログが赤枠で表示される

### 描けないもの

`\special{dvisvgm:raw ...}` のように SVG を直接書き込む記法は、
図として想定していない要素 (リンクや外部画像など) を持ち込めるため、
検査に引っかかって描画エラーになる。回路の記法として使うぶんには問題ない。

### 使えるパッケージ

`circuitikz` のほか、`tikz-cd` / `chemfig` / `pgfplots` / `amsmath` /
`amssymb` / `tikz-3dplot` などが読み込まれている。

## mermaid

` ```mermaid ` フェンスを書くと図として描画される
(mermaid v11.16 を動的 import)。

````markdown
```mermaid

    A --> B
```
````

| `classDiagram` | クラス図 |
| `stateDiagram-v2` | 状態遷移図 |
| `erDiagram` | ER 図 |
| `gantt` | ガントチャート |
| `pie` | 円グラフ |
| `gitGraph` | git ブランチ図 |
| `mindmap` | マインドマップ |
| `timeline` | 年表 |
| `quadrantChart` | 4 象限チャート |
| `xychart-beta` | 折れ線・棒グラフ |
| `sankey-beta` | サンキー図 |
| `block-beta` | ブロック図 |
| `packet-beta` | パケット図 |
| `kanban` | かんばんボード |
| `architecture-beta` | アーキテクチャ図 |

### サイズ調整

図の先頭に init ディレクティブを書くとフォントサイズを変えられる
(フォントに合わせて図全体も縮む)。

```text
%%{init: {"themeVariables": {"fontSize": "12px"}}}%%
```

図はコンテナ幅が上限(useMaxWidth: true)なので、
自然サイズより大きく引き伸ばされることはない。

### 制限(securityLevel: "strict")

- `click` によるリンク・コールバックは無効
- ラベル内の HTML はエスケープされる
- `securityLevel` や `maxTextSize` などの secure 設定は
  init ディレクティブから変更できない

## 問題(quiz)

` ```quiz ` フェンスを書くと、押して答えられる択一問題になる。
資格試験の CBT と同じく、**解答するまで正解と解説は出ない**。

````markdown
```quiz
問: スイッチ S を閉じた直後に流れる電流 $i_0$ [A] は。
1. $0$
2. $\dfrac{E}{R_1}$
3. $\dfrac{E}{R_1+R_2}$
正解: 2
解説: 投入直後のコンデンサは短絡とみなせるので、
回路は $E$ と $R_1$ の直列になる。
```
````

- 行頭のキーワードで区切る。全角のコロン(`問：`)・句点(`1．`)・
  数字(`１.`)も読む。
- **選択肢は 2〜9 個**。番号は 1 から連番で書く
  (`(1)` や `1)` の形は選択肢と見ない)。
- `正解:` は選択肢の番号を 1 つだけ。`解説:` は省略してよい。
- `問:` `選択肢` `解説:` はそれぞれ複数行書ける。
  空行を挟めば解説を段落に分けられる。
- 書き方に誤りがあると、赤枠で「何が悪いか」と元の文字が出る
  (黙ってコードブロックに落ちることはない)。

### 中で使える記法

文章の装飾(太字・リンク・インラインコード・表)と**数式**が使える。
選択肢のように押すところに書いたものは、見出しやリストにしても
中身の文字だけになる。

一方、**本文の拡張記法はカードの中では効かない**。

| 記法 | カードの中では |
| --- | --- |
| `#タグ` | リンクにならない(文字のまま) |
| `> [!NOTE]` などの注意書き | ただの引用になる |
| `![画像\|200]` の幅指定 | 効かない |
| シークレット断片 | 表示できない |
| 脚注(`[^1]`) | 本文の脚注と番号が衝突する。使わない |

凝ったものはフェンスの外に書く(回路図と同じ作法)。

回路図を添えるときは、` ```circuitikz ` フェンスを ` ```quiz ` の**すぐ上**に
並べて書く(問題フェンスの中に図は入れられない)。

答えた状態は保存されない。ノートを開き直せば未解答に戻る。

### 分からないときは

選択肢の下の「解説を見る」を押すと、**解答しないまま**
正解と解説を開ける。当てずっぽうで選ばずに済ませるための逃げ道で、
このときは ○ だけが付き、正誤(○ / ×)の判定は出ない。

### 試してみる

```quiz
問: $R$ [Ω] と $C$ [F] の直列回路の時定数 $\tau$ [s] は。
1. $RC$
2. $\dfrac{1}{RC}$
3. $\dfrac{C}{R}$
正解: 1
```

## 答え隠し(`||答え||`)

`||` で囲んだところが隠れ、`▶` を押すと開く(`▼` で閉じる)。
**1 行 1 語**で単語帳を書くための記法。

```text
1. [ ] infect ||動 ～に感染させる；infection 名 感染(症)||
2. [ ] relocate ||動 ～を移転させる；移転する||
```

上は次のように表示される(押すまで訳は出ない)。

```text
☐ infect ▶
☐ relocate ▶
```

- ノートの右上に**「答えを表示」**が出る。まとめて開いて読むときに使う
  (紙の単語帳の赤シート)。答え隠しがあるノートにだけ出る
- 開いた答えは色が変わる。開いた状態は保存されない(開き直すと閉じている)
- **答えの中に `|` は書けない**。改行も跨がない(1 行に収める)
- **表の中では記法にならない**。GFM の表では `||` が空セルを意味するため
  (`| a || b |` は今までどおり空セル)
- 閉じ忘れ(`||訳`)と空(`||||`)はそのまま文字として出る。文字として
  書きたいときはインラインコード(`` `||` ``)に入れる
- 一覧のカードには答えを出さない(`▶` だけになる)
- **印刷では閉じた答えは出ない**(`:::details` と同じ)
- 検索は本文を引くので、**答えの文字でも検索できる**(隠しているのは表示だけ)

`:::details` との違いは、**同じ行に収まる**こと。`:::details` はブロックなので
1 語ごとにリストが分かれ、1 語 4 行になる。長い解説を畳むなら `:::details`、
単語帳の訳なら `||答え||`。

### 英単語の発音

答えを**発音記号 `/…/` で始める**と、開いたときに発音ボタンが出る。
記法は要らない(発音記号がその目印)。

```text
- [ ] concise ||/kənˈsaɪs/ 簡潔な、要領を得た His answer was concise and clear.||
```

開くとこう表示され、🔈 を押すと US 発音で読み上げる。

```text
☐ concise ▼ 🔈 /kənˈsaɪs/ 簡潔な、要領を得た 🔈 His answer was concise and clear.
```

- 左の 🔈 は**単語**(`||` の直前の英語)、右の 🔈 は**例文**を読む
- 例文と見なすのは、答えの末尾にある `.` `!` `?` で終わる**2 語以上**の英文
- 発音記号そのものは読み上げない。読むのは綴り(ブラウザは発音記号を
  受け付けないため)
- `read` `desert` のように品詞で読みが変わる語は、単語のボタンだと
  どちらか一方になる。**例文のボタンを使う**と文脈で決まる
- 端末の音声を使うので**オフラインでも鳴る**。iPhone は
  「設定 > アクセシビリティ > 読み上げコンテンツ > 声 > 英語」から
  拡張版を入れると自然になる
- **iPhone は「着信音量」で鳴る**(メディア音量ではない)。着信音を切って
  いると、動画や音楽は鳴るのに読み上げだけ無音になる。設定 > サウンドと触覚
  の「着信音と通知音」を上げる。消音スイッチでも黙る
- 発音記号で始まらない答え(電験ノートなど)には何も出ない

## 学習状況の表(matrix)

` ```matrix ` フェンスを書くと、**検索に当たったノートのチェックを
1 枚の表**にする。開くたびに集計し直すので、いつでも最新になる。

````markdown
```matrix
#電験三種
```
````

**検索式 1 行だけで表になる。** 列はノートに出てきたチェックがそのまま並び、
並び順は番号順になる。既定から外したいときだけ設定を足す。

````markdown
```matrix
#電験三種 !#後回し
sort=updated
col=学習済み,自信あり
```
````

| 書くところ | 意味 |
| ------------ | ------ |
| 1 行目 | 対象を決める検索式(検索窓と同じ書き方)。空なら全部 |
| `sort=` | 並び順。既定は `itemNo`(番号順) |
| `col=` | 列に出すチェックの名前。カンマ区切りで 4 つまで。**省略すると検索結果のノートに出てきたチェックが並ぶ** |
| `mark=` | セルの記号を **未 → 済** の順で。3 つ目は「項目なし」 |

- **1 行目は必ず検索式**として読む。`#bjt hFE=195` のようなプロパティ
  検索もそのまま書ける。
- `sort=` に書けるのは `itemNo` / `updated` / `accessed` / `title` と、
  その逆順(`itemNoDesc` / `updatedAsc` / `accessedAsc` / `titleDesc`)。
  URL の `?sort=` と同じ言葉。
- 大文字小文字と全角は気にしなくてよい(`SORT=ItemNo` も通る)。
- `col=` の区切りは**全角カンマでもよい**(`col=学習済み，自信あり`)。
  読点(`、`)は名前の一部として扱うので区切りにならない。
- 書き方に誤りがあると、赤枠で「何が悪いか」と元の文字が出る
  (`cols=` のような綴り違いは正しい綴りを教える)。

### 表の読み方

| 記号 | 意味 |
| ------ | ------ |
| ✓ (緑) | チェック済み |
| ☐ (赤) | 未チェック |
| — (灰) | **そのノートにその名前の項目が無い** |

チェックの列の見出しは、列の幅を記号 1 文字ぶんまで狭めるために
**横に寝かせて**表示する (下から上へ読む)。

`—` を分けているのは、`- [ ] 自信あり` の書き忘れを見つけるため。
未チェックと同じ印にすると、書き忘れが「まだやっていない」に紛れる。

表の上には件数と、列ごとの **率と実数**(`学習済み 66.6% (6)`)が出る。
率の分母は**その項目を持っているノートの数**なので、`—`(項目なし)の行は
数に入らない。切り上げないので、`100.0%` は本当に全部付いたときだけ出る。

記号は `mark=` で変えられる。

````markdown
```matrix
#電験三種
mark=🟥✅️
```
````

- **未 → 済** の順で 2 つ。3 つ目を書くと「項目なし」の記号になる
  (`mark=🟥✅️➖`)
- 絵文字でも漢字でもよい(`mark=未済`)。2 つか 3 つ以外はエラー
- 記号の間は空けても、カンマで区切ってもよい(`mark=☐ ✓` / `mark=☐,✓,—`)。
  空白とカンマは記号として数えない
- 絵文字は自前の色を持つので、既定の緑/赤は付かない(漢字や英字なら付く)
- 読み上げは「済 / 未 / 項目なし」のまま変わらない
- 状態 1 列(`col=` を省いたとき)の記号は変わらない

行の番号を押すとノートが開く。そのとき**検索式も一緒に渡る**ので、
本文の下に「← 前 / 次 →」が出て、表 → 1 問目 → 次 → … と回って
戻ってこられる。

### 列を省くと

`col=` を書かなければ、**検索結果のノートに出てきたチェックの名前**が列になる。
多く出てきた名前が左、同数なら先に出てきた順。5 種類以上あるときは 4 列までで、
残りは件数を知らせる(`col=` で選べる)。

名前を書いていないチェック(`- [x]` だけ)しか無いときは、代わりに**状態**の
1 列になる。

| 表示 | 意味 |
| ------ | ------ |
| ☐ 未着手 (赤) | チェックが 1 つも付いていない |
| ◐ 学習中 (黄) | 一部だけ付いている |
| ✓ 習得 (緑) | 全部付いている |

### 承知しておくこと

- 対象になるのは**チェックを 1 つ以上持つノート**だけ。
- 列の名前は文字が一致したものだけを拾う(前方一致はしない)。
  ノート側で `- [ ] 学習済み` と表記を揃えておく。
- 表に載るのは 200 件まで。溢れたら件数を「全 500 件中 200 件」と断り、
  率も**載っている 200 件のぶん**として出す(残りは読んでいないので数えない)。
- 1 つのノートに置ける表は 4 つまで。
- **公開したノートでは表が出ない**(コードブロックのまま出る)。
  表には非公開のノートの番号や見出しが並ぶため。
