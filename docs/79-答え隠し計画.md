# 答え隠し計画 (`||答え||`)

単語帳を**1 行 1 語**で書けるようにする。答えは `||` で囲んで隠し、
押した行だけ開く。

```markdown
1. [ ] infect ||動 ～に感染させる；infection 名 感染(症)||
2. [ ] relocate ||動 ～を移転させる；移転する||
```

見た目の目標は市販の単語帳 (`samples/03` = 英単語ターゲット) で、
**見開きに 50 語が一望できる密度**。この密度が機能の本体で、
記法の見栄えではない。

## 1. なぜ `:::details` では駄目か — リストが割れていた

いまの書き方は 1 語につき 4 行で、ラベルを 2 回書く。

```markdown
- [ ] word1
:::details[word1]
日本語訳1
:::
```

不便の本体は行数ではなく**リストの分断**だった。実測 (描画と同じ
プラグイン列で解析):

```text
:::details を挟む            フェンスを挟む (字下げなし)
list                         list
  listItem                     listItem
containerDirective  ← 分断    code        ← 同じく分断
list                         list
  listItem                     listItem
containerDirective           code
```

50 語書けば 50 個の独立したリストになる。行間が場所によって食い違うのも
(86769d4 で直した loose list の問題の親戚)、ここから来ていた。

### `answer` フェンスにしても直らない

当初の案は ` ```answer ` フェンスだったが、採らない。

- **字下げなしのフェンスも同じくリストを割る** (上の実測)。
- 字下げすれば `listItem > paragraph + code` と入れ子にはなるが、`code` は
  段落の**次のブロック**なので、答えは必ず単語の**下の行**に出る。
  `□英単語 ▶日本語訳` と同じ行に並べるには、答えがその行の**中身**
  (inline) でなければならない。
- 1 語 3 行の入力コストが残る。50 語で 150 行、iPhone で打つ機能としては重い。

**行内に置きたいものは行内記法で書く。** ブロックの器を行内に見せる CSS の
細工で寄せる手はあるが、ブロックモデルと戦うことになるうえ入力コストは
減らない。

## 2. 記法: `||答え||`

- Discord / Obsidian のスポイラー記法と同じ綴り。覚え直す負担が小さい
- 答えの中に `|` は書けない (表の記法と見分けが付かない)。改行も跨がない
- 空 (`||||`) と閉じ忘れ (`||訳`) は記法にせず**文字のまま残す**。
  壊れた入力を例外にせず「それらしく」読む既存の流儀 (docs/56 §5)
- 文字として書きたいときはインラインコード (`` `||` ``) に入れる

### 表の中では記法にしない

GFM の表では `||` が**空セル**を意味する (`| a || b |`)。表の中で記法に
すると、書いた表が黙って壊れる。`tableCell` の下は変換しない。

`link` の下も変換しない。開くのは `<button>` なので、`<a>` の中に置くと
不正な入れ子になる。

### 行内の 1 つのテキストの中だけを見る

`||` の間に強調やリンクが挟まっているもの (`||**訳**||`) は記法として
扱わない。単語帳の答えは素の文字なので足りるし、跨いで探すと閉じ忘れの
解釈が難しくなる。**取りこぼしても文字のまま出る**ので、静かに消えない。

## 3. 実装は remarkTagLinks の双子

[remarkAnswerSpoiler.ts](../src/components/remarkAnswerSpoiler.ts) は
[remarkTagLinks.ts](../src/components/remarkTagLinks.ts) と同じ形
(mdast の `text` ノードだけを見て分割する)。だから `code` /
`inlineCode` の中は自動で対象外になる。

- 出力は `data.hName` で `span` に差し替えた `emphasis` ノード +
  `answer-spoiler` の class。**remarkAlerts が blockquote に class を刻んで
  部品を差し替えるのと同じ作法**で、サニタイズはその class 1 つだけ許可する
- 差し替えは `spanWithAnswer` ([markdownPipeline.tsx](../src/components/markdownPipeline.tsx))。
  **KaTeX が作る span もここを通る** (数式は sanitize の後に作られる) ので、
  目印を持たない span は素のまま返すこと
- プラグインは `BASE_REMARK_PLUGINS` ではなく **MarkdownView 側**に足す
  (remarkTagLinks と同じ)。一覧のプレビューに押せる部品を置かないため

## 4. 閉じているときは場所を取らない

- 閉じている間は印 (`▶`) 1 文字だけ。**幅を残してぼかす方式は採らない** —
  答えの長さがヒントになるうえ、1 行 1 語の密度が崩れる
- 開いた中身は**開くまで描かない**。`display: none` で持つと、ページ内検索や
  ソースの表示から答えが読める。印刷にも出ない (`:::details` の閉じた中身が
  出ないのと同じ)
- 開いた答えは色を変える (`text-rose-700`)。50 行開いたときに語と訳が目で
  分かれる (`samples/03` が訳をピンクで刷っているのと同じ理由)
- 開いた状態は**保存しない**。quiz カード (docs/58 §3) と同じ約束

### ノート全体の「答えを表示」

紙の単語帳の**赤シート**に当たる操作。50 語を 1 語ずつ押して確かめるのは
紙より不便なので、まとめて開ける口を初版から用意する。

- 状態は context で配る ([RevealAllAnswers.tsx](../src/components/answer/RevealAllAnswers.tsx))。
  サーバで描いた本文を children としてそのまま通すので、本文の描画は
  サーバのまま (client なのは状態を持つためだけ)
- **答え隠しを持つノートだけに出す** (`hasAnswerSpoiler(memo)`)。持たない
  ノートに出すと、押しても何も起きないボタンが並ぶ
- 判定はコードフェンスの中まで見分けない安い走査。外した場合の症状は
  「押しても何も開かないボタンが出る」だけで、答えが漏れる向きには倒れない

## 5. 一覧には答えを出さない

隠した物がカードに出ていたら隠した意味がない。2 つの経路を塞ぐ。

| 経路 | 塞ぎ方 |
| --- | --- |
| カードの要約・本文プレビュー | `stripLineMarkdown` の表に**中身ごと落とす**規則を足す |
| ノート全体のプレビュー画 | 同じプラグインを `mask` で通し `▶` の文字だけにする |

前者は `memoSummary` / `memoPreview`、後者は `NotePreviewThumb`。

要約の他の記法 (太字・リンク) は「剥がして中身を残す」のに、これだけ
**中身ごと落とす**のは意図的。

## 6. サーバに触らないので制限が無い

`matrix` (docs/77) と違って集計をしないので、公開ノートでもオフラインでも
そのまま動く。漏れの心配も無い。

## 7. 承知しておくこと

- **番号が出ない。** `1. [ ]` と書いても、タスク項目は
  `[&_li.task-list-item]:list-none` (MarkdownView の PROSE_TWEAKS) で
  マーカーを消しているため、`samples/03` の `□ 1 infect` の「1」は出ない。
  出したいなら「番号付きのタスクリストだけマーカーを戻す」別の変更が要る
- 答えが長いと iPhone 幅で 2 行に折り返す。1 行に収めたいなら答えを短く
  書く (紙の単語帳も列幅で切っている)
- 検索は今までどおり本文を引くので、**答えの文字でも検索できる**
  (隠しているのは表示だけ。正本は本文という原則のまま)
- `- [ ] 学習済み ||メモ||` のように書くと、`matrix` の列の名前
  (`checkStates` のラベル) に `||メモ||` が混ざる。単語帳と進捗表を同じ
  ノートで混ぜない前提で許容する

## 8. やらないこと

- **`{{答え}}` 記法** — `||` が表と衝突する場合の代替案として検討したが、
  除外 (§2) で足りた。2 通りの綴りを受け付けると、やめられなくなる
- **答え付きの印刷** — いまは閉じた答えは印刷されない。「答え付きで刷る」は
  別の要望として後から足せる
- **語と訳の入れ替え (逆方向のテスト)** — 記法は「隠す場所」しか持たない。
  訳から語を当てたいなら行を逆に書く
- **quiz との統合** — quiz は択一・採点あり (試験の再現)、こちらは自己採点の
  暗記カード。役割が違うので分けたまま
