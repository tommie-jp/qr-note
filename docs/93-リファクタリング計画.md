機能を足さず、挙動を変えずに、アプリ本体 (`src/`・`scripts/`・`do*.sh`・
`docs/`) の構造を整える。535 コミット・92 本の計画書を経て、1 ファイルに
複数機能が同居する箇所と、同じ形のコードが散らばった箇所が目立ってきた。
本書はその全体像と、壊さずに直す順番を決める。

対象は `qr-search/` (アプリ本体リポジトリ) のみ。`ver1/`・`qr-demo/`・
ワークスペース側は触らない。

## 1. 方針

- **挙動を変えない**。UI・API・DB スキーマ・URL は据え置く。
  変えたくなったら別の計画書にする
- **1 ブランチ 1 テーマ**。共有ヘルパ 1 家族、巨大モジュール 1 本、
  クラスタ 1 つ、が単位。ff-only で `main` に入れる
- **順番は「安全網 → 共有基盤 → 巨大モジュール分割 → 部品分解 →
  ディレクトリ移動」**。ツーリング (Phase 5) は `src/` と独立なので
  いつでも並行できる
- **ディレクトリ移動は最後、かつクラスタごと**。理由は 3 つ。
  (1) 並行編集との衝突を短時間に閉じ込める、(2) 中身を割ってから
  動かせば移動の diff が小さい、(3) コメントと docs のパス参照を
  1 回で追随できる
- **バレル (`index.ts`) は作らない** (現状 0 本の流儀を保つ)。例外は
  `app/actions/` (import 10 か所を動かさないため) と
  `components/icons/` (30 か所) の 2 つだけ
- **import の書き換えは手でやらない**。`ts-morph` か `sed` + `tsc` で
  一括し、`grep` でコメント・docs のパス参照を拾う
- **先に葉を切る**。`server-only` を貼る前に、型と定数だけの葉
  (`circuit/types.ts` など) を切り出して、クライアントが合法的に
  import できる先を用意する
- **テストは移動の前に書く**。直接テストが無い巨大モジュールは、
  分割で生まれる純粋関数にテストを付けてから中身を動かす
- 新しい依存は最小限。状態管理ライブラリ・jsdom・testing-library は
  入れない (§11)

## 10. 落とし穴 (先に分かっていること)

- `server-only` は vitest (node 環境) で import すると throw する。
  §2-2 の alias を先に入れないとテストが全滅する
- `outputFileTracingIncludes` はルートパス文字列に依存。`src/app` の
  ルートは動かさない (§6-3)
- `proxyClientMaxBodySize` (`next.config.ts`) と `uploads.ts` と
  `proxy.ts` の matcher (`api/import$` 除外) は 3 者で 1 つの不変条件。
  テストが押さえているのは前 2 者だけ
- 並行編集: ユーザーは同じツリーを編集する (memory)。移動 PR は
  時間を合わせて短時間に閉じ、`git add .` は使わない
- コメントが docs 番号とファイルパスを指している。移動のたびに
  `grep` で追随しないと、次の読み手が迷子になる
- `MemoEditor` の react-hooks 抑止は理由付き。消すときは再現確認 (§5-2)
- `@types/node` を 24 に上げると、`Buffer`/`fetch` 周りで型エラーが
  出る可能性がある。Phase 0 の中で単独 PR に
- `MenuIcons` の分割は 30 か所の import 書き換えを伴う。バレルを
  置いてから中身を割る (順序を逆にしない)
- 未テストの `secret/` は暗号処理。分割の前に、既存の
  `secretKeyring.test.ts`・`secretEnvelope.test.ts` を土台に
  `secretUnlock`・`secretApi`・`secretPrf` のテストを足す
- Prisma の型を client 部品が `import type` している 7 か所は、
  §2-2 の `no-restricted-imports` で誤って値 import に変わらないよう
  `import type` のみ許可にする
