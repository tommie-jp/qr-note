# ページ計画

ノートを**ページの集まり**として扱えるようにする。編集画面の ＋ で新しい
ページを足し、閲覧画面はページ送りで読む。区切りの無いノートは 1 ページの
ノートとして今までどおり。

狙いは「長いノートを畳む」ことではなく、**1 枚に 1 つのことを書ける器**を
用意すること。問題集 (docs/58) は 1 ページ 1 問、レシピ (#1084) は工程ごと、
部品メモは「自分の測定 / 原文の仕様」で分かれる — どれも既に本文の中で
`---` を引いて手で分けている使い方で、それに画面を合わせる。

§8 の 1〜7 まで実装済み。実装して分かった判断は §4 (行番号) と §8 (置き場所)
に追記してある。

## §1 正本はメモ本文 — 表も列も足さない

ページは `items.memo` の中の区切りから**その場で導く**。`pages` テーブルも
`page_no` 列も作らない。

- `title` / `tags` / `props` / `task_todo` と同じ「正本は memo、他は派生」の
  延長線に置く。quiz フェンス (docs/58 §1) が専用テーブルを作らなかったのと
  同じ判断。
- 行に割ると、全文検索 (PGroonga の `items.memo`)・git 履歴
  (`notes/<itemNo>.md` の 1 ファイル。docs/57)・エクスポート
  (`src/lib/zip/noteFile.ts`)・オフライン同期 (`/api/sync/items`)・公開ビュー・
  画像 GC (docs/20) の**全部**に手が入る。派生にすればどれも無変更で済む。
- ページに固有の id を持たせない。持たせた瞬間に「本文を手で書き換えたら
  id とページがずれる」という、この app に無かった種類の壊れ方が生まれる。

## §2 区切りは mdast の `thematicBreak` (自前の正規表現にしない)

remark でパースし、`thematicBreak` ノードの `position` で本文を切る。
`src/lib/circuitFences.ts` が正規表現ではなく remark を使っているのと同じ
理由 — **表示側 (react-markdown) と必ず同じ解釈にする**ため。

ここは正規表現との差が実害になる。ローカルの写し (599 件) で確認した:

| 本文 | remark の解釈 | ページ境界 |
| --- | --- | --- |
| `赤LED` の次行に `------` | setext 見出し (h2) | **ならない** |
| 空行の次に `---` | thematicBreak | なる |
| ```` ```text ```` の中の `---` | code | ならない |
| `---　うどん出汁` (後ろに文字) | ただの段落 | ならない |

`---` を含むノートは 11 件あるが、**うち 10 件は `LED` / `電圧V` / `# 周波数`
の下に引いた表の罫線**で、CommonMark ではこれは setext 見出しの下線として
読まれる。自前の `/^-{3,}$/` だと表が真っ二つになるところを、AST に任せる
だけで避けられる。

実際にページが分かれるのは 4 件 (#1084 うどん・#4788・#4481・#1) だけで、
いずれも「自分のメモ ―― 原文」のように**意味の上ですでに区切り**。
**移行スクリプトは要らない**。

`***` / `___` も CommonMark の水平線なので remark は同じく区切りと読む
(実データには 0 件)。記法として案内するのは `---` 1 つに絞るが、他の 2 つを
弾く仕掛けは入れない — 弾くと「表示は線なのにページは分かれない」という
説明できない状態を作る。

見出し行 (`#` + 空白) を自動でページ境界にする案は採らない。既存ノートが一斉に
断片化するうえ、この本文では行頭 `#` がタグ記法と隣り合っていて、
「どちらのつもりで書いたか」を機械が決めることになる。

## §3 ページ名は「そのページの先頭行」から作る

`--- ページ名` と区切り行にラベルを載せるのは §2 の表のとおり標準の水平線から
外れる (remark は段落として読む)。代わりに `memoSummary()`
(`src/lib/memoSummary.ts`) をページごとに呼ぶ。

- `title` 列が「memo の先頭行から Markdown 記法を剥がした見出し」なのと
  **同じ規則**になる。目次・ページ送りのラベルはこれで足り、新しい規則を
  書き手が覚える必要がない。
- ノート全体のタイトルは今までどおり `memoSummary(memo)` = 1 ページ目の
  見出し。ページ化しても一覧の見え方は変わらない。

**`isStructureLine()` に水平線の行を足すこと。** いまは `---` を剥がす対象が
無いので、`---` で始まるノートのタイトルが `---` になる。既存データでは
先頭が水平線のノートが無いため表に出ていないが、ページを足す操作が
それを日常にする。要約と一覧プレビューが同じ関数を見ている
(`memoSummary` / `memoPreview` の「片方だけ直すと別の行が選ばれる」の約束) ので、
直すのはこの 1 か所。

## §4 閲覧 — ページ送りは client、描画は server

`MemoPanel` の作法 (Server Component を ReactNode の slot で受け取り、状態は
client が持つ) をそのまま重ねる。`<NotePager pages={ReactNode[]} />` を作り、
`markdownView` slot の中に入れる。

- 本文を描くビューは 3 つ — `ItemView` (持ち主)・`PublicItemView` (公開)・
  `OfflineNote` (オフライン)。**ページャは 3 つとも通す**。片方だけページに
  すると、同じノートが公開リンクでは 1 枚続きに見える。
- `MarkdownView` の中には入れない。docs ページ・quiz・シークレット断片も
  同じ部品を通っており、そこにページの概念は無い。
- 回路図 (`renderCircuits`) は今までどおり memo 全体に対して 1 回。ページごとに
  呼び直すと同じ図を何度も引くだけで、結果は変わらない。

**非表示ページは `hidden` 属性ではなく `hidden print:block` のクラスで隠す。**
理由は印刷 — `/print/<itemNo>` は QR シールのページで、ノート本文を刷るのは
`/item` のブラウザ印刷。`hidden` 属性で隠すと、いま開いているページしか
紙に出ない。クラスなら印刷で全ページを出せる。ページの間に
`break-before: page` を当てれば、画面のページと紙のページが一致する。

全ページを最初から描いてよい (mermaid は `mermaid.render` が body の一時要素で
描くので、隠れた枠の中でも壊れない。KaTeX も文字列描画、circuitikz は
サーバで描いた SVG)。ブラウザのページ内検索が全ページに効くのも利点。

- 現在ページは URL のフラグメント `#p3` で持つ。編集から戻ったとき・共有した
  リンクを開いたときに同じページが開く。範囲外の番号は 1 ページ目に丸める。
  フラグメントはサーバに届かないので、初期描画は必ず 1 ページ目でマウント後に
  合わせる。書き込みは `replaceState` — `pushState` にするとページを送るたび
  戻るボタンが 1 段深くなる。
- 1 ページのノートではページャの帯ごと出さない (「1 / 1」を見せない)。

**チェックボックスの行番号にページの開始行を足す** (実装して分かった一点)。
`rehypeTaskLines` が刻む番号はページの中で 1 に戻るのに、
`toggleMemoTaskAction` が書き換えるのは `items.memo` — 素通しにすると
2 ページ目のチェックを押したとき 1 ページ目の行が反転する。
`MarkdownView` に `lineOffset` を足し、足し算は `NoteBody` の 1 か所に置く
(3 つのビューへ配らない)。シークレット断片が `onToggleTask` を渡さないのと
同じ問題への別の答え — 断片は本文のどこから来たか判らないので押せなくする
しかないが、ページは開始行が判るので足せば押せるままにできる。

## §5 編集 — CodeMirror は 1 枚のまま、＋ は区切り行を挿す

**「今のページだけを `value` に渡して切り替える」方式は採らない。**

- undo 履歴がページごとに分断される。本文を触らずに装飾だけで済ませてきた
  ライブプレビュー (docs/70) の判断と真逆になる。
- `@uiw/react-codemirror` の `value` 同期は巻き戻りの前科がある。ページ切替の
  たびに全文を差し替えるのは、その経路を一番踏む形。
- 画像挿入・OCR・録音・シークレット・書式メニュー・下書き退避が、全部
  「いまどのページか」を意識する必要が出る。

代わりに **1 枚の本文のまま、ページ感はナビと装飾で出す**。

- ＋ボタン … カーソルのあるページの**直後**に `\n\n---\n\n` を挿入し、
  新しいページの先頭へスクロールしてフォーカスする。末尾固定にしない —
  5 ページ目まで書いた後に 2 ページ目を足したいことのほうが多い。
- 置き場所は下部バーの `EditToolbar`。**横スクロール帯の中でよい** (＋は
  ポップアップを開かないため)。目次・ページ操作のメニューを後から足すときは、
  書式メニューと同じく**帯の外**へ出すこと — 帯は `overflow-x-auto` を持ち、
  上へ開くメニューが切り取られる (EditToolbar のコメント参照)。
- ライブプレビュー ON のとき、区切り行を「── 3 ──」の帯ウィジェットにする。
  **縦の間隔は margin ではなく padding で取る** — ブロックウィジェットの
  縦 margin は CM6 の高さ測定から漏れ、図 1 つあたり数 px ずつクリック位置が
  ずれていく (fenceBlocks で踏んだ)。
- **空ページを畳まない。** ＋を押した直後は「末尾に空のページがある」状態
  そのもの。`splitPages` が空を捨てると、押しても何も増えていないように見える。

## §6 派生キャッシュと検索は**ノート単位のまま**

| 対象 | 扱い |
| --- | --- |
| 全文検索 (PGroonga) | 無変更。ヒット判定はノート単位 |
| `tags` / `props` / `task_todo` / `task_done` | 無変更。ページを跨いで合算 |
| `title` | 無変更 (= 1 ページ目の見出し)。§3 の `isStructureLine` だけ直す |
| git 履歴・差分 (docs/57) | 無変更。区切り行が diff に出るだけ |
| エクスポート ZIP・ENEX 取り込み・オフライン同期 | 無変更 |
| テキストタブ (`MemoPanel`) | 無変更。生の本文をそのまま出す (分割しない) |
| 一覧プレビュー (`NotePreviewThumb`) | **1 ページ目だけ**を描く。ノートの「表紙」になる |

タグやチェック数をページ単位に割る案は採らない。`is:todo` が「このノートに
残作業がある」から「このページに」へ意味を変えてしまい、検索式の意味が
ノートとページの間で揺れる。

検索結果から**当たったページへ着地させる**のは Phase 3。派生列は足さず、
ノートを開いた側で本文を分割して語を探す (600 件規模で列を足す理由が無い)。

## §7 本文 10,000 字の上限を先に上げる

`MAX_TEXT_LENGTH` (`src/lib/validation.ts`) は 10,000 字。現状の最大は
6,949 字・平均 262 字なのでまだ余裕があるが、**ページは本文が伸びる前提の
機能**なので、実装より先に上げておく。

- 上限を見ているのは 3 か所 — フォーム投稿 (`src/app/actions.ts`)・
  ENEX 取り込み (`src/lib/enex/importEnex.ts`)・ZIP 取り込み
  (`src/lib/zip/noteFile.ts`)。**同じ定数を全部が見ている**のが要点で、
  片方だけ緩いと「取り込めたのに保存し直せないノート」ができる (定数の
  コメントのとおり)。
- `src/app/api/circuits/route.ts` が「1 フェンスが MAX_TEXT_LENGTH を
  超えることはない」と前提を書いている。上げるならこのコメントも見直す。
- 32,000 字あたりが妥当 (1 ページ 500 字 × 60 ページ)。上げすぎない理由は、
  この列が pg_dump・git 履歴・オフライン同期の全部を通ること。

## §8 実装ステップ (TDD)

1. `src/components/notePages.ts` — `splitPages(memo): NotePage[]`
   (`{ name, body, start, end, line }`)。テスト先行:
   - setext 見出し (`LED` + `------`) を割らない
   - フェンス・折りたたみの中の `---` を割らない
   - 先頭・末尾の区切り (空ページが残ること)
   - 連続する区切り (`---` `---`)
   - `***` / `___` も区切りになること
   - 区切りが無ければ 1 ページ (`name` はノートのタイトルと一致)

   **`lib` ではなく `components` に置いた。** 折りたたみの構文
   (`remarkDetailsSyntax`) を描画側と共有するため — 知らないまま解析すると
   `:::details` の中の水平線でページが割れ、閉じられていない `:::` が本文に
   出る。`lib` から `components` を import すると層が逆になるので、置き場所の
   ほうを合わせた (`markdownPipeline` / `remarkDetails` と同じ棚)。

   水平線になりうる行が 1 行も無ければ remark を通さず 1 ページを返す近道も
   置く。一覧は 60 件をまとめて描くので効く (実データでは 599 件中 11 件しか
   当たらない)。近道の判定は**本物の規則より広く**拾うこと。
2. `isStructureLine` に水平線を足す (§3)。`memoSummary` / `memoPreview` の
   既存テストに「`---` で始まるノート」を 1 件足す
3. `MAX_TEXT_LENGTH` の引き上げ (§7)
4. `NotePager` (client) と `NoteBody` (分割 + 行番号のずれ) を足し、
   `ItemView` / `PublicItemView` / `OfflineNote` の 3 か所を `NoteBody` に
   差し替える。`#p3`・印刷で全ページ・1 ページなら帯を出さない
5. 編集の ＋ ボタン (`EditToolbar` + `MemoEditorInner`)。挿入位置と
   スクロールのテスト
6. 一覧プレビューを 1 ページ目に絞る (`notePreviewSource` の切り詰めの前段)
7. `docs/メモ記法.md` に「ページ」の節。**setext 見出しとの違い** (前に空行が
   要る) を実例で書く — ここを外すと、表の罫線のつもりで引いた線でページが
   割れたときに理由が分からない

## §9 対象外 (割り切り)

- **ページの並べ替え UI** … 本文の切り貼りでできる。git の diff では移動が
  「削除 + 追加」に見えるが、これは行指向の履歴を選んだ時点の性質
  (docs/57) で、ページに固有の話ではない。
- **ページごとの QR シール** … この app の「1 QR = 1 item」という物理との
  対応を変える話。紙のシールをページ単位で貼りたくなったら別の計画で。
- **ページごとの更新日時** … 正本が本文の外に増える。`updated_at` は
  ノート単位のまま。
- **ページを跨ぐ脚注** … ページは別々に描くので、1 ページ目で定義した
  `[^1]` を 2 ページ目から参照しても繋がらない (脚注の一覧はページごとに
  出る)。同じページの中で閉じて書けば今までどおり。ページを跨いで参照
  したくなったら、そこは 1 つのページにするのが素直。
- **隠れたページの画像の先読み** … `display:none` でもブラウザは `<img>` を
  取りに行く。ページ数が増えたノートで転送が増えるが、`?thumb=1` を使う
  一覧と違い本文は原寸を出す設計なので、ページを分ける前から同じ量だった。
  実測で困ったら `loading="lazy"` を検討する。
- **オフライン一覧の表紙** … `OfflineList` は行の部品が別実装
  (docs/71 §7 と同じ理由で保留)。
