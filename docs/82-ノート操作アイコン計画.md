# 82. ノートの操作をアイコンにする

`/item/<no>` の見出し行に並ぶ操作を、**色付きのアイコン**にする。合わせて
ページ送りを**やめて通しで読む**切り替えを足し、スマホでも説明が読めるように
**長押しの吹き出し**を用意する。

[75-ノート上部圧縮計画.md](./75-ノート上部圧縮計画.md) の続き。あちらは帯を
畳んで縦を詰めた。ここでは**横**を詰め、空いた分をアイコンに使う。

```text
変更前                                    変更後
─────────────────────────────────         ─────────────────────────────────
item #1 [🔒非公開][📴オフライン]           item #1 [🔒][☁]
編集 履歴 QR 記法                          ✏編集 ⑂履歴 ▣QR ▤ ▤記法

[前のページ] 1 / 3 テスト [次のページ]     [‹] 1 / 3 テスト [›]
```

実測 (幅 414px): 見出し行の高さは 92px のまま。トグルから文字を落とした分で
アイコン 4 つとページの切り替えを賄えている。

## §1 何を変えないか

- **押せる物は増やさない。** ページの切り替え 1 つだけが新顔で、他は同じ操作の
  見た目が変わるだけ。
- **文字を消すのは「状態を出すボタン」だけ。** 行き先のあるリンク (編集 / 履歴 /
  QR / 記法) は文字を残す — 4 つ並ぶので、絵だけにすると毎回読み解くことになる。
- 下部バー ([31](./31-下部操作バー計画.md)) と同じアイコンの作法に従う。
  ライブラリは足さない (`MenuIcons.tsx` の inline SVG)。

## §2 操作リンクは「色付きアイコン + 文字」

| 操作 | 絵 | 色 |
| ------ | ---- | ---- |
| 編集 | 紙と鉛筆 | emerald |
| 履歴 | コミットグラフ (既存の `HistoryIcon`) | orange |
| QR | 位置検出パターン (既存の `QrIcon`) | sky |
| ページ | 紙 + 送りの山形 / 上下へ続く帯 | indigo |
| 記法 | 本 | purple |

**色が重ならないことがこの一群の要件**。並んだ 4〜5 個を絵の形より先に色で
拾い分けるためのもので、同じ色が 2 つあると色で絞れなくなる
([31 §11-4](./31-下部操作バー計画.md) の「色はアイコン側が持つ」に従い、
色は `MenuIcons.tsx` 側に置く)。

`ACTION_LINK_CLASS` はもともと `gap-1.5` を持っており、アイコンの席は空けて
あった (`ui.ts` のコメント)。寸法は変えていない。

公開ビュー (`PublicItemView`) の QR も同じ見た目にする。持ち主が自分のノートを
未ログインのブラウザで開いたときに、同じボタンが別物に見えないようにするため。

## §3 ページ送りをやめて通しで読む

[74-ページ計画.md](./74-ページ計画.md) で入れたページ送りは、**書いた人の
区切り方**に画面を合わせる機能だった。読むときにそれが邪魔なこともある —
ページを跨いで探す・端から端まで一息に読む・印刷前に全部見る。

- 置き場所は **QR の右**。ページは「本文の読み方」の話なので、状態のトグル
  (公開・オフライン) ではなく操作リンクの側に並べる。
- **区切りのあるノートにだけ出す。** 1 ページのノートでは押しても何も変わらず、
  押せるのに何も起きないボタンになる (数えるのは `ItemView`。本文を描く
  `NoteBody` は本文パネルの奥に居て、ページ数を見出し行へ返す道が無い)。
- 通し表示は**画面が印刷と同じ積み方になる**だけ。枠も定義の配り方
  ([74 §4](./74-ページ計画.md)) もそのままで、隠す class を外し、継ぎ目に
  本文の `---` がもともと引いていた罫線を戻す。帯 (前後ボタン・「1 / 3」) は
  出さない — 送る先が無いのに置くと、押しても何も起きないボタンが並ぶ。
- `#p3` は通し表示でも効かせる。開く代わりに**そこまでスクロールする** ——
  共有されたリンクが「開いても何も起きない」にならないように。ページ送りから
  切り替えた瞬間も、読んでいたページの位置に留まる。
- **本文の中のアンカー (脚注・「本文に戻る」・手書きの `[x](#id)`) には手を
  出さない。** 隠れたページが無いのでブラウザのジャンプは必ず実在する要素に着き、
  ページを開くための細工 ([74 §4](./74-ページ計画.md)) はここでは要らない。
  同じ脚注を 2 ページから参照していると文書順で最初の写しに着くが、着く先は
  同じ文章で、これは [74 §9](./74-ページ計画.md) で承知した割り切りのまま。

### 設定の正本は localStorage (React の外)

**ノート単位ではなく端末単位**にする。ページ送りが煩わしい人はどのノートでも
煩わしいはずで、ノートごとに覚えると開くたびに本文の長さが変わって落ち着かない
([70 §4](./70-編集ライブプレビュー計画.md) の判断と同じ)。

切り替えるボタンは見出し行に、切り替わる本文は本文パネルの奥にあり、
**間に Server Component が挟まる**ので props でも context でも繋げない。
`localStorage` をそのまま正本にして `useSyncExternalStore` で購読する
(`lib/notePagerPref.ts`。`secretSession.ts` と同じ形)。

- サーバ描画では必ず既定 (ページ送りあり)。端末の設定はブラウザにしかないので、
  `getServerSnapshot` に既定を返させてハイドレーションの食い違いを避ける
  (effect で `setState` する形は、React の lint が止める上に一瞬ちらつく)。
- 公開ビュー・オフラインの本文も同じ購読を通る。同じノートが画面によって
  違う積み方に見えないため ([74 §4](./74-ページ計画.md) と同じ理由)。

## §4 前後のページはアイコンだけ

帯の前後ボタンは山形 (`‹` `›`) だけにして、`COMPACT_ICON_BUTTON_CLASS` の
36px 角に収める。空いた横幅はページ名に回る (長い見出しほど切り詰められていた)。

名前は `aria-label` と長押しの吹き出しに残す。ノート内検索の一致送り
(`ChevronUpIcon` / `ChevronDownIcon`) が上下なのに対し、こちらは左右 —
向きで見分ける。

## §5 長押しの吹き出し (`PressTip`)

アイコンにした操作は絵だけでは意味が判らないことがある。PC は `title` の
ホバーで読めるが、**スマホにはホバーが無い** — [75 §3](./75-ノート上部圧縮計画.md)
で「説明は tooltip へ移した」と書いたものは、スマホでは読めない場所へ移した
のと同じだった。長押し (0.5 秒。`lib/longPress.ts` の閾値を流用) をその読み口
にする。とくに [65 §7](./65-オフライン対応計画.md) の「印を付ける前に落とす量を
出す」が、これでスマホにも戻る。

実装で効いている判断は 4 つ:

1. **子ではなく包みに手を付ける。** 中身は `Link` だったり `<form>` の中の
   submit ボタンだったりと様々で、それぞれに長押しの結線を配ると同じ仕掛けが
   散らばる。押下も click も包みまで上がってくるので、包み 1 枚で足りる。
2. **握り潰しは `onClickCapture`。** 長押しを終えて指を離すと click が続く。
   包みの `onClick` (バブリング) では遅い — `next/link` は自分の `onClick` の
   中で遷移を始め、`ConfirmSubmitButton` は自分の `onClick` で `window.confirm`
   を出す。capture なら子より先に走り、`stopPropagation` でそれ自体を止められる
   (`useLongPress` が返す `onClick` の中身は preventDefault + stopPropagation
   なので、そのまま capture へ移し替えるだけで足りる)。
3. **portal で body へ出す。** `fixed` の基準は直近の filter / backdrop-filter /
   transform を持つ祖先になる ([62 §3](./62-下部バー長押し計画.md) で `SlotMenu` が
   `fixed` を避けた罠)。押した点に出す物なので、基準は必ず画面でなければならない。
4. **横は画面を 3 つに割って寄せる。** 押した点にぴったり合わせると、行の端の
   アイコン (左端の公開トグル・右端の記法) で吹き出しが画面の外へ出て、
   **ページごと横スクロールする**。器を `inset-x-2` の全幅にして寄せるだけなら、
   幅を測らずにはみ出しを防げる。

右クリックは奪わない (`rightClick: "native"`)。PC にはホバーの tooltip が
あるので奪う理由が無く、リンクの「アドレスをコピー」を潰すほうが損
([66 §5-2](./66-行アクション計画.md) と同じ判断)。

指を離した後も 2 秒は残す。長押しの最中は指が吹き出しを隠しており、読み始めるのは
離した後だから。他の場所への押下とスクロールでも消す (`fixed` なので、
スクロールすると何も指していない吹き出しが貼り付いたまま残る)。

## §6 状態のトグルはアイコンだけ

| 状態 | 絵 | 色 |
| ------ | ---- | ---- |
| 非公開 | 南京錠 | 灰 |
| 公開中 | 地球儀 | 緑 |
| 印なし | 雲 (中身はサーバのまま) | 灰 |
| 印あり | 受け皿へ落ちる矢印 | 青 |

`STATE_TOGGLE_CLASS` を 44px 角にして文字を落とす。状態は絵と色で言い、名前は
`aria-label` が、説明は長押しの吹き出しが言う。**既定の状態 (非公開・印なし) を
読み上げるためだけに見出し行の幅を払わない**というのは、帯をやめたとき
([75 §1](./75-ノート上部圧縮計画.md)) と同じ判断の続き。

オフラインは色だけの区別にならないよう絵を変える。**斜線を入れた雲 (圏外の印) に
はしない** — あれは「通信できない」という状態の絵で、ここは「中身がどこに
あるか」を出している (`OfflinePinIcon` のコメントと同じ判断)。

ページの切り替えも文字を持たない。ここだけ文字を足すと、区切りのあるノートで
操作の行が 1 行増えて本文が下がる (幅 414px で実測) — ページを畳んで本文を
早く出すための機能が本文を押し下げるのでは元も子もない。

## §7 対象外 (割り切り)

- **アプリ全体のアイコン化** … 長押しの吹き出しを足したのはこの画面の操作
  だけ。下部バーのスロットは長押しを**メニュー**に使っており
  ([62](./62-下部バー長押し計画.md))、同じ指の動きに 2 つの意味を持たせない。
- **ページ送りの設定を端末間で同期** … 端末ごとに画面の高さが違うので、
  むしろ揃わないほうが素直。DB に列を足す話にもなる。
- **通し表示でのページ名の表示** … ページ名は先頭行の見出しから作っている
  ([74 §3](./74-ページ計画.md)) ので、本文にほぼ同じ字が続けて出る。
- **吹き出しの矢印 (三角の突起)** … 押した点に寄せて出しているので、指の
  すぐ上に出れば対応は判る。端で寄せた分だけ位置がずれる形なので、突起を
  付けると逆に「何も指していない矢印」になる。
