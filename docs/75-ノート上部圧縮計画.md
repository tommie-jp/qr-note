# 75. ノート画面の上部を 1 行に畳む

`/item/<no>` を開いたとき、本文が画面のかなり下から始まっていた。見出し行の
下に「🔒 非公開」の帯と「📥 オフラインで使う」の帯が全幅で 2 段積まれ、
`space-y-4` の隙間と `main` の `pt-6` がそこへ乗っていたため。

新しい機能は足さない。**同じ操作を縦に細くする**だけの変更
([62-下部バー長押し計画.md](./62-下部バー長押し計画.md) と同じ性格の直し)。

```text
変更前                                    変更後
─────────────────────────────────         ─────────────────────────────────
item #1094      編集 履歴 QR 記法          item #1094 [🔒非公開][📴オフライン]
                                                       編集 履歴 QR 記法
🔒 非公開            [公開する]           #電験三種 #理論 #過渡現象 #難
                                          markdown テキスト 編集
📥 オフラインで使う — 添付…  [保存をやめる]
                                          電験三種 理論 過渡現象 問8 …
#電験三種 #理論 #過渡現象 #難

markdown テキスト 編集
```

実測 (幅 618px): 本文パネルのタブ行が 300px 付近から 150px 付近へ上がった。
本文が始まるまでに画面の高さの半分近くを使っていたことになる。

## 1. 帯をやめる判断

どちらの帯も**状態を 1 語で言えば足りる**ものだった。非公開もオフライン印なしも
このアプリの既定の状態で ([62 §8](./62-下部バー長押し計画.md))、ノートを開く
たびに全幅の箱を 2 つ読まされる値打ちはない。**既定の状態の説明に、いちばん
高い場所を払っていた**のがそもそもの間違い。

## 2. 状態と操作を 1 つのボタンが兼ねる

見出し行の右へ、`STATE_TOGGLE_CLASS` (`src/components/ui.ts`) の小さな
ボタンとして 2 つ並べる。

- **ボタンに書くのはいまの状態**で、押した後の動作名ではない。1 つのボタンが
  状態と操作を兼ねる以上、「公開する」と書くと「いま公開中」と読み違える
- 高さは `min-h-11` (44px)。隣の `ACTION_LINK_CLASS` と同じで、**行は伸びない** —
  見出し行はもともと 44px のリンクを持っている
- 文字だけ `text-sm`。見出し + トグル 2 つ + 操作リンク 4 つを 1 行に収めたい。
  幅 390px では 2 段に折り返す (`flex-wrap`)
- 色は状態ごとに呼ぶ側が全部持つ。`SECONDARY_SKIN` を流用すると素の `bg-white`
  が `bg-green-50` と衝突し、勝敗は「クラス属性の並び順」ではなく「CSS 内の
  定義順」で決まるため意図した色にならない (`BOX_SKIN` を `py` と分けたのと同じ罠)

| 状態 | 見た目 |
| ------ | -------- |
| 非公開 | 🔒 非公開 (灰) |
| 公開中 | 🌐 公開中 (緑) |
| 印なし | 📴 オフライン (灰) |
| 印あり | 📥 オフライン (青) |

オフラインの 2 状態は文字が同じで、違いは絵と色だけ。色だけの区別にならないよう
絵を変え、読み上げには `aria-pressed` で状態を渡す。公開のほうは文字が状態
そのものなので `aria-pressed` は付けない (二重に読まれるだけ)。

## 3. 消えた文は tooltip へ

帯にあった説明と添付の量は `<form>` の `title` に移した。tooltip は祖先から
引かれるので、`ConfirmSubmitButton` に prop を足さずに済む。

| どこ | 中身 |
| ------ | ------ |
| 非公開 | ログインした人だけが見られます |
| 公開中 | この URL を知っていれば誰でも見られます |
| 印なし | オフラインで使う（添付 12.3 MB） |
| 印あり | 保存をやめる（端末から消す） |

**承知の損**: スマホでは tooltip が実質読めない。とくに
[65 §7](./65-オフライン対応計画.md) の「押す前に落とす量を出す」は、スマホでは
出ないのと同じになった。それでも畳んだのは、量が要るのは**印を付ける一瞬**
だけで、その 1 回のために全ノートの上部を 1 行分払うのは高いと見たため。
添付の無いノートでは括弧ごと出さない (「（添付 0 B）」は読む値打ちがない)。

## 4. 公開の事故は文ではなく確認で止める

公開は事故ると取り返しがつかない (見た人の手元からは消せない) ので、
[22 §7](./22-ノート公開計画.md) は「状態を文で書く」ことでそれを守っていた。
文を畳んだ分は、**押した瞬間の確認**に置き換える。

- 非公開 → 公開の側だけ `ConfirmSubmitButton` を通す
  (`#1094 を公開します。URL を知っていれば誰でも見られます。よろしいですか?`)
- 公開 → 非公開は確認なし。押し間違えても元に戻せる
- オフライン印はどちらの向きも確認なし。外せば消えるだけ

送るのは今までどおり**望む状態** (`public=1` / `0`、`pin=1` / `0`)。
裏返す作りにすると二重送信や戻るボタンで意図と逆に倒れる。

## 5. 縦の隙間

- `main` の `pt-6` → `pt-2` (`src/app/layout.tsx`)。**全ページに効く**
- `ItemView` の `space-y-4` をやめる。見出し行・タグ・本文パネルは地続きに積み、
  間隔が要る物だけが自分で余白を持つ:
  - 通知の束 (未登録の案内・ゴミ箱バナー・URL 欄) … `space-y-3 py-3 empty:hidden`。
    1 つも出なければ箱ごと消えて余白も残らない
  - タイムスタンプ … `mt-4`。本文と地続きだと本文の続きに見える。
    余白は使う側が持つ (`ItemTimestamps` は `/edit` と公開ビューでも使う)

### 5-1. 踏んだ罠

- **`&&` ではなく三項で `null` を返す**。`item.url` が空文字だと `&&` は `""` を
  返し、空のテキストノードで `:empty` が外れて余白だけが残る
- **`SavedToast` は束に入れない**。画面下部に浮く `fixed` なので場所は取らない
  のに、束が「空でない」状態になる。消えるまでの 2 秒だけ余白が開き、消えた
  瞬間に本文が跳ね上がる
